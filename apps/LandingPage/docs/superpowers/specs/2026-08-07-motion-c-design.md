# C 方案：轻微视差产品叙事动效

## 目标

把落地页的过渡和动画从“元素各自出现”改成有连续节奏的产品叙事：用户滚动页面时，能感受到自己正在靠近一款游戏，而不是被一组动画效果打断。

## 设计判断

采用 C 方案「轻微视差，像走进游戏」作为第一版动效方向。它借鉴 Apple 产品页常见的固定舞台、分层运动和克制停留，但不使用持续漂浮、夸张缩放、技术进度条或 3D 模型。

动效只服务三件事：

1. 帮助用户知道现在读到哪一层内容。
2. 把“想法 → 感觉 → 场景 → 试玩”变成连续的一次体验。
3. 让游戏画面有一点空间感，但不抢走文案和产品价值的注意力。

## 交互与动效语言

### 1. 首屏：三层轻微深度

- 背景游戏画面保持满屏，但随指针和页面滚动只做极小幅度位移，避免图片像普通轮播一样跳动。
- 遮罩层不移动，保证文字对比度稳定。
- 标题、正文和按钮作为前景层，只产生 2–6px 的反向位移，形成“文字浮在场景上”的感觉。
- 首屏进入动画采用一次性的阶梯揭示：标题先出现，正文稍后，行动按钮最后出现；进入后不反复播放。

### 2. 内容页：滚动进入、一次完成

- 页面各 section 在进入视口时才开始揭示，使用透明度、12–24px 位移和很小的模糊变化组合。
- 每个 section 的标题、正文、列表按 80–120ms 间隔错开，避免整块同时跳入。
- section 离开视口时不反向播放，避免上下滚动时产生晃动。
- 取消依赖浏览器支持度不一的全局 `animation-timeline` 作为唯一入口，使用 `IntersectionObserver` 作为主逻辑，并保留 CSS fallback。

### 3. 第三页：固定画布中的创作转变

- 第三页视觉画布在桌面端保持稳定，右侧文案随页面自然阅读。
- 进入第三页时，四个阶段按现有文案顺序推进；只有画布内部内容改变，外框、尺寸和定位不跳动。
- 阶段切换使用“上一层淡出 + 下一层轻微上移淡入”的共享过渡，而不是四种不同动画。
- “让场景成形”阶段继续使用便利店场景的简化构成，但各层只做一次短暂的出现动画；“亲自试玩”阶段使用现有便利店游戏插图，并加入很轻的前景选择提示视差。
- 阶段不再依赖定时器，而是由第三页的滚动进度驱动；鼠标悬停和键盘聚焦不会抢走滚动控制，点击阶段按钮会平滑滚动到对应节点。
- 现有阶段按钮继续保留，作为手动控制和无障碍入口。

### 4. 指针反馈

- 保留当前光标圆点，但只在可悬停设备上显示。
- 页面元素可读取统一的 `--parallax-x` / `--parallax-y`（范围 -1 到 1），仅应用于允许产生深度的图层。
- 不把指针位置用于文字、表单和可交互控件的布局，避免误触和布局抖动。

## 技术边界

- 使用 React 状态、`IntersectionObserver` 和 `requestAnimationFrame` 的单一调度点；不引入动画库。第三页通过固定画布和滚动进度形成多屏叙事。
- 所有持续监听都在组件卸载时清理。
- 不新增图片素材；复用 `/images/game/hero-game-native-v1.png` 和 `/images/game/store-choice-v1.png`。
- `prefers-reduced-motion: reduce` 下取消位移、模糊、阶段自动播放和指针视差，但保留内容、按钮和阶段切换功能。
- 移动端降低视差幅度，第三页保持正常文档流，不使用桌面端 sticky 行为。

## 涉及文件

- `src/App.tsx`：补充归一化指针坐标，提供页面级视差变量。
- `src/components/NarrativeSections.tsx`：增加 section 可见性、第三页自动播放可见性和暂停逻辑；保持现有多语言结构。
- `src/styles.css`：重做首屏分层、section 揭示、第三页共享切换和移动端/减少动画规则。
- `src/__tests__/App.test.tsx`：覆盖第三页阶段控制和用户交互暂停行为。
- `src/__tests__/responsive-css.test.ts`：覆盖视差变量、可见性状态和减少动画规则。

## 验收标准

- 首屏不再出现文字和背景同时突兀跳入；三层有明显但克制的先后关系。
- 页面滚动到各 section 时，内容只揭示一次，不会因为来回滚动持续抖动。
- 第三页滚动时四个阶段依次推进，固定画布不跳动；点击阶段按钮会定位到对应节点。
- 桌面端和窄屏布局没有横向溢出；移动端不会因为视差或 sticky 造成内容重叠。
- 减少动画设置下页面仍完整可读，且测试、构建和 `git diff --check` 均通过。
