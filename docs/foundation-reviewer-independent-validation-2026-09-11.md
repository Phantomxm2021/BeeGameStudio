## 新发布门槛

1. **程序生成覆盖清单。** 根据冻结八文档与需求的原文行号、标题与最多 24 行分段生成 source units，保留表格/代码块/图示内容，不依赖模型自己宣称审过哪些材料。每个单元必须有核查结论、完整来源区间；显式文档依赖必须带上目标文档证据。重复项、漏项、越界和静态不确定项不能通过。
2. **机械问题由宿主产生。** 检查闭合输入集合中的 Markdown 内联文档链接、显示的文档名与目标，以及显式公式 ID 声明表/标题。跳过外部 URL、代码示例和注释，不把明确的公式“系列”误认为单个 ID。不猜相似名字，也不把固定实验问题写入规则。程序 findings 由宿主追加，模型不能抑制或伪造。
3. **每条语义结论必须有证据结构。** 记录对象、属性、作用范围、actual/expected 两侧的原文摘录、合理替代解释及为何仍不成立。原文位置与摘录由程序核对；计算 ID 和结果必须匹配实际成功执行的宿主工具记录，不能用模型写出的 ID 代替执行证据。
4. **全新会话独立复核。** 主审结束并结算后关闭原进程，使用相同模型配置启动新的 Reviewer 验证会话，重新提供原始输入、宿主覆盖清单、候选报告和已核实计算记录；不继承主审对话、隐藏推理或自检保证。复核必须逐单元、逐语义 finding 给出原文证据和 supported/unsupported/uncertain 结论，并列出遗漏。大输入不能继承主审的分页读取记录，验证会话必须自己完成读取。
5. **未通过不发布。** 有缺项、不支持、不确定或新发现遗漏均阻止报告发布。明确复核否决不自动反复调用模型索取通过；主审结构纠正有独立的有界次数限制。取消、预算、真实 usage、结算与重放仍覆盖两个阶段。结算失败后重试账务不会重跑已完成模型步骤。
