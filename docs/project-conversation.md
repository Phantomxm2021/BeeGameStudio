# 项目 Agent 与交付状态

## 目标

一个项目由同一个原生 Agent 会话承接原始目标和后续对话。“修复按钮文字”“玩家速度调快”“为什么画面不对”不会启动新的交付阶段或重跑已完成内容。

## 实现边界

- HTTP 入口负责身份、项目归属、附件、请求 ID 和并发互斥。
- `project-conversation.ts` 将原始输入交给项目主会话，不创建 implementation worker，不添加影响分析阶段。
- Session Manager 负责流式事件、权限、计费、停止及原生会话恢复。同一项目连续请求复用 Claude Code 会话；语言变更只重启传输并恢复原生 UUID。
- Agent 自行决定调查范围、工具、委派与修改顺序。涉及玩法/数值需求时，同步相关文档和实现；不把文档永久锁成只读，也不强制整套文档重写。是否允许修改仍以用户请求和原生权限为准。
- 资源、生图、Preview 能力按需查阅；能力文件不包含原需求的扩大改写。测试浏览器清理不关闭用户的项目 Preview。
- 新项目不创建旧阶段 `run.json`，也不启动阶段 worker 或 checklist drafting。主机保存原始目标、当前交付里程碑、暂停状态与当前版本的验收收据；Agent 自行决定工作顺序、是否委派及如何验证。
- 旧阶段控制器及其生产入口已移除。磁盘上的旧 run 仅作历史记录，不驱动项目请求、继续、停止、排队或 Chat 上下文，也不与原生交付状态双写。

## 消息与结果

- 用户原文只记录一次。网络重发按 `clientMessageId` 幂等，不按文本去重。
- 内部续做指令和历史 worker 指令保留在审计 transcript，但不进入 Chat；不改写历史事件或编号。
- 普通请求使用原生最终结果，不要求额外 `runtime-*.json`，不把一次回复当作验收通过。
- 修改不会重置已完成任务、重建资源或重跑文档阶段。未交付时的新里程碑或新增校验信息由同一原生会话接续，不凭旧阶段记录派遣其他 Agent；用户明确停止后不自动续做。
- Agent 提交 `.beegame/delivery/acceptance.json`，主机仅在报告、证据、构建输出与源码版本均新鲜时记录交付收据。发布门禁再次核对这些字节；Chat 中的 `passed` 不等于交付通过。
- 完整交付的 `passed` 还要求在实际目标运行环境验证约定范围；模拟渲染只能作诊断。首版范围内有已知问题或未验证要求时，报告为 `failed` 或 `blocked`，不能用 `passed` 抵消。Scene/UI/VFX 注册表不接收通用玩法配置，项目自有共享数值数据由游戏自行加载，不能在文档里承诺一个不受支持的内容类型。
- “继续”恢复同一 Agent 和原目标；并发继续只认可当前运行中的一轮。旧 `workflow/retry` 不用于新项目。

## 无费用验收

临时项目与模拟 runner 验证：新项目只启动一个主 Agent、不生成旧阶段 run、后续对话不重复显示用户消息、停止/继续和 queue/steer 维持同一会话、旧 run 不能重新派遣 worker、源文件/证据/构建改动使发布验收失效。离线测试不代表真实模型交付、浏览器游玩或耗时验收；不调用模型、不修改示例项目。

直接 CLI 与 BGS 的耗时/质量对照必须使用同一份已确认需求和首版范围；不能将仅含一句创意且允许 Agent 自行扩张的 CLI 项目，与已限制为小型首版的 BGS 项目直接比较。
