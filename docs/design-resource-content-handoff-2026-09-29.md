# 文档 → 资源 → Content 调整

## 范围与依据

仅修改系统，不修改私有测试项目。不新增阶段、自动续跑或发布门禁。
已证实问题：文档最小尺寸布局相交；资源阶段跳过计划图集；字体来源误记；Content 重复补偿居中锚点、固定遮罩、未采用计划 Tilemap。

参考 Unity 的锚点/Pivot/父容器与资源组织原则，不移植其引擎或默认坐标方向：
- https://docs.unity.cn/Packages/com.unity.ugui%402.0/manual/UIBasicLayout.html
- https://docs.unity3d.com/Manual/class-SpriteAtlas.html

## 修改与验收

1. Author/Review：明确父容器、pivot、尺寸策略；在参考和最小支持尺寸核算占用矩形。Scene 区分世界与取景，不拉伸世界适配屏幕。不扩大平台范围。
2. 资源：兼容采样、共同加载的小精灵优先图集；大背景/字体/音频/模型分开。生产来源不改变交付结构；真实记录下载来源、验证解码。已有图集/引用校验继续使用，不增加另一套验证器。
3. Content：现有 check-content 增加可选只读 --layout 命令，复用 Editor 的响应式和坐标函数，输出 anchor/pivot/最终矩形/越界提示；不修改数据、不把有意重叠判失败。

示例：`bun .beegame/delivery/check-content.mjs --layout ui/start.json 640 360`。
以实际项目约定的尺寸运行；输出不是视觉 PASS。文字换行、遮挡、层级和美观仍需现有 Editor 预览。动态状态应切换后观察。世界空间 UI 不用屏幕矩形判定适配。

免费回归覆盖：重复减半宽、居中、伸展遮罩、嵌套偏移、响应式、旋转/Pivot、禁用子树、非法几何、CLI 参数与只读行为。
后续新项目实测：文档布局成立；图集结构与规划一致；UI/Scene 数据和 Editor 一致；实际运行消费数据。未实测前不宣称质量或耗时已改善。

## 自审边界

辅助函数只计算已有契约，没有新运行引擎。越界提示不等于错误（可有动画起点/滚动内容），几何不证明字形或遮挡。没有自动判断文档语义与美术风格，图集不适用于所有资源。

## 来源无关的图集交付补充

- AI、程序绘制、资源库的静态小精灵遵循同一图集原则，按共同使用和采样需求分组，不按生产工具分组。
- AI 优先一组一张素材表；程序绘制优先直接画入共享图片并由坐标输出帧数据。已有单图可整理入图集，不必重做美术。
- 大背景、独立加载内容分开；动态文字、血条和简单实时几何不强制烘焙。
- 运行时按解析后的 URL 共享进行中的加载与解码结果，帧引用区域；资源生命周期结束后释放。不同时加载同用途的源图和图集，不承诺自动合批。
- Scene Editor 现有 texture-cache 已共享加载，区域视图共享 THREE.Source，无需新增加载器。补测并发共享、最后使用者释放、失败释放后重试；不据此推断所有生成游戏都已正确缓存。
