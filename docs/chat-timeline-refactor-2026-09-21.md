# Chat 整理：实施进度与后续验收

## 范围

本次先修消息身份、Thinking 边界、历史与实时一致性，以及必要的工具详情。前两阶段仅离线验证；第三阶段获用户授权后构建并重启服务。未运行付费模型、未修改用户项目的原始 transcript 或 native log。工作区已有的其他改动保留。

## 已实施

- Native trace 保留 message/block、源事件时间；Thinking 与正文均使用带身份的脱敏快照，不再按字符串长度推测增量。
- SDK 的单 block 最终回执关联原始 block，不把回执数组下标当作源 index。同消息多个文本 block 不再被 message 级去重丢弃。
- 保留正文中的空白 delta；最终正文校准对应 block；迟到 partial 不再重开已完成正文。
- 项目 Chat 使用持久化 append 序号；SSE 与历史共用该序号，取消查询时的重新排序编号。
- 历史压缩按执行范围、消息、block 归并；保留中断正文和完整工具结果，去掉工具输出截断。
- 有原始证据可重建的旧 stage 投影由重建结果取代展示，避免新旧身份同时出现；不删除原始记录。
- 前端正文按 message ID 更新，支持快照替换；保留各块 streaming 状态。接收成功后才推进游标。
- SSE 增加静默超时，忽略已应用游标，保护项目切换后的过期回调，恢复可见时重连补取。
- Thinking 独立计时，完成后停止；未知时长不填 0，亚秒显示“少于 1 秒”。
- 工具活动仍复用 BeUI AgentActivity，详情复用 ToolResult + Drawer；输入输出完整可查，失败显式标记。

## 本阶段验证

- 新增测试覆盖：原始 Thinking 边界与时间、同 query 多消息、同消息多文本 block、并行 Thinking、迟到快照、中断正文、长工具输出、持久游标、worker mirror 去重、读取重启、交错正文、UTF-8 分片、重复 SSE 游标、心跳超时和工具详情。
- 对 rainy-lighthouse-idle-scene 的 author 原始日志离线回放：49,846 行 → 81 个 Chat 事件 → 46 个历史展示记录；2 个最终文本块与源文本逐字一致，0 个孤立 partial。该统计是指定已结束 author 日志的结果，不代表所有阶段都已完成验收。
- 前端与后端类型检查、相关测试作为交付门槛；不把测试数量当作产品验收完成的依据。

## 第二阶段：增量读取与记录分离

- Native worker 新任务将脱敏后的模型内容、Thinking、工具与 task 生命周期写入独立 `chat-events.jsonl`；运行遥测继续写入 `native-events.jsonl`。不再将同一正文复制到诊断文件。独立 worker 可以跨 API 生命周期运行，因此必须保留它自己的持久内容来源。
- 去掉 Chat checkpoint 的旧 8 MiB block / 128 MiB 诊断容量截断。内容落盘失败会报错，不伪装成正常完成；脱敏和私有字段排除仍然有效。
- 历史恢复和 live follower 共享增量文件读取与 stage projector；每轮只解析新增完整行。中文 UTF-8 分片、未写完的尾行会在下次继续，文件替换/截断会重建投影状态。
- 同一任务存在专用 Chat 文件时只读取它；旧任务没有该文件时才从原始诊断记录回放。没有改写或删除用户项目的历史记录。
- 主 session / worker transcript 也改为增量读取，移除原来用于检查路径而额外读取整份 transcript 的操作。并发历史/SSE 查询共享一次正在进行的汇总。
- SSE 直接推送只复制游标之后的数据；客户端取消 reader 时立即唤醒连接清理并退订。journal 普通追加失败不会污染后续追加队列；初始 journal 读取损坏仍明确失败，不绕过。

### 第二阶段验证

- 22 个后端/原生链路测试、76 个相关前端测试通过；后端类型检查通过。120 秒自动后台慢测试未执行。
- 本地模拟模型 + 已有 CLI 的后台任务与中断集成测试通过：Chat 文件包含部分生成内容，诊断文件不含该正文；没有使用外部付费模型。
- rainy-lighthouse 项目全 stage 日志离线回放得到 262 条 Chat 事件、18 个 Thinking 结束事件；无新增数据时再次读取条数相同。本次单次采样首次约 86ms，后续约 3ms，仅为文件读取/投影测量，不是浏览器性能承诺。
- 指定已结束 author 日志的 2 个最终文本块，仍与新读取链路输出逐字一致。
- 未重启服务，未构建/替换正在运行的 CLI，未将离线验证当作线上已生效验收。

## 明确尚未完成

1. Chat 内容已与新任务诊断文件分离，热路径不再重复全文读取/解析；仍有文件目录发现、内存事件汇总和 worker 展示富化，不应宣称所有性能瓶颈或整个系统的日志整理均已完成。累计快照的存储成本和长期内存占用还需测量。
2. 原先已丢失的 Thinking start/index 无法精确恢复；历史记录只能依可用证据展示，不能伪造精确耗时。
3. 中断/取消的消息级收尾已补齐并测试，独立子任务不因父回合正常结束而被标成结束；真实运行中的整项目停止/并行子任务仍需端到端验收。Todo 全阶段历史已完成本项目验收；媒体及结构化引用的真实新任务链路仍待验证。
4. 长对话渲染/存储上限、滚动锚点和性能需实际浏览器测量。本阶段不宣称已消除所有卡顿。
5. 第三阶段已构建 CLI 并重启五个主服务，浏览器验证见下；尚未运行新付费模型任务，不能将已有历史展示或模拟 SSE 验证当作新模型运行全链路验收。

- rainy-lighthouse 全项目 journal 回放：123 条最终回执全部逐字保留，孤立 partial 从 4,386 降为 0。单元测试另外保留了真正中断、无回执的 partial，并验证并行子任务、工具边界及 journal 中途重启。

## 第四阶段：Todo、内容完整性与历史恢复

- Todo API 独立返回各阶段的 TodoWrite 更新，不依赖 Chat 当前分页。前端按来源 session、stage、stage stream/turn、parent tool 区分执行范围，使用原始任务 ID/完整内容识别任务，避免同名跨阶段任务和被缩短的路径误合并。UI 复用 BeUI TodoList，按阶段分组。
- rainy-lighthouse 项目 journal 回放得到 34 次归并后的 Todo 更新、4 个执行范围、30 项任务。真实页面验证文档编写 8、资源准备 6、内容编写 8、游戏实现 8，全部完成。进入 Todo 不触发 Chat 全历史加载。
- 历史恢复保留子任务详情、引用和已提供的附件。引用不再因为每组都从 source-1 开始编号而互相丢弃；来源链接只允许 HTTP(S)。用户图片和文件名可以显示，Markdown 图片限制尺寸并延迟加载。
- 删除 Markdown 层按 JSON 字段猜测并隐藏正文的机制；合法 JSON 显示完整原文，不再只取 summary/final，也不再把代码中的字面反斜线 n 和 wp_ 前缀替换掉。
- 删除 2,000 条消息的静默截断；显式加载的历史不会再丢失。批量历史合并用一次数组复制和身份索引，避免每条历史都复制和扫描全部消息。没有引入虚拟列表，也不宣称任意长度对话的性能已经解决。
- Scene Editor 加载/错误画面的 Escape 现在中止加载并关闭；编辑器 ready 后的快捷键仍由编辑器处理，避免绕过未保存提示。
- 附件审计发现失败回滚会递归删除整个历史附件目录：改为顺序写入、仅清理本次成功写入的文件。临时目录回归验证历史文件保留、失败批次文件移除；没有删除用户项目附件。

## 第五阶段：附件持久恢复与自动重连验收

- 新提交的图片和文档统一写入项目附件目录。传给模型的图片仍使用原始图片输入；用户消息只记录 type、storageId、文件名和 MIME，不把 base64 复制进历史日志。
- 附件读取接口复用项目所有权与 workspace 解析；限制为附件目录内的随机文件标识，拒绝路径穿越和越界软链接，设置 no-store/nosniff。测试确认重建 API 实例后仍可读取、另一用户不能读取。
- 修复 adapter → history → display 和 live → store 的附件字段遗漏。图片通过鉴权请求读取为临时 Blob URL，卸载时取消请求并释放 URL；文件显示原始文件名。旧日志未保存的图片仍无法凭空恢复。
- 删除 adapter 与 store 按相同用户文字合并消息的逻辑。不同 ID 的重复请求、多个空正文图片消息必须分别保留；仅匹配消息/client ID 的本地预显示消息与服务端回执才合并。旧测试把“不同 client ID 也合并”当作正确行为，本轮按消息身份标准纠正。
- 使用真实前端 SSE adapter + transport hook 验证静默 20 秒后的自动重连：从 after=1 续传、忽略已收事件、Thinking 结束保持 2 秒、收到最终消息。测试仅模拟网络字节流，不调用付费模型，不能替代新模型任务全链路验收。
- 浏览器真实项目连续分页：38 → 196 → 407 个 article，旧消息正常出现，视图留在历史内容区域。这里只证明分页可用，不把自动化工具耗时当成浏览器渲染性能测量。
