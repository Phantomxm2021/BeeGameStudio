# Reviewer 主流程收敛实施

## 工作方式

一个 Reviewer 保持全部八文档与已提供原始需求的上下文：

1. 理解整个游戏及各文档分工。
2. 找出疑点，回查相关原文；需要时调用只读 read 与 calculate。
3. 区分确定缺陷、合理分工/不同范围和待验证疑点。
4. 合并同根因问题，给出原文位置、实际/预期差异、实际影响和修订方向。
5. 补查正常流程与失败、暂停、恢复、重开边界，直接提交报告。

缺少原始需求时，只审查内部一致性、完整性和可实现性，不宣称符合未知用户意图。完整阅读不等于无遗漏；没有将上述步骤变成必须输出的表格或多个 Agent。

## 已切除

- 删除 single-agent-coverage.ts：不再提取 54 项候选清单、生成覆盖 ID、要求逐项填写或验证 coverageGaps。
- 删除覆盖实验测试，改为验证新审查接口不含这些协议的回归测试。
- 删除 amend_coverage 动作、补正执行分支和覆盖退回反馈。
- 移除针对样本逐次累积的 CROSS-DOCUMENT CHECK、INTERPRETATION CHECK 等专项提示，替换为完整阅读、统一判断、按需验证的简洁提示。
- 新模型 schema 不包含 coverage、numericEvidence、numericBindings、correct_draft。
- 移除生命周期反馈中的数值绑定/占位符/字段补正指令，以及 numericMismatches 分析负担。
- 可选草稿确认反馈不再要求数值证明协议；没有强制草稿或额外确认轮次。

## 保留及其边界

| 部分 | 责任 | 不承担的责任 |
| --- | --- | --- |
| 模型 | 整体理解、跨文档语义分析、验证疑点、报告真实影响 | 不以“全部读过”自证无遗漏 |
| 原文快照与引用校验 | 完整传入源文，验证引用范围并复制原文 | 不用引用存在证明判断正确 |
| read / calculate | 回读复制输入、执行明确表达式 | 不替模型选择事实含义或判定设计合理性 |
| 执行与计费保护 | 顺序运行、超时/轮数/重复工具保护、停止、结算与记录 | 不以预算耗尽冒充审查通过 |
| 可选草稿与引用补正 | 避免引用位置错误导致全文反复重写 | 不强制每次经过额外评审轮 |

保留旧 numericEvidence/coverage 字段形状、数值证明解析及历史诊断枚举，是为了读取和验证已有记录；它们没有暴露在新模型输出 schema 中。历史归档没有被删除或重写，旧覆盖实验没有被恢复为新流程，也未把未完成实验标成通过。

没有新建机械错链检查器：这一轮先切除偏差并恢复基线，不在清理时再叠加第二套审计系统。没有修改模型配置、源设计文档、Revision 或 Reviewer→Revision 集成。

## 验收与后续改动原则

工程验收检查原文无截断、缺失需求如实披露、直接 final 可发布、无覆盖清单协议、无模型数值补正协议、引用校验、只读工具边界、停止与计费、历史记录兼容。不能把这些测试通过等同于语义审查质量通过。

后续真实质量验证须在固定模型配置、输入和预算下进行；同时使用已知样本与未用于调试的新样本。分别统计：

- 明确问题的漏报；
- 无证据或错误范围解释产生的误报；
- 引用/计算/工具声明的准确性；
- 费用、耗时、重复与失败情况。

不以问题总数或模型的完整性声明判定成功。不把某一次 7/7 当成稳定达标，也不为命中一个已知错误把该错误写进提示。发现问题先分类为模型判断、上下文、工具、协议或执行错误，再做单一可验证改动；没有稳定收益的改动不保留。

本轮仅做工程清理与回归，没有新付费实测，因此不宣称 Reviewer 的语义质量已经修好。生产运行时的重启/发布与多样本模型验收是后续独立步骤。
