范围：仅复现已交付报告的错误，并修复测试执行器的认证续期与终态核验。**新增模型调用 0、真实认证/计费请求 0、费用 0。** 未改变 Reviewer 候选、提示、schema 或模型回合策略；不进入保留样本、真实八文档或旧协议退役。

## 离线复现的结果

| 原模型报告：S08 引用 UI 8–10 行 | 接受，与原报告完全一致 | 行号合法、原文物化准确，不代表该证据相关 |

后两项只是内存中的反例，不写回正式报告或评分样本，不送给模型。对“证据不相关”的标签来自先前逐条人工核对，程序没有新增一个能判断所有语义相关性的规则。S06/S08 在离线回归中的定向断言也不进入生产提示或模型输入。

复现输出保存于 `claude-code-main/output/reviewer-v2-offline-followup/reproduction.json`；其中 `meteringReplay` 是旧 3.7852 积分回执的离线核验，**不是本轮收费**。为验证纯终态核对函数而注入的历史 `leaseStatus=free`，不冒充一次新的在线进程清理检查。

## 对状态漏报的原因分析

已排除的路径：原始请求包含完整生产 base prompt；B24 为全文内联而不是分页，S06 的 `status=planned` 与当前汇总 `verified` 都已发送。最终模型原始响应本身就没有 S06 finding，并在 summary 把 S06 判为一致。宿主重放未删除 finding 或改写模型判断，计算工具也没有涉及该状态判断。

因此可确定：**这次直接状态矛盾的漏报已经发生在模型输出中，不是源文档丢失、截断或报告传输损坏。**

与输出相容的一种解释是，模型把“maturity/status 两字段独立”误泛化成“当前条目与状态汇总无需一致”，或未仔细对照第二次 status 声明。报告强调字段独立与已验证内部一致性，支持考虑这个方向，但不足以证明模型的内部推理过程。现有单次记录不能区分概念混淆、注意遗漏或过早自信收尾，也不能证明是稳定的模型能力上限。

本轮没有据此添加 S06 专用规则、自动字段抽取流水线、泛化关键词裁判或强制第二模型复核；语义质量仍是历史的未通过状态。

## 执行器修复

历史执行器及已停止的批次保持只读。新增仓库内继任入口 `scripts/reviewer-reliability/semantic-runner.ts`，并复用以下测试专用支持模块；未改产品认证/计费实现。

### 正常认证续期

- `evaluation-credential.ts` 区分短期 access token 到期与整段登录会话到期，保留 30 秒安全余量；首次绑定指定 owner 的一个 session，后续不能静默切换账户或会话。
- 需要续期时调用既有本机 GET `/api/auth/session` 核对 owner，再 POST `/api/auth/session/refresh`。正式服务负责 refresh token 轮换和落盘；执行器重新读取同一会话，确认新 token 已持久化并仍属于原 owner。不会自行写认证存储或导出 refresh token。
- 原来被忽略的 `forceRefresh` 已接通，并发续期合并为一次。只读配置查询可在确切 401 后强制续期并重试一次；不把普通 403/503 当作无限刷新理由。计费和模型调用不使用这个重试包装器。
- 覆盖现有 dashboard store 实际以错误消息前缀承载 HTTP 状态的形式；不会仅凭任意响应正文含“401”判断为认证失效。
- 认证请求禁止重定向、限定原 loopback origin，并设超时；配置请求也有取消超时。错误输出采用固定代码，避免原始响应或 token 泄漏。

### 终态核验

- `evaluation-finalization.ts` 不再仅凭 `status != running` 结束观察。必须等待执行锁为 free、所有 attempt 用量已封存且 usageObserved、正式 receipt 已保存并 settled。`native-turn` 封存本身不被误当成子进程退出。
- 核对 owner、attempt、用量、idempotency key、服务端 record/debit 事件和金额；完成报告还需匹配 publication/result digest。缺失或不一致即不能继续付费会话。
- 费用停止、超时或观察异常只请求一次 public stop，并使用独立的 120 秒收尾期限等待清理和结算；不复用已经耗尽的运行期限、不 resume、不重建 handle。不论是否交付报告，保存可得的完整状态与失败信息。
- 配置核验明确区分 unchanged / changed / unknown。读取失败或 30 秒核验超时记为 unknown，而非“已确认修改”；迟到的成功也不覆盖既成核验结果。只有 unchanged 可通过后续会话门槛。
- 无法核验完整结算时，最终积分记为 null，并另列已取得回执的已知金额，不把未知费用伪装为零。

继任入口默认仅预检。付费路径要求全新目录和单独批准的模型、次数、预算登记；它拒绝原历史批次及其归档路径。当前没有创建有效付费登记，也没有执行其模型路径。未来新批次仍需准备绑定新目录的捕获与冻结材料；本轮不借“修复执行器”恢复已取消的第二会话。
