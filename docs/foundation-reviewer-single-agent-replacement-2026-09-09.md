# Foundation Reviewer：单 Agent 全文审计替换

状态：源码入口与外层交接已切换，旧策略源码及专用协议已移除，离线回归已实施。运行服务尚未重启，真实模型质量验收尚未执行。本文替代旧 Reviewer 的事实提取、多专项审计与定向复审设计；历史验收记录仅代表当时实现。

## 目标与边界

Reviewer 继续是独立模块，唯一生产入口为 `stage-modules/foundation-reviewer/public.ts`。不得依赖 Author、Revision 或 Delivery Workflow 的 private 实现，不借用主会话、调度器或共享可变状态。外部只提供复制后的公开输入，以及绑定用户的配置、计费客户端。

每次审计由一个 Agent 读取完整八份文档和可用的已确认需求：整体理解、核实疑点、整理统一问题、最后检查遗漏。初稿和修复后的文档使用同一执行路径。没有事实抽取 Agent、十专项扇出、升级确认 Agent、定向复审或候选版本第二套审计策略。

## 实施顺序

1. 定义新版公开数据协议：完整文档、原始需求及来源、当前版本身份；问题携带原文证据、推理、影响和修复范围。不生成旧事实库或义务矩阵。
2. 实现单 Agent 私有执行器。全文进入同一上下文；只读证据查询和受限计算用于验证，不允许修改项目、联网或生成任意系统副作用。最终报告必须通过原文定位与证据字节校验；无法完成审计不得输出通过。
3. 实现独立持久化生命周期：输入快照、单执行所有权、停止与显式恢复、真实用量及幂等计费、先完整写入再发布。崩溃后不凭内存状态推定完成或重复启动付费调用。
4. 更新公开交接：Author → Reviewer 传递已确认需求；Revision → Reviewer 传完整候选文档。Revision 消费新版问题证据；外层仅循环全量审计与修复，不判定审计内容。
5. 原子切换公开入口并移除旧策略源码、旧专用测试和无调用残留。旧执行记录不自动恢复；历史项目文档与结果文件不删除。
6. 完成协议、证据、只读工具、生命周期、计费、跨模块交接和依赖隔离回归。真实模型验收与运行服务重启单独执行，不以模拟测试代替真实质量验收。

## 验收要求

- 一次审计只有一个审计 Agent；输入包含全部八份原文，不以摘要或专项 packet 代替。
- 候选审计与初次审计执行相同的全文策略。
- 需求缺失必须明确标记；不能仅把需求 digest 当作需求内容。
- 引文不存在、位置错配、输出不完整、模型阻塞、用量缺失均不得冒充通过。
- 审计不修改被审文档，修复只由 Revision 完成。
- 重复请求、停止、重启、计费重试和发布失败有明确且可验证的行为。
- 生产依赖图中不再存在旧事实提取、专项扇出、定向复审执行链。
- 对外如实区分代码测试通过与真实审计质量验收。

## 落地结果

- Reviewer 输出协议 v3，外层工作流存储协议 v52。初次及候选审计都使用完整八文档与需求正文；候选身份仅用于来源绑定，不改变审计策略。
- 一个顺序审计上下文通过宿主保存的完整 transcript 延续。每个动作使用独立原生进程执行，不是多专项 Agent；最终报告前必须提交初稿，再由同一审计上下文检查遗漏和误报。只读工具和受限算术计算不获得项目文件或网络访问权。
- Revision 接收原文引文、推理、影响、修复指令和需求正文；每个工作单元只能写指定整篇文档，其余七篇为只读上下文。候选重新进入完整审计，不再保留旧事实 catalog、定向 PASS/FAIL 或同轮候选保留重试协议。
- 保留原有账户配置、独立执行所有权、停止/显式恢复、用量持久化和幂等计费边界。旧版执行记录不兼容恢复，不改写或删除历史项目文档、结果及证据。
- 增加公开接口离线链路、跨文档与需求证据、独立打包/独立进程、生产导入边界测试；保留并迁移 Revision 的执行、计费、文件和恢复回归。
- 验证结果：Reviewer、Revision、Delivery Workflow、公开基础设施与项目复制相关测试共 370 项通过、0 失败（79 个测试文件）；agent-workflow-server TypeScript 检查与 git diff 空白检查通过。

退役源码/测试已在本机临时目录归档，便于恢复；归档不是生产兼容层。当前真实运行仍使用此前已启动的进程，启用新代码需要单独重启并启动新版流程。
