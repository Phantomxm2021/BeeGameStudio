# BGS 游戏交付：质量、耗时与成本的系统修订计划

日期：2026-09-27。性质：跨项目证据与执行计划，**不是已完成声明**。适用当前「每项目一个原生主会话」架构；不恢复旧控制器，不修改任何测试游戏。旧实现仅作故障线索，不作正确性标准。

## 目标与边界

目标不是让 BGS 代替 Agent 开发游戏，而是让 Agent 在完整、准确、可验证的项目环境里，自主交付符合已确认需求与八文档的可运行游戏。成功同时满足：产物完整、Scene/UI/资源数据确为运行来源、目标设备上的关键画面和交互可验证、发布证据对应当前版本，并且墙钟、token、credits 可归因。2D、3D、XR 使用各自适用的数据与设备检查；不要求 BGS 实现游戏引擎。

| 责任 | BGS 持有 | Agent 持有 |
| --- | --- | --- |
| 需求与阶段 | 已确认范围、单会话身份、当前交付阶段、产物契约、阶段结果和中断后的接续点 | 如何规划、执行、修订；是否调用子代理以及选用什么工具 |
| 资源与内容 | 资源库/生成/网页能力及价格、权威格式和原样校验错误；路径与权限边界 | 资源取舍、绘制/生成/检索、Scene/UI/VFX 数据设计 |
| 实现与验收 | 可选消费能力、预览/测试工具生命周期、证据与当前文件的关联、真实用量记录 | 游戏代码、运行时数据加载、调试、测试方法及问题修复 |

BGS **不**用关键词路由用户意图、不强制资源来源/子代理/浏览器/代码结构、不替 Agent 改测试项目，也不以自动续跑替代 Agent 的判断。BGS 可以拒绝把缺证据或过期证据标成“已验收”；这是发布真实性边界，不是创作指令。

## 执行顺序与量化验收

### 1. 交付状态只记录事实，不编排做法

**改动范围**：project-delivery、project-conversation 及其事件/测试。保持一个主原生 session；阶段是“当前待闭合责任”，不是文件写入权限表。Agent 同回合写了后续内容可以保留，但 BGS 只能确认当前阶段已满足的产物，不得据此跳过评审、资源、内容或验收。Review 有意见而 revision 未实际闭合的案例必须停在文档责任；没有意见不额外开空白回合。Stop 后下一条用户消息先携带真实阶段/现存产物给同一会话，由 Agent 理解用户意图；Queue 等当前回合完成，Steer 才在运行中介入。BGS 不做“继续/continue”关键词表。

**免费夹具**：迟到的子代理回执、空白修订、单回合提前写代码、停止后恢复、Queue/Steer 各一次。**通过条件**：一个项目仅一个主 session；阶段不跳过；空白修订不触发自动前进；无因同一错误重复派发的付费回合；已有项目内容不被平台覆盖。

### 2. 把权威契约与错误放在项目侧，贯穿资源→内容→运行

**改动范围**：资源作者契约、内容契约/校验 CLI、可选 Scene/UI 消费入口、Editor/Preview 对照夹具。不增加第二个 JSON/YAML 标准或 BGS 引擎。项目内能看到全部合法资源来源的字段和最小实例；校验错误指出具体字段、期望与实际值，不把“格式错误”伪装成“文件缺失”。图集帧、UI 祖先显隐、Transform/排序、Tilemap、加载时机由同一权威数据定义。给 Agent 可选复用接口及最短示例；项目可直接写自己的加载代码，不能以“是否导入 BGS 包”判对错。

**免费夹具**：四种资源来源、嵌套图集帧、父节点禁用、父子 Transform/排序、Tilemap、startup/on-demand；2D 与 3D 各有适用数据样本，XR 验格式/适配语义而不虚称真机。分别跑契约、Editor、可选消费入口和最小 Web Runtime。**通过条件**：同一数据在适用消费端语义一致；100% 引用可解析；startup 不预取 on-demand 文档；原样错误足够定位字段；不扫描或改写游戏源码来“修正”Agent 的实现。

### 3. 降低资源试错成本，但不替 Agent 选资源

**改动范围**：在 author 可见的资源库能力摘要、标签/授权/尺寸、Web 获取、AI 生成价格与尺寸、程序绘制能力；资源阶段显示实际用量和失败原因。Agent 决定何时检索、绘制或生图。对可能耗时/收费的资源，建议先做代表性样张并在八文档里说明是否复用、图集策略和运行尺寸；这只是可用能力与成本信息，不是 BGS 强制顺序。平台不暗中提升 AI 输出尺寸，也不替 Agent 保留无用资源。

**验收**：新项目可从能力入口查到每种来源的可用性和成本；生成请求的指定尺寸/计费在实际调用与账本一致；记录“首个可用样张耗时、候选数、弃用数、素材总字节、资源阶段 credits/token/墙钟”。无样张或高成本不自动停 Agent，除非触及用户明确给出的预算。

### 4. 将最终验收从自报 PASS 改为“覆盖事实 + 当前版本”

**改动范围**：acceptance report、发布就绪判定、预览证据索引。Agent 仍自主测试并判断质量；BGS 只核对报告声称验证了哪些已确认目标（例如桌面键鼠、触屏、手柄、代表性 Scene/UI、启动/按需加载）及对应证据的环境、时间和版本。范围内未测试必须标为 unverified，不能把 375×667 桌面 viewport 当成触屏验证。一个截图不证明整局玩法；静态求解不证明运行可玩。超出已确认范围的浏览器/设备可以列 limitation，不一概阻断。证据过期或文件变化就失去当前发布资格；不让 implementation 自报 PASS 直接完成。

**免费夹具**：缺图但逻辑断言全过、禁用层级泄漏、仅桌面竖屏未模拟 touch、改文件后沿用旧截图、已确认手柄缺证据、范围外 Safari 未测。**通过条件**：100% 已确认验收项有可追溯证据或明确 unverified；缺证据/过期时不能显示“当前版本已验收”，范围外限制不误阻断。不实现像素评分器或游戏特例判定器，审美/玩法语义仍由 Agent 与用户判断。

### 5. 修原生执行环境与测试工具生命周期

**改动范围**：project-execution-access、原生工具启动环境、Preview/CDP 浏览器封装。先用 Bash 生成临时图、再 Read 的最小复现，查真实 TMPDIR、cwd 与工具进程继承；如果项目临时目录承诺与实际不一致，修传递链，不开放主机目录读取。Write/Edit 参数错误应原样反馈可用 schema。BGS 自己启动的浏览器必须静音、关闭且留下失败记录；Agent 自起进程由项目会话监管/报告，不无差别杀宿主 Chrome。不要把代理/权限失败吞成“网络错误”。

**通过条件**：项目临时文件可在原生 Bash→Read 链内使用；越界读写仍被拒绝；BGS 托管浏览器每次退出后遗留进程数为 0，测试播放音频数为 0；平台原因工具失败按类别可见。先复现再改，尤其不把一次读拒绝当成应取消沙箱的证据。

### 6. 一套只读成本与性能口径，验证修订是否值得

**改动范围**：复用 native-runtime、项目事件、原生 transcript usage 与计费账本；增加只读汇总报表，不再新建调度器。按项目/阶段记录：墙钟、Agent 活跃时长、等待/中断时长、工具次数/失败类别、浏览器启动与孤儿数、输入/缓存读/缓存写/输出 token、credits、返工次数和最终覆盖。原生 usage 以消息 ID 的最后快照去重；子代理计入项目总量但不再叠加到主会话 usage；credits 以账本为准，不用 token 粗估替代。若事件无法准确归阶段，标记“未归因”，不捏造精度。

**验收**：报表总 credits 与账本一致；各阶段 token 之和与去重项目总数一致，差异必须解释；停止间隔不计活跃时长；每一类高频失败可追到原始事件。先以五项目历史数据出诊断基线（缺字段注明），再以同模型、同范围、同环境的新项目比较；至少 3 次免费/小规模冒烟确认正确性，再有 5 次同类完整交付才报告耗时/成本趋势。目标是中位数墙钟和 credits 下降、质量门禁不退步；样本不足只报观察值，不承诺百分比。

## 落地批次与停止条件

- 只增加能解决已证实缺口的东西：阶段事实校验、契约同源、验收覆盖和成本归因；不用额外的游戏引擎、复杂资源优化器或语义审查状态机。
