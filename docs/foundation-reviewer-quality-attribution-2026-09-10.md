# Reviewer 质量归因与最小推进方案

## 边界

Reviewer 负责发现、核实并报告问题，不修改被审计文档。Revision 交接不计入 Reviewer 质量评分。当前实现冻结；本文件不修改生产提示词、报告结构或工作流，不启动付费调用。

## 工作假设

优先检验“报告扩写负担”而非继续增强格式约束：关键距离 60 已正确计算，但扩写覆盖弦长、唯一点位和影响时引入新断言；报告又从有限检查扩大到无其他错误的全称声明。报告正文（不含引用）约 6850 字符，八项发现均要求实际、预期、推理、影响与修复建议，存在重复表达和额外断言机会。

这是待检验的假设，不是已证明的根因。约七万 token 的首轮上下文可能影响检索覆盖，但输入长不等于已证明超出模型有效处理能力。

## 最小解决方案

不加代理、检查阶段、字段、数字模板或自动修复。先只验证一个候选审计指令：

> 核实疑点后简洁报告问题。实际与预期给出直接冲突，推理说明证据为什么支持结论。不要为充实报告增加无必要的新计算或影响推测。修复建议只写应恢复的一致性，不制定坐标重排等实施方案。只描述实际完成的检查和计算；遗漏检查说明覆盖与局限，不宣称绝无其他问题。完成自查后直接 final。

该候选用于替换实验中的相关工作说明，不叠加到生产提示词，不提供七个锚点答案，也不把具体游戏问题写进通用提示词。所有证据、工具、输入、时限、报告结构和发布逻辑维持一致。

## 受控推进

1. 当前报告作为已观察基线，保留失败结果，不再以该文档是否被修好作为验收目标。
2. 后续模型实验只运行 Reviewer 的独立公共接口，不接 Revision；必须先确认这一隔离，避免再次自动交接。
3. 使用相同模型配置与输入，基线和候选各两次作为小规模筛查；记录实际模型标识、预算、调用量与结果。两次不构成统计保证，不能据此宣称稳定可靠。
4. 对比七个诊断锚点、明确误报、报告自身错误、工具使用陈述真实性与费用。争议项单列。评估内容，不匹配固定措辞，不用另一个 LLM 单独充当真值。
5. 若候选未减少报告自身错误或增加明确漏报，不采用；若有改善，再用未参与提示词设计的独立样本验证后，才考虑更新生产指令。
6. 只有提示词对比不能解释问题时，再单独对比模型或上下文长度，不能同时换模型、拆输入和改提示词。

在线对比尚未执行。本次推进产物是冻结基准和可检验方案，不是假定方案已经有效；后续付费实验需明确执行范围并确认 Reviewer-only 入口。

## 用户授权后的指令实现

用户随后要求“开始修复”，已将上述候选方向落实到 single-agent-prompt.ts：

- 简洁报告有证据的问题；不为填充字段增加推导或猜测影响。
- 修复建议只描述应恢复的一致性，不承担文档改写或实施设计。
- 只声称实际有成功反馈的工具检查；遗漏检查说明范围与局限，不作绝无其他错误的保证。
- 上下文存在合理解释时，不将疑点当作已证实缺陷。
- 清理尾部 move toward a draft 的残留指令，统一为完成自查后直接 final。

本次仅修改审计提示词与对应测试，未改变报告结构、执行流程、模型、预算和历史记录。新增测试核对职责要求及八文档/需求序列化无损。

离线验证：91 个测试、610 项断言通过（13 文件，包括本地模拟模型的 CLI 集成）；服务端 TypeScript 和 diff 检查通过。这些测试不证明模型质量改善。服务未重启，未执行在线对比，未进入 Revision；真实发现质量仍待独立验证。
