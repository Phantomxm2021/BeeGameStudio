# Reviewer 可恢复审查改造

本次仅实现并离线验证已批准的七项可靠性方案，不触发新的付费模型验收，不改写历史审查状态或原始八文档。

2026-09-11 最终结果：267 项测试通过、0 失败，2,422 项断言；根项目、workflow server、workflow 三项类型检查通过。已将验证后的构建安装到本地项目并重启空闲开发服务，5 个健康端点均为 200。31 条原有工作流、15 个历史审查读取结果、原始八文档及配置保持不变；替换的 CLI 入口已备份，旧构建分块未删除。

## 实现边界

新请求使用不可变策略 `recoverable-coverage-evidence.v2`。历史请求继续按各自保存的旧协议读取与恢复，不自动升级、不重写旧结果。默认审查不再要求模型重复提交完整覆盖账本。

1. 宿主按顺序绑定审查单元、工作标识、输入摘要与结果位置。模型输出不包含 unitId、哈希、计算 ID、引用下标或机械检查 ID。
2. 模型选择封闭来源表中的行号并说明 actual / expected / context 角色；宿主从冻结输入提取原文和证据摘录。解释不能替代原文，越界引用和额外 excerpt 字段会被拒绝。
3. 冻结原文、覆盖计划、工作尝试、工具记录、计量、结算与提交均保存。每项先确认子进程退出与计量封存，再结算、提交；不能凭模型摘要恢复进度。
4. 每批最多 8 个单元，仅输出当前批。局部来源包以 64 KiB 为软上限，超出关联文档通过只读工具按需读取；不会在每批重放整份报告。当前单元本身过大时仍受整体分页机制约束。
5. 相同计算返回经过宿主重算验证的已有回执。压缩丢失任务正文时，下一次模型请求前恢复当前任务与计算回执；仅保留摘要或标记不算恢复。连续无新增工具信息会警告并停止，重复同一个传输 ID 不重复计数。
6. 主审批次后执行全局主审；再以独立新会话逐批复核，最后执行全局复核。全局检查每份文档及可用需求各有一个检查项，不重复输出 155 项账本。分页全局检查要求本次执行实际读取全部原文。未完成、否定或不确定结论禁止发布通过，否定复核不会自动重试直到同意。
7. 格式纠正只重跑当前未提交批次。相同被拒输出再次出现，或当前批达到纠正上限，即停止。计量缺失、仍有未封存工作时拒绝自动恢复；主进程丢失但所有工作已封存时，可显式接续并保留原租约证据。结算失败必须显式续跑，用同一事件 ID 重试。

## 离线验证

验证使用冻结原文、确定性故障夹具及本地假模型端点，不连接付费模型：

- 冻结案例仍有 155 个单元，执行链为 20 个主审批次 + 1 次全局主审 + 20 个复核批次 + 1 次全局复核。
- 已知 7 项核心问题的证据回放包含 3 项语义问题和 4 项机械问题；程序另检出 LEVEL 文档的一项标签/目标不一致，共 8 项。此处语义结论由回放夹具提供，不代表模型自行召回。
- 原 SVG 的 700 是示意画布高度；应用区域从 y=40 到 y=696，高度 656。不能把外层画布高度当作应用高度冲突。保留原始 SVG 并核对了渲染与坐标。
- 故障覆盖包括禁止模型生成 ID/摘录、分页未读/伪造读取、跨批读取不得继承、缺少全局凭据、独立否定复核、失败批次重试、重复输出停止、暂停续跑、结算失败、计量缺失及旧主进程失联后的有条件接续。
- 真实 CLI 对本地假模型端点的强制自动压缩测试通过：实际执行压缩请求后，恢复完整当前任务且不重复注入，并恢复先前计算的整数回执、值和表达式。测试与 CLI 位于同一受控子进程，不依赖未跟踪的孙进程。
- 错绑到其他单元的发现、超出最终证据格式容量的引用，在当前批次就被拒绝，避免提交后才在最终发布时发现结构错误。
