# 动态资源与运行时呈现：审计、实施与验证

日期：2026-10-23。基线：`a9dd708a0`。范围：BGS 系统源码与制作指导；四个测试项目及原始证据只读。

## 目标与结论

让已确认设计中的动作、状态变化、场景层次、UI 呈现和声音进入实际资源生产与运行时实现。以用户目标与原始设计为依据，不以旧版表现或某个测试项目通过作为标准。

本次确认了制作与集成的断点，但没有发现资源工具只能输出单图、Skill 正文丢失、图集帧被系统抹去或质量检查错误放行的证据。调整落在制作与实现职责的交接指导；不把项目渲染错误伪称为通用引擎 bug。

## 证据与责任层

| 证据 | 归因与改动边界 |
| --- | --- |
| Fox 单张角色图只做整体变换，背景未实现约定的独立层；失败切屏使已有震动失去显示时间 | 资源表示选择与项目生命周期接线不足。可复用的改进是先确定需要哪些可独立控制的变化，再选表示方式；不为所有游戏规定分帧、四层背景或固定死亡延迟 |
| Vault 的角色令牌与少量变形没有兑现约定动作，部分事件反馈和音乐变化未实现 | 必需表现没有完整进入实现；不增加通用动作清单或合成音乐模板 |
| Bomb 已有开放/点亮图集帧，渲染仍选默认帧；参考构图与运行时呈现落差明显 | 项目消费者未使用已有资源状态，视觉生产没有保持选定构图；不禁止 HTML/Canvas，也不把整张参考图当运行时界面 |
| Snake 死亡粒子与仍被绘制的原蛇同时出现 | 原主体与替代效果的生命周期未协调；不在系统中加入蛇或碎裂专用规则 |
| 音频文件、解码与播放调用存在，用户仍报告听不到或缺少环境感 | 代码存在与实际输出不同。没有足够证据认定用户浏览器被 BGS 静音；保留实际听感缺口 |

完整链路核查结果：

- `bgs/runner.ts`、`bgs/skills.ts` 和执行权限链能注册、发现并读取内置 Skills 与其 references；隐式选择和实际应用仍依赖模型，没有证据支持改写加载器。
- `media-production.ts` 与现有图集读取器保留命名帧、裁剪、透明空间、padding 和帧区域。打包图集与播放动画分属生产工具和项目 runtime。
- 可选 production surface 明确提供有限静态展示；动态行为由所选引擎/项目代码实现。扩大该 helper 为通用游戏引擎没有证据与收益支持。
- 现有 Preview 支持短视频与选定 Web Audio 节点采集；静态检查、无头浏览器静音和选择性音频探针各有明确边界。没有新增录制器或验收门禁的必要。
- 当前主上下文把 basic correctness 与用户体验判断分开，但“technical effects”容易遗漏已约定的可见/可听表现。现有执行段落也没有明确贯通资源状态选择、实际反馈与结束生命周期。这是本次收紧的职责风险；不能据此断言历史案例由当前文字导致。部分案例运行早于现有 Skill 修订。

## 已实施的最小方案

1. **资源生产**：在现有 `ASSET_PLAN.md` 与 `TECHNICAL_DESIGN.md` 之间连接所需动作/变化、表示方式与消费者。区别整图变换、独立部件/层、不同姿态和运行时绘制；检查交付资源是否真能支撑选定变化。继续使用原 Manifest，不增加映射文件或数据库。
2. **运行时实现**：现有执行指导直接连接动作/状态、视觉/声音响应与最终外观。已加载的资源还需要正确选帧、切换或播放；界面切换和对象移除不能提前取消设计要求的反馈。原主体保留、变化或被效果替代，由具体设计决定，复用已有生命周期设施。
3. **实施责任**：已确认的视听要求属于实现范围。缺失是未完成；没有运行观察是未验证。用户负责主观清晰度、手感与乐趣的判断，等待这些反馈不意味着持续实施或自动寻找通关路线。
4. **观察方法**：按受影响要求观察短片段，动态看过程、音频看实际输出。沿用现有工具与有效证据；无法观察时说明限制，不靠连续重跑补齐报告。
5. **范围一致性**：新项目 guide 明确只有 full-game assignment 才要求全游戏交付，避免与已有 playable-slice 等较小任务的边界竞争。

变更覆盖 6 个生产/指导文件，以替换原段落为主，没有新增业务 API、状态字段、工作阶段、模型审查器、前端界面或依赖。独立审查后进一步区分“未实现”和“未观察”，保留程序绘制及静态反馈的适用空间。

## 验证方法与实际结果

使用既有临时合成 fixture，不写入用户测试项目、不调用真实模型或图像服务。

- 媒体与资源测试实际解码、裁剪和提取图集帧像素，覆盖透明空间、空中姿态偏移、padding、错误输入、非覆盖写入、注册和 PCM 输出。
- 浏览器测试实际观察帧推进、暂停与恢复；注入暂停/恢复故障后检查应失败并保留证据。源驱动的短路径覆盖结束、暂停与重试。
- Web Audio fixture 经过普通按钮输入产生声音，采集真实选定节点输出、解码并测量信号及静音尾段；也覆盖未选节点、限时和驱动失败。其结果不代表扬声器可听或真实游戏混音质量。
- 工作流测试覆盖初始与后续请求、范围、既有 guide 不被重写及完成证据边界。Skill 校验检查格式与引用入口，不能证明模型会正确采用方法。

首次运行中需要回环端口的测试被沙箱阻止；在允许本机监听后运行相同 fixture。这是环境前提修正，不是修改断言掩盖产品错误。

原生验证首次暴露的是既有测试观察器缺陷：原生 `AdditionalContextStore` 按 key 只追加变化片段，测试却从历史最后一个首块开始串接，重复计算旧尾块和新尾块。已只修 `context-integration.test.ts`：按完整 key 取最新值、选择当前 scalar/chunk family，并检查完整序号；新增无 CLI 回归覆盖增量尾块与长短/块数变化。原有 developer 角色、4000 字节限制和完整文本精确比较均保留。原生运行时和增量去重机制没有改动。

上述通过项合计 107，未把环境失败尝试算作通过，也不把数量作为游戏质量证据。生产/指导变更共增加约 164 个空白分隔词（非 tokenizer 计量），没有新增模型调用、强制阶段或每项资源审查；不据此推算实际 token 收益。

## 保留边界与后续验收

本轮改进仍依赖模型选择并应用已有方法。没有确定性程序可以从任意设计文档可靠判断所有动作、构图或混音是否兑现；本次没有用更多规则或另一轮 LLM Review 假装解决这一限制。

离线结果证明相关工具和传递链的具体能力，不能证明未来生成游戏已变好。下一次正常授权的真实项目运行，应以其确认设计核对：资源能支撑所需变化，消费者实际选择并播放，短动态片段包含后果和恢复，实际声音输出覆盖所声称的范围。保留第一份原始结果，系统开发代理仍不手修产物。未观察的行为不记为通过，已发现的项目问题要先定位责任层，再决定系统是否需要调整。

本轮无付费生成、真实项目重跑、测试产物修改、前端改动或服务重启；没有测得真实游戏质量、token 或耗时收益。
