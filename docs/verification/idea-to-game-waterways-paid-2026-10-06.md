## 系统归因和修复

2026-10-06 后续修复仅修改系统与合成测试，原测试现场和“未通过”结论不变。

根因是**接入工作缺少可直接复用的工具，任务范围与执行边界没有落实到程序**。作者错误触发反复排查，历史越长，每一次小请求越贵。不能据此证明高上下文造成了某一次误判，更不能断言模型能力到极限；也不能只把这些问题归为模型没有认真读 Prompt。

| 归因 | 明确问题 | 系统修复及能力边界 |
|---|---|---|
| 系统接口缺口 | 新生产接口只有压缩实现；异步、参数、扁平 DOM、支持范围不清楚。 | 随内容工具发布 `production-runtime.md`；格式入口公布签名及能力列表，列表与渲染代码共用；错误 host 参数明确报错。仍不能保证模型永不误用。 |
| 系统接入缺口 | 每次由作者重新写开发静态服务和生产复制，漏掉根资源清单，文档相对路径取错。 | 提供经过实际构建验证的 `bgsContentPlugin()`，复用已有注册加载器，说明开发／发布基址。没有另建脚手架、引擎或第二套文件格式。其他构建技术仍需其自身正确接入。 |
| 作者测试错误及共享工具缺口 | 测试重复抄棋盘尺寸，忽略渲染相机、父节点、画布缩放及 iframe 坐标。 | 提供 `sceneNodeClientPoint2d()`，直接复用渲染的层级和相机计算，接收真实画布尺寸和测量框。它只算坐标，不证明点可点击、没被遮挡或游戏规则正确。 |
| 系统任务边界缺陷 | 长阶段直到作者交接才清上下文；停止仅靠模型自觉。 | 主循环最多 40 次迭代，单次任务最多 12 分钟；程序触限停止、清理能力、不推进、不自动重跑。保存文件不变，显式恢复从真实文件和用户要求继续；失败排查历史不再累加。 |
| 系统阶段范围不一致 | 提示允许代表性版本，布局门槛仍要求全部目标尺寸。 | 可玩阶段先做首个目标尺寸的核心交互与结束／重开；完整制作与最终门槛仍要求全部尺寸、界面和用户要求。暂缓不等于删需求。 |
| 系统恢复和排队缺陷 | 失败后任意新消息被当作制作恢复；队列错误地依赖发布资格，还通过对象展开继承旧任务的 initialBrief／autoContinuation，把人类问题重新标成制作任务。 | 只有启动或显式 Continue 派发阶段。队列只传路由和新用户消息，不继承旧派工字段；提问不写阶段回执，消息不受发布门槛阻断，并优先于自动制作。Stop／旧项目限制仍保留。 |
| 环境兼容及模型执行偏离 | Bun 的 cwd／CDP 失败；已有 Node 指令仍被忽略。 | 公共用法使用本轮已成功的 Node Vite／Playwright 路线，未放宽项目隔离。Bun 错误的全部底层原因未单独证实，不宣称修复了 Bun 本身。 |

40 次／12 分钟是当前支持范围的初始运行保护值，不是已验证的最优阈值或 Credit 上限。主循环迭代不等于全部提供方请求数，底层重试、辅助请求和子任务可能另有调用。限制防止一次任务无界运行，不能保证任务在上限内完成；复杂任务可能需要诊断后显式恢复。
