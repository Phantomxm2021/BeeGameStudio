## 1. 目的与范围

本文档定义首版全部声音与音乐的**行为**：每个声音类别传达什么、什么性格与音区、何时触发、多长、是否循环、何时停止、被重复触发时如何表现，以及并发优先级、电平层级、状态过渡、静音作用域与可访问性要求。

本文档**不**列文件名、不做库存表、不规定编码格式与采购来源；文件规格、数量、采购与加载方式统一由《ASSET_PLAN》汇总。全文以行为编号（A-xx）/类别引用，事件绑定与资源解耦：同一行为编号可由一个或多个素材经随机/变调实现，替换素材不得改变行为定义。

2D 横屏游戏，全部声音为非定位的 2D 反馈，不做声像位移与空间音频。

## 2. 总体声音性格

- 美术方向按**"霓虹复古街机、风格化"**假定：合成器/芯片质感为主（短促方波/三角波类弹跳体、亮脆的数字碎击、干净的复古 UI 音），不追求写实录制的物理碰撞质感；允许带轻度模拟感（短噪声尾、轻微饱和），但保持现代混音的干净与层次。
- 上述美术方向若与最终 ART_DIRECTION 不一致，**以 ART_DIRECTION 为准**，音频性格随之校准（如改为更偏合成波/更偏写实），但本文档定义的触发、优先级与过渡行为不变。
- 整体审美取向：短、脆、有反馈把握感；弹射音位于中高频且彼此可分辨；避免长时间占频段、避免浑浊低频堆叠。
- 声音不得"谎报"玩法：无声事件不伪造结果，发声时机与 GDD 判定一致（含同帧多事件的优先级，见 GDD 6.2）。

## 3. 必需声音行为

### A-01 发球（ball.launch）

- 用途：确认球离板进入"游玩中"，给玩家"开始行动"的起势。
- 性格：上扬的短合成滑音/发射音，中高音区，干脆带一点能量感；区别于任何弹射音（弹射为"撞"，发球为"放出去"）。
- 触发时机：发球输入生效、球离开挡板的同一逻辑帧（GDD：Ready → Playing）。
- 时长与循环：约 0.12–0.25s，单次，不循环。
- 停止条件：自然播放结束；进入暂停时若仍在响，随音效总线一并淡出/停止（见第 7 节）。
- 重复触发：发球为状态转换事件，Ready 状态下持续按键不得连发；仅在每次实际进入 Playing 时触发一次。

### A-02 球碰挡板（ball.paddle）

- 用途：确认成功接球，并暗示"击球点决定角度"的操控手感。
- 性格：中频为主、有"实体弹性"的短促合成击打（比边界音更圆、更有肉感），起音快、衰减干净。
- 触发时机：球与挡板发生弹射的逻辑帧。
- 时长与循环：约 0.06–0.12s，单次。
- 停止条件：自然结束；被更高优先级声音（失误）抢占时允许被截断/压低（见第 5 节）。
- 重复触发：单次碰撞只发一次；连续挡板碰撞（理论上少见）按第 5 节流式规则处理，不叠发声。
- 可选微行为：音高或亮暗随击球点偏离中点轻微变化，提供角度的潜意识线索（可选增强，见第 10 节）。

### A-03 球碰边界（ball.wall）

- 用途：确认球与左/右/上边界弹射。
- 性格：比挡板音更高、更硬、更"空"的短数字敲击/电子滴答，中高音区，听感轻于挡板音。
- 触发时机：球与边界发生弹射的逻辑帧；底部不弹射，碰底部不发此声（走 A-05）。
- 时长与循环：约 0.04–0.09s，单次，三类边界共用同一行为类别（不要求按左/右/上区分）。
- 停止条件：自然结束。
- 重复触发：连续撞墙（如近垂直往返）按节流规则处理；间隔极短（同帧/数毫秒）时合并为一次或轻微变音的单次反馈，严禁逐碰撞叠加。

### A-04 碎砖（ball.brick / brick.break）

- 用途：确认砖块被击碎、得分增长；是游戏中最高频的正反馈，需要"爽脆、可连击"。
- 性格：三者中最高、最亮的脆裂声——短噪声/颗粒感数字碎裂，亮高频 + 极短低频点击垫底，清脆不拖沓。
- 触发时机：球的碰撞导致砖块被击碎的逻辑帧。
- 时长与循环：基础素材很短（约 0.05–0.12s），单次。
- 停止条件：自然结束；在高频连击下允许被新碎砖事件主动截断重启（见第 4.2）。
- 重复触发：**不允许每个砖块简单叠加播放**，受第 4 节合并/节流/变调策略约束。

### A-05 失误落底（life.lost）

- 用途：强负反馈：球越过底部、扣一条生命；必须与所有弹射声明显拉开层级。
- 性格：明显下沉的失败音——音高下扫、带低中频能量与轻微"坠落/消能"质感，时长比弹射声长得多，情绪上"疼一下"但不刺耳。
- 触发时机：失误成立（生命扣减）的逻辑帧，一次落底只触发一次（GDD 6.2 第 4 条）；落底后球停止，此后不再有弹射/碎砖声。
- 时长与循环：约 0.4–0.8s，单次，不循环。
- 停止条件：自然播放完成；进入结算/暂停界面不截断它（它本身就是该时刻的主反馈）。
- 重复触发：同一次落底绝不重复；下一次失误需新的落底事件。
- 备注：最后一条生命的失误走 A-07（失败），A-05 与 A-07 不叠加——失败声取代失误声（或失误声为失败声引子，由实现取其一，听感上只呈现一条失败反馈线）。

### A-06 过关（game.win）

- 用途：全部砖块击碎、本关通关的强正反馈与结算宣告。
- 性格：明亮、上扬、有完成感的短胜利乐句/琶音（合成器复古质感），2–4 个音的小句式，明显区别于一切单次击打音。
- 触发时机：最后一块砖块击碎、判定过关的逻辑帧（含 GDD 6.2 第 1 条"碎砖与落底同时→过关"的情形）；该帧的碎砖反馈按第 4.3 处理为单次碎砖组音，胜利乐句紧随/叠加于其上，但碎砖不重复发声。
- 时长与循环：约 0.8–1.5s，单次，不循环。
- 停止条件：自然播放；玩家在乐句期间点"重开/退出"时允许淡出截断（见第 7 节）。
- 重复触发：一局只可能一次。

### A-07 失败（game.over）

- 用途：生命归零、失败结算的强负反馈与终局宣告。
- 性格：下行、收束的短失败乐句/低沉终结音，情绪比 A-05 更终局、更长、更完整。
- 触发时机：最后一条生命随落底失去、进入 GameOver 的逻辑帧。
- 时长与循环：约 0.8–1.5s，单次，不循环。
- 停止条件：自然播放；期间点重开/退出允许淡出截断。
- 重复触发：一次失败结算一次。

### A-08 界面按钮（ui.click）

- 用途：确认界面按钮聚焦/按下（暂停、继续、重新开始、返回开始界面，以及开始界面的"开始游戏"）。
- 性格：干净的短复古电子确认音，中音区，轻量、不抢眼；不同按钮共用同一行为类别，不逐按钮定制。
- 触发时机：按钮实际激活（确认动作发生）时，而非悬停/聚焦时。
- 时长与循环：约 0.04–0.08s，单次。
- 停止条件：自然结束。
- 重复触发：一次有效激活一次；长按不连发。键盘聚焦确认与点按等价，同一激活不得因双事件响两次。

## 4. 弹射音的音调变化与碎砖高频策略

### 4.1 三类弹射必须可分辨

| 行为 | 相对音高 | 音色关键词 | 时长倾向 |
|---|---|---|---|
| A-02 挡板 | 最低（中频） | 圆、弹性、有实体感 | 略长 |
| A-03 边界 | 中高 | 硬、空、轻的数字敲击 | 短 |
| A-04 碎砖 | 最高、最亮 | 脆裂、颗粒噪声、亮高频 | 短，带碎裂尾 |

调校验收方向：遮眼听同一局录音，三类声音在连续混响（dry，基本无混响）中仍可按音高与音色区分；碎砖声不得与边界声同为"滴答"而仅靠画面分辨。

### 4.2 高频碎砖：避免机关枪式堆叠

- **音高随机/微移**：每次碎砖在基准音高上做小范围随机（建议 ±半音~±小三音 取向，具体听感标定），消除同高同音的机械连发感。
- **截断重启（voice choke/retrigger）**：碎砖声音轨设很少的并发名额（建议 1–2 路）；新碎砖事件发生时，允许截断同轨上尚未播完的上一个碎砖声并从头触发，得到密集但干净的"哒哒"连击，而非尾音堆叠糊成一团。
- **最短触发间隔与合并**：间隔小于阈值（如数毫秒内的连锁碰撞）合并为一次反馈。
- **保形**：无论连击多密，单次碎砖听感始终是短脆音，不做渐强、不加长、不提高密度以外的情绪。

### 4.3 一球同时碎多块：只发一次碎砖组反馈

- 依 GDD 6.2 第 2 条，一帧/同一时刻击碎多块砖时，音频侧只发出**一次**碎砖组反馈，不为每块砖各发一声、不做多声叠加。
- 该次反馈可带轻微"计数感"：按当组砖块数（如 1 / 2 / 3+ 块）分少数几档，使组反馈在音高、亮度或颗粒层数上轻微加强，档位很少（建议 ≤3 档），禁止随块数线性叠加声音层数。
- 若该组包含最后一块砖：碎砖组音仍只发一次，随后由 A-06 过关乐句接管情绪。

## 5. 并发、优先级与电平层级

### 5.1 优先级（高 → 低）

1. P0 终局/重要反馈：A-06 过关、A-07 失败、A-05 失误
2. P1 发球 A-01
3. P2 高频玩法反馈：A-04 碎砖、A-02 挡板、A-03 边界
4. P3 界面音 A-08
5. 背景音乐（独立总线，受 ducking 约束，见第 6 节）

### 5.2 相对电平层级（方向性指标，最终以听感混音标定）

- P0 重要反馈为全场最响层：建议比常规弹射/碎砖响约 **+4 ~ +6 dB** 的方向；失误声发生时**必须压过当前所有弹射/碎砖声**（弹射声让路：静音、截断或快速压低，二者不得在响度上相争）。
- 碎砖/挡板/边界位于同一基准层，彼此响度差控制在约 ±2 dB，靠音高与音色区分而非靠响度。
- UI 音轻于玩法反馈，约低 2–4 dB，不与弹射争夺注意。
- 背景音乐相对音效整体避让：音效发声时音乐经轻度 ducking/或本身电平足够低，音乐响度建议比音效基准低约 **−8 ~ −12 dB** 的方向，且不占用碎砖的高频亮区。
- 总线峰值必须留足余量，任何连击场景不得削波（预留 headroom，目标峰值 ≤ −1 dBTP 方向）。

### 5.3 最大同时发声数（取向）

- 总播放音路取**保守上限**（建议全场音效同时活跃 ≤ 6–8 路的方向）：碎砖 1–2 路（可互截断）、弹射类合计 2–3 路、P0/P1 各独占 1 路、UI 1 路。
- 超出名额时按优先级淘汰：低优先级且已起音的声音先被截断/让路，P0 永不被弹射类抢占名额。
- P0 触发时可主动压低或截断在响的 P2 弹射声（失误压过弹射是硬性要求）。

## 6. 背景音乐

**首版选定：一首轻量、循环的街机底乐（music.bed），而非"仅音效氛围"。**

- 理由：本作是连续数十秒到数分钟、节奏稳定的高频操作循环，一条轻循环底乐可提供街机场景的持续能量与时间黏着感，单纯音效氛围在长时间无碰撞间隔（球在空中）时会显空；单首短循环的成本与"仅氛围"接近，不构成复杂系统。
- 规格取向：短循环（数秒~十余秒无缝循环），中低频律动/铺底为主，旋律稀疏或无旋律，**主动让出中高频与高频**，不与碎砖、弹射频段争夺；音量低、可长期耐受不腻。合成器/芯片复古质感，与第 2 节一致。
- 不发明音乐系统：首版只有这一条循环，无分层、无动态编曲、无速度随进程联动、无多曲目切换。
- 过渡行为：
  - **暂停**：底乐立即压低（ducking 到很低，如 −12 dB 以下取向）或暂停播放，二选一实现取向为"暂停播放（停在当前位置）"；继续时从停下处恢复，不重头开始。
  - **过关/失败**：进入结算瞬间底乐停止（快速淡出，约 0.2–0.5s），由 A-06/A-07 接管；结算界面保持安静（不另铺结算音乐）。
  - **重开**：底乐随新局重新起播（允许从头或从固定进入点开始）。
  - **返回开始界面**：底乐停止；开始界面是否低音量铺同一底乐属可选取舍（见第 10 节），受自动播放约束（第 8 节）。

## 7. 状态过渡音频

| 过渡 | 音频行为 |
|---|---|
| 开始界面 → 发球（Ready） | "开始游戏"按钮发 A-08；进入 Ready 后等待玩家发球，不自动发声（可选待机滴答见第 10 节） |
| 发球准备 → 游玩中 | A-01 发球音；底乐起播（若此前未播） |
| 游玩中 → 已暂停 | 全部在响音效立即停止/极快淡出；底乐按第 6 节暂停或压低；暂停界面安静，按钮操作发 A-08 |
| 已暂停 → 继续 | A-08；底乐恢复；**不补发**暂停期间的任何声音（与 GDD 6.3 一致） |
| 游玩中 → 过关 | 单次碎砖组音（若最后一击同时碎多砖）+ A-06；底乐淡出停止 |
| 游玩中 → 失败 | A-07（取代 A-05，不叠加）；底乐淡出停止 |
| 结算 → 重开 | A-08；所有声音复位；进入新局 Ready，阵列/生命重置后等发球 |
| 任意界面 → 退出（返回开始界面） | A-08；停止全部音效与底乐，进入开始界面的安静状态 |
| 页面失焦/标签页切换 | 建议视同自动暂停处理（技术侧实现取向）：停声、停乐，回到页面后不自动补响 |

## 8. 静音、音量作用域与自动播放约束

### 8.1 音量分组（首版取向）

- 总线分三路：主音量（Master）、音乐（Music）、音效（SFX）。
- 首版提供：主静音/主音量，以及**音乐与音效分离**的独立开关或音量（分离为必需取向，至少支持分别静音；独立推子可视 UI 资源取舍）。
- 作用域：设置**仅作用于当前页面会话**。首版无任何跨会话持久化（与 GDD 一致）：不写入 localStorage、不记忆静音/音量，刷新后回到默认（默认：全部开启，默认音量）。
- 音量变化应使用平滑渐变（很短的 gain ramp），避免爆音；静音即总线增益归零，不停止播放逻辑（恢复时行为连续）。

### 8.2 浏览器自动播放策略（给技术/UI 的硬性接口要求）

- 浏览器在用户手势前禁止/限制音频出声与 AudioContext 启动。因此：**首次发声必须由用户"开始游戏"的手势触发——开始界面的"开始游戏"按钮就是音频解锁点**。
- 接口要求：
  1. 在"开始游戏"按钮的点击/键盘确认/触屏点按（用户手势事件）处理中创建或 resume AudioContext，并完成一次静默的音频管线初始化（解锁）。
  2. 解锁成功前，任何事件（含开始界面底乐、UI 音）都不得尝试发声；解锁失败不得阻塞游戏可玩性（无声可玩，见第 9 节）。
  3. 开始界面在解锁前保持安静；不依赖加载完成自动播乐。
  4. 技术侧需处理 AudioContext 被浏览器挂起（如失焦）后的再次 resume（仍应在手势处理中进行）。

## 9. 可访问性

- **音频不单独承载任何关键信息。** 失误与生命扣减、剩余生命数、过关、失败必须同时具有明确的视觉对应（生命 HUD 变化、结算面板、分数变化等），UI/UX 文档负责保证；无声状态下游戏信息完整、流程可完成。
- 不为颜色/音高赋予唯一信息含义：即使采用"碎砖音高随行变化"（可选），也不依赖玩家辨音做任何判断。
- 声音默认安全：无突然巨响惊吓，最大响度受控（第 5 节）；尊重系统/浏览器音量与用户静音设置，静音状态下绝不漏音。
- 不提供字幕类音频替代物的要求（首版无语音）；如未来加入语音，须同步提供视觉文本。

## 10. 必需音频与可选增强

**必需（首版验收范围）：**

- A-01 发球、A-02 挡板、A-03 边界、A-04 碎砖（含 4.2/4.3 的节流与合并行为）、A-05 失误、A-06 过关、A-07 失败、A-08 UI 音
- 一首轻量循环底乐及其暂停/结算过渡
- 音乐/音效分离的音量或静音、会话内作用域、自动播放解锁
- 第 5 节优先级与电平层级行为

**可选增强（不影响首版验收，加入须不改变既有行为）：**

- O-01 发球准备的待机滴答/轻氛围（Ready 停留时的稀疏滴答，发球即停；必须很轻、可被关闭，不制造倒计时压力——GDD 中 Ready 不计时）。
- O-02 碎砖音高随砖块颜色行/行位置变化（仅丰富感，不承载信息）。
- O-03 挡板击球点改变 A-02 的音高/亮度微线索。
- O-04 开始界面低音量铺同一底乐（解锁后）。
- O-05 连击计数感的进一步细化（超出第 4.3 三档的玩法——首版不建议）。

## 11. 文件规格与采购边界

- 音频文件格式、码率、采样率、时长素材切分、素材数量、循环点工艺、采购/自制来源与许可核验，统一由《ASSET_PLAN》汇总定义，本文不重复、不列库存。
- 采购/制作验收以本文行为编号为准：素材必须支持 4.2 的截断重触发、4.3 的分组档、无缝循环（底乐）与干声短尾；许可与来源在导入前核验。
- 事件绑定（哪个事件触发哪个行为）与素材选择分离，便于替换素材而不动玩法代码。

## 12. 对下游的接口移交

### 12.1 建议事件名（技术侧按此发射/订阅）

| 事件名 | 对应行为 | 触发要点 |
|---|---|---|
| `ball.launch` | A-01 | Ready → Playing，每次发球一次 |
| `ball.paddle` | A-02 | 挡板弹射；可带击球点偏移参数（可选微行为用） |
| `ball.wall` | A-03 | 左/右/上边界弹射（底部不发） |
| `ball.brick` | A-04 | 碎砖；载荷须含**当组砖块数**（用于 4.3 合并与计数档），同帧多砖由玩法侧聚合为一次事件或由音频侧按帧聚合 |
| `life.lost` | A-05 | 失误成立且仍有生命；一次落底一次 |
| `game.win` | A-06 | 过关（含与落底同帧时过关优先） |
| `game.over` | A-07 | 最后一条生命失去；与 life.lost 不重复发声 |
| `ui.click` | A-08 | 按钮激活；开始/暂停/继续/重开/退出共用 |
| `music.bed` | 底乐 | 起播/停止/恢复控制；按状态机驱动 |
| `game.pause` / `game.resume` | 过渡控制 | 暂停全部音效并停乐/压低；恢复不补响 |

### 12.2 并发与优先级要求（移交技术实现）

- 实现第 5 节优先级与音路名额：碎砖 1–2 路可互截断；总音效音路上限 6–8 路取向；P0 永不被抢占。
- `life.lost`/`game.win`/`game.over` 触发时，在响弹射/碎砖立即截断或快速压低，保证 P0 响度压过。
- 同帧碎砖聚合为一次 `ball.brick`（或音频侧按帧聚合并只出一次声）；组块数分档（建议 ≤3 档）。
- 底乐 ducking/暂停/淡出行为按第 6、7 节；无复杂音乐逻辑。
- 所有增益变动走 ramp，防削波、防爆音。

### 12.3 静音/音量接口

- `audio.setMasterVolume(v)` / `audio.muteMaster(bool)`
- `audio.setMusicVolume(v)` / `audio.muteMusic(bool)`
- `audio.setSfxVolume(v)` / `audio.muteSfx(bool)`
- `audio.unlock()`：在"开始游戏"用户手势处理中调用，创建/resume AudioContext；返回成功/失败状态供 UI 容错。
- 设置仅会话内有效，刷新即默认；技术侧不得自行加入持久化（如未来要加，属设计变更）。

### 12.4 依赖与未决

- 依赖《ASSET_PLAN》落素材规格与采购；依赖 UI/UX 保证第 9 节视觉对应与开始按钮手势链路；依赖技术文档落实事件与总线。
- 声音性格以最终 ART_DIRECTION 为准确认（第 2 节）；在其确认前按"霓虹复古街机、风格化"推进。
