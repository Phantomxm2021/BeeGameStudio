## 1. 目的、范围与边界

把 GDD 第 6、7、10 节委托的可调数值一次性拍板：球速与提速、发球角度、挡板宽度与键盘速度、生命数、各行分值、固定逻辑步长与防螺旋。本文拥有这些参数的**最终调值权**；场景文档提供的是几何初值，本文确认或改值。

不做的事：

- 不改变 GDD 已确立的玩家可见规则（无道具、无特殊砖块、砖块全部一击即碎、底部不弹射）；数值为规则服务，不为拟合计算而改规则。
- 不规定碰撞检测与更新算法（归 TECHNICAL_DESIGN / 实现批次）；本文只给步长与稳定性参数方向。
- 不维护手算派生表：单步位移、各行小计、救援断点等派生值一律由模型脚本计算，见附录，本文不复制其表格。
- 不声称执行过运行时检查；模型只生成数值与规则检查，不证明手感。

本游戏无长期成长系统、无资源经济（GDD 2.2 明确排除），故不引入成长曲线/经济模型；局内提速是节奏参数，不是成长线。

## 2. 受影响的玩家体验与设计取向

| 体验 | 取向 |
|---|---|
| 公平（fairness） | 居中发球、零记忆布局；失误只扣生命不扣分；同帧规则按 GDD 6.2 固定优先级，不依赖设备刷新率 |
| 张力（tension） | 球始终运动、底部开口；随清场进度球速分四档抬升，把后段压缩成高压窗口 |
| 精通（mastery） | 挡板击球点是玩家唯一的方向控制手段，角度映射必须单调、可读、边点与中点差异明确 |
| 节奏（pacing） | 以**击碎数**而非时钟触发提速：进度由玩家行动驱动，跨设备一致、可观察 |
| 资源压力 | 仅三条生命：失误成本恒定且有限，不做连击惩罚或经济压力 |

## 3. 发布配置（Release Config）

以下为首版确定的初始值；机器记录与全部派生值见附录表 1–表 3（本文不复制派生表）。坐标系：左上原点，单位为**逻辑像素**（Scene 参考框 1280×720，非宿主像素）。

### 3.1 球速与发球

- **初始速度 s₀ = 360 逻辑像素/秒。** 依据：中部飞行区纵深 296（阵列底边 y304 → 挡板顶 y600），近竖直下落穿越时间约 0.82s，给持续预判留出可观察窗口，又不会慢到拖沓。
- **四档提速（按累计击碎数 d）：** 360 → 420（d≥6，即清完一行）→ 480（d≥18，三行）→ 540（d≥36，六成）；**上限 540 逻辑像素/秒（=1.5·s₀）。** 每档 +60（+16.7%），阈值对应玩家可观察的阵列分组；档位之间无插值，达到阈值立即生效。
- **发球偏转角 = 40°（相对竖直向上；发布实现取此定值）。** 水平符号：自进入本次 Ready 以来最后一次有效横向输入的方向；无前置输入时向右。实现允许的发球窗口为 **30°–50°**（在窗口内选择仍合规；首版发布实现取定值 40°）。
- 选择**击碎数触发而非时间触发**：结果由玩家行动决定、跨设备完全一致、玩家可观察；纯时间触发会在被动局面下强制加压。

### 3.2 挡板

- **宽度确认为 120 逻辑像素（高度 16 不变）。** 宽度/场地内界宽（960）= 1/8；半宽 60 给击球点映射提供足够的角度分辨率，同时对到位精度保持要求。**Scene 无需改值**（若未来改值，必须改 `breakout_level.json` 中挡板 sprite 与碰撞体两处尺寸）。
- **键盘移动速度 = 560 逻辑像素/秒**（方向键 / A、D 按住积分）。取值依据是第 6.2 节救援断点：上限球速下仍保有可救援余量。
- 鼠标 / 触屏按 GDD 采用横坐标跟随，**无速度参数**（即时到位）；挡板纵向固定 y608，横向中心被夹在 220–1060。

### 3.3 生命

- **初始生命 = 3 条，确认 GDD 值。** 失误一次 −1；3 → 2 → 1 → 0（0 即失败）。

### 3.4 砖块分值（GDD 未决项，本文拍板）

- 6 行自上而下分值 **60 / 50 / 40 / 30 / 20 / 10**（行 1 为顶行）。顶行球最不易到达（需先穿过下方各行并被瞄准抬升），给更高分值作为方向控制的奖励；**全部砖块行为完全相同——一击即碎，分值不影响任何判定**。取整十数便于口算与校验，单关总分 = 2100（派生值见附录表 3）。

### 3.5 固定逻辑步长与防螺旋

- **固定逻辑步长 fixedDt = 1/120 秒 ≈ 0.008333s（逻辑 120Hz）。** 依据：上限速度 540 时单步位移 4.5px，小于砖间最小间隙 8 与球直径 16，非扫掠实现也不会在一步内跨过最小碰撞特征；60/120/144Hz 刷新率由累加器自然归一，高刷屏不再“球速翻倍”。
- **单帧最大逻辑步数 maxStepsPerFrame = 8**（=8/120 ≈ 66.7ms 的逻辑预算）：覆盖单帧卡顿至约 15fps 的突发掉帧；超出上限时**钳制累加器、丢弃多余时间**，不进入螺旋，也不回溯补发（与 GDD 6.3 取向一致）。
- 步长是稳定性参数；在其上运行的速度/角度等玩法调值以本文为准。具体更新与插值算法归 TECH。

## 4. 可执行规则公式

符号：球中心 (x_b, y_b)，挡板中心 (x_p, y_p=608)，挡板半宽 w=60，当前档位速率 s；角度以弧度内部计算（本文用度描述），y 轴向下。

### 4.1 挡板反弹角度

击球点归一偏移：

```
h = clamp((x_b − x_p) / w, −1, 1)        // h∈[−1,1]；h=0 中点，h=±1 边点
θ = h · θ_max，θ_max = 60°
反弹后速度：v′ = ( s·sinθ, −s·cosθ )      // 恒向上；水平方向随 h
```

- 中点 h=0 → θ=0（垂直向上）；边点 h=±1 → θ=±60°。
- 直接推论：**每次挡板反弹后 |v_y| ≥ s·cos60° = 0.5s**（最小竖直分量保证）。

### 4.2 弹射反射规则

- 左/右墙：v_x → −v_x；顶墙：v_y → −v_y（球心约束在 x∈[168,1112]、y≥72）。
- 砖块：按扫掠入射轴决定法线 n（x 面或 y 面），v′ = v − 2(v·n)n，即翻转入射轴分量；同帧触及多块砖时所有砖均击碎计分、**只产生一次方向变化**（GDD 6.2.2）。
- 挡板碰撞不使用通用反射，统一由 4.1 覆盖（GDD 6.2.3 挡板优先，球不会向下）。
- 反射只改方向不改速率；无碰撞段速度向量恒定（GDD 6.1）。

### 4.3 提速触发

```
s(d) = 360  if d < 6
       420  if 6 ≤ d < 18
       480  if 18 ≤ d < 36
       540  if d ≥ 36
```

碎砖使 d 增加后立即重算 s；过阈时速度向量按比例缩放、**位置与方向不变**（GDD 6.1）。同帧多砖按累计后的 d 取档。

### 4.4 分数累计

```
S_new = S_old + P_row，P = [60,50,40,30,20,10]（行 1..6）
```

S 只增不减；失误不产生任何 P，只扣生命。

### 4.5 同帧判定（模型 `resolveFrame` 的规则表达）

一帧内汇总：击碎砖块集合 H、是否越过失误线 m；若击碎后存活砖数为 0 → **过关**（含同帧落底，不再扣生命）；否则若 m → 生命 −1（归零即失败）；多砖只记一次反弹。对应 GDD 6.2 全部四个优先级。

## 5. 可达运行状态

| 状态量 | 取值范围（首版） |
|---|---|
| 累计击碎数 d | 0 → 60（整数） |
| 球速 s | {360, 420, 480, 540}（像素/秒），随 d 单调不降 |
| 生命 | 3 → 2 → 1 → 0；仅失误成立时扣一次 |
| 分数 S | 0 → 2100；只有砖块产生分数且不扣减，故上界恰为 2100 |
| 流程状态 | Menu / Ready / Playing / Paused / LevelClear / GameOver（GDD 5.1） |

注：d、s、S 的轨迹由固定布局与玩家行动决定，无随机内容差异。

## 6. 模型场景检查与结论

模型（`docs/balance_model.mjs`）经工具提供的 `readJson` 直接读取 `content/scenes/breakout_level.json`：从三面墙节点反推内界、从挡板/球节点读取尺寸、从 `brick.array` 行为配置生成 60 块砖矩形，并与 60 个砖块节点的 Transform / 碰撞体 / 行号逐一交叉核对。模型为事件驱动扫掠圆 vs 轴对齐矩形，序列确定性、无随机数。

### 6.1 检查覆盖（12 项全部通过；逐条观测值见附录）

模拟的合法序列：Ready 附着 → 40° 发球 → 边界/砖块弹射与挡板回球（含一次 **h=±0.95 边点**回球、一次 **h=0 中点**回球，其余回球由合法击球点瞄准存活砖）→ 在 d≥10 后**一次故意失误落底**（生命 3→2、球停止、已碎砖保持）→ Ready 归中重发 → 继续合法回球直至 60 块全清。断言与观测：

- 非碰撞不减速：每段匀速积分后球精确落在预测碰撞面（120 轮事件，偏离 0 次）；墙碰只翻方向、速率不变。
- 挡板边点反弹角（57°）**大于**中点（0°），符号与击球侧一致。
- 失误：生命 −1、分数前后不变（290 → 290）、球速率 0。
- 重发后阵列不恢复；清场 d=60、总分 S=2100 = 各行分值之和。
- 规则检查（非物理同帧）：最后一砖与落底同帧 → 过关且不扣生命；同帧两砖（含最后砖）→ 两块均计分、一次反弹；普通多砖 → 均计分不扣命；最后一条命落底 → GameOver。

该序列确立的结论是：**存在一条合法的（键盘/指针操作下）可清场路径，且各规则观测结果与 GDD 一致**。它不确立最快通关时间，也不是通用安全上界。

### 6.2 反应时间 / 可救援性检查

场景与假设：

- 竖直下落是救援时间**最短**的承诺轨迹（浅角度下落竖直分量更小、时间更长）；球从第 6 行砖底面反弹离开时中心 y=304+8=**312**；最后可拦截点为球触挡板顶面，中心 y=600−8=**592**；下落距离 **280px**（均由真实几何推导）。
- 挡板中心行程范围 220–1060（按移动行为 bounds 与半宽 60 推导），最大横跨 **840px**。
- 反应时间 **0.22s 为假设值**（经验区间 0.20–0.25s，非目标玩家测量）。

断点（派生数值见附录表 4、表 5）：

- 从 y312 竖直下落：无反应延迟时键盘可横移 435.6px（360 档）～290.4px（540 档）；扣 0.22s 后为 312.4px ～167.2px。**已验证：上限速度下扣反应后 150px 横移仍可救到。**
- **最坏情况（到位才开始移动、横跨全场 840px）：需要 1.50s，而球最快 0.519s 落地——任何档位都救不到。** 这是预期结果：正常玩法中玩家持续跟踪轨迹、并行移动，840px 边界不是常规局面，而是“零预先跟踪”的形式化最坏点。
- 中途误判参考：球到 y500 才开始反应时，仅剩 92px 下落；540 档扣 0.22s 后无任何横移余量（见附录表 5）——即末段高速球几乎不允许临场改判，必须提前预判，这是提速设计的意图所在。

结论与假设的区分：上述时间/距离断点是**在明示假设下由真实几何算出的支持性结论**；真实玩家是否稳定做到、0.22s 是否贴合目标受众，属需 playtest 验证项。

## 7. 风险与缓解

1. **高速穿透（tunneling）。** 缓解：fixedDt=1/120 使单步位移 ≤4.5px（<最小间隙 8、<球径 16）；建议实现采用扫掠碰撞或碰撞后位置校正（算法归 TECH）；maxStepsPerFrame 防止卡顿后单帧长距离跨越。残余风险：极端多步叠加仍可能异常，需实现批次按运行时验证。
2. **近水平死循环。** 角度唯一来源是发球（40°）与挡板反弹（≤60°）；砖块/墙只翻分量、不产生新角度。故全局有界：**任何时刻 |v_y|/s ≥ min(cos40°, cos60°)=0.5，v_y 不可能为 0**，不存在严格水平轨迹。建议实现另在反弹后对最小竖直分量做钳制作为防御性兜底。
3. **难度悬崖。** 每档 +16.7% 且在 d=36（剩 24 块、多为顶行）同时遇到最高速与瞄准要求；属刻意的末段加压，但“一档之差”的体感落差需 playtest 确认；第 9 节给出阈值与速度的可选范围。
4. **死亡螺旋。** 累加器 + 单帧 8 步上限 + 超限钳制：掉帧只丢弃展示时间，不改变规则结果。
5. **侧墙通道重复。** 两侧各有 44px 无砖通道，极端回球可形成短暂空往返；玩家随时可用击球点改出，不构成死局；列入 playtest 观察。

## 8. 支持性结论 vs 需 Playtest 验证的假设

**支持性结论（由真实几何 + 合法动作算出，见附录）：**

- 存在一条合法可清场路径；清场总分恰为 2100，分数只增、失误不扣。
- 挡板角度映射单调：边点 57° > 中点 0°；全局 |v_y| ≥ 0.5s，无水平轨迹。
- 120Hz 步长下单步位移 ≤4.5px，小于最小碰撞特征；救援断点（150px 可救 / 840px 不可救）在明示假设下成立。
- GDD 6.2 四类同帧规则的判定结果正确。

**需 playtest 验证的手感假设（计算器不证明）：**

- 360 初速 / 540 上限与四档节奏是否“紧张但可反应”；发球 40° 是否感觉公平。
- 键盘 560px/s 对真实玩家（含设备、握持、注意力）是否足够；0.22s 反应假设是否贴合目标受众。
- d=36 的高速悬崖是“末段加压”还是“不可救的突变”。
- 分值 60..10 的差异是否提供可感知的奖励反馈而不诱导单一策略。

## 11. 局限与未决

- 场景检查为**单条确定性**合法序列：确立该路径与各断点，不证明所有策略、不提供最快时间或通用安全界。
- 同帧同时性以判定函数做规则检查，未做物理级同帧模拟。
- 0.22s 反应时间与“竖直下落=最短救援”为建模假设；救援结论仅在该假设下成立。
- 未观测任何运行时：手感、公平性与视觉反馈以第 8 节 playtest 假设形式移交。
