## 1. 坐标与布局约定

- 所有界面使用**屏幕空间逻辑像素，原点左上**，+X 右、+Y 下；锚点/枢轴按 content-format 约定：子节点枢轴默认与锚点一致，居中元素 position 为 [0, 偏移]，不重复偏移。
- 参考构图：**960×540**；这是设计参考，不是固定宿主尺寸。屏幕根解析为实际视口。
- 空间行为条件（选择优先级从高到低）：
  1. **portrait**：高 > 宽（在 compact 之后应用）；
  2. **compact**：宽 ≤ `compactMaxWidth`（开始界面根取 680，以容纳 667×375 移动横屏；其余取默认 600）；
  3. **默认**：宽口横屏构图。
- 界面身份、层级、文本、状态、绑定、响应式变体均以作者化 UI JSON 落地；运行时只解析与更新，不生成第二套布局。世界取景（letterbox）与 UI 适配是两条独立坐标链（TECHNICAL §6），本文拥有屏幕空间分配权。

### 1.1 规划屏幕/覆盖层清单

| 文档（拟） | 对应 GDD 状态 |
|---|---|
| `ui/start.json` | 开始界面 |
| `ui/game.json` | 待发球、球运动中（含 HUD 与发球提示） |
| `ui/pause.json` | 已暂停 |
| `ui/result.json` | 胜利结算、失败结算（同一面板，内容按结果切换） |

## 2. 屏幕一：开始界面（start.json）

**进入条件**：应用启动；或从暂停/结算"退出"。**退出**：开始游戏（T1）。

**信息层级与构图**（列容器，垂直水平居中，gap 20）：

| 顺序 | 元素 | 角色 | 内容/来源 |
|---|---|---|---|
| 1 | 标题「打砖块」 | text | 静态；视觉绝对焦点（ART §5.1 的发光标题字） |
| 2 | 砖墙主视觉 | ~~image（assetRef `RES-HERO`）~~ **已由 ASSET_PLAN §4 修订：取消独立图片，改用图集 `brick` 帧运行时组合的缩小砖墙** | 视觉用途：霓虹砖墙母题，暗示关卡目标 |
| 3 | 操作说明 | text | 静态一句："移动挡板反弹小球，击碎全部砖块即可获胜" |
| 4 | 开始游戏 | button（primary，action `START`） | 唯一主行动 |

**构图意图**：标题最先吸引视线，主视觉建立母题，安静的说明文案退后，按钮是唯一高亮可操作元素，四周为负空间。

**响应式**：
- compact（含 667×375 移动横屏）：隐藏砖墙主视觉（`enabled:false`），收紧为标题+说明+按钮，保证垂直方向放得下；标题/说明允许收缩到各自 minSize。
- portrait：沿用默认列构图（主视觉保留），元素宽度不超过宿主减内边距。

**状态**：
- 默认：按钮可激活；焦点默认落在「开始游戏」。
- 加载中：首屏资源未就绪时显示中性加载态，无玩法模拟。
- 错误：启动数据拉取失败显示错误界面+「重试」（不使用内置默认布局顶替）。

## 3. 屏幕二：游戏界面（game.json）

**进入条件**：T1/T9（新一局）；T3 失球复位后仍处于本屏幕。**退出**：T4/T5 结算、T6 暂停覆盖。

### 3.1 区域分配（整体足迹）

- `game-view` 容器：锚定宿主 `[0.02,0.02]–[0.98,0.98]` 拉伸留边，minSize 280×300；世界（480×672）在其内由相机 letterbox 完整呈现。
- HUD 全部为 game-view 内的 **absolute 元素（退出流式分配）**，位于 GDD/关卡允许的顶部 0–48 带：

| 元素 | 锚定 | 尺寸/最小 | 绑定 | 作用 |
|---|---|---|---|---|
| 分数 `hud-score` | top-left，pos [12,10] | 140×28 / 100×24 | text←score | 次级信息，随得分即时更新 |
| 暂停 `pause-btn` | top-center，pos [-36,8] | 72×32 / 64×30 | action `PAUSE_TOGGLE` | 随时可用 |
| 生命 `hud-lives` | top-right，pos [-152,10] | 140×28 / 100×24 | text←lives | 次级信息，失球即时减少 |

- `serve-prompt`：bottom-center，pos [0,-72]，240×28，**仅"待发球"可见**（绑定 visible: phase==ready），文案"按 空格 / 点按 发球"。位置高于挡板与死亡带，不遮挡球。

### 3.2 各相位差异

- **待发球**：挡板可移动、球贴附；发球提示可见。
- **球运动中**：发球提示隐藏；HUD 始终可见。
- 游玩中除顶部 HUD 带外，机动空间与挡板/死亡带无任何覆盖元素（与 LEVEL_SCENE_DESIGN §2.2 一致）。

### 3.3 响应式

- 默认/横屏：上述锚点构图；宽高比变化只改变相机留边，HUD 相对 game-view 锚点不动。
- compact/portrait：HUD 尺寸允许收缩到 minSize；不重排（锚点已保证不重叠、不侵入砖墙）。
- 667×375 移动横屏：game-view 收缩到 minSize 仍满足整个 480×672 世界 letterbox 可见。

## 4. 覆盖层三：暂停（pause.json）

**进入**：T6（Esc/P/暂停按钮；自动暂停同路径）。**退出**：T7 继续、T8 退出本局。

- `scrim`：铺满宿主的半透明暗压层（absolute）；冻结的世界隐约可见，辉光视觉降温。
- `panel`：居中卡片（absolute，列容器，gap 18，内边距 [28,24,28,24]），尺寸 340×264 / 最小 280×248。
  - 标题「已暂停」240×40；
  - 主按钮「继续」220×52（action `RESUME`，默认焦点）；
  - 次按钮「退出本局」220×52（action `QUIT_RUN`）。
- 暂停期间：世界一切输入（移动/发球）在规则入口丢弃；继续不补发暂停期间位移。
- 自动暂停恢复**必须玩家显式操作**，不自动续球。

## 5. 覆盖层四：结算（result.json，胜利/失败共用）

**进入**：T4 胜利 / T5 失败。**退出**：T9 再来一局、T10 退出。

- `scrim`：同暂停的满铺暗压层；胜负情绪差异由 ART §5.5/5.6 定义（胜利面板标题暖亮、失败克制不铺红）。
- `panel`：居中列容器，尺寸 340×300 / 最小 288×276，gap 18：
  1. 结果标题 260×44，text 绑定 `resultTitle`（"通关成功"/"挑战失败"）；
  2. 最终分数 240×32，text 绑定 `finalScore`（"最终分数 XXXX"）；
  3. 主按钮「再来一局」220×52（action `RESTART`，默认焦点）；
  4. 次按钮「退出」220×52（action `EXIT_TO_START`）。
- 结算出现后场地移动/发球输入一律丢弃；两按钮始终可响应。

## 6. 共享组件定义（唯一定义处）

| 组件 | 规格 | 状态 |
|---|---|---|
| 主按钮 primary | 青色填充、深色压边、轻辉光、圆角中档；默认尺寸按屏幕（开始 220×56；面板 220×52），min 180×48 | default / hover或focus（辉光增强）/ pressed（快速压暗+轻挤压）/ disabled（降明度、不响应） |
| 次按钮 secondary | 透明底+同色系描边、无辉光；同尺寸规则 | 同上 |
| HUD 文本 | 正文无衬线、纯色+深色投影、无辉光；分数数字近等宽 | 值变化时小幅强调色跳字 |
| 模态面板 | 大圆角深色卡片、细外框、柔和投影；内列容器 gap 18 | 仅 default |
| 暗压层 scrim | 半透明深色，满铺 absolute | 进入/退出快速淡变 |
| 图标式生命指示 | 心形/几何形（非纯圆），失去时变暗/破碎；**不以颜色为唯一通道** | 存活 / 失去 |

按钮在触屏上命中区不小于 48×48（上述尺寸均满足）。

## 7. 焦点、导航与输入方式

- **键盘/鼠标**：
  - 菜单界面 Tab/方向键在按钮间移动焦点，Enter/Space 激活；进入每个屏幕时默认焦点：开始→开始游戏；暂停→继续；结算→再来一局。
  - Esc/P 触发暂停；暂停面板内 Esc 等同继续。
- **触屏**：所有按钮直接点按；game-view 上 `touch-action:none`，拖拽控挡板、点按发球；暂停按钮与 HUD 命中区不与拖拽冲突（它们是覆盖在顶部的独立控件）。
- 同一行动的物理按键与屏幕按钮发送同构指令，裁定逻辑只有一份（TECHNICAL §3.2）。

## 8. 反馈与动效时序（目的/触发/外观/时序）

对齐 GDD §6 与 ART §6；表现动画不延迟规则判定。

| 事件 | 目的 | 时序要求 |
|---|---|---|
| 击球（墙/挡板/砖，三类可区分） | 确认碰撞 | 瞬时触发，视觉反馈 ≤100ms 内出现 |
| 砖块销毁+得分 | 爽感+确认 | 碎裂约 300–400ms 快速衰减；HUD 分数当帧更新并跳字 |
| 失球（有余命） | 明确失误且进度保留 | 底边收束光 ≤500ms，随后快速复位；砖块/分数视觉不变 |
| 生命减少 | 状态可知 | 指示消退动效约 300ms |
| 进入/退出暂停 | 状态切换 | 暗压层快速淡变约 150–250ms，安静无庆祝光效 |
| 胜利/失败 | 结果表达 | 面板在模拟停止后出现；标题/分数可读，主按钮即刻可激活 |

**减弱动态（reduced motion）**：当系统/宿主偏好减少动态时，禁用闪烁、拖尾与全屏脉冲，仅保留透明度淡变与状态文本；发球提示的呼吸闪烁改为常亮。所有重要反馈同时有视觉与声音双通道（AUDIO_DESIGN），不依赖单一通道。

## 9. 布局计算结果（已执行，几何层面）

四份草稿（`.beegame/tmp/ui-*.json`，无 Manifest 的临时草稿）计算尺寸与结果：

| 草稿 | 检查尺寸 | 命令要点 | 结果 |
|---|---|---|---|
| ui-start | 960×540 / 390×844 / 600×800 / 667×375 | `--layout-draft` | 全部 OK；无 outsideViewport/Parent/ContentArea |
| ui-game | 同上 | 另加 `--game-view game-view --camera camera-draft.json` | 全部 OK；取景 960×540 时相机矩形 370×518@(276,0)；667×375 时 257×360@(192,0) |
| ui-modal-pause | 同上 | `--layout-draft` | 全部 OK |
| ui-modal-result | 同上 | `--layout-draft` | 全部 OK |

修正过程：开始界面在窄/短屏下收窄元素并对 compact 隐藏主视觉；game-view minSize 降至 280×300 以适配移动横屏；发球提示改用锚点居中；模态按钮改为面板直接子项（嵌套流式容器曾导致子项越出 content area）。

**计算器不覆盖（明确保留）**：未加载实际字体，**文本度量未实测**；玩法遮挡、动效与界面整体观感未验证；矩形通过不构成界面质量 PASS。运行时绑定验证同样未做（runtimeVerified=false）。
