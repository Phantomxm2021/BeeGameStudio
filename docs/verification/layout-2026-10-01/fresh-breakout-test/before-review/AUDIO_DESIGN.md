## 1. 目的与边界

本文把 GDD §6 的规则触发点落成**必需的声音行为规格**：每类声音的用途、性格、触发事件、时长/循环、停止条件与重复触发行为；并规定并发混音、状态过渡、静音范围与多通道冗余原则。

本文**不做**的事：

- 不列音频资产清单、不规定素材生产路径（录制/合成/检索/程序化生成均可）、不臆造文件名——归 `ASSET_PLAN`；
- 不规定编解码器、码率、加载管线等实现细节——以技术设计文档为准；
- 不新增玩法内容，不为 GDD §1.2 的排除项预留音频接口（无道具音、无多球音、无多关卡音乐切换）；
- 不重复 GDD 规则与美术规格，仅在必要处引用。

**既定事实（全文一致）**：Web · React · 2D；键盘/鼠标 + 触屏；单一关卡；3 条命；40 块砖；无持久化，静音状态仅内存有效。全部声音为 **2D（非定位）**：单屏固定视角游戏，声像不携带玩法信息，不做 3D 空间化。

**验收状态声明**：本文全部内容为设计意图。实际音频资源尚未产出，**未做任何运行时音频检查**（电平、延迟、并发、外放/耳机表现均未实测），不得在其他文档中转述为"音频已验证"。

## 2. 声音性格总纲：霓虹夜色街机

与美术主题统一：暗场 + 霓虹 + 外辉光，声学对应物为——

- **短、干净、电子化**：以合成器质感的短促音（blip / tick / zap）为主，起音极快（适配高频碰撞），余响短而不浑浊；
- **冷色系统治，暖色留给结果**：挡板与墙为冷调（青/蓝系音高与音色），砖块销毁在冷—暖谱上更亮，胜利为明确的暖色上扬，失败为低频下沉；
- **不使用拟真物理采样的"硬碰撞"**（无沉重木石撞击声）：那与霓虹塑料/灯管的视觉材质矛盾，且高频连撞时易产生刺耳噪声；
- 与美术 §2.2 情绪曲线逐条对应（见 §5 过渡表）。

## 3. 必需声音行为规格

以下 12 类为首版**必需**。三类击中（墙 / 挡板 / 砖块）必须可被玩家盲听区分，这是 GDD §6 的硬性要求；区分手段同时落在**音高、音色、时长**三个维度上，任一维度失效仍可辨别。

时长为建议目标值，最终以素材在运行时的实际听感为准（§9）。

### 3.1 球击中墙（cue：`sfx.hit.wall`）

- **用途**：确认球与左/右/上墙发生反弹，维持节奏读感。
- **性格**：最轻、最冷。高频金属/电子"叮"，音量克制，像远处轻敲霓虹灯管。
- **触发**：球与任一反弹墙碰撞当步（GDD §6）。三面墙共用同一 cue，不做区分。
- **时长/循环**：一次性（one-shot），约 40–80 ms；不循环。
- **停止条件**：自然衰减结束；被暂停/退出时若仍在响则立即截断（§5）。
- **重复触发**：可并发（见 §4 上限）；极短间隔内允许轻微截断自身前一实例以保持干净，但优先走并发池。

### 3.2 球击中挡板（cue：`sfx.hit.paddle`）

- **用途**：正反馈——"接到了"，给玩家安全感与确认。
- **性格**：中音区、稍饱满的电子"啵/噗"，带快速上扬的微小音高包络，青色对应的冷—中性音色，令人安心。
- **触发**：球与挡板碰撞当步。
- **时长/循环**：一次性，约 80–120 ms。
- **停止条件**：自然结束；暂停/退出截断。
- **重复触发**：新实例**截断**同类旧实例（挡板每次接球都是新的重要确认，不堆叠）；不与墙音互相截断。

### 3.3 球击中砖块（cue：`sfx.hit.brick`）

- **用途**：区分"碰到砖"与"砖碎了"之外的碰撞质感（首版一击即碎，故此 cue 与销毁音紧邻；见下注）。
- **性格**：中高频、清脆的电子"滴"，比墙音更亮、更靠前，比挡板音更短更硬。
- **触发**：球与砖块发生碰撞的当步。
- **时长/循环**：一次性，约 30–60 ms。
- **停止条件**：自然结束；暂停/退出截断。
- **重复触发**：走高频并发池（§4.2），允许密集重叠；同一步触及多块砖时每块各触发一次，但受全局并发上限与节流约束。
- **注（实现口径）**：首版砖块一击即销毁，碰撞与销毁在同一步结算。允许实现采用"击中音 + 销毁音"两层紧邻播放，或用一个带碎裂尾段的复合 cue 承载；无论哪种方式，**听感上必须与墙、挡板两类明确可区分**，且销毁反馈不被击中音淹没。若资源紧张，最低可接受方案是单一 `sfx.brick.destroy` 同时承担，但墙/挡板仍须各自独立。

### 3.4 砖块销毁（cue：`sfx.brick.destroy`）

- **用途**：爽感主体 + 得分确认，对应砖块光爆与 HUD 跳字。
- **性格**：比击中音更亮、带微小碎裂/火花质感的短音，可有快速下行或上挑的颗粒尾，干脆不拖泥。
- **触发**：砖块被销毁的当步（与击中同帧，紧随其后）。
- **时长/循环**：一次性，约 100–180 ms。
- **停止条件**：自然结束；暂停/退出截断。
- **重复触发**：高频并发池，密集连撞时与击中音共享砖块组预算（§4.2）；允许最多 2–3 个变体随机轮换（仅音色微差，玩法无差异，且变体属实现细节而非必需资产）。

### 3.5 失球（有剩余命）（cue：`sfx.ball.lost`）

- **用途**：明确传达"球没了，但这局没完、进度还在"。
- **性格**：中频向下滑落的短音（zap-down），带一点被黑暗吞没的收束感；**不做成失败巨响**——还有命，不能谎报状态（反馈不得对玩法状态说谎）。
- **触发**：球触死亡边界且扣命后仍有剩余命（GDD T3）。
- **时长/循环**：一次性，约 300–450 ms。
- **停止条件**：自然结束；退出截断。失球后进入待发球期间允许其放完（不属于暂停）。
- **重复触发**：高优先级，截断一切在播的砖块/墙音（§4.3）；同类新实例截断旧实例。

### 3.6 生命减少（cue：`sfx.life.lost`）

- **用途**：与失球音区分，独立强调"生命指示少了一格"这一规则后果。
- **性格**：低沉、偏短的负面确认音（低正弦/方波两下递减，或单次低脉冲），严肃但克制，不刺耳。
- **触发**：死亡结算中扣除 1 条命的当步（T3 与 T5 路径均触发；T5 时被失败音接续/覆盖，见 §4.3）。
- **时长/循环**：一次性，约 200–300 ms。
- **停止条件**：自然结束；退出截断。
- **重复触发**：高优先级；与 `sfx.ball.lost` 可错开约 80–150 ms 串行播放（先吞没、再扣命），形成一个两段式"失误句"；若最后一命，`sfx.game.over` 在其后约 150–250 ms 接入并可截断生命音尾段。

### 3.7 胜利（cue：`sfx.game.win`）

- **用途**：全局正向高潮，对应光爆余韵与结算面板。
- **性格**：明亮上扬的短乐句（3–5 个上行音的合成琶音/号角感），暖色，释放感，时长为本组最长之一但不冗长。
- **触发**：一步结算后场上砖块为 0、进入胜利结算的当步（T4，胜利即时生效口径之后）。
- **时长/循环**：一次性乐句，约 900–1400 ms。
- **停止条件**：自然放完；退出（T10）截断。在胜利音播放期间点击"再来一局"时，新一局 UI 确认音可截断其尾段。
- **重复触发**：最高优先级，触发瞬间截断全部玩法音（含最后一砖的销毁尾音可保留极短引导后接管，具体以听感不突兀为准）。

### 3.8 失败（cue：`sfx.game.over`）

- **用途**：明确终局，但不羞辱、不劝退（美术 §5.6 同口径）。
- **性格**：低音区下沉短句（2–3 个下行音），暗、短，结尾归于平静；音量与长度均小于胜利音。
- **触发**：扣命后生命为 0、进入失败结算当步（T5）。
- **时长/循环**：一次性，约 700–1100 ms。
- **停止条件**：自然放完；再来一局/退出截断。
- **重复触发**：最高优先级，截断除自身外全部声音。

### 3.9 暂停切换（cue：`sfx.pause.toggle`）

- **用途**：确认进入/退出暂停；状态切换音而非事件反馈（美术 §5.4 "快速、安静"）。
- **性格**：极短的中性电子音；进入 = 一个下抑短音（降温、冻结），恢复 = 镜像的上抑短音。建议两个变体 `sfx.pause.open` / `sfx.pause.close`，结构对称。
- **触发**：T6 / T7 生效当步（含页面失焦自动暂停，T6 同路径）。
- **时长/循环**：一次性，各约 60–120 ms。
- **停止条件**：自然结束；退出本局截断。
- **重复触发**：指令幂等，无效切换不发声（技术设计 §4.6）；open/close 不重叠。

### 3.10 发球（cue：`sfx.ball.serve`）

- **用途**：确认球离板、进入运动相位。
- **性格**：短促上扬的"发射/充能释放"音，与球的暖白高光对应，轻快有能量。
- **触发**：SERVE 指令边沿且当前为待发球（T2）；长按不连发，被相位去重拦截时不发声。
- **时长/循环**：一次性，约 80–140 ms。
- **停止条件**：自然结束；暂停/退出截断。
- **重复触发**：同类新实例截断旧实例（正常节奏下不会发生）。

### 3.11 UI 按钮（cue：`sfx.ui.confirm`）

- **用途**：确认按钮按下（开始游戏、再来一局、退出、继续、退出本局）。
- **性格**：轻柔、中性偏正面的短电子点击，比所有玩法音都退后，不喧宾夺主。
- **触发**：按钮在其可用状态下被实际激活（不可用按钮点击不发声）。
- **时长/循环**：一次性，约 40–80 ms。
- **停止条件**：自然结束。
- **重复触发**：新实例截断旧实例；触屏连点不叠加。

### 3.12 UI 聚焦（cue：`sfx.ui.focus`）

- **用途**：键盘导航时焦点在控件间移动的反馈（鼠标悬停不触发，避免噪声）。
- **性格**：极轻的高频微音，比 confirm 更弱更短。
- **触发**：键盘/可访问性导航导致焦点从一个可交互元素移到另一个时。
- **时长/循环**：一次性，约 20–40 ms。
- **停止条件**：自然结束。
- **重复触发**：快速连按导航键时允许节流（见 §4.2），宁可丢弃部分焦点音也不形成噪声串。

## 4. 并发、优先级与混音

### 4.1 事件频率的事实依据

球速 320 px/s、60 fps 下单步位移约 5.33 px（平衡文档 §4.1）；砖块厚 20 px、间隙 4 px。球在砖群内可出现**一步跨多块、连续多步高频销块**的情形（GDD §5.3 允许同一步销多块），峰值可理解为短时间内每帧数个碰撞事件。若不设限，销块音会堆叠成噪声墙，并掩盖失误与胜负。因此必须设置全局并发预算与抢占策略。

### 4.2 相对电平表与并发上限

电平以"相对刻度"给出（0 = 该组基准目标响度，单位近似 dB）。所有电平经**主增益（mute 开关所在节点）**统一收口；下表为组内相对关系，非最终绝对音量，绝对值需在目标设备实测校准（§9）。

| 总线/类别 | 相对电平 | 优先级 | 同类别最大并发实例 | 抢占/截断策略 |
|---|---|---|---|---|
| 胜利 `sfx.game.win` | +0（基准，最响档） | P0 | 1 | 触发即抢占全部 P2/P3 声部 |
| 失败 `sfx.game.over` | −2 dB | P0 | 1 | 同上 |
| 失球 `sfx.ball.lost` | −2 dB | P1 | 1 | 抢占全部 P3；截断在播砖块/墙音 |
| 生命减少 `sfx.life.lost` | −3 dB | P1 | 1 | 与失球串行，不互抢 |
| 击中挡板 `sfx.hit.paddle` | −4 dB | P2 | 1（自身截断） | 不抢别人；被 P0/P1 抢占时静音让位 |
| 发球 `sfx.ball.serve` | −5 dB | P2 | 1 | 同上 |
| 砖块销毁 `sfx.brick.destroy` | −6 dB | P3 | 4 | 与击中音共享**砖块组总预算 6 路**；超限丢弃最旧/最静实例（不截断 P0–P2） |
| 击中砖块 `sfx.hit.brick` | −8 dB | P3 | 含在砖块组 6 路内 | 密集时优先保留销毁音，击中音先被丢弃 |
| 击中墙 `sfx.hit.wall` | −9 dB | P3 | 2 | 超限丢弃新事件（墙音丢失可接受，视觉涟漪仍在） |
| 暂停切换 `sfx.pause.toggle` | −8 dB | P2 | 1 | 正常播放；暂停生效后一切声音停止 |
| UI 确认 `sfx.ui.confirm` | −9 dB | P3 | 1（自身截断） | 结算/菜单环境下相对可再略提高，但不超过 P2 |
| UI 聚焦 `sfx.ui.focus` | −14 dB | P4 | 1 | 50 ms 节流，超节流直接丢弃 |

补充规则：

- **全局总发声数硬上限建议 8 路**（含全部 one-shot）。超出时按 P4 → P3 → P2 顺序丢弃；P0、P1 永不被丢弃。
- **砖块组节流**：任一个 100 ms 窗口内，砖块击中+销毁音合计最多触发 8 次；销块视觉与计分不受影响（规则与表现分离，GDD §5.6），仅声音被节流。这保证多块同销时是"一串脆响"而非一声炸响。
- **削波防护**：主输出建议加一个软限幅（limiter/`DynamicsCompressorNode` 轻量配置），保证峰值并发不削波；限幅只兜底，不可把常态电平推到依赖限幅的程度。
- 所有 one-shot 播放前随机 ±0.5–1 dB 微差、击中砖块音可附极小微调偏移（见 §7.2 可选项），降低机械重复感。

### 4.3 重要事件的"透传"保证

失球、生命、胜负为 P0/P1：它们触发时，玩法高频声部立即让位（截断或静音），且自身电平高于砖块组 4–9 dB。验收口径：在最密集的连撞情境中触发失球/胜负，玩家必须能**第一眼（视觉）+ 第一耳（声音）**同时感知到结果事件。

## 5. 状态过渡的声音处理

与 GDD T1–T10 及美术 §2.2 情绪曲线对应。

| 过渡 | GDD | 声音处理 |
|---|---|---|
| 开始界面 → 新一局 | T1 | UI confirm 音；随后无额外过场音乐，进入安静的待发球态（世界本就安静，期待感由视觉的逐块点亮承担） |
| 待发球 → 球运动中 | T2 | `sfx.ball.serve` |
| 球运动中 → 待发球（失误续玩） | T3 | §3.5/§3.6 的"失球 + 扣命"两段式句；复位后发球提示出现，无补发、无循环背景音 |
| → 胜利结算 | T4 | `sfx.game.win` 接管，截断玩法声部；乐句放完后结算界面保持安静，等玩家操作 |
| → 失败结算 | T5 | 生命音后接 `sfx.game.over`；结束后归于安静 |
| → 已暂停 | T6 | `sfx.pause.open` 响完即冻结；**暂停期间一切声音停止**：所有在播 one-shot 立即截断，无任何声音在暂停期间起播；音频时钟挂起（建议 `AudioContext.suspend()` 或等效总线静音 + 停止调度） |
| 已暂停 → 原相位 | T7 | `sfx.pause.close`；**恢复不补发**暂停期间任何声音（与 GDD §5.7"不补发位移"同口径），也不补播被截断的音效 |
| 已暂停 → 开始界面 | T8 | UI confirm；截断全部声音，音频上下文回到空闲 |
| 结算 → 新一局 | T9 | UI confirm；`createRun()` 重置期间无声音残留（上一局的胜负音若在播即截断） |
| 结算 → 开始界面 | T10 | UI confirm；截断全部声音 |

其他边界：

- **页面失焦自动暂停**（技术设计 §4.5）：与手动暂停同一路径同一声音处理；从隐藏标签页回来时不自动发声、不自动续局。
- **首手势解锁**：AudioContext 在首次用户手势后创建/恢复（技术设计 §7.1）。若首个事件发生在上下文就绪前（理论上开始按钮本身就是解锁手势，正常不会出现），该音效允许静默跳过，不排队补发——避免解锁瞬间突然连放一串旧音。
- 首版**无 ducking 系统**：没有持续音乐（见 §6），暂停即全部停止即可，不需要音量压低/恢复的斜坡机制。该机制不预先建造。

## 6. 背景音乐决策：首版不做背景音乐

**决策：首版只做音效，不做背景音乐（含开始界面与结算界面）。**

理由：

1. **体量决定收益**：单局推算约 80–130 s（平衡文档 §4.4，未实测），且开局、失误复位、胜负出现的时机高度不规则。如此短的时长内，音乐还没建立起循环聆听就被暂停、截断或重开，过渡处理（开始/游玩/结算三段起止、循环点、ducking）的复杂度高于其情绪收益。
2. **玩法的节奏由音效本身构成**：球的碰—碰—碎是天然的节拍层，干净的电子音效在静默背景上就是"街机机台声"，静默本身就是霓虹夜色的情绪组成（暗场声学对应物）。铺上音乐反而抹平失误与胜负的留白冲击。
3. **规避平台与混音风险**：移动端外放、自动播放策略、浏览器标签页频繁挂起，都让短循环音乐更易出现突兀启停；在没有实测条件下引入音乐系统，风险大于价值。
4. 符合"不强行造系统"的原则：不为将来的多关卡预留音乐切换框架。

若试玩后明确认为开始界面/结算需要音乐性，**增强方向**（可选，不阻塞首版）：开始界面一段 8–16 s、可无缝循环、低电平（建议 −12 dB 以下）的合成 pad/慢琶音"夜色铺底"，开始游戏时快速（150–300 ms）淡出截断；结算仅复用胜利/失败乐句，不另起音乐；游玩中保持无音乐。任何此类增强仍须服从暂停即停、静音统一、无持久化三条既有约束。

## 7. 必需与可选增强的边界

### 7.1 必需（阻塞首版验收）

§3 的 12 类 cue（其中击中砖块在最低资源方案下可与销毁合并，但墙/挡板/砖三类可区分不可让步）、§4 的并发与抢占规则、§5 的过渡停止/不补发规则、§8 的静音与多通道冗余。

### 7.2 可选增强（不阻塞首版，不预先建系统）

- **环境氛围铺底**（ambience）：开始界面极低电平的夜色 hum/电流弱噪声；暂停与游玩中停止。电平须低于全部 P3 声部（建议 −18 dB 以下），且不得引入可辨识旋律而干扰读球。
- **砖块按行音调差异**：销块/击中音随砖块所在行做半音级微调（上行音阶映射，最上行最高），帮助玩家从听觉感知销块位置。玩法无差异，且不能破坏"同种砖块"的听感（建议音程跨度 ≤ 纯五度，音色保持同一）。此项依赖美术按行色序，可与之对齐，但首版不做也成立。
- 挡板接球音随命中点偏移微调（中心最低、边缘最高），把技巧信息多给一个通道；须克制，避免变成新的信息负担。
- 胜负乐句的更完整编曲、销块音色变体数量增加。

以上任一增强落地时都必须回归 §4 的并发预算与 §8 的静音/冗余原则，不得借机突破。

## 8. 静音、音量与多通道冗余

### 8.1 静音（唯一设置项）

- 静音开关作用于**全部声音的唯一主增益节点**：开启后所有 one-shot（及未来任何可选音乐/氛围）一律无声；音频系统仍可正常订阅事件、创建上下文，但不输出。
- **仅内存有效**：不写 localStorage / IndexedDB / cookie；刷新页面即重置为默认（有声）。与 GDD §7、技术设计 §7.5 一致，不提供任何变通持久化。
- 不设独立的音乐/音效分轨音量，不设音量滑条（首版无音乐；唯一设置项为静音，归 GDD/Tech 既定）。主电平绝对值在实现内一次性校准，用户不可调。
- 静音状态下切换暂停、触发胜负等均不发声；取消静音后**不补发**期间错过的任何声音。

### 8.2 关键信息不得只依赖听觉（硬性原则）

每一个重要声音都有对应的视觉/交互提示，静音游玩时游戏信息完整、可正常游玩。对应关系（视觉规格权威为美术 §6，触发点权威为 GDD §6）：

| 声音 | 必备的非听觉通道 |
|---|---|
| 击中墙 | 撞击点冷色涟漪 + 墙体边缘光一亮（美术 §6） |
| 击中挡板 | 挡板明度一闪/轻微挤压 + 冲击光（美术 §6） |
| 击中砖块/销毁 | 砖块亮闪、光爆碎片、HUD 分数即时跳字（美术 §6；GDD §6） |
| 失球 | 底边向下收束光、暗压、红橙警示脉冲；砖块与分数视觉不变（美术 §6） |
| 生命减少 | HUD 生命指示即时减少并带消退动效（美术 §6；GDD §6） |
| 胜利/失败 | 结算面板、结果文案、最终分、光效收束/上扬（美术 §5.5/§5.6） |
| 暂停切换 | 暗压覆盖层、辉光降温冻结/反向恢复（美术 §5.4） |
| 发球 | 球离板运动本身 + 发球提示消失（美术 §5.3） |
| UI 确认/聚焦 | 按钮状态变化、焦点视觉框、面板切换 |

另需考虑：听障玩家与无声环境（办公、移动端默认静音浏览）下，以上视觉路径必须自足；反过来声音也为"低头操作/余光看屏"提供通道。两侧是冗余关系，不是替代关系。

## 9. Cue 命名约定（供实现与 ASSET_PLAN 使用）

仅为建议约定，不构成资产清单：

- 统一前缀 `sfx.`，按"对象.事件"分层：`sfx.hit.wall` / `sfx.hit.paddle` / `sfx.hit.brick` / `sfx.brick.destroy` / `sfx.ball.lost` / `sfx.ball.serve` / `sfx.life.lost` / `sfx.game.win` / `sfx.game.over` / `sfx.pause.open` / `sfx.pause.close` / `sfx.ui.confirm` / `sfx.ui.focus`；
- 可选变体以序号后缀：`<cue>.v1`、`<cue>.v2`；
- 可选氛围/音乐若未来启用，使用独立前缀（如 `amb.` / `music.`）与独立总线，不与 `sfx.` 混轨；
- 事件名与 GDD §6 / RuleEngine 输出的规则事件（技术设计 §3.1 第 6 项）保持一一对应，AudioController 按 cue 名订阅，不在代码中写死文件名。

## 10. 待决问题与依赖

- **实际音频资源全部未定**：cue 的素材来源（合成/录制/检索）、许可与 provenance 核查归 `ASSET_PLAN`；在资源到位并通过许可核查前，本文所有规格均无法验收。
- **绝对电平未校准**：§4.2 为相对刻度。目标设备的**手机外放（含竖屏小机）、笔记本扬声器、耳机**三档实际电平与频响差异需在真实运行时实测后统一标定；移动端小扬声器对低频（失球/生命/失败音）的还原是明确风险点，可能需要上修低频音的基频或增加中频成分。
- **峰值并发与节流参数未实测**：§4.2 的 8 路全局上限、砖块组 6 路/100 ms 窗口为设计初值，需在目标设备验证 CPU（Voice 开销）与听感后收敛。
- **触发延迟未实测**：Web Audio 从规则事件到发声的实际延迟（尤其低端 Android）需实测，若与碰撞视觉不同步，优先保证"听感同步于可见事件"。
- **击中砖与销毁的合并/分离方案**（§3.3 注）待 ASSET_PLAN 资源形态确定后锁定。
- 依赖：`ASSET_PLAN`（资产、许可、规格）、交互契约（键盘焦点导航是否首版启用，影响 `sfx.ui.focus` 范围）、统一评审对 §6"不做音乐"决策的确认。
- **运行时音频检查尚未执行**：本文不声明任何声音已在浏览器/真机中播放验证。
