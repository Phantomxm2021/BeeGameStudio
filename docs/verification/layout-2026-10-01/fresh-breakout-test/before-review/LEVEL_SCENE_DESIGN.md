## 1. 关卡 L1：唯一首版关卡

### 1.1 目标与生成/结束条件

- **关卡目标**：击碎全部 40 块砖块（8 列 × 5 行，同一种砖块，一击即碎）。
- **生成条件**：玩家从开始界面进入（GDD T1）——满生命（3）、分数 0、砖墙完整，球贴附于挡板顶面中央（"待发球"）。
- **胜利结束**：场上砖块数为 0（GDD §5.4，胜利优先于同帧漏接）。
- **失败结束**：球触及死亡边界且剩余生命为 0。中途失球只复位球与挡板，**砖墙与分数保留**。

### 1.2 区域划分

场地自上而下分为四个功能带（设计坐标，见 §2）：

| 区域 | y 范围（逻辑像素） | 作用 |
|---|---|---|
| HUD/覆盖允许带 | 0–48 | 分数、生命、暂停按钮；允许 UI 叠加，不含玩法碰撞 |
| 砖墙体 | 64–180 | 5 行砖块所在；球在砖间反弹 |
| 机动空间 | 180–613 | 球飞行的主要区域，玩家在此读轨迹、调整接球点 |
| 挡板/死亡带 | 613–672 | 挡板活动（顶面 y=620）；底边 y=672 为死亡边界 |

### 1.4 砖块布局（作者化网格）

- 网格规格：**8 列 × 5 行 = 40 块**；砖块尺寸 **52×20**，水平/垂直间隙均为 **4**。
- 网格总宽：8×52 + 7×4 = 444；左右对称留边各 18 → 网格左上角原点 **(18, 64)**。
- 第 c 列（c=0..7）、第 r 行（r=0..4）砖块左上角：
  `x = 18 + c×56`，`y = 64 + r×24`。
- 所有砖块同色同种、同分值、无加固/特殊类型（GDD 排除项）。视觉上可用行做明度/色相微差以辅助行定位，但规则完全相同（具体配色见美术方向文档）。

### 1.5 挡板与发球位

- 挡板尺寸 **80×14**，仅水平移动；初始中心 x=240（左上角 x=200），顶面 y=620。
- 移动夹在左右墙内：挡板中心 x ∈ [40, 440]。
- 待发球时球（半径 7）贴附于挡板顶面中央，球心初始为 (240, 613)，随挡板水平移动，发球前不离开。
- 发球后球以固定初速度与倾角上行（数值见 BALANCE_DESIGN）。

### 1.6 布局如何支撑引导、挑战与节奏

- **引导**：砖墙对称居中、首发球倾角固定，玩家第一次挥拍即看到"边缘大角度、中心近垂直"的反馈；开始界面用一句中文说明操作，无需教学关。
- **挑战曲线（同一关内）**：砖块完整时球几乎总能撞到东西，宽容；随着砖块被清空，可反弹目标减少、出现"空洞"，球更容易穿过砖阵直上直下，迫使玩家更精确选择接球点。最低一行清空后，球的垂直飞行距离从约 440px 增至约 480px，反应时间略增，但空洞带来的漏判风险同步上升。
- **节奏**：挡板与砖墙底边相距约 440px，在发布球速下球从砖墙区域回落至挡板约 1.8 秒量级（推导与假设见 BALANCE_DESIGN §5），构成"观察—移动—接球"的稳定拍点；失球复位不重置进度，把一次失误的代价控制在"一次发球 + 一条生命"，维持心流不中断。

## 2. 世界坐标、单位与尺度

- 坐标系：**原点左上，+X 向右，+Y 向下**；单位为**逻辑像素（设计坐标）**，非设备物理像素，亦非固定宿主窗口尺寸。
- 关卡参考世界尺寸：**宽 480 × 高 672**；`pixelsPerUnit = 100`（仅用于逻辑像素↔引擎世界单位换算，禁止重复相乘）。
- 摄像机：**正交**，`orthographicSize = 3.36`（世界单位半高 = 672/2/100），参考 viewport 480×672，取景策略 **letterbox**：任何宿主宽高比下都完整显示整个 480×672 场地，不足方向均匀留边，世界布局与碰撞不随宿主改变。

### 2.1 世界范围 vs 显示范围

- **世界范围**恒为 480×672，不随容器变化。
- **显示范围**：游戏视图节点在宿主内以 anchorMin [0.02,0.02] / anchorMax [0.98,0.98] 拉伸留边；摄像机在该视图内 letterbox 呈现世界。
- 宽高比变化时：**不裁剪任何玩法区域**——三边反弹墙、全部砖块、挡板及**底边死亡线必须始终完整可见**；变化只体现在四周留边宽窄。屏幕 UI 的具体空间分配与布局选择归 UI_UX_SPEC，本文只提出可见性要求。

### 2.2 必需可见区域与 UI 覆盖限制

- 必需可见玩法区：整个 480×672 场地，无遮挡。
- 允许 UI 叠加的区域：
  - **顶部 0–48 带状区**：HUD（分数左上、生命右上、暂停顶部居中），其元素不得侵入砖墙体（y≥64）。
  - **暂停与结算覆盖层**：允许半透明全屏覆盖并冻结模拟（GDD T6–T10），覆盖层不是玩法遮挡（此时模拟已停止）。
  - 除此之外，机动空间与挡板/死亡带在游玩中不允许任何覆盖元素。

## 3. 空间计算验证（已执行，几何层面）

使用空间计算器对临时草稿（无 Manifest/内容索引）进行验证，命令：

```
bun .beegame/delivery/check-content.mjs \
  --layout-draft .beegame/tmp/ui-draft.json <w> <h> \
  --game-view game-view --camera .beegame/tmp/camera-draft.json
```

| 宿主尺寸 | 结果 | game-view 边界（左上→右下） | 摄像机 letterbox 矩形 |
|---|---|---|---|
| 960×540（桌面横屏） | ok；所有节点 outsideViewport / outsideParent = false | (19,11) → (941,529) | 370.29×518.4，x偏移275.66，y=0 |
| 390×844（手机竖屏） | ok；所有节点 outsideViewport / outsideParent = false | (8,17) → (382,827) | 374.4×524.16，x=0，y偏移143.04 |

HUD 三元素（分数、生命、暂停按钮）在两种尺寸下均完全在视口内、不侵入砖墙体。

**计算器不覆盖的范围（明确保留）**：文本度量（未加载实际字体）、玩法遮挡、动效表现均未验证；`runtimeVerified=false`。这只证明矩形几何与取景输入可行，不构成界面或玩法质量 PASS。最终屏幕空间分配以 UI_UX_SPEC 复核为准。

## 4. 场景落地约定（供内容编写）

- Scene 文档：kind `scene-2d`，`settings.coordinateSystem` = {origin:"top-left", units:"logical-pixels", width:480, height:672, pixelsPerUnit:100}。
- 每个砖块为独立 GameObject（40 个），semantic 标注 `brick`，配 `box-collider-2d`（52×20）与 `sprite-renderer`；也允许在后续内容阶段评估改用 tilemap 表达砖墙，但规则身份（40 个可独立销毁实体）不变。
- 挡板节点 semantic `paddle`，box-collider-2d 80×14；球节点 semantic `ball`，circle-collider-2d 半径 7；死亡边界为 semantic `death-boundary` 的触发器盒（贴底边，全宽）。
- 所有节点的位置/尺寸/资源绑定写入 Scene JSON，运行时只读取与动态更新，不存在代码里的第二份布局。
