# 音频设计 AUDIO_DESIGN

- 版本：v0.2（评审修订：静音控件落地至 content/ui；本文件为实现与验收基线）
- 作者：Bee Game Studio 主 Agent
- 日期：2026-10-01
- 上游：GDD.md（事件/状态）、BALANCE_DESIGN.md（节奏：球速 420px/s、回球间隔约 0.6–2.4s）、ART_DIRECTION.md（霓虹街机气质）。文件规格与来源归 ASSET_PLAN，本文件只定义声音行为。

---

## 1. 音频目标

- 每次球的接触在听觉上可辨类别（挡板 / 墙 / 砖碎 / 砖损），让玩家不看画面也能确认回击质量。
- 音乐保持低频运行的街机律动，提供"通电"能量感但不与高频反馈抢耳。
- 静音游玩时不损失任何关键信息——所有声音事件都有对应的视觉/界面变化（§6）。

## 2. 音乐（Music）

| 项 | 规格 |
|---|---|
| 角色 | 1 条循环背景音乐：合成波/芯片音乐（synthwave-chiptune），中速，带稳定节拍，呼应美术方向 |
| 触发 | 玩家在开始界面点击「开始游戏」后开始（遵守浏览器手势播放规则：加载阶段不自动发声） |
| 循环/时长 | 无缝循环，单段约 60–90s |
| 停止 | 返回开始界面、失命后进入失败结算时淡出停止（约 0.5s）；暂停时音乐**随游戏一起暂停**，继续后从断点恢复（不重头播放） |
| 关卡胜利 | 音乐做一次明亮收束（短上行乐句/淡出 1s），不直接硬切 |
| 电平 | 相对电平基准 −12 dB；进行中持续在音效之下，不做动态变速 |

- 开始界面默认**静默**（无菜单音乐），避免无手势自动播放问题并保持菜单安静；这是首版刻意选择。

## 3. 音效事件（SFX）

均为短促非循环单音（2D，无方位差异——单屏竞技场）；合成质感（电子音色），与音乐同族。

| ID | 触发 | 声音性格 | 时长 | 重复触发行为 |
|---|---|---|---|---|
| `sfx-paddle` | 球击中挡板 | 实心、有弹性的中频"啵"，带音高暗示：**击球点越靠边音高越高**（映射偏转角度，帮助感知出射方向） | 0.08–0.12s | 每次接触独立触发，不截断前一个（天然间隔 >0.1s） |
| `sfx-wall` | 球击中顶/左右墙 | 干净的高频轻击，比挡板音更短更薄 | 0.05–0.08s | 同上 |
| `sfx-brick-break` | 砖块 hp 归零 | 明亮的碎裂电子音 + 短噪声粒，清脆上扬 | 0.12–0.18s | 见 §4 并发规则 |
| `sfx-brick-hit` | 2 命砖首次被击中（未碎） | 闷一些的中频"嗒"，明显区别于碎裂音（低半档亮度） | 0.08–0.1s | 同上 |
| `sfx-serve` | 球从挡板发出 | 短促上扬启动音 | 0.1s | — |
| `sfx-life-lost` | 球出底 | 下行坠落空音，略带噪声尾；全事件表中唯一明显下行音色 | 0.5–0.7s | 与失命过渡（1.2s）同步，过渡结束前自然收尾 |
| `sfx-win` | 关卡清空 | 明亮琶音/短胜利乐句 | 1.0–1.5s | 单次 |
| `sfx-lose` | 生命归零 | 低沉收束音，2–3 个下行音 | 1.2–1.6s | 单次；替代音乐收束位置 |
| `sfx-ui` | 按钮激活 / 焦点确认 | 极短电子确认音 | 0.04–0.06s | 高频操作时每按一次触发，不叠加（见 §4） |

## 4. 并发、优先级与混音

频繁碎砖（砖缝同时命中、连续碎砖）是首要的重叠场景：

1. **同批次多砖击碎**（GDD §5.3）：只播放**一次** `sfx-brick-break`（可按击碎数微提亮度/音高），不为每块砖叠加一个实例，防止爆音与机枪化。
2. 帧内多类接触同时发生时优先级：`sfx-paddle` > `sfx-brick-break` > `sfx-brick-hit` > `sfx-wall`——被压低的后级事件直接舍弃（同帧只播最高优先一个）。
3. UI 音在 80ms 内再次触发时复用同一实例（截断重启），保证快速操作不堆积。
4. 相对电平（以 sfx 为 0 dB 基准）：
   - brick-break / paddle：0 dB
   - brick-hit / wall：−3 dB / −5 dB
   - life-lose：+1 dB
   - win / lose：+2 dB（结算时刻的主导声音）
   - music：−12 dB（恒定，不引入 ducking 系统）
5. 主控限幅，防止任意叠加上爆。

## 5. 状态转场上的声音行为

| 转场 | 声音行为 |
|---|---|
| 加载 → 开始 | 静默 |
| 开始 → 发球准备 | 音乐淡入（0.5s） |
| 发球 | sfx-serve |
| 进行中 → 暂停 | 音乐与全部音效立即挂起（不淡出——世界冻结，声音同样冻结） |
| 暂停 → 继续 | 从断点恢复，无突兀音 |
| 失命过渡（仍有生命） | sfx-life-lost；音乐保持（不中断），过渡结束重新发球时 sfx-serve |
| 失败结算 | sfx-life-lost 结束后接 sfx-lose；音乐淡出停止 |
| 胜利结算 | sfx-win；音乐明亮收束 |
| 再玩一次 | 停止结算音 → 音乐回到正常循环/淡入 |
| 返回开始界面 | 全部声音淡出（≤0.5s）后静默 |
| 标签页失焦 | 自动等同挂起（浏览器本身会挂起音频）；回到标签且状态为暂停时不自动继续 |

## 6. 可访问性与设置

- 提供**静音切换按钮**（44×44 图标控件，字符「♪」）：开始界面位于屏幕右上角；暂停面板位于面板右上角（绝对定位）。已在 `content/ui/start.json`、`content/ui/pause.json` 以 `mute-btn` 节点落地；默认非静音，激活后图标给出可辨的切换状态（如加禁用斜线）。
- 首版不做独立音乐/音效双音量滑杆、不做音量持久化（与 GDD §1.6 一致；刷新后恢复默认）。
- 关键信息不依赖听觉：失命（图标消失+暖闪）、砖碎（消失+粒子）、砖损（裂纹+闪白）、胜/负（界面标题与光色）、按钮激活（按压反馈）均有视觉冗余。
- 浏览器自动播放策略：所有音频只在首次手势之后启动；若手势后仍被拦截，静默降级，不阻塞游戏，不弹错误。

## 7. 必需 vs 可选增强

**首版必需**：§3 表中全部 9 类 SFX + 1 条循环音乐 + 静音控制。

**可选增强（首版不做，记录不实施）**：多首音乐曲目与音乐切换、音量双滑杆与持久化、击球力度/位置的多层音高采样、环境氛围层。
