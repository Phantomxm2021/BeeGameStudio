## 1. 产品定位与首版范围

### 1.1 一句话概述

一款横屏、2D、街机风格（Stylized）的打砖块游戏：玩家左右移动底部挡板，反弹一颗球击碎上方全部砖块，球漏出底部则失去生命。

### 1.2 已确认的平台与形态

| 项目 | 确认值 |
|---|---|
| 发布平台 | Web |
| 引擎/技术栈 | React |
| 维度 | 2D |
| 屏幕方向 | **仅横屏（Landscape）** |
| 类型 | Arcade |
| 视觉风格 | Stylized（风格化） |
| 输入 | 键盘/鼠标、触控（Touch） |

### 1.3 首版目标

交付一个**小而完整的可玩版本**：一个可重复游玩的完整核心循环，配以代表性内容。玩家从进入页面到开始游戏、胜利、失败、重试或退出的全过程均可用。

### 1.4 首版包含（Required）

- 1 个关卡：固定排布的单层砖块阵列（代表性排布，砖块带生命值差异，具体行列数、砖块构成与排布由场景数据定义）。
- 1 块玩家挡板、1 颗在场上的球（同一时间场上始终只有一颗球）。
- 生命制（有限生命数）、分数、砖块击碎、碰撞反弹、出底判定。
- 完整流程界面：开始界面、游戏内 HUD、暂停、关卡胜利结算、游戏失败结算（含重试与退出）。
- 键盘、鼠标、触控三类输入的挡板控制；发球、暂停、确认等操作输入。
- 横屏与最小可用尺寸校验，不满足时给出提示。

### 1.5 首版排除（Exclusions，明确不做）

- 多关卡、关卡选择、关卡编辑器。
- 道具掉落（多球、激光、加长挡板、粘球等一律不做）。
- 多种球、特殊弹道、移动/不可击碎砖块。
- 排行榜、成就、每日挑战、账号与联网功能。
- 内购、广告、外部数据存储。
- 音效/音乐以外的额外润色内容（视音频由后续专门文档定义，不属本文档规则）。
- 竖屏布局：不做竖屏适配（见 §8）。

### 1.6 持久化与重玩

- 首版**不做跨会话持久化**：不保存最高分、不保存进度、不写入存储。
- 每次重新打开页面都从开始界面进入，分数与生命重置。
- 关卡内容固定，重玩时布局不变；重玩差异仅来自球与挡板的动态过程，无解锁内容。

## 2. 玩家目标、行动与核心循环

### 2.1 玩家目标

- **单局目标**：在生命耗尽前，击碎关卡内全部砖块。
- **即时目标**：阻止球漏出场地底部，并让球尽量击中砖块。

### 2.2 玩家可用行动

| 行动 | 键盘/鼠标 | 触控 | 可用状态 | 后果 |
|---|---|---|---|---|
| 移动挡板（水平左右） | 键盘左右方向键/ A、D 按住；或鼠标在游戏区域内水平移动 | 在游戏区域内按住并水平拖动，挡板跟随手指水平位置 | 发球准备、进行中、暂停恢复后的进行中 | 挡板水平移动，始终限制在场地左右边界内 |
| 发球 | 空格键 / 鼠标点击游戏区域 | 点按游戏区域 | 发球准备（球吸附于挡板时） | 球脱离挡板进入运动 |
| 暂停 / 继续 | Esc 或 P 键；点击暂停按钮 | 点按暂停按钮 | 进行中 ↔ 已暂停 | 切换暂停 |
| 界面确认（开始/重试/返回开始） | 按钮点击或对应快捷键（按钮上标注） | 点按按钮 | 各结算/开始界面 | 执行对应界面跳转 |

- 挡板只能水平移动，不能垂直移动；移动为 1:1 位置映射，挡板中心不越过场地左右墙。
- 鼠标移动无需按住即可控制挡板；触控必须按住拖动（避免无触接触碰导致挡板跳动）。
- 键盘控制为持续移动；具体移动速度、键位灵敏度等数值由数值平衡文档定义，本文档不重复参数表。
- 控制语义的详细输入契约由交互相关文档承接，不得改变本文件定义的"行动—后果"关系。

### 2.3 挑战与反馈循环

1. 球在场地内运动，击中砖块则砖块受损/碎裂并加分；击中墙、挡板则反弹。
2. 玩家通过挡板位置改变球的反弹去向（击球点影响反弹角度，见 §4.3），形成"瞄准—回击—碎砖"的操作循环。
3. 球漏出底部 → 失去一条生命 → 若仍有生命则回到"发球准备"重新发球；生命耗尽则失败结算。
4. 全部砖块清空 → 关卡胜利结算。
5. 结算后可即时重试，形成街机式短循环重玩。

即时反馈（最小集合，表现细节由美术/UI 与音频文档定义）：挡板与球的运动可见；砖块被击中时呈现受损或消失的可辨变化；HUD 实时显示分数与剩余生命；出底失命、胜利、失败均有明确的界面/文字反馈。

## 3. 游戏状态与流程

### 3.1 状态定义

| 状态 | 进入条件 | 允许的行动 | 转出 |
|---|---|---|---|
| **加载/进入（Boot）** | 打开页面 | 无（自动完成资源与数据加载） | 加载完成 → 开始界面；若当前为竖屏或尺寸不足，进入"提示界面"（见 §8），不进入可玩布局 |
| **开始界面（Ready/Menu）** | 加载完成；或从结算/暂停选择"返回开始" | 查看标题；开始游戏 | 确认开始 → 发球准备（新局：分数清零、生命重置、砖块阵列重置、球与挡板归位） |
| **发球准备（Ball Stuck）** | 新局开始；或失命后仍有生命 | 移动挡板（球随挡板一同水平移动，保持在挡板上方固定相对位置）；发球 | 发球 → 进行中 |
| **进行中（Playing）** | 球被发出 | 移动挡板；暂停 | 全部砖块清空 → 胜利结算；球出底 → 失命解析（§5.2）；主动暂停 → 已暂停 |
| **已暂停（Paused）** | 进行中玩家主动暂停 | 继续；返回开始界面 | 继续 → 进行中（球从暂停瞬间的位置与方向继续，不重置）；返回开始 → 开始界面（当局放弃，不保存任何内容） |
| **失命过渡（Life Lost Transition）** | 球出底且尚有剩余生命 | 无（短暂反馈播放期间不可操作） | 过渡结束且生命 > 0 → 发球准备；生命 = 0 → 失败结算 |
| **胜利结算（Level Clear）** | 关卡内最后一块砖在同一解析批次中被击碎（含 §5.3 同时性规则） | 再玩一次；返回开始 | 再玩一次 → 新局发球准备；返回开始 → 开始界面 |
| **失败结算（Game Over）** | 失命后生命归零 | 再玩一次；返回开始 | 同上 |

### 3.2 流程要点

- 除失命过渡等明确的短暂过渡外，任何状态下 Esc/暂停操作不得导致卡死；暂停只能从"进行中"进入。
- 结算界面出现时，球与挡板的模拟停止；"再玩一次"始终以完整新局开始（重置分数、生命、砖块、球、挡板），不存在接续。
- 游戏在浏览器标签中运行；关闭页面即结束，无任何状态保留（与 §1.6 一致）。

## 4. 场地、实体与可观察规则

### 4.1 场地与边界

- 游戏场地为横屏矩形：顶、左、右为反弹墙，**底部为开放死亡边**。
- 球击中顶墙或左右墙时反弹，不出界。
- 球整体越过底部死亡边（越过场地底边）即判定为出底失命。
- 挡板活动于场地底部区域，其水平活动范围以左右墙为界。

### 4.2 砖块

- 关卡由固定的砖块阵列构成，每块砖占据网格中的一个位置。
- 砖块有生命值：被球击中一次扣 1；生命值归零即被击碎、从场上消失并计为"已清空"。
  - 首版砖块以 1 命砖为主，可包含少量 2 命及以上的多命砖作为代表性差异；具体砖块构成、行列数、间距与排布为场景数据内容（由数值平衡文档给出生命/分值配比，由场景 JSON 给出排布）。
- 多命砖被击中但未碎时，留在原位并有可辨的受损表现。
- 砖块不移动；除被球击碎外没有其他消失途径。

### 4.3 球与挡板反弹（可观察规则，不规定实现算法）

- 球击中墙：按墙面反弹。
- 球击中砖块：反弹，且该砖块在同一次相互作用中扣减生命（见 §5.1 相互作用定义）。
- 球击中挡板：球向上反弹；**反弹方向取决于球击中挡板的水平位置**——击中挡板中部接近垂直向上，越靠近挡板两端，水平方向偏转越大。这是玩家唯一的回球控制手段。
  - 偏转范围（最小/最大出射角度）、球速等具体数值由数值平衡文档定义。
- 球的运动在玩家观察上为连续运动；速度在关卡内不因时间自行变化（无加速、无道具变速）。
- 球不得穿过墙或砖块；若在一次更新中球同时触及多个对象，按 §5.3 处理。

### 4.4 计分

- 每次击碎砖块获得分数；不同砖块的分值由数值平衡文档定义，多命砖可按砖块类型给分（首版采用"击碎时一次性给分"，击中但未击碎不给分）。
- 分数仅在当局有效，HUD 实时显示，胜利/失败结算时显示当局总分。

### 4.5 生命

- 玩家持有有限生命数（具体数值由数值平衡文档定义），HUD 持续显示剩余生命。
- 每次球出底扣 1 条生命；新局时重置为初始生命数。

## 5. 系统交互与判定优先级

本节规定在结果可能产生歧义之处的统一规则；具体数值不在此重复。

### 5.1 什么算一次"相互作用"

- 相互作用发生在运动中的球与墙、挡板或砖块产生接触之时。
- 同一次接触中，"反弹"与"砖块扣命/击碎（及加分）"作为同一相互作用同时成立，不存在"先反弹后扣命"或反之造成的可观察差异。
- 球与一块已经在同一相互作用中被击碎的砖块不再发生第二次接触（砖块消失，球按反弹后的轨迹离开）。

### 5.2 出底失命的解析时机

- 判定以球越过底部死亡边为准；一旦越过，本次运动结束，立即进入失命解析：扣减 1 条生命、停止球的模拟、播放失命反馈，之后按剩余生命进入发球准备或失败结算。
- 出底判定不与挡板"救球"并存：球已越过死亡边后，挡板的任何移动都不能取消失命。

### 5.3 同时触及多个对象 / 同帧多结果

- 当球在同一次运动更新中同时接触多块砖（如砖缝、边角）：**所有实际接触到的砖块均在该批次中各承受一次击打**，反弹方向按接触结果统一解析为一条离开轨迹，保证结果唯一、确定，不出现二次弹跳或随机结果。
- 当"击碎最后一块（批）砖"与其他事件同时发生时：
  - 与球出底同时发生不可能构成有效局面（砖块在场地顶部区域，死亡边在底部）；若关卡清空成立，则**关卡清空优先**：进入胜利结算，不再解析出底。
- 当多块砖在同一批次中被击碎时，分数累加，关卡是否清空以该批次解析结束后的砖块剩余数判断。
- 所有同时性规则只产生一个确定性结果，玩家不会观察到矛盾的中间态。

### 5.4 进行中动作/过渡期间的输入

- 失命过渡、结算界面期间：移动与发球输入无效（不缓冲、不排队）。
- 暂停期间：移动输入无效；继续后不补偿暂停期间的任何输入。
- 发球准备期间：移动挡板有效，球随之移动；仅一次发球输入生效，重复点击不产生额外效果。

### 5.5 暂停时的世界状态

- 暂停冻结全部运动与计时；恢复时从冻结点继续，球的位置、方向、各砖块生命、分数、生命数均保持不变。暂停不扣分、不扣命、不改变关卡内容。

## 6. 完成条件（可在游玩中观察）

### 6.1 关卡胜利（首版"通关"）

- 可观察条件：场上所有砖块均被击碎（无砖块残留），随后出现胜利结算界面并显示当局分数。
- 胜利后玩家只能选择"再玩一次"或"返回开始"；无下一关。

### 6.2 游戏失败

- 可观察条件：球出底时玩家生命从 1 变为 0，随后出现失败结算界面并显示当局分数。
- 失败后可"再玩一次"（完整新局）或"返回开始"。

### 6.3 首版整体验收意义上的完成

- 玩家仅凭游戏内界面即可：开始一局、用三种输入之一正常操控挡板并发球、观察到碎砖/计分/失命、在胜利或失败后重试或退出，全程无卡死、无需要刷新页面的状态。

## 7. 内容与数据归属（平台数据约定）

- 场景层级、砖块阵列的变换与排布、挡板与球的初始位置/尺寸、UI 布局及其响应式变体、资源绑定，均以**人工编写的 Scene/UI JSON 为唯一可编辑数据源**；运行时代码（React）加载/编译这些数据并实现玩法，代码常量不得替代上述由数据决定的内容。
- 本文档中的参考尺寸均为**设计坐标**，不是宿主设备的固定像素尺寸。
- 玩法规则（状态机、碰撞后果、计分/扣命规则）属于运行时逻辑，以本 GDD 为权威；可调数值（球速、偏转角度、生命数、分值、砖块生命配比、挡板与球的尺寸区间等）以数值平衡文档为唯一权威，GDD 不维护重复参数表。
- 美术表现、HUD 与界面视觉、音频由后续批次文档定义，不得改变本文件的规则与状态流。

## 8. 屏幕方向与最小可用尺寸

- 仅支持**横屏**。设计以横屏设计坐标为基准（宽 > 高）。
- **最小可用尺寸（设计坐标）**：横向有效游戏区域不小于 **960 × 540**（16:9 基准）；在此尺寸下，完整砖块阵列、挡板活动空间、球与 HUD 必须均可用且不遮挡游戏区域。
- 当设备/窗口处于**竖屏**，或可用空间低于上述最小尺寸时：
  - 显示全屏中文提示：竖屏时提示"请旋转设备至横屏"；空间过小时提示"窗口尺寸过小，请放大窗口"。
  - **不做强制重排、不做不可用的缩小布局、不切换为竖屏玩法**；方向/尺寸恢复后自动回到正常流程（加载阶段则继续进入开始界面）。
- 具体的响应式变体与提示界面布局由 UI 文档依据 Scene/UI JSON 定义。
