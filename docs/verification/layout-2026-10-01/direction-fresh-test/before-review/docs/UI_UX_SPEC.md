## 1. 全局约定

### 1.1 坐标与度量

- 屏幕空间：**左上原点，逻辑像素**；`anchor/pivot` 为归一化坐标（[0,0] 左上，[1,1] 右下）；拉伸用成对的 `anchorMin/anchorMax + sizeDelta`。
- 参考分辨率 **960×540**（设计参考，非固定窗口）；目标视口（根节点 `data.targetViewports`）：**960×540（最小支持）、1200×540、960×600、1280×720**。
- 根节点 `data.minimumControlSize = [44,44]`（最终宿主逻辑像素，所有按钮/可点区的下限）。
- 方向限定 Landscape：竖屏或尺寸不足 → message 界面（§8），不存在第二套布局。

### 1.2 世界层与界面层的空间关系

- Canvas 世界按 letterbox 取景（关卡文档 §4，技术文档 §6）；屏幕 UI 覆盖于其上。
- 进行中唯一允许的持久覆盖是 **HUD 顶条（高 56）**；其下 y=56 处仍高于砖块顶边（世界 y=80 经取景映射后），满足关卡文档 §5 的净空要求。
- 整屏覆盖（暂停/结算/message）出现时模拟已停止。

### 1.3 共享组件（定义一次）

| 组件 | 规格 | 状态 |
|---|---|---|
| 主按钮 `btn-primary` | 固定 240×56（结算/开始）或 240×52（暂停内），圆角 14，青底 `#29D3E0` 深字，字号 20–22 | 默认 / hover 微亮 / active 下压（scale 0.97，80ms）/ disabled 灰底不可点 |
| 次按钮 | 240×52，底 `#2C2860` 浅字；文字按钮无底色、字色 `#9E9AC8` | 同上 |
| 面板 | 霓虹描边圆角板（`panelBg`），内边距 [28–32, 24–28] | — |
| 图标按钮 | 44×44 圆角 10 | 默认 / hover / active |
| 标题字 | 粗几何无衬线，HUD 正文等宽数字 | — |

焦点/键盘导航：窗口内按钮支持 Tab 顺序与 Enter 激活；当前焦点以 2px 青描边标示。鼠标/触控操作不显示焦点环（指针交互后清除）。

## 2. 界面总表（与 GDD 状态对应）

| 文件 | 界面 | 进入条件（GDD 状态） | 退出 |
|---|---|---|---|
| system.json | 加载 / 加载错误 | Boot | 成功 → start；错误重试成功 → start |
| start.json | 开始界面 | 加载完成；返回开始 | 开始游戏 → 发球准备（HUD 显现） |
| hud.json | HUD + 发球提示 | 发球准备 / 进行中 | 随覆盖层切换隐藏部分元素 |
| pause.json | 暂停层 | 进行中 → 暂停 | 继续 / 重开 / 返回开始 |
| results.json | 胜利或失败结算 | 关卡清空 / 生命归零 | 再玩一次 / 返回开始 |
| message.json | 旋转 / 尺寸提示 | 竖屏或 <960×540 | 方向尺寸恢复自动回原状态 |

## 3. 开始界面 start.json

**构图（ART §6）**：全屏深色安静背景；中轴列容器 `stage`（560×420，center 锚点）自上而下：徽标（球+挡板形状，120×96）→ 标题「打砖块」64px → 副标题 → **主按钮「开始游戏」（首要焦点，默认聚焦）** → 操作提示小字。视线顺序：标题 → 发光按钮；大量负空间保持界面不拥挤。

- 元素固定尺寸，列容器居中；窗口变化时整组保持居中（不拉伸按钮）。
- 行动：开始按钮 / Enter → 初始化新局（GDD §3.2）；控件提示纯信息。
- 状态：无 disabled 元素；按钮 hover/active 反馈如 §1.3。

## 4. HUD hud.json

**顶条 bar**（顶拉伸，高 56，半透明深底），两端对齐：

- 左：**分数**「分数 0」（等宽数字，22px，绑定当局分数，碎砖即更新）——HUD 首要信息。
- 中：3 枚生命图标（24×24 圆点，间距 8）；失命时对应图标消失并轻抖（200ms）；新局恢复 3 枚。
- 右：暂停按钮（44×44，图标文字「II」）→ 进入 pause。
- **发球提示**「点击 / 空格 发球」（底部偏上 center，仅在发球准备显示），进入进行中即淡出（150ms）。

状态差异：发球准备时发球提示可见、暂停可用；进行中提示隐藏；失命过渡/覆盖层出现时整份 HUD 仍在但顶条不响应点击（输入路由按 GDD §5.4 拒绝）。

## 5. 暂停层 pause.json

- 全屏压暗（66%）+ 居中面板 320×320，列：标题「暂停」→「继续」（主按钮，默认聚焦）→「再玩一次」→「返回开始界面」。
- 世界在压暗层后隐约可见，传达"冻结"（ART §6）。
- 行动结果：继续 → 进行中（冻结点恢复）；再玩一次 → 新局；返回开始 → start（当局废弃，不保存）。
- Esc/P 在暂停层等同「继续」。

## 6. 结算层 results.json（胜利 / 失败共用几何）

- 全屏压暗 72% + 居中面板 380×340，列：结果标题（40px）→「总分 N」（22px）→「再玩一次」（主按钮，默认聚焦）→「返回开始界面」文字按钮。
- **同一份布局，状态绑定内容/光色**（节点 `data.boundText`）：
  - 胜利：标题「通关」青色 `#29D3E0`，配合世界层明亮脉冲（ART §6）。
  -失败：标题「游戏结束」暖红 `#FF7A5C`，整体亮度压低。
- 出现时机由 simulation 批次解析后触发（GDD §5.3）；面板以 200–300ms 缩放+淡入。
- 行动：再玩一次 → 新局发球准备；返回开始 → start。

## 7. 系统界面 system.json（加载 / 错误）

- 居中两个互斥分组（运行时按阶段启用其一）：
  - 加载组：青色圆形指示（40×40，可加旋转动效 800ms 循环，reduced-motion 下静止）+「加载中…」。
  - 错误组：「加载失败，请检查网络」（暖红，可两行）+ 按钮「重试」（200×52，主按钮样式）。
- 重试：重新执行装载流程；连续失败保持在错误组（不白屏、不自动反复刷新）。

## 8. 提示界面 message.json（旋转 / 尺寸）

- 全屏深底 + 居中列：图标「↻」（仅竖屏原因显示）+ 主文案 + 最小尺寸说明。
- 文案绑定原因：竖屏「请旋转设备至横屏」；尺寸不足「窗口尺寸过小，请放大窗口」。
- **无按钮**：方向/尺寸恢复后自动返回进入前的状态（游玩中转竖屏前世界已被冻结为暂停态，恢复后继续——技术文档 §7）。

## 9. 自适应行为（明确选择，不留备选）

- 四个目标视口下：全屏覆盖层与 HUD 根始终拉伸；**面板/按钮/文字保持固定尺寸、居中**，不整体缩小；背景渐变与世界层填充留边区。
- 宽高比更宽（1200×540）：UI 顶条拉宽，元素靠两端；更高（960×600）：面板保持居中，无重排。
- 文本长度：中文文案均按实际最大长度预留（结算标题 4 字、分数最大 4 位即「分数 4000」）；字体实际度量在内容评审阶段用真实字体核查（当前未测）。
- 超出支持范围（竖屏 / <960×540）：唯一行为是 message 界面，不做滚动或裁剪式妥协。

## 10. 反馈与动效（目的—触发—表现—时长）

| 反馈 | 目的 | 触发 | 表现/时长 |
|---|---|---|---|
| 碎砖 HUD 加分 | 确认得分 | 砖块击碎事件 | 分数即时刷新，一次短促高亮（120ms） |
| 失命图标抖消 | 确认生命损失 | 出底 | 图标消失 + 轻抖 200ms；同步失命音效 |
| 发球提示淡出 | 状态切换 | 球离板 | 150ms 淡出 |
| 暂停压暗/恢复 | 冻结/继续 | 暂停切换 | 200ms 淡入/淡出 |
| 结算面板入场 | 结果宣告 | 胜/负 | 250ms 轻微缩放+淡入 |
| 按钮按压 | 操作确认 | pointerdown / Enter | scale 0.97，80ms |

- **Reduced motion**：检测 `prefers-reduced-motion`，缩放/脉冲改为即时切换，仅保留淡入与必要的状态变化；所有动效不携带关键信息（关键状态均有文字/形状）。

## 11. 空间计算结果与限制

- 命令 `bun .beegame/delivery/check-content.mjs --design-layouts`：六个文件 × 四个目标视口全部 **`valid:true`，无 issues**——控件/面板分配、44×44 最终控件下限通过。
- 限制：该检查只验证矩形几何与声明的控件最小值；**不验证**状态覆盖完整性、字体度量、文字换行、重叠意图、视觉质量与运行时交互。上述项目均未经运行时验证；重叠候选与真实字体适配留待评审/实现阶段。
