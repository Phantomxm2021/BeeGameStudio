## 1. 技术基线

| 项 | 选择 | 理由 |
|---|---|---|
| 平台 | Web 静态页面（现代 evergreen 浏览器） | 已确认 |
| 框架 | React（UI 层与流程编排） | 已确认 |
| 世界渲染 | **HTML5 Canvas 2D**（由 React 挂载，一帧一绘） | 单屏、少实体、需要确定性运动与辉光/粒子；Canvas 比数百 DOM 节点稳定 |
| 界面渲染 | React DOM（HUD/菜单/结算，依据 UI JSON） | 天然的声明式状态绑定与可访问性 |
| 循环 | `requestAnimationFrame` + 固定步长模拟 | 行为不依赖帧率；具体步长见 §4 |
| 数据 | content/ 下已注册的 Scene/UI JSON + content/index.json | 平台数据约定 |

不引入物理引擎、游戏引擎、状态管理库等重依赖；需求不支持的复杂度不预先建设。

## 2. 模块职责

```
src/
  main/              启动入口：创建宿主、引导初始化
  data/
    contentLoader    读取 content/index.json；按 loadPhase 装载 Scene/UI 文档与资产清单
    dataBinding      将场景节点（id/层级/transform/components/behaviors）实例化为运行时实体；
                     将 UI 节点解析为 React 可渲染结构（可使用 BGS 可选布局助手）
  input/
    keyboard         方向键/AD、Space、Esc/P；按下/抬起状态
    pointer          鼠标移动 + 触控拖动（pointer events 统一），输出"期望挡板位置"
    inputRouter      按当前游戏状态决定输入是否有效（GDD §5.4）
  game/
    stateMachine     GDD §3 的状态机（唯一的状态权威）
    simulation       固定步长：球运动、扫掠接触检测、反弹/砖块扣命/计分、出底、同时性批解析
    rules            GDD §5 规则（相互作用定义、优先级、确定性）；不含数值，数值来自配置
  render/
    worldCanvas      背景层/墙线/砖/挡板/球/粒子的 Canvas 绘制与取景换算
    hudReact         HUD React 组件（分数/生命/暂停）
    flowReact        开始/暂停/胜利/失败/旋转尺寸提示界面
  audio/             音频播放（资产与事件由后续文档定义）
  config/            运行时共享调校 JSON（项目自有单一文件，从 BALANCE 发布值产出）
```

- 规则求值与表现分离：simulation 只改状态数据，render 只读状态；React 状态切换驱动界面，画布每帧从同一状态源读取。

## 3. 信息流与生命周期

1. **初始化（Boot）**：`contentLoader` 读 index → 先并行拉取 `loadPhase:"startup"` 的入口场景与首批 UI 文档及资产清单 → `dataBinding` 构建实体（砖块 60、挡板、球）与 UI 树 → 读窗口方向/尺寸：
   - 竖屏（height ≥ width）或宿主逻辑像素 < 960×540 → 显示对应中文提示界面（旋转/放大），**不构建可玩布局、不计时**；持续监听变化，恢复后自动继续。
   - 满足条件 → 进入开始界面。
2. **开始一局**：stateMachine 收到开始动作 → 从场景数据**重新实例化**世界（砖块 enabled/hp、挡板 (480,500)、球吸附 (480,484)），分数 0、生命 3 → 发球准备。
3. **帧流程（进行中）**：rAF 给时间戳 → 累积固定步长 → 每步：输入路由（挡板目标位置/发球/暂停）→ simulation 求值（可能产出"一批相互作用事件"）→ 更新状态；渲染在每帧一次（Canvas + React HUD 按变更刷新）。
4. **暂停**：停止步进、冻结世界（不取消已注册 rAF，仅停止累积消耗）；继续时从冻结点恢复（GDD §5.5）。
5. **失命**：simulation 判定出底 → 生命 −1、球停用 → 进入失命过渡（1.2s 计时，输入无效）→ 生命>0：球重置为吸附态到发球准备；=0：失败结算。
6. **胜利**：一批相互作用解析完后无砖块存活 → 胜利结算（优先级规则 GDD §5.3 在 simulation 内实现）。
7. **重试**：等价于步骤 2，销毁当前实体订阅并重建，防止旧计时器/监听残留。
8. **退出/清理**：返回开始界面或卸载时，注销键盘/指针/窗口监听、取消 rAF、释放音频源；无全局单例悬挂。初始化顺序显式化：**loader → binding → 输入注册 → 首状态进入**，任何模块不在加载完成前读状态。

## 4. 模拟与接触检测（行为约束，非实现算法限定）

- 固定步长 **dt = 1/120 s**（每步球移动 3.5px），渲染按 rAF 插值或直接步进均可；120Hz 步长保证 7px/帧（60fps）以内的运动被至少两次采样。
- 接触检测须为**扫掠/连续式**：以球本步的运动线段对砖 AABB、挡板顶面、墙做求交，杜绝穿透（对应 BALANCE §6 风险）。
- 同一步内的求交结果收集为一个批次后统一解析：多砖各扣 1 命、唯一出射轨迹、清空判定与出底优先级全部在批次提交时一次性生效——保证 GDD §5.3 的确定性与无矛盾中间态。
- 反弹角度按 BALANCE §3.1 公式，以接触点相对挡板中心计算；速度大小恒定 420。

## 5. 数据归属与绑定

- `content/index.json`（`beegame-content-package.v2`，dimension 2d，sceneModel game-object-v2，entryScene 指向 L1）为装载注册；`scenes/breakout-l1.json` 保存关卡文档 §3 的完整节点树（id 稳定、中心 transform、collider、brick behaviors 的 hp/score）；UI 各界面保存于 `content/ui/*.json`（批次 3 产出，本设计不预设其内容）。
- 运行时**不复制**排布：砖块位置、尺寸、hp、分值全部来自场景 JSON 的节点与 behavior config；BALANCE 的发布值通过单一项目配置 JSON 进入运行时（球速、生命、时长等），代码里不出现替代常量。
- UI JSON 的 anchor/容器/响应式字段被实际用于布局（使用可选 `initializeUiLayout/resolveUiNodesForViewport` 或映射为等价 CSS），不得"读了字段却另写一套布局"。
- 资产（含图集帧）经 manifest 解析后加载；Canvas 绘制按 sprite/帧区域取图。
- 数据绑定验证方式（验收阶段执行）：临时改一个节点的位置/一块砖的 hp/一个资源帧引用，不改编排代码，观察目标运行时结果随之改变，然后还原。

## 6. 取景换算与指针映射

- 世界→屏幕：按关卡文档 §4 的 letterbox 结果——缩放 `s = min(vw/960, vh/540)`，参考视图居中偏移 `(ox, oy)`（如 1200×540 时 ox=120；960×600 时 oy=30）。数值由相机计算输入/检查工具产出，代码只消费，不维护第二张视口表。
- 指针→世界：`worldX = (clientX − ox) / s`、`worldY = (clientY − oy) / s`；挡板取"期望中心 x"并钳制 [60, 900]；落在留边区内的拖动按外推处理（保持最后有效方向），不得产生坐标跳变。
- React UI 与 Canvas 的屏幕空间一致（同在宿主逻辑像素系），HUD 覆盖位置以 UI 文档为准。

## 7. 加载、存储、失败处理与性能

- **加载**：startup 文档并行、首屏只等必需项；其余 on-demand；图片经浏览器缓存复用，图集按共享源加载、消费者卸载后释放（格式约定）。加载失败重试一次并给出可理解的中文错误，不白屏。
- **存储**：首版不写 localStorage/cookie/服务端（GDD §1.6）。
- **方向/尺寸**：监听 `resize/orientationchange`；游玩中转竖屏立即自动暂停并显示旋转提示（世界冻结、不扣命），恢复后从暂停点继续。
- **性能预算**：60 块砖 + 单球 + 粒子在 Canvas 上量级极小；目标稳定 60fps、单次固定步长求值远低于帧时；粒子数量有上限（单次碎裂 ≤12）。HUD 分数变化走局部 React 更新。
- 浏览器兼容：pointer events、Canvas2D、rAF 为基线；不支持 WebGL 依赖。

## 8. 具体可行性风险与验证

| 风险 | 验证方式（不预建框架） |
|---|---|
| 砖角/砖缝穿透与多砖批解析 | 实现后用脚本化回放若干边界弹道（砖缝斜射、两角同时接触）断言唯一轨迹与扣命数 |
| 数据绑定流于"读取但未使用" | §5 的临时改值-观察-还原测试，覆盖 transform 与资源引用 |
| 留边区指针映射/误触 | 在 1200×540、960×600 与最小 960×540 下手动操作验证 |
| 低端机辉光性能 | 若外发光成为瓶颈，改用预渲染发光贴图而非关闭反馈（保持美术规则） |
| 120Hz 步长与 rAF 不同源设备 | 以固定步长+时间累积验证 60/120Hz 宿主结果一致 |
