## 1. 设计基调与音频职责

### 1.1 音色方向

- 情绪对齐"深夜霓虹街机 / 合成波"方向（美术指导同期撰写，若最终美术偏离该方向，音色情绪以美术为准微调，但行为契约不变）。
- 全部音效为**短促、电子、清脆**的合成器音色：短起音（attack 近乎为零）、快衰减，避免任何绵长、声学写实或浑浊的声音。
- 音色家族统一从同一合成器审美出发（明亮的方波/锯齿波短音、数字感短噪声爆破、短 FM 叮音），使全部事件听起来属于同一台"街机"。
- 全部声音为 **2D 非定位音**：不做左右声像摆位模拟、无距离衰减、无 3D 空间音频。击左墙与击右墙可以有细微音色/音高差异以便辨识，但不做位置化处理。
- 无语音、无旁白需求。

### 1.2 音频在本游戏中的三项职责

1. **确认每一个可操作结果**：发球、碰撞、碎砖、漏接、界面操作都必须即时有声，让玩家"听到自己造成的后果"。声音与视觉帧同步，不提前、不滞后到可察觉的程度。
2. **强化节奏**：碰撞音与碎砖音构成对局的节拍层；同帧连碎时音高微升（见 2.4），给玩家连击中的上升感。
3. **标记终局与重大转移**：漏接、生命减少、关卡完成、游戏结束使用明显区别于日常碰撞的句法，让玩家不用看屏幕也能分辨"出事了"和"结束了"。

音频是增强反馈层，不是信息的唯一载体（见第 8 节）。

## 2. 逐事件声音行为表

下表每个事件定义：用途/玩家意义、音色性格、触发时机、时长/循环、停止条件、高频重复触发行为。所有时长为设计目标级描述，具体数值在实现调音时确定。

### 2.1 发球（Serve）

- **用途/玩家意义**：确认玩家的发球指令被接受，对局从"待发"切入"进行中"。
- **音色性格**：一记明亮、上扬的短合成音（pitch 快速上滑），干脆有"出发"感。
- **触发时机**：Ready → Playing 的状态转移当帧，与球离开挡板同步；仅有效发球触发一次（GDD 规定输入释放时触发一次，长按不连发，音频侧不额外补发）。
- **时长/循环**：极短，一次性（one-shot），不循环。
- **停止条件**：自然衰减结束；若发球后极短时间内发生漏接（理论上可能），漏接音优先级更高，发球音被截断让位（见第 3 节）。
- **高频重复**：由状态机保证不会高频出现；音频侧不做额外节流。

### 2.2 球击中墙（左墙 / 右墙 / 顶墙）

- **用途/玩家意义**：确认反弹，帮助玩家追踪球路。
- **音色性格**：短、硬、电子的"嘀"声（短促击拍，tock/tic 质感），比碎砖音更闷、更短，能量偏低。左墙与右墙可用同一音色或仅做极细微音高区分；顶墙与左右墙同类。
- **触发时机**：球与刚性边界碰撞反弹生效当帧。
- **时长/循环**：极短 one-shot，不循环。
- **停止条件**：自然衰减结束；被同一优先级层更新的同类墙音截断重触发（见下）。
- **高频重复行为**：墙音属于最低优先级的高频音。相邻两次墙音间隔极短（球在角落连续反弹）时，**后发的墙音直接替换（截断重触发）前者**，不叠加，避免机关枪式叠音。墙音在任何情况下不得压制碎砖、漏接与终局音。

### 2.3 球击中挡板（Paddle Hit）

- **用途/玩家意义**：确认"接住了"，这是玩家最关心的操作结果之一，需比墙音更有满足感。
- **音色性格**：比墙音略厚、略低的短合成拍击，带一点弹性（极短的音高下坠），结实但不沉重。
- **触发时机**：球与挡板碰撞反弹生效当帧。
- **时长/循环**：短 one-shot，不循环。
- **停止条件**：自然衰减结束。
- **高频重复行为**：由玩法保证不会连发（一球一击）；无需节流。挡板音优先级高于墙音，同帧若同时存在挡板与墙的碰撞声（罕见），只播挡板音。

### 2.4 击碎砖块（Brick Break，含同帧多砖规则）

- **用途/玩家意义**：确认砖块销毁与得分，是对局中最频繁的正反馈，承担节奏与爽感。
- **音色性格**：清脆、闪亮的短碎音（短噪声瞬态 + 高频 FM/数字叮音），比墙音明亮、能量更高。
- **触发时机**：砖块被销毁生效当帧（GDD：销毁在该次碰撞结算中立即生效）。
- **时长/循环**：短 one-shot，不循环。
- **停止条件**：自然衰减结束。
- **同帧多砖规则（必需规则）**：GDD 允许一次结算接触多块砖并全部销毁计分。声音处理如下：
  1. **同一次结算（同一逻辑事件，通常即同一帧）内无论击碎几块砖，只发出一个碎音**，不为每块砖各发一个声音——避免密集爆音与瞬间削顶。
  2. 该碎音的**音高随本次连碎数量微升**：以单碎音高为基准，每多一块砖升高一个小而固定的音程台阶（如半音级），设上限台阶（建议最多 3–4 级台阶，即 4 块以上不再继续升高），防止极高音刺耳。
  3. 连碎数仅统计**同一次结算内**的销毁数；跨帧的连续碎砖属于各自独立的碎音事件（其跨事件的连击音高处理见下）。
  4. 多砖碎音的瞬态响度可比单碎略强（让玩家"听得出打了多块"），但强度递增受限，不得因此削顶（见 3.3）。
- **跨帧高频重复行为（必需规则）**：连续碎砖时，每次结算各发一个碎音；为避免极快连发造成的爆音叠加，碎音设最小重触发间隔节流：间隔短于阈值时，截断上一个碎音的余音并重触发新碎音（只保留最新瞬态）。**碎音音高随短时间连击微升为可选增强，不是必需**（见第 9 节）；必需的音高微升仅指 2.4 中"同一事件内多砖"的情形。

### 2.5 漏接（球越过死亡线，Miss）

- **用途/玩家意义**：明确告知失误与代价即将发生，是负反馈中最重的非终局事件。
- **音色性格**：明显区别于所有碰撞音的下坠音——音高明显向下滑落的短合成音，带一点失落感，但保持电子质感、不滑稽化。
- **触发时机**：死亡线判定生效当帧（GDD：先处理碰撞反弹与销毁，再在结算末尾检查死亡线；若同帧最后一块砖被击碎且越线，判定为关卡完成，则**播放关卡完成音而不播漏接音**，音频必须与 GDD 的消除优先判定一致）。
- **时长/循环**：短于终局句、长于碰撞音的一次性音，不循环。
- **停止条件**：自然衰减结束；其后紧接着的"待发复位"音（若有余命）在漏接音收尾后或轻微重叠处进入。
- **高频重复行为**：不会高频出现；漏接音优先级高于全部碰撞/碎砖音，触发时立即压低或截断仍在响的高频音（见第 3 节），确保漏接清晰可闻。

### 2.6 生命减少后的待发复位（Reset to Ready）

- **用途/玩家意义**：标记"扣命完成、已回到待发，可以继续"，给玩家一个重新准备的节拍点。
- **音色性格**：两声轻短的电子确认音（低—高或单声中性短音），克制、不庆祝。
- **触发时机**：Playing → Ready 转移完成（生命数减 1、球与挡板复位）当帧。仅在**扣减后仍有余命**时播放；生命数为 0 时播放游戏结束句，本事件不发生。
- **时长/循环**：短 one-shot 组合，不循环。
- **停止条件**：自然衰减结束；玩家立刻发球时，发球音可在复位音尾之后进入，必要时截断其尾音。
- **高频重复行为**：不会高频出现；优先级同漏接层（重要转移音）。

### 2.7 关卡完成（Level Complete / 胜利短句）

- **用途/玩家意义**：宣告胜利终局，给予明确的完成奖赏。
- **音色性格**：一段简短上扬的合成器胜利短句（3–5 个音符的小琶音/号角式短句），明亮、圆满，是全游戏最"完整"的一段音。
- **触发时机**：Playing → Level Complete 转移当帧（含 2.5 所述"最后一砖与越线同帧"的情形）。
- **时长/循环**：数拍长度，一次性播放，不循环。
- **停止条件**：自然播放完毕；玩家在结算界面选择重开/退出时，若短句仍在响，做短促淡出或随状态切换停止（见第 5 节），不硬切出爆音。
- **高频重复行为**：不会高频出现；最高优先级层，与背景音乐的关系见第 4 节。

### 2.8 游戏结束（Game Over / 失败句）

- **用途/玩家意义**：宣告失败终局。
- **音色性格**：一段简短下行的合成器失败短句（3–5 个音符，音高下行、收束感强），情绪低落但克制，不刺耳、不滑稽。
- **触发时机**：扣减后生命数为 0、Playing → Game Over 转移当帧；此情形下不播 2.6 的复位音。
- **时长/循环**：数拍长度，一次性播放，不循环。
- **停止条件**：同 2.7。
- **高频重复行为**：最高优先级层。

### 2.9 界面音（UI）

- **用途/玩家意义**：确认界面操作被接收。
  - **按钮点按（确认类）**：中性、轻短的电子"嘀"声，用于开始、继续、重新开始等。
  - **返回/取消/退出类**：比确认音略低或略短的一声，性格上区分"退回"与"确认"。
  - **暂停开**：进入暂停时一个短促的下沉/收束音（配合音乐挂起，见第 4 节）。
  - **暂停合（继续）**：一个短促的回升音。
- **音色性格**：全部为极短、轻量、电子的点按音，响度低于玩法事件音，不与碎砖/碰撞争夺注意。
- **触发时机**：点击/按键生效当帧（与界面响应同步）。
- **高频重复行为（必需节流规则）**：界面音必须防连触（快速连点、按住空格/回车、触控抖动）。同一按钮的同一操作设最小触发间隔；间隔内的重复触发不发声（输入本身的合法性由交互逻辑决定，音频只负责不重复出声）。暂停开/合音由状态机保证成对、不连发。

## 3. 并发、优先级与相对电平

### 3.1 重叠规则

- 允许重叠：背景音乐（见第 4 节）可与任意音效同时存在；不同层级的音效允许短时重叠（如碎砖余音未消时击墙）。
- 同层高频音不叠加：墙音、碎砖音按 2.2/2.4 的截断重触发与节流规则处理，同类瞬态不同时堆叠。
- 高优先级事件发声时，低优先级的高频音让路：漏接、复位、终局短句触发时，仍在响的墙音/碎砖音立即截断或被快速压低，保证关键事件清晰。

### 3.2 优先级分层（从高到低）

1. **终局层**：关卡完成、游戏结束——最高，发声时其他音效让路，背景音乐弱化/停止（见 4.3）。
2. **重要事件层**：漏接、待发复位、发球——高于全部高频碰撞音。
3. **玩法反馈层**：碎砖（含多砖）、挡板击球。
4. **背景反馈层**：击墙音。
5. **界面层**：UI 点按音（轻量，不与玩法争抢；暂停/继续音可视为界面层中略高者）。
6. **音乐层**：持续垫底，受 ducking 规则约束。

同时只能有一个"最高层级事件"发声；同层级冲突时（理论上极少，如胜利与漏接）以 GDD 的状态判定为准，只发判定结果对应的声音。

### 3.3 相对响度（定性，不给 dB 表）

- 背景音乐为最低层：作为氛围垫底，响度明显小于全部音效（约为"感觉得到但不抢戏"的程度）。
- 界面音轻于玩法音：点按音明显弱于碎砖/挡板音。
- 玩法音中：碎砖音最突出（正反馈），挡板音次之，墙音最弱（避免高频墙音形成噪声疲劳）。
- 漏接与复位音需在碎砖密集时仍清晰可辨，响度设定以"满屏碎砖中漏接一出立刻被听见"为准。
- 终局短句为最显眼的前景声。
- 多砖碎音虽可比单砖略强，但任何叠加与 ducking 后的**主总线输出不得削顶（clipping）**：主输出预留余量（headroom），并对主总线做轻量限幅（limiter）作为最后保护；高频连发场景优先用截断/节流而非靠限幅硬压。

### 3.4 连触节流总则

- 每个高频/可重复事件（墙、碎砖、UI 点按）必须有各自的最小重触发间隔或"截断重触发"策略（已在第 2 节逐一声明）。
- 全局并发音效数量设上限（少量，个位数），超过上限时按优先级丢弃最旧/最低的声音实例，绝不无限制起音。

## 4. 音乐（背景音乐）

### 4.1 首版结论

**首版包含一首可循环的低调合成器背景音乐**（街机机厅氛围 / synthwave 底色）。理由：

- 本游戏节奏快、单局短、重复游玩频次高，持续的低调音乐能显著强化"深夜街机"情绪与对局节拍感；
- 成本可控：只需一首短循环，不引入音乐系统（无多轨切换、无动态分层、无音轨库、无自适应作曲）；
- 音乐必须克制：低能量、低旋律侵略性，循环时长以短时间重复聆听不疲劳为准，不与碎砖音争夺高频注意力。

除这一首循环外，首版不做其他音乐（标题曲、结算曲等均不单独制作；终局以音效短句承担）。

### 4.2 无缝循环

- 乐曲必须做成**无缝循环**（loop point 处无爆音、无可察觉接缝）；循环由 Web Audio 采样级循环或等长无间隙调度实现，不用"播完再从头播"的粗糙方式。

### 4.3 音乐在各状态的行为

- **进入对局（Title → Ready 起，或发球进入 Playing 时）**：音乐开始；建议在 Ready 即淡入，让待发界面已有氛围。
- **进行中**：持续循环。
- **暂停（Playing → Paused）**：音乐**挂起**（暂停播放，记住播放位置），同时配合暂停开音；或作为备选实现为大幅压低到近乎静音。两种实现择一，但继续时必须从原位置/原电平恢复，不重新开始曲目。首版推荐：挂起（冻结），行为最确定。
- **继续（Paused → Playing）**：音乐恢复。
- **结算（Level Complete / Game Over）**：触发终局短句时音乐**快速弱化（ducking）或停止**，让胜利/失败句成为前景；推荐短促淡出后停止。停留在结算界面期间音乐不强行恢复。
- **重开（结算 → Ready）**：音乐重新淡入（可从曲目起点开始，因为是新一局）。
- **标题界面**：手势解锁前不得出声（见第 6 节）；解锁后、开始游戏前，标题界面是否放音乐：**首版标题界面不放音乐**，保持安静，音乐只随对局开始——减少解锁边界的复杂性与突兀感。

### 4.4 页面失焦（visibilitychange / blur）

- 页面失焦（切标签页、最小化）时：若处于 Playing，等效处理为自动暂停（GDD/交互层面的暂停策略由对应文档定义），音频层面音乐挂起、音效全部停止，绝不允许后台标签持续发声。
- 页面重新获得焦点时：不自动恢复声音；若游戏进入了暂停态，等玩家显式继续后再恢复，恢复时遵循暂停→继续的同一规则。

## 5. 跨状态音频过渡

总原则：**任何状态切换都不允许产生突兀爆音（硬切的咔哒声、叠层轰鸣）**；以极短淡出/淡入或截断到零交叉点实现，过渡时长以"玩家几乎察觉不到过程、只察觉结果"为准。

- **标题 → 对局（开始）**：首次开始同时完成音频解锁（见第 6 节）；音乐淡入，发球前无其他突兀声音。
- **待发 → 进行中**：发球音起，音乐已在底层（无切换）。
- **进行中 → 暂停**：暂停开音，所有玩法音效立即停止（不允许余音在暂停菜单里继续响），音乐挂起或压低。
- **暂停 → 进行中**：暂停合音，音乐恢复；模拟恢复后新的碰撞才重新发声。
- **进行中 → 漏接 → 待发**：漏接音 →（有余命时）复位音；期间在响的高频碰撞音截断；音乐保持（漏接不停止音乐）。
- **进行中/漏接 → 终局（胜利/失败）**：终局短句起，音乐快速弱化或停止；其他音效全部静默。
- **失败 → 重开（结算 → Ready）**：终局句若未结束则短淡出停止；新局音乐重新淡入；不允许上一局任何声音残留到新局。
- **退出（暂停 → Title，或结算 → Title/外层页面）**：全部音乐与音效立即做短促淡出后停止；退到标题界面后保持静默（4.3）。退出不结算成绩，音频上也不播胜利/失败句。

## 6. Web 平台音频规则（Autoplay 策略）

1. **AudioContext 必须在首次用户手势中创建/恢复**：以标题界面"开始"按钮的点击（或同等的开始操作手势）作为解锁点，在该手势的事件处理中创建或 `resume()` AudioContext。
2. **手势解锁之前，标题界面不得发出任何声音**（无音乐、无 hover 音、无自动音效）。
3. **解锁成功后**：按第 4、5 节规则开始对局音频。
4. **解锁失败 / 浏览器禁止音频 / 设备无输出时：静默降级**——游戏正常可玩，仅全部音频不发声；不弹阻断式错误、不反复重试打断玩家。可在后续手势中再尝试恢复 AudioContext（恢复成功前继续静默）。
5. 所有音频播放代码必须容忍 AudioContext 处于 suspended/不可用状态而不报错影响玩法。
6. 键盘（空格/回车）开始游戏同样属于用户手势，可作为解锁点；但实现上以点击开始按钮为主路径，确保移动浏览器兼容。

## 7. 混音、静音与持久化

### 7.1 控制项（首版）

- **至少提供主静音开关（Mute On/Off）**，作用于全部音频（音乐 + 全部音效），全局生效。
- 主音量调节滑块：**可选，不做硬性要求**；若实现，需与静音联动（取消静音后恢复上次音量）。首版以"静音开关"为必需交付，音量滑块可作为后续增强。
- 静音为**即时生效**：开启时正在响的声音立即安静（快速淡出，不爆音）；取消静音后不补播被静音期间错过的任何声音。

### 7.2 持久化与作用域

- 静音（及可选音量）设置写入 **localStorage**，键名与数据格式在实现时统一约定；刷新页面后保留。
- 作用域为**全局**：在标题、对局、暂停、结算所有状态下一致生效；玩家在任何界面切换静音都立即应用，无需重开。
- localStorage 不可用（隐私模式等）时，设置仅在本次会话内存活，不因此报错。

### 7.3 交接给 UI_UX_SPEC 的视觉界面需求

音频侧需要 UI 提供以下视觉元素（**具体位置与排布由 UI/UX 决定**，音频侧只声明需求）：

1. **HUD 上常驻可见的静音开关按钮**（对局进行中、暂停、结算、标题界面中至少在对局与暂停界面可达；推荐全局常驻），一键切换。
2. 按钮需有**两种明确可辨的状态图标**：有声（如喇叭/声波图标）与静音（如喇叭带叉/禁用图标）；图标状态必须与实际音频状态严格一致（静默降级期间——见第 6 节——的图标表现由 UI 决定，但不得误导为"正在发声"，建议显示为静音/不可用态）。
3. 点击该静音按钮自身可以不发 UI 点按音（取消静音后的反馈音可有可无，由 UI 与音频共同确认），避免"点静音却响一声"的矛盾。
4. 若提供音量滑块（可选）：需要一个可拖动的水平滑块与当前值的可视反馈；此为可选项，首版不提供时 UI 亦无需预留。
5. 图标需在霓虹街机底色上保持对比度与可点按尺寸（具体尺寸/对比度标准遵循 UI/UX 与可访问性规范）。

## 8. 可访问性

- **关键信息均有视觉对应，音频不单独承载任何关键信息**：
  - 碎砖与得分：砖块消失、分数即时变化（GDD 已保证立即生效）；
  - 漏接：球越过死亡线、生命数减少有视觉表现；
  - 生命与终局：剩余生命、结算界面均为视觉呈现；
  - 暂停/状态变化：覆盖层与界面视觉呈现。
- 因此静音游玩、听障玩家不会丢失任何玩法信息；音频提供的是情绪与节奏增强。
- 不做仅靠音频区分的事件（例如不依赖"只在声音里"提示球从哪一侧来）；2.2 中墙音的细微差异仅为锦上添花。
- 尊重系统与用户的音量/静音设置；遵守第 6 节手势规则，避免在用户未预期时发声（这本身也是可访问性与网页礼仪）。

## 9. 必需音频行为 vs 可选增强

### 9.1 必需（首版验收范围）

- 第 2 节全部事件的声音与触发时机，且必须与 GDD 状态判定一致（尤其：同帧末砖+越线播胜利音不播漏接音；生命为 0 播失败句不播复位音）。
- **同一事件（同帧）多砖只发一个碎音、音高随同事件连碎数微升并设上限**——此为必需规则。
- 墙音截断重触发、碎砖最小间隔节流、UI 音连触节流、全局并发上限与主总线防削顶。
- 第 3 节优先级分层与相对响度关系。
- 一首无缝循环背景音乐：对局淡入、暂停挂起、结算弱化/停止、失焦不发声。
- 第 5 节全部状态过渡无爆音。
- 手势解锁、静默降级、静音开关 + localStorage 持久化（全局作用域）。

### 9.2 可选增强（不影响首版验收，不预先构建系统）

- **碎砖音高随跨事件连击（跨帧连续碎砖）微升**：可选；若做，需在连击中断后回落，且同样受防削顶约束。
- 多砖碎音随数量增强瞬态响度（在受限范围内）：可选微调。
- 主音量滑块（静音开关为必需，滑块可选）。
- 左/右墙音的细微辨识差异、标题界面音乐（首版明确不放）。
- 任何自适应/动态音乐分层、多首曲目、音乐与玩法强度联动：**首版明确不做**，不引入超出需要的音乐系统。

## 10. 文件规格（供 ASSET_PLAN 汇总）

以下仅给出资产规划所需的规格级别，不重复资产清单：

- **格式**：面向现代浏览器，音效与音乐优先使用 Web Audio 可直接播放的压缩格式（如 AAC/.m4a 与/或 OGG 视兼容目标而定）；具体格式矩阵与降级方案由 ASSET_PLAN / 实现按目标浏览器确定。
- **音效时长级**：全部为短促音效（碰撞类为亚秒级瞬态；漏接与终局短句为数秒以内），避免长素材，便于快速截断与节流。
- **声道**：**单声道（mono）**。本游戏全部为 2D 非定位音，单声道即可，体积更小且不存在伪空间感；音乐可用立体声以保留合成器宽度，但不做定位玩法用途。
- **采样率与码率**：以"听感无损于短电子音、体积小、加载快"为原则，具体数值由 ASSET_PLAN 规定，本文不预设参数表。
- **合成替代**：若选择以 Web Audio 程序化合成部分/全部音效（与合成器审美高度契合），则无需对应的音频文件资产；此决策影响资产数量，需与 ASSET_PLAN 对齐，但不改变本文任何触发与优先级行为。
- **许可与来源**：任何外购/第三方音频必须确认许可与来源；自制或程序化合成可规避来源风险。

**验证说明**：本文是设计文档，作者未对运行时音频做过实际检查（无设备实测、无延迟/电平测量）。实现完成后，应通过真实玩家路径在浏览器中验证：手势解锁、静音持久化、暂停/失焦挂起、同帧多砖只发一声且不削顶、终局无爆音；自动化/无头测试保持静默，除非测试对象本身就是音频输出。
