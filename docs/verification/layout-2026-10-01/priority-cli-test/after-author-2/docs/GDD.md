## 1. 首版范围

### 1.1 首版要交付的体验

一个完整、可反复游玩的单局打砖块体验：玩家横向移动底部挡板，弹射一颗小球击碎场上全部砖块即获胜；小球漏接会损失生命，生命耗尽则失败。首版包含**一张固定布局的关卡**、计分、生命数、本地最高分，以及从进入游戏到胜利/失败/重开/退出的完整流程。

### 1.2 明确排除项（首版不做）

- 多关卡、关卡选择、关卡推进与难度曲线
- 道具/掉落物（多球、激光、加长挡板等）
- 多种砖块类型（首版砖块均为一次击碎；无加固砖、炸弹砖等）
- BOSS、特殊敌人、移动砖块
- 多人模式、排行榜（在线）、成就
- 存档式进度、解锁内容、内购与广告
- 竖屏布局与可旋转重排

以上内容不影响首版完整性；如后续版本加入，需更新本文件。

## 2. 玩家目标与核心循环

### 2.1 目标

- **单局目标**：在生命耗尽前击碎场上全部砖块。
- **街机式追求**：在重复游玩中争取更高得分，并超过本地保存的最高分。

### 2.2 核心循环

1. 玩家左右移动挡板，预判并接住下落的球。
2. 球击中砖块 → 砖块消失、得分，球反弹。
3. 玩家通过挡板接球位置控制反弹方向，继续瞄准剩余砖块。
4. 球漏接 → 损失一条生命，球重新置于待发状态；或砖块清空 → 关卡完成。

挑战来自对球轨迹的预判与用挡板位置做方向控制；反馈为即时的碰撞反弹、砖块消除、计分变化与音效（音频细节见音频设计文档）。

### 2.3 计分与生命（可观测规则）

- 每击碎一块砖获得固定分数；**具体分值、初始生命数、球速等全部可调数值由数值平衡文档统一规定**，本文件不重复维护参数表。
- 分数在单局内累计；生命数对玩家可见。
- 本地最高分：单局结束（胜利或失败）时，若当局得分超过已保存的最高分，则更新并持久化到本机；最高分在主界面展示。清除浏览器数据可能使其丢失，这是预期行为。除此之外无其他持久化内容。

## 3. 玩家动作

| 动作 | 键盘/鼠标 | 触控 | 后果 |
|---|---|---|---|
| 移动挡板 | 鼠标水平移动（指针映射到挡板 X）；或键盘左/右方向键、A/D 按住持续移动 | 在游戏区域内按住并水平拖动，挡板跟随触点 X | 挡板在场地左右边界内水平移动；不能上下移动 |
| 发球 | 点击鼠标左键 / 空格键 / 回车键 | 点按屏幕 | 仅在"待发"状态有效：球离开挡板进入运动 |
| 暂停/继续 | Esc 或 P 键 | 界面上的暂停按钮 | 切换暂停（见状态机） |
| 确认/重开 | 界面按钮；结算界面可用前述按键快速重开 | 点按界面按钮 | 在结算界面重新开始一局 |
| 退出 | 主界面/暂停菜单中的退出按钮 | 同 | 关闭或回到承载页面（Web 环境下为退出对局回到标题/外层页面） |

输入映射的细节（按键清单、触控热区、指针捕获行为）以交互契约文档为准，两处冲突时以该文档为权威。挡板在"待发"和"进行中"均可移动；暂停及各类结算覆盖层显示时，移动与发球输入无效。

## 4. 游戏状态与流程

### 4.1 状态定义与进入条件

1. **加载/标题（Title）**：页面打开并完成资源加载后进入。展示标题、开始按钮、本地最高分；横屏空间不足时展示提示（见第 7 节）。
2. **待发（Ready/Serve）**：一局开始、或每次损失生命后仍有余命时进入。球静止吸附在挡板上方，随挡板移动，场景中显示"点击/按空格发球"提示。
3. **进行中（Playing）**：玩家发出发球指令后进入，球开始运动。
4. **暂停（Paused）**：仅可从"进行中"进入；显示暂停菜单（继续、重新开始、退出）。继续后回到"进行中"，球从暂停时的位置与方向恢复。
5. **关卡完成（Level Complete）**："进行中"击碎最后一块砖块时进入。展示祝贺、当局得分、是否刷新最高分，以及"再来一局"。
6. **游戏结束（Game Over）**：损失生命后生命数为 0 时进入。展示当局得分、最高分，以及"重新开始"。

### 4.2 状态转移

- Title → Ready：选择开始；新局分数清零、生命数重置为初始值、砖块按布局全部生成。
- Ready → Playing：有效发球输入（输入释放时触发一次，长按不连发）。
- Playing → Paused / Paused → Playing：暂停切换。
- Playing → Ready：球越过底部死亡线且仍有余命；生命数减 1，球与挡板复位到待发布局，已击碎砖块保持消失、分数保持累计。
- Playing → Level Complete：场上砖块全部被击碎。
- Playing → Game Over：球越过死亡线且扣减后生命数为 0。
- Level Complete / Game Over → Ready：选择重新开始，等价于 Title → Ready 的完整重置。
- Paused → Title：从暂停菜单退出；当局成绩不结算、不计入最高分。
- 结算界面 → Title/外层页面：退出。

首版只有一关，故"关卡完成"即终局；重开后布局、分值、生命完全相同，重复游玩的差异仅来自动态球路与玩家自身发挥，不设置随机布局或难度递增。

## 5. 场上规则与系统交互

### 5.1 场地与碰撞

- 场地为横屏矩形：顶、左、右为刚性边界，球反弹；**底部为死亡线**，球整体越过（或触及，以平衡文档定义为准）即判定漏接，球不反弹。
- 挡板位于底部区域，仅水平移动，被左右边界约束。
- 球与砖块、挡板、墙体均发生弹性反弹；球与挡板碰撞时，**击中挡板的水平位置决定反弹的垂直/水平角度**（中心近垂直、边缘更倾斜），这是玩家控制球路的主要手段。
- 所有砖块均可被一次击碎，击碎后立即从场上消失并加分；球按其碰撞面反弹。
- 球与球之间无交互（首版只有一颗球）。

### 5.2 同时性与生效时机（解决结果歧义）

- 一次碰撞结算中，先处理球与墙/挡板/砖块的碰撞反弹与砖块销毁计分，再在该次结算末尾检查球是否越过死亡线。因此：若同一帧内最后一块砖被击碎且球越过死亡线，判定为**关卡完成**（消除优先于漏接）。
- 若同一次结算中球接触多块砖：对接触到的砖块**全部予以销毁和计分**，反弹方向按最先接触的碰撞面确定；具体接触次序的判定规则属于实现细节，但玩家可观测结果必须稳定一致，不因帧率变化而改变销毁集合。
- 生命数、分数、砖块数量的变化在对应事件发生的当次结算立即生效，UI 即时反映，不设延迟或缓冲。
- 状态转移（如进入暂停、漏接复位）发生的当刻起，不再接受旧状态下的输入：暂停生效后该帧的移动/发球输入丢弃；漏接判定后球立即停止受挡板影响。
- 过渡/覆盖层（暂停、结算）显示期间，场上模拟冻结；覆盖层关闭前发生的任何输入不排队、不补执行（界面按钮自身的点按除外）。

### 5.3 失败保护（可读性规则）

- 球的水平速度分量不得在反弹后变为 0（避免球在垂直方向上无限往返、砖块无法被触及）；该约束的量化下限由数值平衡文档规定。
- 球速等具体数值随游戏时间是否变化（如缓慢加速）及其幅度，由数值平衡文档规定；若规定加速，其规则对玩家一致可重复，不因帧率而异。

## 6. 界面与表现概要

- 游戏内必备信息：当前分数、剩余生命、最高分（标题与结算界面至少展示最高分）。
- 必备界面/覆盖层：标题界面、待发提示、暂停菜单、关卡完成结算、游戏结束结算、方向/尺寸提示（见第 7 节）。
- 视觉为风格化街机风：构图、配色、光照、材质、特效的具体方向由美术指导文档确定；界面布局、反馈与可访问性由 UI/UX 文档确定。
- 音频（击球、碎砖、漏接、胜利/失败、界面音）由音频设计文档确定。
- 关卡内砖块布局（行列数、间距、在场地中的位置）以及挡板、球的初始摆放，属于**场景创作数据**：以 Scene/UI JSON 为可编辑来源，运行时代码加载该数据呈现，不在代码常量中固化布局决策。本文只规定"一张固定布局的满砖阵"这一设计事实，具体坐标与尺寸由场景数据给出。

## 7. 屏幕方向与尺寸要求

- 首版**仅支持横屏（Landscape）**，不提供竖屏重排。
- 设计参考坐标为横屏 16:9 场地；**最小可用尺寸为 800×450（设计坐标）**。UI/场景文档可在此之上定义响应式变体，但不得通过不可用的缩小来适配更小空间。
- 当设备处于竖屏、或可用空间低于最小尺寸时：显示"请旋转设备至横屏 / 窗口尺寸不足"的提示页，游戏不开始、不强制重排；恢复到可用横屏空间后可进入游戏。
- 参考尺寸是设计坐标，不是对宿主窗口物理像素的固定要求。

## 8. 首版完成条件（玩家可观测）

满足以下全部条件即视为首版玩法完成：

1. 横屏浏览器中可从标题界面开始一局；空间不满足时出现提示页。
2. 可用鼠标、键盘、触控三种方式在边界内移动挡板，并能从待发状态发球。
3. 球正确地与墙、挡板、砖块反弹；挡板击球位置改变反弹角度；砖块一次击碎并加分。
4. 击碎全部砖块进入关卡完成结算；漏接扣生命并复位，生命耗尽进入游戏结束结算。
5. 暂停可中断并无损继续；可从暂停和结算界面重新开始或退出。
6. 当局分数、生命数正确显示与变化；最高分在结算时正确更新并在刷新页面后保留。
7. 砖块布局来自 Scene/UI JSON 创作数据，修改 JSON 即可改变布局而无需改动玩法代码。
8. 上述结果在连续多局重开后保持一致（无残留分数、生命或砖块状态）。

- **本 GDD**：范围、目标、动作、状态流程、可观测规则、完成条件的唯一权威来源。
