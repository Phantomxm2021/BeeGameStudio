## 0. 一句话方向

**深夜霓虹机厅（Neon Arcade / synthwave 气质）**：一块深色的电子游戏场，砖块是墙上成排的发光灯牌，球是一颗带着光尾的白色流弹，挡板是玩家手中唯一的发光器具。屏幕像一台在暗处亮着的街机机柜，亮的东西都在"发光"，暗的东西都在退后。

选择理由：单屏、无角色、无敌人的街机体验需要的不是叙事场景，而是一个让"球的轨迹"和"击碎瞬间"被放大的信息场；深色底 + 自发光元素天然给出最高的主体对比，且灯牌砖阵与"一整片一次击碎"的玩法在视觉上同构——打掉一盏灯，墙上暗一格。

## 1. 情绪与核心母题

### 1.1 玩家应有的感觉

- 进入标题：**夜里一台为你亮着的机器**——安静、期待、带一点仪式感，而不是喧闹的嘉年华。
- 对局中：**快、脆、掌控感**。每次击中像灯管爆裂一样干脆，球路清晰可判，玩家觉得自己是在操作光，而不是在追一个圆点。
- 漏接：**一瞬的失落**（光熄灭、被吸走），不是惩罚性的爆炸羞辱。
- 胜利：**整面灯墙全部点亮/引爆后的暖色余韵**；失败：**冷色收束、机柜转入待机**。

### 1.2 核心图形母题

统一母题为**"光的拖尾与一道反弹光弧"**，全游戏只允许这一套光效语言：

1. **球拖尾**：球身后短而收尖的光尾，是标题画面与对局共同的主角图形。
2. **反弹光弧**：球撞挡板/砖墙瞬间，沿碰撞点弹出的一道短促弧光（半个括号形），是"脆"的来源。
3. **灯牌辉光**：所有可击碎/可交互物的发光边缘，粗细有层级，但语法一致（见第 2、4 节）。

标题画面的动态只允许使用这三个母题（拖尾缓缓滑过、光弧偶发），不得引入烟花、星空、粒子海洋等无关母题。

### 1.3 标题画面的焦点与安静区域

- **第一视觉焦点**：标题字处理 + 其下方/内部贯穿的一条球拖尾光弧。标题字使用紧凑、几何感的显示字体（见 9.2），字面本身做"通电的霓虹灯管字"效果：字形由发光描边构成，局部灯管可有极轻微的辉光呼吸；一条球的光尾从标题一侧划向另一侧，划出时可在字面上留下短暂的增亮。
- **第二焦点**：开始按钮（视觉身份见第 9 节）。
- **安静区域**：屏幕**左下至中下的大片区域必须保持暗与净**——无网格线、无装饰粒子、无背景图形，只允许极暗的渐变。理由：进入对局后这块区域对应挡板活动区与球的下行空间，标题期就保持安静，可以让玩家视线习惯"底部是操作区、焦点会回到这里"；最高分等辅助信息置于安静的角落，以低明度小字呈现，不与标题争夺。
- 背景可有极弱的透视网格（synthwave 地平线式），但透明度必须压到"注意不到、只在纯色截图时才看得出"的程度，且**不得延伸进底部安静区**。

## 2. 形状语言

### 2.1 总规则：圆角家族，统一半径语言

- 世界中一切可交互、可击碎、被发射的物体（挡板、球、砖块、按钮）一律使用**圆角形**，传达"通电、圆润、可触碰"。
- 场地边界（墙）与危险元素（死亡线）使用**直角/细线**语言，传达"刚性、边界、不可通过"。圆角物与直角物构成全游戏最基本的形状对立：**圆的属于玩家和玩法，直的属于规则与危险**。
- 圆角半径分两级，全项目统一：
  - **大圆角**：挡板、大按钮、面板——半径约为自身短边的 1/4～1/3，呈现胶囊/厚牌感。
  - **小圆角**：砖块、小控件——半径小而明确，远看近似方、近看有圆角，保证成阵时行列边缘整齐成直线（砖阵的外轮廓必须是干净的几何矩形，不能因圆角显得参差不齐）。
- 球为正圆，是圆角语言的极限形态。

### 2.2 轮廓与辉光规格（设计语言，不给像素表）

所有发光物采用三层结构，由内向外：

1. **实体芯**：一块高饱和但明度中等的填充色，决定物体"是什么色"。
2. **亮缘**：贴着轮廓的一圈更亮的描边（接近该色相的高明度端），像灯管的壁。砖块仅上缘与左右缘明显，下缘收弱，使整面砖阵读起来是"一面被上方照亮的墙"。
3. **外辉**：亮缘之外一圈弥散的同色相辉光，无硬边，亮度快速衰减。

辉光粗细的**相对**层级（以球为 1）：

| 元素 | 外辉强度（相对） | 说明 |
|---|---|---|
| 球 | 1.0（基准，最强对比由近白色相保证，而非仅靠辉光） | 永远在场内最跳 |
| 挡板 | 0.7～0.9 | 击球瞬间可短暂超过基准 |
| 砖块 | 0.35～0.5 | 成阵时形成均匀的光墙，任何单砖不得比球亮 |
| 墙体 | 无外辉，只有暗描边/极弱内缘光 | 退后 |
| 死亡线 | 极弱危险色辉光，常态几乎不可见 | 见 6.5 |
| UI 焦点（按钮/选中） | 0.5～0.7 | 与砖块同级或略高 |

辉光只能使用物体自身的色相（同色系外溢），**不允许多色霓虹混用**（一块砖不能同时外溢两种颜色），否则球的白色焦点会被噪声淹没。

### 2.3 禁用形状行为

- 不出现尖角、尖刺、裂纹、碎片形预制贴图（碎砖粒子除外，且为圆角小块/光点，见 7.1）。
- 不给砖块加投影到游戏空间（灯牌只发光、不投射实体阴影），避免砖阵在视觉上"压向"球的活动区。
- 不在世界元素上使用描边的黑白硬线（卡通描边），亮缘必须是彩色自发光。

## 3. 调色板

### 3.1 明度骨架（先于色相）

画面按明度分为四层，任何素材先满足明度关系再谈色相：

1. **最高明度（近白）**：球及其拖尾、击球火花尖、标题文字高光——全场数量最少。
2. **中高明度（亮霓虹色）**：挡板、砖块亮缘、UI 主交互色。
3. **中明度**：砖块实体芯、UI 次级元素。
4. **低明度（深色）**：游戏空间底、墙、背景；占屏幕面积 80% 以上。

检验方式：把画面转灰度，球必须是灰度图中最亮的移动物体，挡板其次，砖阵是一面中等亮度的墙，其余全部沉下去。

### 3.2 具体色相分工

- **背景层**：深紫蓝到深蓝的低明度渐变（近黑的靛蓝，色相稳定在蓝紫区间，不使用纯黑，纯黑会让辉光边缘发脏）。可有极暗的第二色相微差（顶部略偏紫、底部略偏蓝），明度差控制在"几乎看不出"。
- **游戏空间**：比背景略亮一档的深蓝面板色，与背景之间用极暗的边界线区分，像机柜屏幕内的场地；不使用明亮的场地底色。
- **挡板（玩家语义色）**：**青色（cyan）**——冷静、可控、属于"我的工具"。亮缘偏青白。
- **球（交互/主角语义色）**：**近白（带极淡冷味的白）**，拖尾由白过渡到青色——与挡板共享青调，暗示"球从你的器具发出"。球是全场唯一近白元素。
- **砖块**：在暖霓虹区间按行做色相递进（见 6.3）：**品红 → 玫红 → 橙 → 琥珀**。砖的光偏暖，与冷色的场地和玩家构成冷暖对照：玩家在冷色里，击碎的是暖色的灯。
- **墙体边界**：低明度蓝紫，仅以细亮缘（暗青/暗紫）勾勒，不发光外溢。
- **UI**：结构色用青色（与玩家一致，表示"可操作"）；数值与标题用近白；次级文字用灰蓝。

### 3.3 语义色总表

| 语义 | 色相 | 形状/亮度配合 |
|---|---|---|
| 玩家（挡板） | 青 | 大圆角胶囊，常态中高明度 |
| 主角/交互核心（球） | 近白 + 青尾 | 正圆，最高明度 + 拖尾 |
| 可击碎物（砖块） | 品红→琥珀暖色区间 | 小圆角灯牌，整面均匀 |
| 安全/反弹边界（墙） | 暗蓝紫 | 直角细线，无辉光 |
| 危险/失败（死亡线、漏接、生命减少） | 红（红玫色，霓虹红，不用血腥暗红） | 直角细线/向下收束动效 |
| 成功/确认（按钮确认、胜利） | 青为操作色；胜利额外引入**暖金/琥珀** | 暖色迸发只在结算使用 |
| 暂停/禁用 | 去饱和的灰蓝 | 压暗层，见 7.5 |

胜利允许的暖金色只在结算转场出现，对局中暖色只来自砖块，避免语义串味。

### 3.4 关键信息不得只靠颜色

- **砖块状态**：首版砖块无类型差异；被击中即灭，不设"选中/残血"态。若实现上出现瞄准悬停（鼠标）或任何高亮态，必须以**辉光增强 + 亮缘描边增亮**表达，不叠加新色相。
- **生命**：以**心形/小球形图标（形状）+ 数量**表达；失去的一颗变为暗色空轮廓（形状从实心变空心），不能只把图标改红。危险红只在减少瞬间的短反馈中出现。
- **状态提示**（待发/暂停/胜负）：以文字 + 图形符号 + 明度变化共同传达，颜色只做情绪强化。
- **新纪录**：用"NEW RECORD"文字标 + 图标（星/闪电形）+ 暖金辉光三重表达，不只靠变色。
- 所有前景文字与背景的明度对比需满足阅读清晰；UI_UX 文档负责具体对比度数值核验。

## 4. 材质与细节密度

### 4.1 材质定位：发光灯牌，不是实体砖，也不是扁平色块

- 砖块读感为**嵌在深色墙上的发光灯牌/霓虹管牌**：亮、匀、有一点点灯管的体积暗示，但没有重量感、没有石/木/金属材质。
- 挡板读感为**一根磨砂发光推杆/灯管**：表面有均匀内发光，两端亮缘略强（像灯管端帽）。
- 球读感为**一颗实心光点**：核心纯白，外缘极短的青调辉光；不画纹理、不画表情、不画球面高光斑（一个小白核即可，加纹理会在高速旋转时产生噪声）。

### 4.2 允许的表面细节（白名单）

砖块仅允许：

1. 上缘一道短高光（亮缘的一部分）；
2. 牌面内的均匀内发光（中心略亮）；
3. 极轻微的灯管渐变（上下明度微差）。

挡板额外允许：击球点附近的瞬时增亮。球不允许表面细节。

### 4.3 密度上限（硬性）

- **禁止**：砖面纹理图、扫线纹理、做旧/污渍、描边图案、砖面文字或数字、渐变之外的任何图案。
- **判定标准**：球静止贴在任意一块砖前时，球的轮廓必须零歧义；满砖阵与球同时在画面中时，视线先到球。任何为了"丰富"而加的细节若削弱这一条，删除。
- 整面砖阵的纹理感只能来自"砖块 + 间隙 + 行间隔"的栅格节奏本身，不来自单块砖的纹理。
- 背景允许的最大细节：极弱透视网格 + 一层几乎不可见的微噪点（仅用于让深色不发死），二者都不得在球与砖阵区域形成可见线条。

## 5. 层次构图

### 5.1 五层前后关系（由后向前）

| 序 | 层 | 内容 | 明度角色 | zIndex 区间（语义） |
|---|---|---|---|---|
| L1 | 背景层 | 深色渐变、极弱网格、微噪点 | 最低 | 最后方 |
| L2 | 场地/砖块游戏层 | 游戏空间底板、墙、死亡线、整面砖阵 | 低～中 | 中后 |
| L3 | 主体层 | 挡板、球、球拖尾 | 最高 | 中前 |
| L4 | 特效层 | 碎砖粒子、击球火花、光弧、漏接/结算光效 | 短暂高亮 | 前 |
| L5 | 屏幕 UI 层 | HUD、菜单、结算面板、待发提示、旋转提示 | 高（但面积克制） | 最前 |

要点：

- **球与挡板（L3）在任何时刻都高于砖阵（L2）**：球飞入砖阵缝隙时必须完整压在砖块之上，禁止砖块遮挡球。
- **特效层（L4）高于世界但低于 UI 面板**：碎砖粒子可以从 UI 下方穿过的视觉区域存在，但结算面板出现时面板必须压得住粒子（面板自身带深色半透明底）。
- **辉光叠加规则**：跨层辉光只允许"加法式增亮"的视觉结果（光与光相遇变亮），不得出现灰色脏边或实体遮挡感。L4 的辉光不得在球所在位置叠加到使球轮廓糊掉。

### 5.2 独立透明层与宽高比适配

- L1 与 L2 必须分离：背景层独立铺满（可随相机/容器做 letterbox 区域填充），游戏空间是其中居中的矩形面板；不同宽高比下，**背景负责填满、场地负责不变形**。
- L4 必须为独立透明层：粒子与光弧不含底色，才能同时叠加在砖阵、场地、背景上，并在暂停/结算时被整体压暗或冻结。
- L3 的球拖尾建议与球同属主体层但作为独立透明渲染对象，使拖尾可被砖阵辉光增亮而不污染砖块颜色。
- L5 为屏幕空间 UI，独立于世界坐标（契约：UI 使用 top-left 逻辑像素，与世界相机适配分开）。
- 各层排序以 zIndex 表达"数值越大越靠前"，具体数值由场景/内容文档落定，本文只锁定层间次序。

### 5.3 适配纪律

- 任何宽高比下，明度层级与"球第一焦点"不得改变；letterbox 区域使用背景层深色，不得出现白边/宿主页面亮色。
- 砖阵、挡板、球的相对构图（砖在上、板在底、球为主角）不随宽高比重排；重排只在 UI 层发生且归 UI_UX_SPEC。

## 6. 各类元素的可辨识设计

### 6.1 球（主角，第一焦点）

- 近白正圆 + 青色短拖尾。拖尾**短、收尖、快速衰减**：长度约为球直径的数倍，速度越快拖尾越长越亮，但始终是"短尾"而非彗星长尾——长尾会遮挡砖阵并模糊球的实际位置。
- 拖尾末端允许 1～2 个离散的渐隐光点，禁止长串粒子。
- 撞墙/砖瞬间本体不允许变形（球不能被压扁——变形会让玩家误判碰撞点），反馈由光弧与火花承担。
- 球越过死亡线时，拖尾方向随之下沉并迅速熄灭（见 7.2）。

### 6.2 挡板（玩家器具）

- 青色大圆角胶囊，两端略亮。常态辉光稳定。
- **击球瞬间**：沿击球点出现一次**极短的水平压缩回弹**（压扁随即弹回）+ 击球点辉光骤增 + 一道青色光弧沿板面上缘弹出。压缩幅度小、回弹脆，像击中一根有弹性的灯管。
- 左右移动时不允许拖影（挡板拖影会干扰对板真实位置的判读）；只允许辉光随速度轻微拉伸。
- 挡板抵达左右墙时可有极轻的"抵边"微光，不弹、不震屏。

### 6.3 砖块（一面有节奏的灯墙）

- 所有砖块在玩法上完全等价：**色相变化只是行间视觉节奏，绝不能暗示强度、分值或类型差异**。
- 行级色相递进规则：自上而下沿品红 → 玫红 → 橙 → 琥珀做**缓慢、连续**的暖色位移，相邻两行色差小到不抢眼，整面墙远看是统一的暖光，近看才有节奏。也可以整组围绕品红—橙之间循环，但循环必须平滑，不得出现跳变的"色带分区"。
- **禁止**：按行使用红/黄/绿等容易被读成"难度/血量"的交通灯配色；禁止把某几行做成明显不同明度。
- 砖与砖之间留深色细缝，成阵时形成栅格节奏；砖阵外缘是一个干净的大圆角/直角矩形面（与场地语言协调）。
- 满阵时整面墙的总亮度必须低于球与挡板，可通过压低砖芯明度、辉光不外扩过大实现。

### 6.4 墙体边界

- 顶、左、右：暗蓝紫的直角窄边，内侧一线极弱的暗青亮缘，暗示"硬且可反弹"。无外辉光、无装饰（不画螺栓、不画砖纹）。
- 球撞墙时，撞点可有一点与球同色的短时微光（墙面被照亮的一瞬），随即暗下——墙本身不发光。

### 6.5 底部死亡线

- 一条细的直角线（或等距短划虚线感），常态呈极暗的红玫色、辉光几乎不可见，**危险但不能抢眼**：对局中玩家余光能意识到"那里是底线"，但视线不会被吸下去。
- 仅在球接近底部时允许辉光轻微增强（实现层可做，视觉上是"被球逼近点亮"）；球越过的瞬间转为一次短促的红线闪灭，随即进入漏接反馈。
- 不使用脉冲红光、不使用锯齿/电流动画常驻。

## 7. 状态变化表现

所有特效遵循同一原则：**对局内反馈极短，结算转场更长更从容**；任何反馈不改变球与挡板的可读轮廓（除挡板击球压缩这一既定动作）。

### 7.1 击碎砖块

- 砖块在撞击当帧熄灭（灭灯），同时：
  1. 一次**短闪光**：砖位置上同色相的亮光快速闪灭（时长为全游戏最短档之一）；
  2. **少量碎光粒子**：圆角小光块/光点，沿反弹方向有轻微抛射，带同色辉光，数量克制（单数块砖的粒子远看是一小簇火花，不是爆炸）；
  3. 撞击点一道半弧光（暖色相，与砖同行的颜色一致）。
- 砖消失后位置只留深色墙面与砖缝，不残留焦痕/空洞贴图。
- 同帧多砖击碎时闪光合并处理，避免满屏白闪；最亮区始终让位于球。

### 7.2 漏接（失落反馈）

- 球越过死亡线：死亡线短闪，球不反弹而是**带着下沉的拖尾被向下"吸走"并快速熄灭**（缩小、辉光由白转冷红、熄灭），像光点掉进暗里。
- 同时全场砖阵与背景做一次**极短、极轻的明度下沉**（像机柜电压一暗），随即恢复。
- 不做爆炸、不做红屏、不做震屏：情绪是"丢了"，不是"被炸了"。

### 7.3 生命减少

- HUD 中一颗生命图标从实心亮形变为暗色空轮廓（形状变化为主），变化瞬间可有一圈短红辉光从该图标位置散开并消失。
- 该反馈与漏接反馈同期结束，时长同属短档。

### 7.4 待发状态（球吸附挡板 + 呼吸提示）

- 球静止贴在挡板上缘正中（或按场景数据的吸附点），随挡板一起移动；球与板之间有一小段共用的青辉光，视觉上"球挂在板上通电"。
- 球与"发球提示"做**缓慢的呼吸**：辉光与提示整体以慢速明暗起伏（呼吸周期明显慢于任何对局特效），传达"准备好了，按下即发"。
- 发球提示文字配一个向上弹起的小球形/空格键形小图形，不只靠文字。
- 发球瞬间：呼吸停止，拖尾首次拉出，挡板一次轻压缩——开局第一下要有"出膛"的脆感。

### 7.5 暂停

- 一层深色半透明压暗层覆盖世界，且世界整体**去饱和**（霓虹褪色但仍隐约可见），模拟机柜进入待机；游戏模拟冻结，粒子与拖尾停在原地。
- 暂停菜单面板为深色半透明底 + 青色亮缘（UI 层），是画面唯一保持饱和与清晰对比的区域，视线自然落到菜单。
- 继续时压暗层撤去、颜色恢复，恢复过程快而干净，不做花哨转场。

### 7.6 胜利（暖色迸发）

- 最后一块砖击碎后，不立即切面板：先有一次**短暂的暖色迸发**——剩余砖位以暖金/琥珀光连锁点亮又散开（可理解为整面墙最后一次通电），粒子为暖色、数量明显多于单次碎砖，明度短暂上扬。
- 之后画面归入一个暖调余韵（深色场被暖光轻微烘染），结算面板在余韵上浮出。
- 胜利是全游戏唯一允许"粒子多、画面暖、时长稍长"的时刻。

### 7.7 失败（冷色收束）

- 最后一条命漏接：球被吸走后，砖阵辉光**自上而下（或整体）冷色收暗**，像机柜一盏盏熄灯；色彩抽离为冷蓝，画面变暗、变静。
- 无迸发、无庆祝粒子；结算面板以冷色基调浮出。失败面板与胜利面板同构（同一套面板语言），仅以冷暖基调与图形（暖金火花 vs 冷暗余灯）区分。

### 7.8 旋转提示页 / 尺寸不足页

- 背景沿用深色场（与标题同源），中心一个**设备旋转图形**：一个直角的横屏框轮廓，内部一枚小球形，配合一道表示旋转的圆弧箭头；图形做缓慢的转动示意呼吸（转动角度小、循环平滑，不真的翻转 90°）。
- 文案："请旋转设备至横屏 / 窗口尺寸不足"，配近白中字。
- 此页不出现砖阵与完整标题字，保持最简，避免玩家误以为游戏已开始；恢复可用横屏空间后提示页淡出、回到标题/原流程。

## 8. 动效性格

### 8.1 整体节奏：快、脆、弹

- **快**：对局内一切反馈都在玩家能感知的最短档结束，绝不拖泥带水；慢的只有待发呼吸与结算转场。
- **脆**：反馈起手极快、收得干净（闪光不拖尾、粒子短命），听觉上也应是"啪"而非"嗡"（音频文档据此对齐）。
- **弹**：挡板的压缩回弹、球反弹的方向改变都带弹性暗示，但弹性只出现在挡板这一处形变上，球与砖不做果冻形变。

### 8.2 时长相对关系（不给毫秒，留给实现与平衡）

从短到长：

1. 碎砖闪光 / 击球光弧（最短）
2. 碎砖粒子 / 击球火花（短）
3. 挡板压缩回弹（短，与击球同期）
4. 漏接反馈 / 生命图标变化（短，略长于碎砖）
5. 待发呼吸一个周期（明显更长，慢速循环）
6. 暂停进入/退出压暗（中短）
7. 胜利迸发 → 面板浮出、失败收束 → 面板浮出（中长，结算转场是对局反馈的数倍时长）

规则：**任何对局内微观反馈不得长于结算转场**；同屏同类元素的特效时长必须统一（所有砖的碎法一致，不随机出长短不一的效果）。

### 8.3 动效约束

- 辉光呼吸只允许出现在：待发球与提示、标题字（极轻微）、旋转提示图形。砖阵与墙体不做呼吸（动的墙会干扰对球的追踪）。
- 不使用屏震（首版无任何强烈冲击事件需要它）；不使用慢动作。
- 循环动效必须严格无缝、相位稳定，避免长时游玩后出现可见跳帧感。

## 9. UI 视觉身份

UI 的空间排布、尺寸、热区、锚点归 UI_UX_SPEC；本节只规定"看起来是谁"。

### 9.1 共享世界的霓虹语言

- **HUD（分数 / 生命 / 最高分）**：像贴在机柜屏幕内侧的发光仪表——文字为近白，标签为灰蓝小字，数值无重投影、无实体面板底（或仅极淡的深色底）；生命图标为与球同形的小光点/心形发光体，失去后变暗空轮廓。HUD 整体明度低于球：扫视时在，盯球时不干扰。
- **菜单按钮**：使用世界的大圆角胶囊/厚牌语言，深色半透明底 + 青色亮缘与外辉；常态亮缘稳定，悬停/焦点时亮缘增亮、辉光增强、内部微微增亮（与砖块悬停同一语法），按下时有一次极短的压缩（复用挡板的弹性语言，但幅度更小）。危险操作（如退出）不强制红色，红色仅用于真正的损失语义。
- **结算面板（关卡完成 / 游戏结束）**：深色半透明圆角面板 + 细霓虹亮缘（胜利用暖金亮缘、失败用冷青/冷蓝亮缘），像机柜的结算灯牌；面板压住特效层但允许边缘有微弱光溢出。两类结算共用同一套面板骨架，只换基调色与顶部图形（暖金迸发光弧 / 冷色收束余灯），降低素材分歧。
- **暂停菜单**：同一面板语言，青色亮缘。
- 所有面板底必须有足够实的深色，保证其上数字在任何粒子/砖阵背景上都清楚。

### 9.2 字体方向

- **显示字体（标题、结算大标题、面板标题）**：几何感、紧凑、带工业/电子气质的无衬线或带方正结构的字体（街机机柜标牌的气质，而非可爱手写体或衬线体）；标题字以霓虹灯管式发光描边呈现。字形要"硬挺、通电、有重量"。
- **正文/标签字体**：清晰的中性无衬线，中文字重常规，用于提示、菜单、说明；不发光或仅极弱辉光，优先阅读性。
- **数字（分数 / 最高分 / 生命计数）**：必须使用**等宽/表格式数字（tabular figures）**，保证计分跳动、位数增长时数字不左右抖动；数字字重高于标签，颜色为近白。得分数变化时允许一次极短的增亮/轻跳反馈，但数字位不位移。
- 字体资产选型与中文覆盖（字重、字符集）由资产计划落地；本文锁定性格与等宽要求。

### 9.3 UI 与世界的边界

- UI 不绘制砖纹、不伪装成"贴在 3D 场景里"的物体；它是机柜屏幕上的发光仪表与灯牌，与世界共享光语言、保持屏幕空间平面性。
- UI 不使用世界中没有的色相（除胜利暖金这一已批准的结算专用色）。

## 10. 一致性验收标准（生成 / 检索 / 程序化素材共用清单）

任何素材或画面交付前，逐条过检；任一不过即返工，不接受"风格差不多"。

**形状与轮廓**

- [ ] 可玩/可交互物全部圆角（大/小两级半径），边界与死亡线为直角细线；无尖角混入。
- [ ] 砖阵外轮廓是整齐的几何矩形，圆角统一，行列不错落。
- [ ] 球为正圆且永不形变；仅挡板有击球压缩。

**辉光语言**

- [ ] 全部采用"实体芯 + 亮缘 + 同色外辉"三层结构；无黑白卡通硬描边。
- [ ] 外辉强度层级符合 2.2：球 > 挡板 > 砖/UI，墙无外辉，死亡线常态近乎无辉光。
- [ ] 每个物体只外溢自身色相，无多色混用；跨层光叠加只变亮、不变脏。

**明度与颜色**

- [ ] 灰度图检验：球是最亮移动物体，挡板其次，砖阵为中等亮度墙，深色占大面积。
- [ ] 背景为深蓝紫而非纯黑；游戏空间与背景明度分明但不跳。
- [ ] 语义色符合 3.3：玩家青、球近白、砖暖、危险红、胜利暖金（仅结算）。
- [ ] 无交通灯式行配色；砖的行间色差只是节奏，不暗示类型/强度差异。

**信息冗余（不只靠颜色）**

- [ ] 生命以实心/空心形状 + 数量表达，失去时形状改变。
- [ ] 高亮/焦点态以辉光与亮缘表达而非换色相；新纪录有文字 + 图标 + 辉光。
- [ ] 各状态页均有文字 + 图形符号双通道。

**可读性**

- [ ] 球贴在任意砖前轮廓零歧义；满砖阵在屏时第一眼是球。
- [ ] 砖面无纹理/文字/图案，表面细节在白名单内。
- [ ] 死亡线危险可辨但不抢眼；砖阵总亮度不超过挡板与球。
- [ ] 结算面板底足够实，数字在任何背景上清晰；数字等宽，计分跳动不抖位。

**层次与适配**

- [ ] 球与挡板永远绘制在砖阵之上；特效在世界之上、UI 面板之下。
- [ ] 背景层、特效层为独立透明层；任意目标宽高比下无白边、构图与明度层级不变。
- [ ] letterbox 区域为背景深色；世界不随宽高比变形。

**动效**

- [ ] 微观反馈（碎砖、火花、压缩）短于结算转场；同类元素时长统一。
- [ ] 呼吸只出现在标题、待发、旋转提示；无常驻脉冲、无屏震、无慢动作。
- [ ] 胜利为暖色迸发、失败为冷色收束，两结算面板同构异调。
