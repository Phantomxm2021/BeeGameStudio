## 3. 挡板反弹角度映射（确切公式）

### 3.1 归一化击球位置

球接触挡板瞬间，取接触点相对挡板中心的水平偏移：

```
u = clamp( (b_x − p_x) / (W_p/2), −1, 1 )
```

其中 b_x 为球中心 x，p_x 为挡板中心 x，W_p=96 为挡板宽。**u=0 为中心，u=+1 为右端，u=−1 为左端。**

### 3.2 线性映射 + GDD 5.3 角度下限（分段线性，确定函数）

主体为线性映射 θ_lin(u) = θ_max·u；为保证水平分量永不为 0（GDD 5.3），在中心附近施加角度下限 θ_min：

```
s(u) = +1, u > 0
       −1, u < 0
       sgn(v_x,in),  u = 0 且 v_x,in ≠ 0     （保留入射水平方向）
       +1,           u = 0 且 v_x,in = 0     （固定 tie-break，向右）

|θ(u)| = θ_max·|u|,  若 θ_max·|u| ≥ θ_min
         θ_min,       若 θ_max·|u| <  θ_min     （即 |u| < θ_min/θ_max = 0.25）

θ(u) = s(u)·|θ(u)|
```

挡板反弹后速度（球向上）：

```
v_x = v·sin θ(u)
v_y = −v·cos θ(u)
```

### 3.3 角度上下限及论证

- **上限 θ_max=60°**：
  - 此时垂直分量 v_y = 360·cos60° = 180 px/秒，仍足以保证球"向上走"而不是擦顶横飞；
  - 一次上行的最大水平位移 Δx = Δy·tan60° = 1.732·Δy，足以覆盖到边角砖（第 6.2 节给出数字）；
  - 超过 60°（如 70°）时垂直分量只剩 123 px/秒、反应区穿越时间升至 134/123≈1.09 秒但球路近水平，砖阵内会长程横滑、瞄准的"中心近垂直"手感被压缩——上限取 60° 是可控性与可达性的折中，而非更陡更好。
- **下限 θ_min=15°**：对应 |v_x|_min = 360·sin15° ≈ 93.2 px/秒。即便球落在 u=0 的中心区，球也必然带着水平分量离开，满足 GDD 5.3；最坏情形纯走廊横穿 800px 需 800/93.2 ≈ 8.6 秒必碰侧墙，实战中砖阵更早截断，不可能无限垂直往返。
- 中心区（|u|<0.25）角度恒定为 15°：这是 GDD"水平分量不得为 0"与"中心近垂直"两条规则共同允许的唯一形态——近垂直（15°）但非纯垂直。

## 4. 死亡线判定规则

**采用"球整体越过"：当球的顶边越过死亡线，即 ball center y − r ≥ 480，等价于 ball center y ≥ 485 时，判定漏接。**

- GDD 5.1 允许在"整体越过"与"触及"之间由本文定义；取"整体越过"给出最大接球窗口，规则对玩家更宽容且表述无歧义。
- 判定以固定步结算末尾的连续（swept）检查为准，规则本身与帧率无关；球中心 y=485 这一阈值直接可用，不设额外像素容差。
- 几何上挡板下缘 y=448，球一旦整体越过 y=480，物理上早已无接球可能（球顶低于挡板下缘后不存在可碰撞姿态），故该阈值不改变任何"可救/不可救"的实质判定，只统一事件发生时刻。

## 5. 随时间加速：决策（关闭 GDD 未决项）

**首版不加速。球速在整局中恒定为 v=360 px/秒，与游戏时间、击球次数、剩余砖数均无关。`acceleration.enabled=false`。**

理由：

1. 首版只有一关、60 块砖，一局时间量级约 1–2 分钟（第 6.4 节），不存在长局后期需要提速提张力的问题；
2. 恒定速率下难度完全由球路角度与玩家自身发挥构成，挑战来源与 GDD 2.2 一致，规则最简单、最可重复；
3. 加速的唯一收益（末期张力）在单关短局中收益微弱，却会让"快而可控"的手感在玩家适应后被抽走，风险大于收益。

若未来 playtest 证明需要末期张力，允许在第 7 节的调音假设表中启用极温和加速；**首版发布配置不含加速，本条即为对 GDD 第 10 节"是否采用随时间缓慢加速"的关闭决定。**

## 6. 关键选择的场景论证（上游事实 → 情形 → 计算 → 结论）

### 6.1 反应时间：最斜角穿越反应区 vs 键盘横移到位

**情形 A（球纵向穿越时间）**：球以最大斜角 θ=60° 下落穿过 134px 反应区。

- 垂直分量 v_y = 360·cos60° = 180 px/秒；
- 按边缘口径（砖阵下沿 y298 → 挡板上缘 y432）：t = 134/180 = **0.744 秒**（弧长口径：路径 134/cos60°=268px，268/360=0.744 秒，一致）；
- 更严格的球心口径（球心离开砖阵 y303 → 球心接触挡板 y427，竖向 124px）：t = 124/180 = **0.689 秒**；
- 对照：θ=15° 时 t=134/(360·cos15°)=134/347.7=0.385 秒；纯垂直 134/360=0.372 秒。

**情形 B（挡板横移时间）**：球落向最侧边（接球点需挡板中心到极限 x=832，球心近 x=875），挡板从居中初始位 x=480 出发。

- 距离 = 832−480 = 352px；键盘速率 v_p=600 px/秒；
- t_p = 352/600 = **0.587 秒**。

**结论**：最坏情形下，键盘横移所需 0.587 秒 < 球穿越可用的 0.689 秒（严格球心口径）/ 0.744 秒（边缘口径），**几何上键盘玩家来得及，余量约 0.10–0.16 秒**。且实战中玩家在球尚在砖阵内时已开始预判移动，真实余量更大；鼠标/触控为直接跟随，挡板到位只受人的反应延迟（约 0.2–0.25 秒）约束，远小于 0.69 秒。注意：0.10 秒的理论余量偏薄，"键盘 600 px/秒 + 球速 360 的组合在最差情形确实舒服"属于必须 playtest 的手感假设（第 8 节）。

### 6.2 边角砖可达性：θ_max=60° 一次上行

**情形**：最上排边角砖 r1c1（中心 (120,116)），自挡板击球上缘一次上行，竖直行程取 Δy ≈ 316px（球心 y427 → 砖体高度 y≈111；与任务给定的约 316 一致）。

- θ=60° 时单位竖直行程的水平位移：Δx/Δy = tan60° = 1.732；
- 一次上行最大水平位移：Δx_max = 316×1.732 = **547px**；
- 从中路发球点击球（p_x=480，接触点 x≈480）到砖中心 x=120，需要 Δx=360px，对应角度 θ_req = arctan(360/316) = arctan(1.139) = **48.7° < 60°**；
- 更宽松的路径：挡板可直接移动到 x=128（左极限）位于第 1 列正下方，以近垂直小角度直达（LEVEL_SCENE_DESIGN 4.2 已论证每列砖都有竖直/近竖直路径）。

**结论**：**最上排边角砖可在一次上行中到达**（中路起步需约 49°，小于 60° 上限；板到列下方时近垂直即可）。若球路、板位极端不利，备援路径为：球以斜角碰侧墙后 v_x 翻转，经砖阵上方 24px 走廊（y80–104）进入边角砖的上方/侧面（LEVEL_SCENE_DESIGN 4.2 第 2 条）。几何层面无死砖；"在合理击球次数内击中边角砖"属运行时观察项，不由几何论证替代。

### 6.3 发球安全性：不会近水平长漂

**情形**：发球角度 |α_serve| 被限制在 [20°,40°]，球从待发位 (480,427) 发出。

- 最差为 40°：垂直分量 = 360·cos40° = 275.8 px/秒；
- 到达砖阵下沿（球心 y427 → y303，竖向约 124px；边缘口径 129px 取 129）：t = 129/275.8 = **0.47 秒**即进入砖阵；
- 同期水平位移 = 360·sin40°×0.468 = 231.4×0.468 = **108px**，即球在 x≈372–588 内接触第 6 排砖；第 6 排砖横向铺满 x84–876、砖缝 8 < 球径 10，球不可能恰好穿过缝隙而不碰砖。

**结论**：角度下限 20°（离竖直）/ 上限 40°（离水平 50°）保证球最迟 0.47 秒、横向漂移不超过约 108px 即撞砖，**不会出现近水平发球导致长时间不碰砖的情形**。"固定标称 30° + ±10° 受限随机"兼顾每局变化与安全。

### 6.4 单局节奏：量级估算（非验证结果）

以反应区往返估算平均击球间隔：典型球路取 θ≈30°–45°，垂直分量约 360·cos35°≈295 px/秒；一次"挡板→砖阵→挡板"的反应区往返约 2×124/295 ≈ 0.84 秒，加上砖阵内短程反弹耗时，**估计平均每次接球间隔约 0.9–1.2 秒**。60 块砖中，球一次上行常可击碎 1–2 块（末排阶段约为 1 块），估计需要约 40–70 次接球循环，即活跃游玩约 **40–80 秒，含发球、漏接复位后单局时间量级约 1–2 分钟**。

**这是基于几何与发布速度的估算，不是运行时验证结果**；实际时长取决于玩家水平、多砖连碎频率与漏接次数。

## 9. 数值风险：计算支持的结论 vs 必须 playtest 的假设

### 9.1 有计算支持的结论（几何 + 发布值直接推出）

1. 最坏情形（θ=60°）反应区穿越 0.69–0.74 秒，键盘横移 0.59 秒，理论上来得及；
2. 最上排边角砖一次上行可达：中路起步需 48.7° < 60°，单弧最大水平位移 547px；
3. 发球最迟 0.47 秒、横移 ≤108px 即碰砖，不存在近水平长漂；
4. 水平分量下限 |v_x|≥93.2 px/秒，最坏约 8.6 秒必碰侧墙，GDD 5.3 的卡死情形在数值上不成立；
5. 满分 6000、分数为 100 整数倍、生命 3 条，全部可精确观测。

### 9.2 必须 playtest 才能确认的手感假设（本文不预支结论）

1. **360 px/秒是否"快而可控"**：计算只证明不是不可能，"舒适/紧张"的手感无法离线判定；
2. 键盘最差情形理论余量仅约 0.10 秒，实战是否从容、600 px/秒的挡板是否过快导致对位粗糙，需 playtest；
3. θ_max=60° 边缘击打是否"公平可读"、θ_min=15° 中心区出角是否被玩家正确感知；
4. 发球 50% 随机侧向 + ±10° 抖动是否被感知为公平而非"发坏球"；
5. 1–2 分钟的单局量级与第 6.4 节实际时长是否吻合；
6. 边角砖虽几何可达，"合理击球次数内击中"仍需运行时观察（LEVEL_SCENE_DESIGN 4.3 同样保留此项）。

以上任何一项被 playtest 推翻，按第 8 节区间调音并复算；若调音区间不足以解决（如需新增系统或改 GDD 规则），按 GDD 第 9 节流程反向修订，**本文不得为凑数字自行改变规则**。

## 10. 工程投影：config/tuning.json

- 依据 TECHNICAL_DESIGN 第 6 节，`config/tuning.json` 是本文数值的**唯一机器可读投影**：文件内容应由本文第 2 节发布值直接生成（或手工保持逐项一致），**不得在代码、场景数据或其他文件中出现第二份副本**。
- 本文参数与 JSON 键名一一对应（键名见第 2 节括号）；几何量（场地、砖位、挡板/球尺寸）不属于本文，仍以 Scene JSON 为权威，tuning.json 不复制几何。
- 角度在 JSON 中以度表达（实现侧换算弧度）；速率均为每秒逻辑像素；加载失败或字段缺失时按 TECHNICAL_DESIGN 启动期报错，不以代码默认值兜底。
- 本文只规定数值与一致性要求，**不规定加载、注入与碰撞算法**。
