## 2. 挡板反弹角度模型（核心技巧公式）

令球与挡板碰撞时，命中点相对挡板中心的偏移为 `d`（像素，向左为负），挡板半宽 `W = 40`：

```
t = clamp(d / W, -1, 1)          # -1 最左缘，+1 最右缘，0 中心
θ_raw = θ_max × |t|             # θ_max = 60°
θ = max(θ_raw, θ_floor)         # θ_floor = 10°，避免近垂直死循环
dir = sign(t) 若 t ≠ 0，否则 = sign(vx_in)   # 中心时沿入射水平方向
vx = v × sin(θ) × dir
vy = -v × cos(θ)                # 恒为向上（挡板只向上反弹）
v = 320（速率不变）
```

**边界口径**：
- 若 t=0 且球为严格垂直入射（`sign(vx_in)=0`）：dir 取发球时的初始水平方向（首版发球向右），保证中心接球**永不产生 0 水平速度的纯垂直球**，始终保留至少 sin10°≈56 px/s 的水平分量。
- 非中心（t≠0）一律以命中位置定方向，即使与入射方向相反也照常（玩家主动选择的反转）。

**设计意图**：中心接球接近垂直（最低 10°），边缘接球给出最大 60° 的横向飞行，让"选接球点"成为可表达的技巧；60° 上限杜绝近水平死循环（60° 时垂直分量仍有 160 px/s），中心口径杜绝纯垂直死循环。t=0 时方向不做随机翻转，沿入射方向，避免不可预期的"中心反转"。

## 3. 碰撞时序口径（与 GDD §5 一致的数值化补充）

- 球触碰死亡边界：以球边缘到达 y=672 为准（球心 y ≥ 665）。
- 球与挡板：球边缘进入挡板碰撞盒（80×14，顶面 y=620）即判定；只对**向下运动**的球生效，向上运动穿过挡板高度区不反弹（物理上不会发生，属防护口径）。
- 砖块碰撞：球边缘与砖块盒相交即销毁该砖、计分、按碰撞面反弹；同一步触及多块时规则按 GDD §5.3，反弹只发生一次。
- 墙：球边缘到达即反弹。

## 4. 可复现情境推导

### 4.1 防穿透核算（60 fps 基准）

- 事实：球速 320 px/s；标准帧步长 = 320/60 ≈ **5.33 px**。
- 最薄玩法对象：挡板高 14、砖厚 20、球径 14。
- 结论：5.33 < 14，单步不可能整体跨过挡板或砖块，配合连续（扫描式）碰撞检测即可保证不穿透。
- 边界情形：
  - 120 fps 高刷屏：步长 2.67 px，更安全。
  - 30 fps 掉帧：步长 10.67 px < 14，仍不穿透。
  - **20 fps 严重卡顿**：步长 16 px > 挡板高 14，存在穿过挡板的风险 → 技术设计须采用扫描式碰撞（按步长路径求交）或对单帧步长钳制；这是明确的实现约束与验收风险点，不通过提高球速之外的方式"将就"。

### 4.2 反应时间核算

- 事实：挡板顶面 y=620，砖墙底边初始 y=180，距离 440 px。
- 情境：球以 θ=40° 从砖墙区域下行，垂直分量 vy = 320×cos40° ≈ 245 px/s。
- 计算：回落时间 ≈ 440/245 ≈ **1.8 s**；θ=25° 时 vy≈290，约 1.5 s；θ=60° 时 vy=160，约 2.75 s。
- 支持的决策：正常角度下玩家始终有 1.5–2.7 s 读取轨迹并移动挡板；挡板横移全速 420 px/s，从中心到任一边界（200 px）约 0.48 s，远小于最快回球时间，**追球在物理上可达**，失误只来自判断而非追不上。

### 4.3 容错核算（生命与目标）

- 玩家有 3 条命，即允许 2 次失误后仍能完赛（第 3 次失误判负）。
- 失球不清空进度：最坏情况下玩家以"每次失球只推进若干砖"的节奏也能缓慢通关，不存在失误导致关卡不可完成的情况。

### 4.4 单局时长（推算假设，非验证结论）

- 假设：平均每次"球上行"击碎 1.5 块砖（待实测的经验假设）。
- 推导：40/1.5 ≈ 27 次上行；每次上下往返按平均垂直速率约 245 px/s、往返距离约 880 px 计 ≈ 3.6 s → 击球时间 ≈ 97 s；加上最多 3 次失球复位与发球停顿，估计单局 **约 80–130 s**。
- 该数字仅用于判断"小而完整"的体量是否合适，**未经过任何实测或模拟，属待试玩验证的假设**。

## 5. 数值风险清单

| 风险 | 类型 | 处置 |
|---|---|---|
| 低帧率（≤20 fps）穿透挡板 | 已识别的实现风险 | 扫描式碰撞/步长钳制（技术设计），实现后实测 |
| 实际球感过快或过慢 | 调优假设 | 发布值 320 居中，预留 280–360 区间，试玩后定 |
| 近垂直往返球难以打破 | 已缓解（θ_floor=10° + t=0 沿用方向） | 试玩观察是否仍出现长时间垂直往返 |
| 砖块清空后大面积空洞导致球频繁直上直下 | 调优假设 | 首发固定倾角 + 角度模型可缓解；若实测沉闷，优先微调 θ_floor/发球角，不新增道具或系统 |
| 单局时长假设偏差 | 未验证假设 | 试玩测量，不预先改设计 |

**已支持的结论**：60/30/120 fps 下发布球速不穿透；挡板追球可达；3 条命下关卡始终可完成。
**待试玩假设**：球速手感、单局时长、空洞期趣味性。

## 6. 调值数据归属

- 本表数值在实现时集中写入**一个项目自有调值 JSON**（由运行时加载，符合 content-format 对项目调值文件的约定），Scene JSON 只持有布局/尺寸等作者化几何与资源绑定，不在多处复制同一数值。
- 修改发布值须同步更新本表版本记录；可选区间不是运行时随机化的授权。
