## 1. 目的与范围

本文把 GDD 的完整状态流落成**可实施的界面与交互规格**：覆盖开始、加载、游玩（HUD）、暂停、胜利、失败、错误恢复共 **7 类玩家可见视图**；规定每个视图的进入/退出条件、元素与信息层级、内容来源、动作与结果、控件状态、空间分配、适配行为、焦点导航与反馈时序。

不做的事：不重复 GDD 规则与数值表；不规定资产生产路径（归 ASSET_PLAN）；不定义相机取景（归 LEVEL_SCENE_DESIGN）；不新增任何 GDD §1.2 排除的界面（无关卡选择、无排行榜、无设置菜单——**静音是唯一设置项**）。

全部界面来自**作者化 UI JSON**（Scene/UI JSON 为唯一可编辑源），运行时加载并解析，代码常量不取代本文决策。

## 2. 全局设计约定

### 2.1 坐标系与单位

- 屏幕 UI：**原点左上，+X 向右，+Y 向下**，单位为**逻辑像素**；与场景维度无关。
- 根节点 `data.referenceResolution = [480, 672]`：设计参考，不是固定宿主窗口；屏幕根在**实际视口**解析。
- 根节点 `data.compactMaxWidth = 600`。
- 锚点/枢轴均为 `[x, y]`，`[0,0]` 左上、`[1,1]` 右下；`layout.position` 是相对锚点的父级局部偏移；子节点枢轴默认与锚点相同（不隐式 `[0,0]`）。
- 拉伸节点成对提供 `anchorMin/anchorMax + sizeDelta`，解析尺寸 = 父尺寸 × (anchorMax−anchorMin) + sizeDelta。
- 本文只给**相对关系与约束**，最终矩形由容器布局从子项约束（size/minSize、gap、padding）推导，不维护手写坐标表。

### 2.2 支持的宿主范围（本规格新增并锁定）

| 用途 | 宿主尺寸（CSS 逻辑像素） | 形态 |
|---|---|---|
| 桌面参考 | 960 × 540 | 横屏，键盘/鼠标 |
| 手机参考 | 390 × 844 | 竖屏，触屏 |
| **最小支持容器** | **320 × 480** | 下限；小于此尺寸不承诺 |

**输入能力与视口形态是两个独立事实**：横屏也可能触屏、竖屏也可能接键盘；界面按「容器尺寸/宽高比」选布局，按「输入能力」选交互反馈，二者不绑定。

### 2.3 屏幕空间总分配（UI 拥有的分区）

全屏宿主分三类区域：

| 区域 | 分配 | 行为 |
|---|---|---|
| `game-view`（游戏视图） | 锚定根：anchorMin `[0.02,0.02]`，anchorMax `[0.98,0.98]`，sizeDelta `[0,0]` | **随容器拉伸**；内部相机以 letterbox 呈现 480×672 世界（LEVEL §2 权威），世界布局永不被裁剪 |
| letterbox 留边（game-view 内相机留边） | 明度 ≤ L1 的纯净暗区 | **固定不可放元素**：无玩法信息、无发光、无动画（ART §4.4） |
| 覆盖层（dim/面板） | 仅暂停、结算、错误、失焦冻结时出现 | 覆盖全屏；此时模拟已停止，不构成玩法遮挡（GDD §4、LEVEL §2.2） |

### 2.4 两类界面承载方式（关键架构决策）

1. **相机参考平面承载（camera-reference-2d）**：开始界面、HUD、发球提示。
   实现为 game-view 下直接子容器：`data.space = "camera-reference-2d"`，`layout.size = [480,672]`，`layout.item.absolute = true`；子项用 480×672 参考平面内的普通局部布局，由连接相机的计算器投影到宿主。这样元素**始终落在世界柱内、永不落入 letterbox 留边**，桌面与手机下都自动对齐场地（桌面 960×540 下世界柱宽约 370、居中）。
2. **屏幕空间覆盖承载**：暂停、结算、错误恢复。
   全屏暗压 + 居中固定宽度面板（见 §4.2）。面板在 960×540 下居中即落在世界柱上方（柱宽 370 > 面板宽 300），在 320×480 最小容器下仍保留 ≥10px 两侧边距。

### 2.5 适配行为与布局选择

- 在 320×480 至 960×540 全范围内，**不切换布局、不重排**：参考平面内容经投影随世界柱缩放，覆盖层面板固定尺寸居中。计算器在 960×540、390×844、320×480、600×700、540×540 五尺寸确认该单一组态成立（§8）。
- 空间不足时的既定行为（唯一解，不留备选给实现者）：
  - 世界方向：letterbox 留边，绝不缩放或裁剪玩法；
  - 面板方向：面板固定最小尺寸；若容器高度低于面板高度（仅可能在 <480 高时，超出支持范围），面板内容区内部滚动——此为运行时唯一允许的滚动，不缩小控件、不裁剪文字。
- 控件尺寸不随容器缩小：按钮命中高度固定 44–48（见 §3），保证触屏可用；可读性靠固定最小字号，不靠等比缩没。
- compact（宽 ≤ 600）/ portrait（高>宽，compact 之后覆盖）变体字段**本轮全部留空**：当前单一组态已满足全部支持尺寸，不编写无行为差异的变体数据。若评审要求在小尺寸改变构图（如 HUD 移位），须同时修订本文与 UI JSON。

### 2.6 层级与绘制顺序

- 绘制顺序遵循 content-format：每节点先背景/边框 → 自身内容（文本/图像/控件）→ 子节点（文档顺序），后绘者覆盖；背景不得后置于内容之上。
- 屏幕空间堆叠（z 序，自下而上）：世界 Canvas → 相机参考平面 UI（开始/HUD/提示）→ 暗压 dim → 面板及其子项 → toast（首版无）。

## 3. 共享组件（定义一次，全局复用）

所有组件为运行时以 DOM/CSS + Canvas 程序化表达（ASSET_PLAN §1：不为按钮/面板烘焙贴图）。视觉语言服从 ART_DIRECTION §3（圆角三档、深色压边描边、受控辉光）。

| 组件 | 规格 | 状态 |
|---|---|---|
| **PrimaryButton**（主行动按钮） | 高 48，宽度按场景（200 或 252）；中档圆角；文字 18px 居中；底色 cyan 主调 + 轻辉光（≤砖块同级） | default；hover/悬停（指针设备）：辉光增强一档；selected/键盘焦点：外描边焦点框（2px，暖白偏移）；pressed：明度下压 + 快速回弹；disabled：明度降至 35%、无辉光、不响应 |
| **SecondaryButton**（次行动按钮） | 高 44，宽 252；透明底 + 1×U 深色系描边，文字 16px | 状态同上，辉光更弱 |
| **静音 Toggle** | 高 40–44；文案「静音」；中档圆角 | default（未选）；selected（静音中）：底色 cyan 填充、文案「已静音」；焦点/禁用同上。**仅内存状态**，刷新重置（GDD §7、TECH §7.5） |
| **面板卡片 Panel** | 宽 300；大档圆角；深色填充（L1–L2 之间）、1.5×U 细外框、柔和投影；本体不发光或仅极轻辉光 | 出现即带 150ms 淡入；reduced motion 下立即显示 |
| **暗压层 Dim** | anchorMin `[0,0]`–anchorMax `[1,1]`；纯色 `#05030f`，opacity 0.72（暂停/结算） | 200ms 淡入；reduced motion 下立即显示 |
| **文本样式** | 标题：几何/电子感无衬线，允许描边+辉光；正文/HUD：中性无衬线纯色（小字不加辉光）；数字：近等宽，跳动不抖动 | 最小字号：正文/提示 14（参考平面坐标，投影后手机上约 11 CSS 像素——可读性待实测，§9） |
| **生命图标** | atlas 帧 `icon-life`，20×20（参考平面） | 存活：彩色 + 轻辉光；失去：即时变暗 + 一次消退动效（200ms） |

## 4. 共享页面布局

### 4.1 相机参考平面布局（开始界面使用，HUD 为其局部元素）

- 平面：480×672，内部为纵向 column 容器，padding `[88,32,56,32]`，gap 20，`justify: center`、`align: center`。
- 子项排列（自上而下，均水平居中）：标题（280×56）→ 砖墙母题容器（grid 8 列）→ 主行动按钮（200×48）→ 操作说明文本（320×20）。
- 各子项固定尺寸，不拉伸、不收缩；容器从子项+gap+padding 推导总高，内容垂直居中分布。
- HUD 是同一参考平面上的**锚定覆盖元素**（全部 `item.absolute: true`），不参与 column 流，因此开始界面与游戏界面可复用同一平面约定。

### 4.2 全屏覆盖布局（暂停 / 结算 / 错误共用）

- 区域分配：dim 铺满根（拉伸）；面板锚 `middle-center`，position `[0,0]`，枢轴默认 middle-center，固定宽 300。
- 面板内部：column 容器，padding `[24,24,24,24]`，gap 14，`align: center`；子项宽度均为 252（= 300−24×2），固定高度，不拉伸。
- 面板高度由内容确定（各屏差异，§6）；空间不足时唯一降级为内容区滚动（§2.5）。
- 三个屏幕只替换子项内容与标题气质，**几何关系完全一致**，故共用同一份布局草稿（§8）。

## 5. 屏幕逐一规格

### 5.1 加载视图（Loading）

- **进入**：Bootstrap 启动、首屏数据（index/开始界面 UI/场景 JSON/字体）未就绪。
- **退出**：startup 文档与首帧资源就绪 → 开始界面；任一致命失败 → 错误视图。
- **元素/层级**：居中 column 组（160×88，middle-center）：旋转指示环（40×40 圆形 shape，cyan，匀速旋转）→ 文本「加载中…」（14px）。无世界模拟、无装饰。
- **动作**：无（不可取消；首版无取消按钮）。
- **状态**：默认持续；加载超过 8s 无响应仍保持本视图（fetch 超时/失败由加载器转入错误视图）。

### 5.2 开始界面（Start）

- **进入**：应用启动完成（GDD 初始相位），或从暂停/结算退出（T8/T10）。
- **退出**：「开始游戏」→ T1 装载关卡进入待发球。
- **元素、层级与内容来源**（参考平面内，自上而下）：
  1. 标题「打砖块」（280×56，44px，标题字 + cyan 系描边辉光）——**第一视觉焦点**，灰度下跳出砖墙；
  2. 砖墙母题：`hero-wall` 容器（grid 8 列、gap 2），40 个 `brick` 帧（34×13）运行时排布成一面缩小砖墙——第二视觉，暗示目标；入场时逐块点亮（一次性，约 800ms，首块在面板出现后 150ms 开始）；
  3. PrimaryButton「开始游戏」（200×48）——**主行动**；
  4. 说明文本「移动挡板反弹小球，击碎全部砖块」（14px）——次级信息；
  5. 右上角静音 Toggle（锚 top-right，position `[−12,12]`，64×40，absolute）——三级信息，不与标题争亮。
- **构图（ART 转译）**：暗场三层明度（暗底/砖墙砖/标题），大面积负空间托起标题；主按钮位于视觉中线下，拇指/光标自然落点；无装饰堆砌。
- **动作与结果**：激活开始按钮（点击/Space/Enter）→ 发 START 指令，同时播放 UI 确认反馈，进入待发球。
- **状态**：开始按钮 default/focused/pressed；静音 default/selected；无 disabled。

### 5.3 游戏 HUD 与发球提示（Gameplay）

- **进入**：T1（新局）或 T3（失球复位）；HUD 在待发球与球运动中两相位持续显示。
- **退出**：T4/T5 进入结算（HUD 被结算覆盖层取代），或 T6 暂停（HUD 仍在但被暗压压暗）。
- **元素（全部在相机参考平面，absolute 锚定）**：

| 元素 | 锚点/位置 | 尺寸 | 内容来源 |
|---|---|---|---|
| 分数 `hud-score` | top-left，position `[12,14]` | 96×28，22px 近等宽数字，4 位补零「0000」 | GameStore 分数（每砖 +100） |
| 暂停按钮 `pause-btn` | top-center，position `[0,1]` | 62×62，文字「暂停」 | PAUSE_TOGGLE 指令 |
| 生命 `hud-lives` | top-right，position `[−12,14]` | 88×28，row、gap 8、尾对齐，3 个 `icon-life`（20×20） | GameStore 生命数 |
| 发球提示 `serve-prompt` | top-center，position `[0,548]` | 240×24，16px「按 空格 / 点击 发球」 | 仅待发球相位启用 |

- **信息层级**：球运动中 HUD 整体退后（明度压不过球/挡板）；玩家余光读分数与生命即可。
- **覆盖安全（与 LEVEL §2.2 对齐）**：HUD 元素全部位于世界 y ≤ 60，不侵入砖墙体（y≥64）；发球提示位于 y548–572（挡板顶面 y620 之上约 48px），球静止贴附时不构成遮挡，**发球后立即隐藏**；球运动中机动空间无任何 UI。
- **动作与结果**：暂停按钮 → T6；发球提示纯展示，发球由键盘/点击/触屏在任意位置触发（T2，边沿一次）。
- **状态**：分数变化即时刷新并跳字（强调色，150ms）；生命图标失去即变暗消退；暂停按钮 default/pressed；无 disabled。

### 5.4 暂停覆盖层（Pause）

- **进入**：T6——Esc/P 或暂停按钮；页面失焦自动暂停（TECH §4.5，`pausedReason=auto`）。
- **退出**：「继续」/暂停操作 → T7 回原相位；「退出本局」→ T8 回开始界面。
- **元素（面板 300×264，按内容推导高）**：标题「已暂停」（28px，无辉光）→ PrimaryButton「继续」252×48（**主行动**，进入时默认焦点）→ 静音 Toggle 252×44 → SecondaryButton「退出本局」252×44。
- **观感**：dim 200ms 淡入；冻结世界的辉光视觉降温、动效全停；进入/退出快速安静，无庆祝光效（ART §5.4）。
- **状态**：自动暂停与手动暂停外观一致；暂停期间一切输入移动/发球忽略；暂停切换指令幂等（重复切换不发声、无副作用）。

### 5.5 胜利结算（Win）

- **进入**：T4——最后砖块销毁、场上砖块为 0（同帧优先于漏接，GDD §5.4）。
- **退出**：「再来一局」→ T9；「退出」→ T10。
- **元素（面板 300×292）**：标题「通关成功」（28px，**暖色强调 + 辉光**，全场情绪高点）→ 标签「最终得分」（13px）→ 最终分数字（32px，L5，从 0 滚动结算到实际值，约 700ms）→ PrimaryButton「再来一局」252×48（主行动，默认焦点）→ SecondaryButton「退出」252×44。
- **背景配合**：最后一砖光爆后砖墙位置余韵光，画面短时提亮转暖再回落（ART §5.5）；特效压低不透明度、不遮面板。
- **状态**：结算出现后场地移动/发球输入一律忽略；分数结算动画期间按钮已可响应。

### 5.6 失败结算（Lose）

- **进入**：T5——扣命后生命为 0。
- **退出**：同胜利（T9/T10）。
- **元素与差异**：与胜利**几何完全相同、共用一份布局草稿**；差异为：标题文案「挑战失败」、使用冷色无辉光（明度低于胜利标题）；最终分仍以 L5 清晰展示；无暖色背景光。
- **背景配合**：失球点光效向下/向心收束、全场短促压暗（红橙仅失球点短暂出现，不铺屏），随后归于平静（ART §5.6）；不羞辱、主行动仍是「再来一局」（默认焦点），视觉鼓励立即重试。

### 5.7 错误与恢复视图（Error）

- **进入**：启动期 index/UI/场景/调值 JSON 拉取或解析失败；首帧必需图片解码失败。
- **退出**：「重试」→ 重新执行失败的装载步骤；成功 → 回到加载视图再进入开始界面。
- **元素（面板 300×196）**：标题「加载失败」（24px）→ 错误信息文本（252×40，14px、行高 20、居中、可换两行：「游戏数据读取失败，请检查网络后重试。」）→ PrimaryButton「重试」252×48（默认焦点）。
- **运行期失败的差异**：游玩中按需文档拉取失败时，**停留在当前安全相位**，错误面板以覆盖层形式出现且不启用 dim 之外的退出路径；不用内置默认布局顶替（TECH §7.2）。
- **状态**：重试中按钮显示 pressed 并短暂禁用（防止重复提交）；再次失败仍回本视图。

## 6. 输入、焦点与导航

| 输入 | 行为 |
|---|---|
| 键盘 | 移动：← → / A、D 按住（420 px/s）；发球：Space（边沿一次）；暂停：Esc/P；菜单导航：Tab/方向键在控件间移动焦点，Enter/Space 激活；开始界面 Enter/Space 直接开始 |
| 鼠标 | 水平移动映射挡板（指针直接映射、无速度上限，TECH §6.4 反算）；点击 = 发球（待发球时）/激活控件；悬停显示 hover 态 |
| 触屏 | 按住拖拽：挡板指针映射（`touch-action: none`，阻止滚动/缩放）；点按 = 发球/激活；命中区 ≥ 44 高（暂停按钮的最小容器例外见 §9.2） |

- 焦点规则：每个覆盖层/菜单出现时焦点落在其**主行动按钮**（暂停=继续、结算=再来一局、错误=重试、开始=开始游戏）；Tab 在面板内控件间环形移动；Esc 在暂停层 = 继续，在结算层无关闭动作（必须二选一，不提供隐式退出）。
- 焦点视觉：2px 暖白偏移焦点框，移动时播放 UI focus 反馈；鼠标点击后焦点框可隐藏直到下次键盘导航。
- 未新增任何手柄/平台输入（GDD 范围外）。

## 7. 反馈与动效时序

反馈服务于「确认状态/引导下一动作」，动画均为表现、不延迟规则判定（GDD §5.6）。关键项：

| 反馈 | 目的 | 触发 | 外观/时序 |
|---|---|---|---|
| 砖墙逐块点亮 | 建立母题与期待 | 开始界面入场 | 40 砖依次，约 800ms 完成 |
| 发球提示呼吸 | 教学、引导发球 | 进入待发球 | 明度呼吸周期 1.6s；发球瞬间隐藏（≤100ms） |
| 分数跳字 | 确认得分 | 砖块销毁当步 | 数字即时更新 + 强调色一跳，150ms 回落 |
| 生命消退 | 确认生命减少 | 扣命当步 | 图标变暗/破碎，200ms |
| 失球收束 | 表达失误但进度保留 | T3/T5 当步 | 向下收束光 + 短促暗压，≤450ms；砖块与分数视觉不变 |
| 暂停开合 | 状态切换确认 | T6/T7 | dim 200ms 淡入/淡出；安静、无庆祝光效 |
| 胜利/失败 | 终局情绪 | T4/T5 | 见 §5.5/§5.6；胜负乐句期间面板已可操作 |
| 结算分滚动 | 最终得分确认 | 结算面板出现 | 700ms 滚动；reduced motion 下直接显示终值 |

**Reduced motion**（`prefers-reduced-motion: reduce`）：所有位移/循环动效退化为即时淡变或常亮：取消逐块点亮（直接全亮）、取消呼吸（提示常亮）、取消分滚动（直接终值）、面板/dim 即时显示；反馈信息不丢失。所有闪屏至多一次、不全白（ART §6）。
