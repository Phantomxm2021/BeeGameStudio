## 1. 文档目的与边界

本文是唯一固定关卡（GDD §1.1：单屏、一个砖阵关卡、普通砖+加固砖、单球单挡板）的**空间设计依据**，覆盖：世界坐标尺度、空间骨架、砖阵完整排布、挡板/球初始位姿、胜负条件的空间判定位置、取景与宽高比策略、最小可用尺寸建议。

边界：

- 玩法规则（反弹裁决、生命/计分、状态流转等）引用 GDD §3–§7，**不复制、不改写**。
- 具体调参（球速、挡板速度、发球角度终值、分值、生命数）以待写的 **Balance 文档**为权威；本文几何数值为空间占位提案，与 Balance 协调后定稿。
- HUD/覆盖层的精确矩形、响应式变体以待写的 **UI_UX_SPEC** 为权威；本文只提出可见性要求与允许覆盖区域。
- 不新增砖块类型、关卡、道具（GDD §1.2）。本文是设计依据，**不是最终 Scene JSON**；正式作者化场景将按 content-format 的 sceneDocument 落入 `content/scenes/`，本文件的几何与网格须被如实承载。

## 2. 世界坐标系与尺度

### 2.1 场地设计坐标

| 项 | 取值 |
|---|---|
| 参考帧尺寸 width × height | **1920 × 1080 逻辑像素（logical pixels）** |
| 原点 | **左上**；+X 向右，+Y 向下 |
| pixelsPerUnit | **100**（逻辑像素 → 世界单位换算，仅相机/引擎单位用，不得对作者位置重复乘算） |
| 角度 | 弧度；2D 平面正角为顺时针；发球方向用设计坐标向量描述 |

### 2.2 世界范围 vs 显示范围

- **世界范围（作者参考帧）**：1920×1080 的逻辑空间，砖阵、墙体、挡板、球的全部作者坐标都在此帧内定义。它是**参考帧，不是宿主像素，也不是浏览器/画布尺寸**（Tech §4.2）。
- **显示范围（运行时）**：实际容器（host）像素尺寸任意。场地经**等比 contain / letterbox 映射**呈现（Tech §4.3）：缩放系数 `s = min(viewportW/1920, viewportH/1080)`，场地在容器内居中，不足方向的留边由背景层填充。映射只改呈现，不改写任何 Transform、不重排砖阵、不改碰撞体积。
- 玩法刚性边界（左右墙、顶墙碰撞面与漏球底线）由场景中墙体/线节点的 Transform 承载，**数值上恰好落在参考帧边缘**（X=0、X=1920、Y=0、Y=1080）；"参考帧边缘"与"玩法边界"语义不同，本关卡设计使二者重合。

## 3. 空间骨架

场地自上而下划分为五个区域：

| 区域 | 设计坐标边界 | 说明 |
|---|---|---|
| 顶墙 | 碰撞面 **Y=0**（结构光占 Y 0–8） | 刚性，球碰后垂直反转 |
| 左/右墙 | 碰撞面 **X=0 / X=1920**（结构光占 X 0–8 / 1912–1920） | 刚性，球碰后水平反转；挡板不得越出 |
| 砖阵区 | X **128–1792**，Y **120–478** | 6 行 10 列完整砖阵，见 §4；上方 Y 0–120 为砖阵顶边距窄带（仅允许 Art §6.3 许可的低 α 静态装饰） |
| 球飞行走廊（安静区域） | X 0–1920，Y **478–880**（高 402） | 球的主要飞行条带；对应 Art §6.3 安静区域 1：仅纯色渐变与 α≤4% 微纹理，无装饰、无常驻 UI、无移动背景元素 |
| 挡板活动区 + 安全带（安静区域） | 挡板中心 X **110–1810**、Y 固定 **960**；安全带 Y **880–1080** | 对应 Art §6.3 安静区域 2：挡板上方净空 66px（≈2.4 倍挡板高，高于 1.5 倍下限），无装饰/常驻 UI 进入；底线 Y=1080 为漏球边界（无碰撞体） |

尺度占位（交 Balance 确认）：挡板 **220×28**，球 **28×28（半径 14）**。

```
Y=0      ┃ 顶墙碰撞面 ───────────────────────────────────────
         ░ 顶边距窄带 (0–120)
Y=120    ┌────── 砖阵区 128..1792 × 120..478 ──────┐
         │  6 行 × 10 列（见 §4 网格）              │
Y=478    └─────────────────────────────────────────┘
         ·                                           ·
         ·        球飞行走廊（安静区域）              ·
         ·            478..880                       ·
Y=880    ·············································
         ·     安全带（安静区域，880..1080）          ·
Y=960          ▲ 挡板 (220×28)，X:110..1810           ▲
         ·            球 Ready: (960,926)             ·
Y=1080   ┄┄┄┄┄┄┄┄ 底线（漏球边界，无碰撞体）┄┄┄┄┄┄┄┄
```

空间意图：砖阵压顶提供目标与信息密度；中部 402px 空走廊保证长飞行轨迹可读、节奏可呼吸；底部安全带让触控接球判断不被手指与 UI 污染。小场地不追加装饰系统，身份对比仅靠 Art 规定的明度分层与安静/密度差实现。

## 4. 砖阵布局（唯一关卡）

### 4.1 几何参数

| 项 | 取值 |
|---|---|
| 行数 × 列数 | **6 × 10 = 60 格** |
| 砖尺寸 | **152 × 48**（圆角半径由 Art 按砖高 14–18% 定义） |
| 水平/垂直砖间距 | **16 / 14** |
| 砖阵左右边距 | **128 / 128**（核算：10×152 + 9×16 + 2×128 = 1920） |
| 砖阵顶边距 | **120**（砖阵下沿 = 120 + 6×48 + 5×14 = **478**） |
| 加固砖数量 | **5 块**（普通砖 55 块） |

### 4.2 类型网格

`N` = 普通砖（1 耐久）；`R` = 加固砖（2 耐久）。列自左向右 c0–c9，行自上向下 r0–r5。

| 行\列 | c0 | c1 | c2 | c3 | c4 | c5 | c6 | c7 | c8 | c9 |
|---|---|---|---|---|---|---|---|---|---|---|
| r0 | N | N | N | N | N | N | N | N | N | N |
| r1 | **R** | N | N | N | N | N | N | N | N | **R** |
| r2 | N | N | N | N | N | N | N | N | N | N |
| r3 | N | N | N | N | N | N | N | N | N | N |
| r4 | N | N | **R** | N | N | **R** | N | N | **R** | N |
| r5 | N | N | N | N | N | N | N | N | N | N |

加固砖坐标（设计坐标中心点）：

| 格位 | 中心 X | 中心 Y | 节拍角色 |
|---|---|---|---|
| r4,c2 / r4,c5 / r4,c8 | 540 / 1044 / 1548 | 392 | **早期"硬碰"节拍点**：球开场向上先触 r5 普通砖，随后在砖阵下沿第二行遇到加固砖——"打中、没碎、还差一击"的教学在开局 1–2 次击球内出现；三点横排保证无论初始球路偏中偏边都可能遭遇 |
| r1,c0 / r1,c9 | 204 / 1716 | 206 | **收尾顶扫节拍点**：砖阵清空末期于两角出现，制造边角大角度反弹的最后挑战，并在构图上框住顶行 |

加固砖的视觉识别（重描边+内嵌板、受损裂纹缺角）由 Art §10 权威定义；砖色为行序装饰、不编码玩法（Art §3.2）。砖阵的耐久、类型与位置将由正式 Scene JSON 逐节点承载（可采用 brick-grid 父节点 + 60 个子节点的作者层级，见 §7 草稿）。

## 5. 挡板与球的初始位姿

| 对象 | 初始位置（中心点，设计坐标） | 备注 |
|---|---|---|
| 挡板 | **(960, 960)** | 水平居中；尺寸占位 220×28；挡板中心 X 活动范围 110–1810（半长 110 贴墙） |
| 球（Ready 附着） | **(960, 926)** | 相对挡板中心固定偏移 **(0, −34)**；球底距挡板顶 6px；Ready 时随挡板水平移动（GDD §3.2） |

发球初速度（GDD §3.2、§5.3）：

- **方向提案：垂直向上，速度向量 (0, −1) 方向**（即与 −Y 轴夹角 0°），球从 (960,926) 直上，首次反弹后玩家立即学习"挡板位置控制出射角"。
- 速度**大小**由 Balance 定义（逻辑像素/秒）。
- 若 Balance 选择发球小幅偏角（建议 ≤±15° 且固定或确定性随机），终值以 Balance 为准；任何发球方向不得出现水平或朝下分量。出射角范围规则（挡板反弹）引用 GDD §5.1。

## 6. 目标与出生/结束条件（空间判定位置）

规则引用 GDD §6，此处只给空间判定位置：

- **出生（Ready）**：新一局或漏球有余命时，挡板 (960,960)、球 (960,926) 重建；砖阵按当前局状态摆放（GDD §6.2、Tech §7.4 从作者化数据重建）。
- **胜利**：场上全部 60 块砖无一剩余瞬间即胜（GDD §6.1）——纯逻辑条件，无额外空间判定线。
- **漏球**：**球整体越过底线 Y=1080**，即球顶边（中心 Y − 14）> 1080 时判定成立；漏球裁决先于同刻任何击碎/接球（GDD §5.2 规则 1、§6.2）。底线无碰撞体，仅 L3 语义虚线（Art §3.1、§8.1）。
- **失败**：漏球后生命数归零（生命初值由 Balance 定义）。

## 7. 取景与宽高比

### 7.1 必须始终可见的游玩区域

任意受支持的横版容器内，经 letterbox 映射后以下内容必须**完整可见、可辨认、可操作**（GDD §8）：

1. 全部砖阵（X 128–1792，Y 120–478，含每一格里的三态辨识）；
2. 完整球飞行走廊（Y 478–880）——球在任一点都不被裁；
3. 挡板活动区、安全带与底线（Y 880–1080），挡板触控操作不被遮挡。

### 7.2 宽高比变化时的裁切纪律

- 场地（Art L3 场地结构、L4 砖阵、L5 挡板/球）按比例 `s` 等比缩放并在容器内**居中**，**绝不允许裁切**（Tech §4.3 contain）。
- **仅背景层允许被裁切/平铺以填满画幅**（Art §8.3）：L0 渐变可裁切铺满；L1 微纹理无缝平铺；L2 远景装饰只锚定四角/上沿允许区，不随宽度拉伸。背景与场地解耦、不烘焙合成。
- 超宽画幅（如 2560×1080）下两侧留边只出现 L0–L2；超高画幅同理上下留边。竖版或小于最小尺寸时不缩排，进入旋转/扩窗提示页（GDD §8）。

### 7.3 UI 覆盖允许区域

- **HUD（L7）**：仅允许落在画面边缘，信息盒随宽高比拉开间距但不进入球走廊（Y 478–880）与安全带（Y 880–1080）；建议上沿占用 Y 0–60 设计带（砖阵自 Y=120 开始，已预留）。
- **覆盖层（L8，开始/暂停/胜负/旋转提示）**：允许覆盖整个实际视口，自带压暗底并截留指针事件（Tech §2.3）。
- HUD 与覆盖层的**精确矩形、锚点、最小控件尺寸、targetViewports 由 UI_UX_SPEC 权威定义**；其最终屏幕分配以该文档选定的 game-view 区域为准，本文不维护第二套矩形表。UI 定稿后需与本取景策略复核。

## 9. 最小可用横版设计尺寸建议（供 Balance / UI_UX_SPEC 确认）

**建议最小可用横版尺寸：960 × 540（设计帧的 0.5 等比）。**

该尺寸下（计算器 #1 实测）：

- 砖阵完整可见：每砖 76×24，砖缝 8/7，砖阵位于屏上 Y 60–239；
- 挡板 110×14、球 14×14（半径 7），底线位于 Y 537–540，挡板活动全程在屏；
- 上沿保留约 60px 高度可供 HUD 边缘放置，球走廊与安全带无场地元素被裁。

采用 960×540 的理由：它是 1920×1080 的整数半比，映射无亚像素误差；再小则砖/球物理像素进入 6px 以内，三态辨识与触控接球判断无保障（Art §10.4）。低于此值（含竖版）按 GDD §8 显示旋转/扩窗提示。最终是否采纳为 `minimumControlSize`/`targetViewports` 项，由 Balance 与 UI_UX_SPEC 确认。
