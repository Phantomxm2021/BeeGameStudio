## 1. 游戏概述与玩家承诺

一款单屏街机打砖块游戏。玩家控制屏幕底部的横版挡板，反弹一颗持续运动的球，击碎上方的全部砖块即获胜；球漏过挡板落出底线则失去一条生命，生命耗尽即失败。

玩家承诺：**"移动挡板、控制反弹角度，在有限生命内清空砖阵。"** 每一次击球都是即时、可读、可复现的技巧挑战。

### 1.1 首版范围（Required，首发布必须包含）

- 一套完整核心循环：发球 → 接球反弹 → 击碎砖块 → 获胜或失败 → 再来一局。
- **一个关卡**：单屏固定砖阵，由场景数据（Scene JSON）编辑，包含普通砖与加固砖两种可观察类型。
- 三种控制方式并存：键盘、鼠标移动、触控拖动。
- 计分与生命数显示；本机保留历史最高分。
- 开始、暂停、胜利、失败、重试、退出（返回开始界面）完整流程。
- 横版方向适配：仅支持横版；空间不足或方向不符时给出旋转/调整提示。

### 1.2 明确排除项（首版不做）

- 多关卡、关卡选择、难度模式、无尽模式。
- 道具掉落（多球、激光、加长挡板等）、移动/特殊机制砖块（普通砖与加固砖除外）。
- 成长系统、解锁内容、账号/云端存档、排行榜、成就。
- 剧情、角色设定、内购与广告。
- 竖版布局：不做强制重排或缩小适配（见 §8）。

### 1.3 与其他文档的边界

- 具体数值（球速、挡板速度与尺寸、砖块行列数、砖块耐久、反弹角度范围、各类砖分值、生命数取值等）由 **Balance 文档**权威定义；本文件只确立规则结构，不重复参数表。
- 砖阵布局、各物体初始位置/尺寸、UI 版面与响应式变体、资源绑定以**作者编写的 Scene/UI JSON 为唯一可编辑源**；运行时代码加载该数据实现玩法，不得用代码常量取代这些已作者化的决策。
- 美术文档定义视觉表现，音效文档定义反馈声音，UI/UX 文档定义界面细节，技术文档说明如何消费上述数据；它们均不得改变本文件的玩家可见行为。

## 2. 核心循环

### 2.1 主循环（单局内）

1. 球停在挡板上待发（Ready）。
2. 玩家发球，球进入场上持续运动。
3. 玩家移动挡板拦截球：
   - 接住 → 依据击中挡板的位置改变反弹方向，继续击碎砖块；
   - 漏接 → 失去一条生命，回到待发或进入失败。
4. 砖块被逐块击碎、得分；场上剩余可击碎砖块减少。
5. 循环直至：全部可击碎砖块清空（胜利）或生命耗尽（失败）。

挑战来自球速下的预判与挡板"以位置控制角度"的技巧；反馈来自即时的碰撞弹跳、砖块破碎、计分与音效。

### 2.2 局外循环

- 胜利或失败后可一键"再来一局"：砖阵、生命、分数重置为新一局初始状态。
- 每局规则与内容完全相同，差异仅来自玩家技巧；除历史最高分外没有任何跨局成长或解锁。

## 3. 游戏对象与基础规则

### 3.1 挡板（Paddle）

- 位于场地底部，仅可沿水平方向在场地左右边界内移动。
- 挡板不会离开场地边界；到达边界即停住。
- 操控方式（同一时刻任一可用，效果等价）：
  - 键盘：长按左/右方向键（或 A/D）持续移动；
  - 鼠标：挡板水平位置跟随鼠标光标（在场地内的投影）；
  - 触控：手指在屏幕上水平拖动，挡板跟随；触点不要求精确按在挡板上。
- 具体移动速度（键盘）、跟随方式的手感参数由 Balance 定义。

### 3.2 球（Ball）

- 场上始终只有一颗球。
- 发球前附着在挡板上方随挡板水平移动；玩家按下发球输入（空格/点击/轻点）后，球以朝上的初速度发出。发球输入在球已发出后不产生任何效果。
- 发出后持续匀速运动（具体速度由 Balance 定义），不因时间或砖块数量加速。
- 与墙面、砖块、挡板发生碰撞时反弹，反弹规则见 §5。

### 3.3 砖块（Bricks）

首版一个关卡内包含两种砖块，外观明显可区分：

| 类型 | 耐久 | 被击中表现 |
|---|---|---|
| 普通砖 | 1 | 击中一次即销毁 |
| 加固砖 | 2 | 第一次击中后变为可辨识的受损状态（视觉变化），第二次击中销毁 |

- 加固砖受损后其位置、碰撞体积不变。
- 砖块均静止，无移动、无掉落。
- 砖阵的行数、列数、间距、类型分布、分值均由 Scene JSON 编排，数值取值由 Balance 定义。

### 3.4 场地边界

- 左、右、顶部为刚性边界：球碰到即反弹。
- 底部为漏球边界（无碰撞体）：球整体越过底线即判定漏球（见 §6.2）。

## 4. 玩家动作与后果汇总

| 动作 | 可用状态 | 后果 |
|---|---|---|
| 移动（键盘/鼠标/触控） | Ready、Playing、Paused 时不改变游戏态（暂停期间输入不作用于场内） | 挡板水平移动；Ready 时球随挡板移动 |
| 发球 | Ready | 球发出，进入 Playing |
| 暂停/继续 | Playing / Paused | 切换暂停；暂停时全场冻结并显示暂停层 |
| 再来一局（重试） | 胜利结算、失败结算、Paused | 重置为新一局并进入 Ready |
| 返回开始界面 | Paused、胜利结算、失败结算 | 退出当前局，回到开始界面 |
| 开始游戏 | 开始界面 | 进入新一局 Ready |

具体按键与按钮归属（如 Esc/P 暂停、按钮文案与位置）由交互契约与 UI/UX 文档定义；本文件只要求上述动作在所列状态下可用且后果一致。

## 5. 碰撞与反弹规则（玩家可观察）

### 5.1 一般反弹

- 球碰到左/右墙：水平方向反转；碰到顶墙：垂直方向反转。
- 球碰到砖块：反弹并按 §3.3 对砖块造成耐久影响。
- 球碰挡板时不做简单的垂直反转，而是**依据击中挡板的水平位置决定出射角度**：击中中点附近接近垂直向上，越靠近挡板两端出射越偏向斜外侧。出射角范围与最小/最大值由 Balance 定义，且任何正常挡板反弹都不会产生水平或朝下的出射方向。

### 5.2 同时碰撞的裁决（顺序影响玩家结果，故显式定义）

球在一次位移/同一时刻可能接触多个对象，按以下可观察规则裁决：

1. **先结算漏球，再结算击碎**：若该次位移中球整体越过底线，则漏球成立（§6.2），即使同一刻接触了砖块或挡板，也不再计为击碎或接球。
2. 未漏球时，球与砖块的接触均生效：
   - 一次接触多块砖（如砖阵边角、球同时擦过相邻两块）：所有被接触的砖块各承受一次击中并各自计分；球的反弹方向按"使其离开砖阵区域"的单次反弹呈现，不出现多次反弹叠加导致的抖动或穿砖。
   - 同一次碰撞中最后一块可击碎砖被销毁：即使该次碰撞同时伴随其他事件，只要未触发规则 1 的漏球，即判胜利（§6.1）。
3. 球同时接触挡板与侧墙：以挡板接球处理，球保持在场内，不出现夹反弹。
4. 任何情况下球不得穿过墙体或砖块内部；如玩家观察到穿模，属缺陷而非规则允许行为。

### 5.3 过渡期间的交互边界

- 暂停期间一切场内运动与碰撞冻结；恢复后从冻结瞬间继续，暂停时长不影响球的位置和速度。
- 球从"待发"到"发出"以发球输入被接受的瞬间为界；该瞬间之后挡板移动不改变已发出的球。
- 漏球判定成立的瞬间起，球与挡板/砖块的进一步交互一律无效，随后进入生命扣除结算。
- 胜负结算界面显示期间，场内不再响应发球、接球等玩法输入，仅响应"再来一局/返回开始界面"。

## 6. 生命、计分与胜负

### 6.1 胜利条件（可观察）

场上**所有砖块（普通砖与加固砖）均被销毁、无一剩余**的瞬间，本局立即获胜：球停止运动，显示胜利结算（含本局得分、是否刷新最高分）。

### 6.2 漏球、生命与失败

- 球整体越过场地底线 = 漏球：生命数减 1。
- 漏球后：
  - 仍有剩余生命：短暂结算后球重新附着于挡板，回到 **Ready** 待发；砖阵保持当前剩余状态，分数不清零。
  - 生命数归零：本局失败，球停止运动，显示失败结算（含本局得分）。
- 初始生命数由 Balance 定义；生命数在游戏中不增加（无道具）。

### 6.3 计分

- 每销毁一块砖按其类型得分（普通砖、加固砖的分值由 Balance 定义；加固砖不因分两次击中而重复计分，以"销毁"为计分时点，还是"每次击中"计分，由 Balance 统一规定并保持类型间一致）。
- 本局分数从 0 开始累加，HUD 实时显示当前分数与剩余生命。
- 历史最高分：仅保存在本机本地；当本局分数超过历史最高分时，在结算时更新并明确提示"新纪录"。清空浏览器数据可导致最高分丢失，这是可接受行为，不做云端恢复。

### 6.4 暂停与中途退出

- Playing 中可随时暂停；暂停不判负、不清分。
- 从暂停或结算界面"返回开始界面"视为主动放弃当前局：本局分数不写入历史最高分（只有正常打完出现胜负结算的局才参与最高分比较）。

## 7. 游戏状态与流转

| 状态 | 进入条件 | 允许的动作 | 转移 |
|---|---|---|---|
| 加载（Loading） | 启动游戏，加载场景/UI 数据与资源 | 无（或仅可跳过的加载呈现） | 资源与数据就绪 → 开始界面；加载失败 → 可重试的错误提示 |
| 开始界面（Start） | 加载完成，或从局内退出 | 开始游戏 | → 新一局 Ready |
| 待发（Ready） | 新一局开始、或漏球后仍有生命 | 移动挡板、发球、暂停 | 发球 → Playing；暂停 → Paused |
| 进行中（Playing） | 球已发出 | 移动挡板、暂停 | 全部砖清空 → 胜利结算；漏球且仍有生命 → Ready；漏球且生命为 0 → 失败结算 |
| 暂停（Paused） | Playing 中暂停 | 继续、再来一局、返回开始界面 | → Playing / Ready（新局）/ Start |
| 胜利结算（Win） | 全部砖块清空 | 再来一局、返回开始界面 | → Ready（新局）/ Start |
| 失败结算（Game Over） | 生命归零 | 再来一局、返回开始界面 | → Ready（新局）/ Start |

一局的定义：从 Start（或结算）进入 Ready 起，到出现胜利或失败结算止；"再来一局"产生的是全新一局。

## 8. 屏幕方向与适配

- **仅支持横版（Landscape）**。设计以横版场地为基准，Scene/UI JSON 中的坐标为设计坐标（参考尺寸），不是固定宿主像素；运行时在保持比例与可玩性的前提下缩放映射。
- 最小可用尺寸：横版方向下必须同时完整可见——砖阵区、挡板活动区、球以及 HUD（分数、生命）均可辨认且挡板触控操作不被遮挡；具体最小设计尺寸与缩放下限由 UI/UX 与技术文档给出，但其结果必须满足上述可见性条件。
- 当设备处于竖版（方向不符）或横版可用空间小于最小可用尺寸时：显示"请旋转设备至横版 / 请扩大窗口"的提示页，**不做强制重排、不做无法游玩的缩小**；恢复到满足条件后自动回到此前界面。

## 9. 反馈与表现要求（玩家可观察的结果）

以下为对反馈结果的要求，具体视觉风格由美术文档、声音由音效文档定义：

- 球每次碰撞（墙、砖、挡板）有可辨识的即时视听反馈；砖块被销毁与"加固砖受损但未销毁"必须视觉上明确区分。
- 漏球、生命减少有明确反馈；胜利与失败结算在情绪与信息上可区分。
- 最高分被刷新时有专门提示。
- 挡板当前位置、球的运动轨迹在任何时刻清晰可读，不得因特效造成碰撞判断不可辨认。

## 10. 首版完成条件（验收时在游玩中可观察）

1. 游戏可在 Web 浏览器启动，加载后进入中文开始界面。
2. 可通过键盘、鼠标、触控三种方式在场地边界内流畅移动挡板，三者行为等价。
3. 球从挡板发出后持续运动，与墙、砖、挡板的反弹符合 §5；挡板击球位置不同会产生可观察的出射角度差异。
4. 普通砖一击销毁；加固砖首次击中呈受损状态、再次击中销毁；不存在穿砖、穿墙。
5. 清空全部砖块必出现胜利结算；球漏出底线扣生命并重置待发，生命归零必出现失败结算。
6. 分数随砖块销毁正确增加并实时显示；新纪录仅在正常打完的局中更新并在本机保留。
7. 暂停/继续、再来一局、返回开始界面在 §4、§7 所列状态下均可用且结果正确；过渡期间不接受规则外输入。
8. 竖版或空间不足时显示旋转/扩窗提示而非错误布局；横版且空间充足时所有玩法元素完整可见、可操作。
9. 排除项（§1.2）内容确实不存在：无道具、无第二关卡/模式、无成长解锁。

## 11. 未决产品决策（留给后续批次，不扩大简报范围）

- **Balance 文档待定义的全部数值**：球速、键盘移动速度、挡板与球尺寸、砖阵行列与类型分布、两类砖分值与计分时点、初始生命数、发球初速角度与挡板反弹角度范围、最小可用设计尺寸。
- 加固砖受损状态的具体视觉语言（颜色/裂纹等）由美术文档决定，GDD 仅要求"可辨识"。
- 结算界面是否展示本局击碎数/用时等附加统计：默认不展示，如 UI/UX 文档提议加入，不得改变 §6 的计分与胜负规则。

以上未决项均在既有规则框架内，不构成新模式或新系统。
