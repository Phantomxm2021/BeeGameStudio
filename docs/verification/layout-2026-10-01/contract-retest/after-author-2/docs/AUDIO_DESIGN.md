## 1. 目的与范围

本文定义首版打砖块游戏**必要的声音行为**：每一类声音/音乐的用途、声音性格、触发时机、时长与循环、停止条件、快速重复触发时的表现，以及并发优先级、电平层级、过渡行为与音量/静音规则。

边界：

- 本文**不给出文件清单、文件格式选型、采样率、资源来源与采购方式**；这些统一由 `ASSET_PLAN` 负责，本文只提供行为需求供其引用。
- 音频不改变 GDD 确立的任何玩家可见规则，不承担唯一信息渠道（见 §9）。
- 首版为单球、单关卡、街机快节奏、事件触发频繁的游戏；全部设计以此为前提，不做自适应音乐、多轨音乐系统、旁白配音、空间化（3D）音频。

## 2. 设计原则

1. **即时、短促、可截断**：碰撞反馈以"一击一声、几十毫秒级"为基准，服务于街机节奏，不拖尾、不掩盖下一次碰撞。
2. **声音是确认与质感，不是规则载体**：关键状态（生命、胜负、新纪录）在 GDD 中均已有视觉呈现，声音只做情绪强化与冗余确认（逐条核对见 §9）。
3. **三层信息优先级**：局结果（胜/负、漏球失生命、新纪录）> 玩家技巧反馈（挡板击球位置）> 常规环境碰撞（墙、砖）。混音、并发、 ducking（瞬时压低）都为保证高优先级信息可被听清。
4. **变化优于重复**：高频碰撞声通过音高递进、轻微随机与截断策略避免机械重复感（见 §5）。
5. **克制**：首版事件种类有限，音频种类与之严格一一对应，不为每种 UI 微交互额外造声。

## 3. 必需声音行为

下表中"触发时机"一律以游戏逻辑事件被确认的瞬间为准（与 GDD §5 的裁决结果一致，而不是物理接触的预判瞬间）。时长为行为目标，最终素材以 `ASSET_PLAN` 交付为准。

### 3.1 发球（Serve / Launch）

- **用途**：确认玩家的发球输入被接受，标志 Ready → Playing。
- **声音性格**：清脆上扬的短弹射声，中高频、带轻微音高上扬，"出发"感；明亮但不尖锐。
- **触发时机**：GDD §3.2 发球输入被接受、球离板的瞬间（Ready → Playing）。
- **时长/循环**：一次性（one-shot），约 0.1–0.2 秒，无循环。
- **停止条件**：自然播完；状态被重置/退出时无需专门淡出（时长极短）。
- **重复触发行为**：球已发出后发球输入无效（GDD §3.2），不发声；Ready 下连点只在实际发球瞬间响一次。

### 3.2 球碰墙（Wall Bounce：左墙/右墙/顶墙）

- **用途**：确认反弹，提供球路节奏。
- **声音性格**：短促、偏闷的轻碰撞（木质/合成钝感均可），音高与音色明显区别于碰砖与碰挡板，是全场最"背景"的碰撞声。
- **触发时机**：§5.1 墙面反弹方向反转的瞬间。
- **时长/循环**：one-shot，约 0.03–0.08 秒，无尾音延留。
- **停止条件**：自然播完或被 voice stealing（§6）截断。
- **重复触发行为**：连续碰墙（如两墙间快速横飞）时允许截断上一声并对每次触发施加 ±半音以内的随机微变调与轻微随机音量；不做旋律性递进（递进留给砖块）。

### 3.3 球碰挡板（Paddle Hit）——技巧位置反馈

- **用途**：确认接球成功；**通过音高反馈击中挡板的水平位置**，让玩家"听得到角度"，与 GDD §5.1 的位置决定出射角形成跨感官冗余。
- **声音性格**：有弹性的中低频"蹦弹"声，比墙声饱满、比砖声圆润。
- **触发时机**：球与挡板碰撞、按接球处理的瞬间（§5.2 规则 3 中挡板优先于侧墙时也以此声为准）。
- **时长/循环**：one-shot，约 0.08–0.15 秒。
- **停止条件**：自然播完。
- **重复触发行为（位置参数化）**：声音依据击球位置参数连续变调——击中挡板中点附近为基准音高；越靠近左端/右端，音高分别向低/高两个方向偏移（方向映射需固定一致，建议"右高左低"），偏移量与归一化位置参数成比例（接口参数见 §10）。该声音不参与连击递进，以保证"位置—音高"映射稳定可学。同一事件只响一声，不因结算而重复。
- **可读性要求**：两端极限位置与中点的音高差须足够明显（目标 ≥ 约一个大三度的听感差），具体映射曲线交 Tech 实现、由音频侧调校。

### 3.4 击中普通砖（= 销毁，Brick Hit – Normal）

- **用途**：确认"击中即碎"，构成连续击砖的爽感主线。
- **声音性格**：清脆的破碎/爆裂短声，中高频、颗粒感强，明亮有打击感。
- **触发时机**：普通砖承受击中并被销毁的同一瞬间（§3.3）。
- **时长/循环**：one-shot，约 0.05–0.12 秒。
- **停止条件**：自然播完；高频连击时允许被新事件截断（§5）。
- **重复触发行为**：参与连击音高递进（§5.1），快速连续碎砖时逐级上行，形成"越打越high"的街机语汇。

### 3.5 击中加固砖——受损未碎（Brick Hit – Reinforced / Damaged）

- **用途**：明确告知"打中了，但没碎，还差一击"，与销毁声必须一听可分；这是 GDD §9 要求视觉区分的听觉对应。
- **声音性格**：低沉、结实的钝击/金属闷响，低频成分明显，音高显著低于碎砖声，带"硬、扛住了"的质感。
- **触发时机**：加固砖第一次承受击中、进入受损状态的瞬间。
- **时长/循环**：one-shot，约 0.08–0.15 秒。
- **停止条件**：自然播完。
- **重复触发行为**：参与连击递进但递进幅度小于普通砖（保持其"沉重"基调）；连续命中加固砖时同样做轻微随机，避免听感完全相同。

### 3.6 销毁加固砖 / 砖块销毁（Brick Destroyed）

- **用途**：确认砖块被彻底销毁（普通砖为击中即销毁，加固砖为第二次击中销毁）；与 3.5 的"受损"声形成对比收束。
- **声音性格**：在 3.4 碎砖声基础上更饱满、带明确碎裂层次，或略上扬，传达"终于打碎"；情绪比普通碎砖声稍强。
- **触发时机**：砖块耐久归零、被销毁的瞬间（计分点附近，具体计分时点以 Balance 为准，不影响声音触发）。
- **时长/循环**：one-shot，约 0.08–0.15 秒。
- **停止条件**：自然播完。
- **重复触发行为**：参与连击递进；**若本次销毁同时触发胜利（§5.2 规则 2，最后一块砖），以胜利声（3.8）为最高优先**，碎砖声可被胜利声覆盖或压制，不要求两者都完整播放。

### 3.7 漏球与失去生命（Ball Lost / Life Lost）

- **用途**：强警示：球漏出底线、生命减 1；是 Playing 中最高优先级的负面事件反馈。
- **声音性格**：明显的下行音调 + 低频"坠落空失"感（如下坠滑音加一声低沉撞击），音高走向与所有正面上扬声相反，一听即知是损失。
- **触发时机**：GDD §6.2 漏球判定成立的瞬间（球整体越过底线；依据 §5.2 规则 1，先于同刻任何击碎）。§5.3 规定漏球成立后球与挡板/砖块交互无效，故**该瞬间之后不再播放任何碰撞声**。
- **时长/循环**：one-shot，约 0.4–0.8 秒，允许为全部碰撞声中最长者。
- **停止条件**：自然播完；漏球后进入 Ready 或失败结算，若在声尾触发新状态切换可不截断（其尾音自然结束）。
- **重复触发行为**：一局内每次漏球音高可逐级再下移一点点，强化"情况变糟"，但不做截断——漏球声必须完整播放。
- **与失败的关系**：若本次漏球导致生命归零，漏球声之后（或其尾音上叠加）转入失败声（3.9），两者须衔接成一个可辨识的情绪段，由 Tech 负责编排时序。

### 3.8 胜利（Game Win）

- **用途**：宣告清空全部砖块、本局获胜，正向情绪顶点。
- **声音性格**：明亮的上行短句/小琶音（街机胜利号角感），大调色彩、节奏明快，2–5 个音的短小上扬乐句。
- **触发时机**：GDD §6.1 最后一块可击碎砖被销毁、胜利判定的瞬间（同刻压过碎砖声，见 §6）。
- **时长/循环**：one-shot 短句，约 0.8–1.5 秒；不循环。
- **停止条件**：自然播完；玩家在乐句播放中立即点"再来一局/返回开始"时允许淡出截断（约 0.1 秒淡出），不阻塞操作。
- **重复触发行为**：每局胜利最多一次；新纪录提示声（3.11）在胜利结算出现"新纪录"时于其后衔接，而非同时炸响。

### 3.9 失败（Game Over）

- **用途**：宣告生命归零、本局失败，负向情绪收束；与胜利在情绪和音高走向上明确可分（GDD §9）。
- **声音性格**：下行短句，低沉、缓慢收束，小调/晦暗色彩，力度由强渐弱。
- **触发时机**：§6.2 生命归零、失败结算显示的瞬间（衔接在漏球声之后）。
- **时长/循环**：one-shot 短句，约 0.8–1.5 秒；不循环。
- **停止条件**：同胜利——立即操作时可短淡出截断，不阻塞输入。
- **重复触发行为**：每局失败最多一次。

### 3.10 暂停 / 继续（Pause / Resume）

- **用途**：确认状态切换 Playing ⇄ Paused。
- **声音性格**：两种极短 UI 音：暂停为一个低沉、收束的短音（"按住/凝固"感）；继续为一个轻亮、放开的短音（"恢复"感）。二者互为呼应、一听可分方向。
- **触发时机**：暂停/继续被接受、状态实际切换的瞬间。
- **时长/循环**：one-shot，各约 0.05–0.1 秒。
- **停止条件**：自然播完。
- **重复触发行为**：快速连按暂停/继续时每次切换只响一声，允许截断前一声音；不在暂停期间回响（暂停时场内一切冻结，UI 音本身可以播放，玩法音全部冻结）。

### 3.11 再来一局（Retry / Restart）

- **用途**：确认放弃结算态、进入新一局 Ready。
- **声音性格**：轻快的重置短音（一个干脆的"复位"声或极短上行双音），中性偏正向。
- **触发时机**：在 Win/Game Over/Paused 下"再来一局"被接受、新一局数据重置完成的瞬间（GDD §4、§7）。
- **时长/循环**：one-shot，约 0.1–0.2 秒。
- **停止条件**：自然播完。
- **重复触发行为**：连点只触发一次有效重置，故只响一声。

### 3.12 返回开始界面（Back to Start / Quit）

- **用途**：确认主动退出当前局、回到 Start。
- **声音性格**：柔和的下行收束短音，轻量、无失败意味（这是正常导航而非惩罚；GDD §6.4 退出不写最高分，不奏失败声）。
- **触发时机**："返回开始界面"被接受、Start 界面呈现的瞬间。
- **时长/循环**：one-shot，约 0.15–0.3 秒。
- **停止条件**：自然播完。
- **重复触发行为**：无。

### 3.13 新纪录提示（New Record）

- **用途**：专门庆祝本局分数刷新本机历史最高分（GDD §6.3、§9）。
- **声音性格**：比胜利声更华丽的闪亮点缀音——明亮的高音小闪烁（如铃声/合成闪耀声），短而有"勋章"感；它是胜利短句的**附加层**，不取代胜利声。
- **触发时机**：仅在正常打完（胜负结算）且确认刷新最高分、结算界面显示"新纪录"提示时触发；先有胜负声，新纪录声在其后约 0.2–0.5 秒衔接。中途退出的局不参与最高分比较，永不触发此声。
- **时长/循环**：one-shot，约 0.5–1 秒。
- **停止条件**：自然播完；立即操作时可短淡出。
- **重复触发行为**：每局最多一次。失败结算中理论上也可能出现新纪录（分数在失败前已超过历史最高），此时新纪录点缀仍可在失败短句之后播放——二者情绪允许并存，由 Tech 保证时序不重叠糊成一团。

## 4. 各声音类别汇总（按信息层级）

| 层级 | 声音 | 基调 |
|---|---|---|
| A 局结果 / 强提示 | 漏球失生命、胜利、失败、新纪录 | 乐句化、最完整、不可被普通碰撞抢占 |
| B 技巧反馈 | 挡板击球（位置变调） | 稳定映射、不参与连击随机 |
| C 常规碰撞 | 发球、墙、普通砖碎、加固砖受损、加固砖销毁 | 短促、可变调、可截断 |
| D 界面导航 | 暂停/继续、再来一局、返回开始 | 极短 UI 音，独立于玩法音通道 |

## 5. 快速重复触发策略（防机械重复）

### 5.1 砖块连击音高递进

- 维护一个短生命周期的"连击步进"状态：在 Playing 中，每次碎砖（3.4/3.6）使下一块砖的音高沿一个固定音阶上行一档（建议五声音阶，保证任何递进都悦耳），步进窗口约 0.5–1 秒内无新碎砖即归零。
- 递进设上限（约一个八度内 5–7 档），到顶后保持最高档并加入音色/力度微变，不再无限升高变尖。
- 命中加固砖受损声（3.5）可计入连击节奏，但使用其自身的低档基准，避免低频声也变得尖锐。
- 漏球、暂停、胜负结算立即清空连击步进。

### 5.2 截断（Truncation）与微随机

- 墙、砖等 C 层声音允许"新事件截断同组最旧声音"，避免快速碰撞时声音堆叠成噪声。
- 每次触发在基准音高上叠加 ±半音以内随机（挡板击球声除外，其音高由位置参数独占）与 ±约 10% 的音量微随机。
- A 层声音**永不被截断、永不参与随机到失真**，必须完整可辨。

### 5.3 同刻多砖（GDD §5.2 规则 2）

一次位移同时接触多块砖时：

- **不逐块播放 N 个碎砖声**（会造成相位堆叠与音量突爆）。
- 合并为一次"复合碎砖"反馈：播放一个碎砖声，按本刻被销毁砖数（multiCount）提升亮度/力度或叠加 1–2 个音层（建议 2 块加一层、≥3 块为最饱满一档并可附一声短促"横扫"装饰），连击递进只前进一步。
- 若同刻包含"最后一块砖→胜利"，整体让位给胜利声（§3.6/§3.8）。
- multiCount 由逻辑层在事件参数中给出（§10），音频侧不自行估算。

## 6. 并发、优先级与电平层级

### 6.1 最大并发原则

- 设全局同时发声上限（目标 6–8 路，含音乐计数时另算，最终由 Tech 按性能确认），超限按 §4 层级从低到高抢占：先回收 C 层最旧/最轻声音，其次 D 层；**A 层与挡板击球声不参与抢占**（A 层同时出现的数量在规则上本就极少）。
- 音乐独立于 one-shot 并发计数之外。

### 6.2 防止频繁碰撞掩盖重要反馈

- **Ducking**：A 层事件（漏球、胜利、失败、新纪录）触发时，瞬时压低 C/D 层与音乐电平（建议音乐降低约 6–10 dB、C 层碰撞降低或直接停发新触发），A 层事件结束后快速恢复（约 0.2–0.3 秒）。
- **静默窗口**：漏球判定成立后进入短结算，期间不接收/不播放任何砖、墙碰撞声（与 GDD §5.3 一致）；胜利/失败结算显示期间场内无玩法事件（GDD §5.3），自然只有结算乐句。
- 挡板击球声（B 层）优先级高于墙、砖：同刻（§5.2 规则 3）只发挡板声。

### 6.3 相对电平层级（混音目标，非绝对值）

- 以 C 层碰撞为基准 0 dB：
  - A 层（漏球/胜负/新纪录）：约 +3 至 +6 dB，最突出；
  - B 层挡板击球：约 +2 至 +4 dB；
  - D 层 UI 音：约 −2 至 0 dB；
  - 背景音乐：明显低于音效，建议峰值比 C 层低约 8–12 dB（见 §7）。
- 最终响度以浏览器外放/小扬声器不爆音、连续碎砖不累积突爆为验收标准；具体数值由 Tech 在总线上限制（建议总线压限）。

## 7. 背景音乐（BGM）——首版决定

**决定：首版包含一条背景音乐，仅一条、短循环，不引入任何音乐切换或多轨系统。**

理由：一局 Playing 可持续数十秒至数分钟，纯音效环境在长 rally 中偏干；一条轻量循环可维持街机氛围与节奏感，同时成本可控。明确不做：分段/自适应音乐、按状态切换曲目、多轨分层、胜利失败专属曲目（胜负由 §3 的 one-shot 乐句承担）。

行为定义：

- **气质与循环长度**：轻快、有律动的复古街机情调，中速偏快，旋律简单不抢耳；循环体建议 8–16 小节（约 15–30 秒），循环点无缝、无明显终止感，可长时间重复不烦。
- **电平**：始终铺底，峰值比音效 C 层低约 8–12 dB；A 层事件触发时被 ducking（§6.2），事件结束恢复。
- **启动/停止时机**：Start 界面是否播放——**Start 界面即开始播放该循环**，但受浏览器自动播放策略约束：首次用户交互前若 AudioContext 无法发声，则在首次交互后无缝开始（§8.3）；进入 Ready/Playing 不切换、不重启（循环不断）。
- **暂停行为**：暂停时音乐立即压低（建议降至 −12 dB 以下或静音）并可选择挂起；继续时恢复。不使用第二首"暂停音乐"。
- **结算界面**：胜利/失败后音乐继续播放但被结算乐句 ducking；乐句结束后恢复铺底或在结算态保持低音量，行为二选一由实现定，但**不得切歌**。
- **返回开始/再来一局**：不重启、不切换，循环持续；仅在真正无音频输出需求（页面隐藏）时按浏览器策略自然挂起。
- **停止条件**：用户在设置中关闭音乐（§8）；页面被浏览器挂起。无任何脚本化的曲目切换。

## 8. 场景/状态过渡声音行为总表

对应 GDD §7 状态机：

| 过渡 | 声音行为 |
|---|---|
| Loading → Start | 无强制声音（加载完成不专门奏乐）；Start 的 BGM 按 §7/§8.3 起播 |
| Start → Ready（开始游戏） | 不另造专用音：以 BGM 连续铺底 + 进入 Ready 后挡板就位的环境静默为准；可选的轻确认音列入 §11 可选项，非必需 |
| Ready → Playing | 发球声（§3.1） |
| Playing → Paused | 暂停短音；玩法音全部冻结，音乐压低（§3.10、§7） |
| Paused → Playing | 继续短音；音乐恢复；从冻结瞬间继续，无补发声音 |
| Playing → Ready（漏球有余命） | 完整漏球声（§3.7），期间无碰撞声；回到 Ready 待发，不奏其他音 |
| Playing → Game Over | 漏球声 → 失败短句（§3.9）时序衔接 |
| Playing → Win | 胜利短句压过同刻碎砖声（§3.8） |
| Win/Game Over → Ready（再来一局） | 重置短音（§3.11），BGM 连续不重启，连击步进清空 |
| 任意结算/Paused → Start（返回开始） | 柔和下行收束短音（§3.12），BGM 继续铺底；不奏失败声、不写最高分 |
| 新纪录 | 胜负短句后衔接新纪录点缀（§3.13） |

所有过渡音都不得阻塞输入：玩家在结算音播放中点按钮，操作立即生效，声音短淡出截断（§3.8/§3.9）。

## 9. 音量、静音与持久化

### 9.1 音量轨别

首版**必须提供两个独立分轨**：音效轨（SFX）与音乐轨（BGM），各自独立音量；再叠一个总音量控制。

- 必需的最小控制集：**总静音开关** + 音乐音量 + 音效音量（后两者为 0–100% 连续调节；滑到 0 等价于该轨静音）。
- 不做更多轨别（无语音轨、无 UI 独立轨）。
- 所有 §3 的 one-shot 走音效轨；§7 循环走音乐轨；ducking 在总线层面实现，不改变用户设定值。

### 9.2 持久化

- 静音状态与三档音量设置必须保存在 `localStorage`，刷新/重开页面后恢复；键名与结构由 Tech 定义并与最高分存储（GDD §6.3）同属本机数据。
- 清空浏览器数据导致设置丢失为可接受行为（与最高分一致），不做云端恢复。
- 首次访问无存储时使用默认值：总音量与两轨均为一个安全的中高默认值（建议 70–80%），且默认**不静音**。

### 9.3 浏览器自动播放策略（首次交互前）

- 音频上下文（AudioContext 等）在用户首次手势（点击/按键/触控）前可能处于 suspended：**Start 界面不得因自动播放失败而报错或卡死**；首次交互前所有程序化声音（含 BGM）静默等待。
- 首次用户手势时创建/恢复音频上下文并记住"已解锁"；若 Start 的 BGM 此前未起播，此刻起播（§7）。
- 发球、按钮等首次点击若正好是解锁手势，对应声音允许从该次交互起正常播放（浏览器允许手势内发声）。
- 页面从隐藏恢复时按需恢复上下文与音乐，不强制重响上一事件。

## 10. 关键信息的视觉/交互冗余确认（声音不作唯一渠道）

逐条核对，以下信息玩家在关闭声音时仍可完整获得：

| 信息 | 视觉/交互对应（GDD 已有） | 声音角色 |
|---|---|---|
| 剩余生命 / 生命减少 | HUD 生命实时显示（§6.2、§6.3） | 强化情绪，非唯一渠道 |
| 漏球 | 球越底线、回到 Ready 待发的可见过程（§6.2） | 警示与情绪 |
| 出射角度/击球位置 | 球实际反弹轨迹的可见差异（§5.1、验收 §10.3） | 位置音高为附加冗余，静音不影响技巧判断 |
| 普通砖销毁 | 砖块消失 + 分数实时增加（§6.3、§9） | 打击确认 |
| 加固砖受损未碎 | 受损状态的明确视觉变化（§3.3、§9） | 听觉二次区分 |
| 胜利 | 胜利结算界面（得分等）（§6.1） | 情绪顶点 |
| 失败 | 失败结算界面（§6.2） | 情绪收束 |
| 新纪录 | 结算界面"新纪录"明确提示（§6.3） | 庆祝点缀 |
| 暂停/继续 | 暂停层显隐、全场冻结（§4、§5.3） | 切换确认 |
| 再来一局/返回开始 | 界面与场内重置/Start 界面可见（§7） | 操作确认 |

结论：不存在任何"只能靠声音获得"的规则信息；音频全部为确认与情绪层。

## 11. 必需音频 vs 可选增强

**必需（首版必须实现的声音行为）**：§3.1–3.13 全部类别；一条 BGM 短循环（§7）；音乐/音效分轨与总音量、静音持久化（§9）；§6 的并发上限、优先级与 ducking；§5.1 连击递进、§5.3 多砖合并。

**可选增强（首版可不做，不影响验收；若做由 `ASSET_PLAN`/Tech 另行评估，不得新增系统）**：

- Start → Ready 的轻确认音、按钮 hover/焦点微音（仅限键鼠，易造成噪音，默认关闭）。
- BGM 在胜利/失败乐句期间的临时简化（如抽掉旋律层）——仍属同一条循环素材，**不构成多轨系统**，且首版可不做。
- 挡板击球位置的立体声像随左右位置轻微偏移（桌面设备有扬声器/耳机时）；移动端外放默认可忽略。
- 结算界面轻微环境氛围底噪。
- 连击到顶档时的额外装饰音。

## 12. 交接给 Tech 的接口需求（本批次必须交接）

### 12.1 事件钩子列表

逻辑层须在下列事件**确认瞬间**向音频子系统发射事件（事件名为建议命名，语义须一致）：

| 事件 | 触发点（GDD） | 必需参数 |
|---|---|---|
| `ball_launch` | §3.1 Ready→Playing | 无（可预留发球角度，首版不用） |
| `wall_bounce` | §3.2 | `wall`: `left`/`right`/`top` |
| `paddle_hit` | §3.3 | `hitPosition`: 归一化击球位置，建议 −1（左端）…0（中点）…+1（右端），用于连续音高映射 |
| `brick_hit` | §3.4–3.6 | `brickType`: `normal`/`reinforced`；`result`: `destroyed`/`damaged`；`multiCount`: 本刻合并击中的砖数（§5.3） |
| `ball_lost` | §3.7 | `livesLeft`: 扣除后剩余生命数（音频据此决定衔接失败声） |
| `game_win` | §3.8 | 无 |
| `game_over` | §3.9 | 无 |
| `new_record` | §3.13 | 无（仅正常打完且刷新最高分时发） |
| `pause_changed` | §3.10 | `paused`: boolean |
| `retry` | §3.11 | 无 |
| `back_to_start` | §3.12 | 无 |

补充约定：

- 事件只在 GDD 裁决**生效后**发出（如漏球先于击碎、挡板优先于侧墙），音频不参与规则裁决；§5.3 规定无效的交互不得发声。
- 同刻多砖只发一个合并后的 `brick_hit`（带 `multiCount`），不逐块发。
- `ball_lost` 且 `livesLeft === 0` 时，逻辑层仍照常发 `game_over`，由音频侧编排二者时序。

### 12.2 音频子系统需要的运行时能力

- 按优先级的并发管理：最大发声数（6–8 路建议）、voice stealing、A 层不可抢占（§6）。
- 播放时参数：音高偏移（连续，供位置映射与连击递进）、音量微调、截断同组旧声。
- 连击步进状态（§5.1）可由音频子系统内部维护，逻辑层只需保证事件顺序正确；若由逻辑层维护则在 `brick_hit` 增加步进参数——二选一，实现阶段定。
- 总线 ducking：A 层事件触发时自动压低音乐与 C 层电平并自动恢复（§6.2）。
- 音乐：无缝循环、音量控制、暂停压低/恢复、无切换接口（§7）。

### 12.3 设置与解锁

- 音频设置 API：获取/设置 总音量、音乐音量、音效音量（0–1），总静音；写入 `localStorage`，启动时读取恢复（§9.2）。
- 首次手势解锁：逻辑层在第一个用户手势时调用音频上下文的创建/恢复；需要一个"音频已解锁"状态供 Start 界面起播 BGM（§9.3）。
- 页面可见性变化时挂起/恢复，避免后台发声。

### 12.4 对 ASSET_PLAN 的输入

本文 §3 各条"声音性格/时长/对比关系"（尤其：受损声必须明显低于碎砖声、挡板位置音高映射区间、胜负乐句的反向走向、多砖合并的层次需求、BGM 无缝短循环）即为资源制作的行为需求，请 `ASSET_PLAN` 据此规划素材数量与规格；音频侧不提供、也不要求其提供超出这些行为的素材。
