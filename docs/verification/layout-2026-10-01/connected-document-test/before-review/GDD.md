- 文档语言：中文（游戏内玩家可见文字同样使用中文）

## 1. 首发范围

### 1.1 产品定位

一个小而完整、开箱即玩的街机风贪吃蛇：玩家在单一固定棋盘上操控一条持续移动的蛇，通过吃食物变长、得分，尽可能存活并追求高分，直到撞到墙壁或自身后结束，可立即重开。

### 1.2 首发必需内容

- 一个可游玩的网格棋盘与一条蛇。
- 一种常规食物：吃掉后蛇身增长、分数增加。
- 分数与历史最高分（本机持久化）。
- 随长度/时间推进的移动节奏加快（难度曲线）。
- 完整流程界面：开始界面 → 游戏中（可暂停）→ 游戏结束 → 重新开始。
- 键盘与触控两套输入，均能独立完成全部操作（开始、转向、暂停、重开）。
- 基础视听反馈：移动、吃食物、死亡、得分/破纪录的可感知反馈（具体形式由美术与音效文档定义）。

### 1.3 明确排除项（首发不做）

- 多种游戏模式、关卡选择、章节或结局。
- 特殊食物、道具、障碍物、加速带等任何额外棋子。
- 成长/养成、货币、商店、皮肤解锁、任务成就系统。
- 在线排行榜、账号、联网对战或异步社交。
- 可穿墙选项、地图尺寸/难度选项等设置项（单一静音开关不属于设置项，作为可用性底线保留，见 5.1）。
- 多人游戏。

### 1.4 完成条件（可在游玩中观察）

1. 进入应用后无需任何配置即可从开始界面开局。
2. 蛇按固定节奏自动前进，玩家输入能稳定改变其方向；吃到食物后蛇立即增长一节且分数增加，场上始终恰有一个食物。
3. 蛇头撞到墙体或自身时本局结束，进入游戏结束界面并显示本局得分。
4. 产生新的最高分时玩家能明确感知，且刷新页面后最高分仍然存在。
5. 玩家可从游戏结束界面一键重新开始；可在游戏中暂停并继续，或退出返回开始界面。
6. 使用键盘或触控单独完成上述全程，不发生反向自杀、转向丢失等规则性错误。

## 2. 玩家目标与核心循环

### 2.1 目标

- 短期目标：让蛇头移动到食物所在格将其吃掉。
- 单局目标：在不可避免的死亡来临前吃到尽可能多的食物，取得更高分数。
- 重复游玩目标：刷新本机历史最高分。

首发没有"通关"，单局以死亡为自然终点；高分纪录是唯一的跨局追求。

### 2.2 核心循环

```
观察蛇头与食物、自身、墙壁的相对位置
        │
        ▼
在下一步前进前输入转向（方向需合法）
        │
        ▼
蛇按当前节奏前进一格 ──► 吃到食物？
        │                    ├─ 是：增长 + 计分 + 刷新食物 +（按曲线）加快节奏
        │                    └─ 否：正常移动，蛇尾收缩
        │
        ▼
  撞墙或撞到自身？── 是 ──► 游戏结束（可重开）
        │
       否
        └──────► 回到观察
```

### 2.3 挑战与反馈

- 挑战来源：蛇只在离散的"步进"时刻转向且不能原地停留；身体随进食不断变长，可活动空间缩小；节奏随进程加快，留给观察和规划的时间减少。
- 核心张力：每一次进食都同时带来分数收益与更长身体带来的风险。
- 反馈：
  - 吃到食物：即时的得分跳变、蛇身增长、食物在新位置出现，以及明确的视听确认。
  - 节奏加快：玩家可主观感知移动变快；界面不强制显示具体速度数值。
  - 危险：撞墙/撞自身瞬间给出明确死亡反馈，随后展示结算。
  - 破纪录：当本局分数超过历史最高分时给予明确提示。

## 3. 棋盘、蛇与食物（可观察规则）

### 3.1 棋盘

- 游戏区域为一个正方形正交网格，行列数、格内视觉留白等具体数值见数值平衡文档。
- 网格四周为不可穿越的边界墙；所有蛇与食物始终占据整格，格与格一一对应，不存在半个身位或叠在同一格的状态。
- 棋盘以设计坐标（design coordinates）描述；实际渲染时按宿主窗口等比适配并保持正方形，不依赖固定宿主尺寸。

### 3.2 蛇

- 蛇由蛇头与若干蛇身段组成，每节占据一个网格格位，所有节互不重叠（除下文"同一步内尾位让出"这一瞬时情形）。
- 蛇持续朝当前朝向自动前进，玩家不能令其停止或后退。
- 初始长度、初始出生位置与初始朝向见数值平衡文档；出生时蛇身不与边界重叠，且蛇头前方存在足够的可活动空间。
- 每前进一步：蛇头进入朝向方向的相邻格；
  - 若该步**没有吃到食物**：蛇尾同时让出最后一节，蛇的总长度不变。
  - 若该步**吃到食物**：该步蛇尾不让出，蛇的总长度增加 1；随后在空位生成新食物。
- 增长只通过吃食物发生，首发无其他增长或缩短途径。

### 3.3 食物

- 场上任何时刻恰好有一个食物，占据一个网格格位。
- 食物被吃掉的同一步内，新食物即出现在一个**当前未被蛇占据**的空格中。
- 新食物的位置对玩家不可预测（不遵循可被利用的固定规律）。
- 除"蛇身所在格"外，新食物可出现在任意空格，包括紧邻蛇头的格——由此产生的风险属于游戏的一部分。
- 若棋盘被蛇填满（理论上的完美局），判定为胜利式结束：本局立即结束并按游戏结束流程结算，同时明确告知玩家达成了"棋盘填满"。这是首发唯一非死亡的单局结束方式。

## 4. 计分、节奏与难度

- 每吃到一个食物得 1 次分，单次分值为固定值（见数值平衡文档，首发不引入连击或浮动分值）。
- 移动节奏（每秒步进次数）随已吃食物数量沿一条固定曲线加快，存在上限；具体初值、递增方式与上限见数值平衡文档，本文不重复参数表。
- 节奏变化在吃到食物后的下一步起生效；同一步内节奏不发生中途变化。
- 分数在游戏中持续可见；历史最高分仅在被刷新时于本局结束后保持为新值。

### 持久化

- 持久化数据保存在本机（浏览器本地存储），共两项："历史最高分"与"静音开关"。静音的具体行为与降级策略以 `AUDIO_DESIGN` 第 5 节为准。
- 不持久化任何局内进度：关闭或刷新页面后再次进入，永远从开始界面、从初始蛇身开局。
- 当本地没有历史纪录时，历史最高分视为 0，且首次开局不显示"破纪录"提示。

## 5. 玩家动作与系统交互判定

### 5.1 可用动作

| 动作 | 键盘/鼠标 | 触控 | 后果 |
|---|---|---|---|
| 开始游戏 | 在开始界面按确认键（空格/回车）或点击开始按钮 | 点击开始按钮 | 进入游戏中 |
| 转向 | 方向键或 W/A/S/D | 在棋盘区域滑动（swipe）或按屏幕方向按钮 | 改变下一步前进朝向（规则见 5.2） |
| 暂停/继续 | 空格 或 P；点击暂停按钮 | 点击暂停按钮 | 游戏中 ↔ 暂停 |
| 重新开始 | 游戏结束界面按确认键或点击重开按钮 | 点击重开按钮 | 以初始状态开启新一局 |
| 退出本局 | 暂停界面中的退出按钮/按键 | 暂停界面退出按钮 | 返回开始界面 |
| 静音开/关 | 开始界面与 HUD 右上角静音图标 | 同左 | 切换全部音效静音；状态本机保留（详见第 4 节） |

转向是四方向（上、下、左、右）的离散选择；鼠标仅承担界面点击，不用来指向移动。具体按键映射、触控热区与手势容差在交互契约文档中定义，本文只规定规则后果。

### 5.2 转向规则（关键判定）

1. 玩家输入不立即移动蛇，只决定**下一次步进**采用的朝向。
2. 不允许 180° 反向：当蛇正在（或下一步即将）朝某方向运动时，直接相反方向的输入被忽略。例如朝右运动时"左"无效，但在同一步进间隔内先按"上"再按"左"，可依次排队为"先上、再左"。
3. 为支持快速连续操作，玩家在一个步进间隔内可缓存至多一个后续转向（即"下一步朝向 + 一个再下一步朝向"两级），每个待执行转向都相对于它实际执行时的前一朝向做合法性校验；超过缓存容量的更早输入被丢弃。
4. 每个步进时刻至多消费一个待执行转向。停顿或节奏快慢不改变上述顺序，避免"快按两键导致原地反向自杀"。
5. 暂停期间的转向输入不进入缓存（或在继续时被清空），玩家不能通过暂停预排路线。

### 5.3 同一步内多种结果的同时性裁决

按以下顺序在一次步进中一次性裁决，玩家观察到的是裁决后的稳定结果：

1. 确定本步实际朝向（消费一个合法转向输入）。
2. 确定蛇头将进入的目标格。
3. 判定目标格当前是否有食物。
4. **碰撞判定**：
   - 目标格在边界之外 → 死亡。
   - 目标格被蛇身占据 → 死亡；**例外**：若本步没有吃到食物、蛇尾会在本步让出其格，而蛇头进入的正是该尾格，则不判定为撞身（尾先让出）。
   - 吃到食物的一步蛇尾不让出，因此进入当前尾格一律按撞身处理。
5. 未死亡时提交移动：有食物则保留尾节（增长）、加分、在空格刷新食物并按曲线重估节奏；无食物则尾节收缩。
6. 若新食物已无空格可放（棋盘填满），进入 3.3 的填满结束。

即：**墙与身的碰撞以"步进后的格位占用"为准，尾格让出与头部进入在同一步内不构成碰撞；进食那一步除外。**

### 5.4 过渡期间什么算一次交互

- 步进之间（蛇停在格上等待下一步）：转向输入按 5.2 缓存；暂停、退出随时可响应。
- 死亡瞬间到游戏结束界面出现之间：忽略一切转向输入；重开/退出输入只在结算界面可交互后生效，死亡动画或过渡期间的提前连点不触发重开。
- 暂停期间：步进计时完全冻结，继续后剩余的步进间隔不因暂停时长而改变（暂停不帮玩家"卡时间"，也不惩罚玩家）。
- 开始界面与游戏结束界面：不存在局内步进，转向输入无效果。

## 6. 游戏状态与流转

| 状态 | 进入条件 | 允许动作 | 转出 |
|---|---|---|---|
| 开始界面（入口） | 应用启动；或从暂停中退出本局 | 开始游戏 | → 游戏中 |
| 游戏中 | 从开始界面开局；从暂停继续 | 转向、暂停 | → 暂停；→ 游戏结束（死亡或填满） |
| 暂停 | 游戏中触发暂停 | 继续、退出本局 | → 游戏中；→ 开始界面 |
| 游戏结束 | 撞墙/撞身死亡，或棋盘填满 | 重新开始、返回开始界面 | → 游戏中（新一局）；→ 开始界面 |

- 每次"重新开始"和从开始界面开局都重置为完全相同的初始状态（初始蛇身、初始朝向、初始节奏、分数为 0、场上一个食物）；首发无任何随局数变化的差异、解锁或随机种子选项。
- 游戏结束界面必须展示：本局得分、历史最高分；刷新纪录时给出明确标识；棋盘填满结束时给出区别于普通死亡的文案。
- 浏览器刷新/关闭等同于离开：再次进入恒为开始界面，历史最高分保留。

## 7. 系统协作关系与数据约定

- **节奏系统**驱动步进时刻；步进是唯一的裁决时刻，转向、移动、进食、碰撞、计分、食物刷新均在步进内按 5.3 顺序完成，不存在步进进行到一半的可交互中间态。
- **输入系统**只产出合法的转向意图与界面指令，不直接移动蛇；合法性以 5.2 为准。
- **食物系统**的刷新依赖蛇身占用结果，因此总是在移动裁决之后完成。
- **分数系统**订阅进食结果更新分数，并在局末与历史最高分比较、写入持久化。
- **界面系统**呈现分数、状态切换与全部操作入口；界面布局与状态可见性以 Scene/UI JSON 为可编辑数据源。

### 平台数据约定

- 场景层级、节点变换、UI 布局、响应式变体与资源绑定均以作者态的 Scene/UI JSON 为唯一可编辑来源；运行时代码加载/编译这些数据并实现玩法，不用代码常量替代上述作者决策。
- 本文中的网格尺寸、布局描述均为设计坐标，适配规则由内容管线与界面文档落实。
- 具体数值参数（网格行列数、初始长度、初始速度、加速曲线、速度上限、食物分值）统一以数值平衡文档为权威来源，本 GDD 不维护重复参数表。
