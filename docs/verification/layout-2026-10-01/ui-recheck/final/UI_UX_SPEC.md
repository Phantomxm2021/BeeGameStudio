## 1. 目的与边界

本文定义首版**全部**玩家可见界面的完整交互与布局：开始界面、游戏屏幕（含 HUD 与待发球提示）、暂停覆盖层、胜利/失败结算、加载错误界面。每个屏幕给出进入/退出条件、元素与信息层级、内容来源、行动与结果、控件状态，以及容器尺寸变化时的行为。

本文不重述玩法规则（GDD）、不重复世界几何表（LEVEL_SCENE_DESIGN）、不定义颜色与材质细节（ART_DIRECTION）、不列资产清单（ASSET_PLAN）。所有布局以作者化 UI JSON 为唯一可编辑源；运行时只读取并绑定，不用代码常量取代作者化决策。

## 2. 全局坐标与尺寸约定

### 2.1 坐标系与单位

- 屏幕 UI 坐标：**原点左上角，+X 向右，+Y 向下**，单位为**逻辑像素**（设计坐标），非设备物理像素。
- 节点 `layout.position` 为相对父矩形锚点的父级局部偏移；最终矩形 = 父矩形 × 锚点关系 + position，再按 pivot 对齐。嵌套节点只使用父级局部坐标，不使用已累加的全局坐标。
- 旋转角为弧度，y-down 平面正值为顺时针；pivot 默认与锚点相同，禁止隐式 [0,0]。
- 固定尺寸控件用 `anchor + position + size`；拉伸区域用成对 `anchorMin/anchorMax + sizeDelta`，解析尺寸 = 父尺寸 ×（anchorMax−anchorMin）+ sizeDelta。
- 世界链（480×672 场地）与 UI 链（屏幕逻辑像素）相互独立，只在 `game-view` 节点发生关系：UI 链提供 game-view 宿主矩形，世界相机在其内 letterbox 取景（TECHNICAL_DESIGN §6）。

### 2.2 参考分辨率与支持范围

| 项 | 值 | 含义 |
|---|---|---|
| 参考分辨率 | **960 × 540**（桌面横屏浏览器） | 表达基准构图，非固定运行时尺寸 |
| 最小支持容器（横） | **320 × 480** | 小窗口/小横屏 |
| 最小支持容器（竖） | **320 × 568** | 小手机竖屏 |
| 代表竖屏 | 390 × 844 | 主流手机 |
| compact 阈值 | `compactMaxWidth = 600` | 视口宽 ≤ 600 命中 compact |

**变体选择与优先级（互斥、按序判定，无前缀合并）**：

1. 视口宽 ≤ 600 → **compact** 变体覆盖基线；
2. 在 compact 解析结果之上，若高 > 宽 → **portrait** 再覆盖；
3. 其余 → 基线。

未覆盖字段逐层继承。输入能力（有无触屏）与视口形状（宽高比）是两个独立事实：触屏不自动选择竖排构图，竖屏也不改变按键映射。两个参考点之间（如宽 601–959）沿用基线，元素按其锚点/容器关系自然伸缩，不产生第三种构图。

### 2.3 屏幕层级（screen-space layering，自下而上）

| 层 | 内容 |
|---|---|
| L0 背景 | 近黑底/网格/光晕（世界画布或 DOM 背景） |
| L1 游戏视图 | game-view 内 Canvas 世界 |
| L2 HUD | hud-bar（分数/暂停/生命）、serve-prompt |
| L3 覆盖层 | overlay-pause / overlay-result 的暗压底 |
| L4 模态卡片 | pause-panel / result-panel 及其子控件 |

## 3. 共享组件（唯一定义）

### 3.1 按钮（Button）

- 视觉：中档圆角矩形，深色填充 + 1×U 深色压边描边；主按钮用青色（ART §3.3 主调）+ 轻辉光，次按钮无青色填充、仅细边框。
- 最小可点区域：**44 × 44**（触屏命中），视觉体可小于命中区但命中盒不小于 44。
- 状态：

| 状态 | 表现 | 触发 |
|---|---|---|
| default | 上述常态 | — |
| hover | 明度 +8%，描边不变 | 鼠标悬停（触屏无此态） |
| focus（键盘焦点） | 外侧 2px 青色焦点环 + 轻辉光 | Tab/方向键导航到达 |
| active/pressed | 明度 +14%，100–150 ms 内回弹 | 按下 |
| disabled | 明度 −40%、无辉光、点击无反馈不发声 | 行动在当前相位不可用 |

- 激活成功才播放 `sfx.ui.confirm`；disabled 点击不发声。焦点移动播放 `sfx.ui.focus`（鼠标不触发）。

### 3.2 文本

- 标题：几何/电子感无衬线，允许描边+辉光（标题专用）。
- 正文/HUD/按钮：中性无衬线，纯色 + 必要深色投影，**不加辉光**；数字近等宽。
- 字号在 UI JSON 的 `style.fontSize` 中以逻辑像素声明；HUD/结算数字以右对齐或居中对齐，跳动不左右抖动。

### 3.3 模态卡片（Modal card）

- 大圆角、深色填充、细外框、柔和投影；本身不发光或仅极轻辉光。
- 内部为纵向 column 容器：padding **[20,20,20,20]**，gap **12**，子项水平居中；顺序固定为「标题 → 信息文本（可空）→ 按钮组」。

### 3.4 HUD 条带（HUD bar）

- 固定高 **48**，row 容器，padding **[8,12,8,12]**，gap 8，`justify: space-between`，`align: center`；水平随父拉伸，垂直固定不缩。

## 4. 共享页面布局

### 4.1 模态覆盖布局（pause/result 共用）

```
root（全屏拉伸）
 └─ overlay（anchorMin[0,0] anchorMax[1,1]）
     ├─ 暗压背景（全屏，黑色 60% 不透明；由容器自身背景承担）
     └─ panel（anchor middle-center, position [0,0]；
               基线 300 宽，minSize 宽260；column，见 §3.3）
```

- 卡片始终锚中、固定尺寸（宽 300；暂停面板高 220，结算面板高 260）；最小支持容器（320 宽）下卡片仍完整在视口，不使用 minSize 收窄；内边距与 gap 固定、按钮保持 44 高——**不缩放卡片、不裁剪文字**。`minSize: 宽260` 仅为解析下限声明，首版尺寸区间内不触发。
- 暂停与结算的差异仅在卡片内容与标题配色（见 §7、§8）；布局完全同一。

### 4.2 游戏屏幕布局（含 HUD 的组合足迹）

```
root（全屏）
 ├─ game-view（anchorMin[0.02,0.02] anchorMax[0.98,0.98]，拉伸；
 │             内含 Canvas，相机 letterbox 呈现 480×672 世界）
 │   ├─ hud-bar（锚 game-view 顶：anchorMin[0,0] anchorMax[1,0]，高48）
 │   │   ├─ hud-score（左，132×24，可 shrink 至 96）
 │   │   ├─ pause-btn（中，72×32）
 │   │   └─ hud-lives（右，108×24，可 shrink 至 96）
 │   └─ serve-prompt（**取景绑定**：以世界坐标作者化 (中心x240, y568, 240×24)，
 │                   运行时经相机 letterbox 换算定位，见下）
 └─ overlay-pause / overlay-result（全屏，仅对应相位启用）
```

- **game-view 拉伸**：随容器变化，始终保留 2% 四周外边距；世界在其内 letterbox，玩法区恒完整（LEVEL_SCENE_DESIGN §2.1）。
- **hud-bar 拉伸**：水平跟 game-view，垂直固定 48；信息不足时 score/lives 文本收缩（shrink 1，下限 96），pause-btn 固定不缩。竖屏 letterbox 顶部留边较大时 HUD 位于该留边投影区——此为本文保留的屏幕空间分配：留边上下带被预留给 HUD（文字不加辉光），规则与 ART_DIRECTION §4.4、LEVEL_SCENE_DESIGN §2.2 一致。
- **serve-prompt 取景绑定**：作者化于**世界坐标**——中心 x=240、顶边 y=568、尺寸 240×24（底边 y=592，距挡板顶面 y=620 恰好 28 世界像素），运行时用 TECHNICAL_DESIGN §6.3 的 offX/offY/scale 把该矩形换算到屏幕 DOM。因此任何宽高比下提示相对挡板的位置恒定，不随 game-view 锚点漂移；它不是按钮，44 命中下限不适用。
- **overlay 固定全屏**：与 game-view 尺寸无关。
- 组合足迹已按 game-view（含 2% 外边距）+ HUD（占用 game-view 内顶部 48）+ prompt + 覆盖层一并计算，非各自独立估算（见 §9）。

## 5. S1 开始界面

- **进入**：页面加载完成（Bootstrap 成功）；或从暂停菜单/结算"退出"返回（T8/T10）。**退出**：点"开始游戏"或确认键 → T1，装载新一局进入待发球。
- 无任何后台模拟。
- **布局**：全屏暗背景；中央固定居中列 `menu-column`（基线 360×360，maxSize 420；column，gap 16，padding 16，居中），子节点文档序：
  1. `menu-title`「打砖块」320×56 —— 绝对视觉焦点，标题字 + 描边辉光，灰度下跳出一切元素；
  2. `mini-wall` 迷你砖墙（grid 8 列，16 块 30×10 小砖，gap 2）—— 母题暗示"这些砖由你击碎"；
  3. `menu-instructions`「移动挡板反弹小球，击碎全部砖块」320×44 —— 次级信息，安静、明度低；
  4. `btn-start`「开始游戏」200×48，青色主按钮 —— 唯一主行动。
- **构图意图（ART §5.1 落地）**：先看到标题（最高亮）→ 再看到砖墙母题 → 操作说明退居第三；大面积暗场留白建立纵深，不铺满装饰。
- **内容来源**：文案写死于 UI JSON（首版无本地化框架）；迷你砖由图集 `RES-SPRITE-GAMEPLAY` 的 `brick` 帧绑定 + 运行时按列/行着色，无独立主视觉图片（ASSET_PLAN §4.1）。
- **动效**：入场时迷你砖自左至右、自上而下逐块点亮（一次性，总时长约 600–800 ms）；reduced motion 下改为全部淡入（200 ms）。
- **响应式**：宽 ≤ 600（compact）时列收为 280×332，子节点对应收窄（标题/说明 248，迷你墙 222，按钮 248）；竖屏继承 compact 结果，不另排。宽屏（>600）下列宽固定不拉伸，仅居中。

## 6. S2 游戏屏幕（游玩相位）

- **进入**：T1/T9 完成后进入"待发球"；**退出**：进入暂停（覆盖层叠加，不离开本屏幕）或 T4/T5（结算覆盖层）。
- **HUD（hud-bar，L2）**：

| 元素 | 内容 | 内容来源 | 绑定/刷新 |
|---|---|---|---|
| hud-score | 「分数」+ 4 位数字（0000–4000） | GameStore 当前分 | 每次销块当步即时刷新；数字小幅上跳强调（200 ms） |
| pause-btn | 「暂停」文字按钮 | — | 激活 → T6 |
| hud-lives | 「生命」+ ♥×当前生命（1–3） | GameStore 生命数 | 扣命当步即时减少，失去的 ♥ 变暗/破碎消退（约 300 ms） |

- **待发球提示 serve-prompt（L2，仅待发球相位，取景绑定）**：文案「按 空格 / 点击 发球」，作者化世界矩形为中心 x=240、y=568–592、宽 240（距挡板顶面 28 世界像素），暖白强调色轻微呼吸（1.2–1.6 s 周期）；发球（T2）后立即隐藏，复位（T3）后重新出现。球此相位静止贴附，提示不构成玩法遮挡（LEVEL_SCENE_DESIGN §2.2 例外条款）。
- **相位—可见性矩阵**：

| 相位 | 世界 Canvas | HUD | serve-prompt | 暗压覆盖 |
|---|---|---|---|---|
| 待发球 | 静态（球贴附呼吸） | 可见 | 可见 | 无 |
| 球运动中 | 动态 | 可见 | 隐藏 | 无 |
| 已暂停 | 冻结（辉光降温） | 被暗压 | 冻结/隐藏 | 可见 |
| 胜利/失败结算 | 冻结 | 被暗压 | 隐藏 | 可见 |

- **构图意图**：运动中球是全场最亮点（L5 + 唯一正圆 + 短拖尾），挡板次之（青色 L4），HUD 信息安静贴顶、绝不与球争注意；顶部条带之外不允许任何屏幕 UI 进入机动空间。

## 7. S3 暂停覆盖层

- **进入**：待发球/球运动中按 Esc/P 或点 pause-btn（T6），含页面失焦自动暂停。**退出**："继续"或再次暂停操作 → T7 恢复来源相位；"退出本局" → T8 回开始界面（不保留分数）。
- **元素**（§4.1 模态布局，卡片 300×220）：`pause-title`「已暂停」（中性色，无辉光）→ `btn-resume`「继续」（青色主按钮，默认焦点）→ `btn-quit-run`「退出本局」（次按钮）。
- 进入时世界快速暗压（120–180 ms）、辉光降温、一切动效停止；音效 `sfx.pause.open` 后全部声音截断；暂停期间不接受任何移动/发球输入。退出反向恢复（`sfx.pause.close`），不补发暂停期间位移与声音。
- **响应式**：卡片 300×220、按钮 200 宽为固定作者值；在最小支持容器 320 宽下仍有 10px 两侧余量（见 §12），因此 compact 不缩窄卡片，保持 44 高不缩放。

## 8. S4/S5 胜利与失败结算

- **进入**：T4（场上砖块为 0，胜利即时生效）/ T5（最后一命扣减）。**退出**："再来一局" → T9（同一 `createRun()` 完全重置）；"退出" → T10 回开始界面。
- **共用布局**（§4.1，卡片 300×260）：结果标题 → 最终分数 → 两个按钮。

| 项 | 胜利 S4 | 失败 S5 |
|---|---|---|
| 标题文案/配色 | 「通关成功」，暖色强调 + 辉光（全场情绪高点） | 「游戏结束」，中性冷色、明度低于胜利，不用红底/大面积红橙 |
| 最终分数 | 「最终分数」+ 数字，L5 高亮，一次从 0/当前值滚动结算到最终值（约 600 ms） | 同样清晰展示，无结算动效或仅一次淡入 |
| 主按钮 | 「再来一局」青色，默认焦点 | 同左——视觉上鼓励立即重试 |
| 次按钮 | 「退出」 | 「退出」 |
| 进入瞬间表现 | 砖墙位置光爆余韵、背景短时提亮转暖再回落（≤800 ms，压低不透明度） | 光向下/向心收束、一次短促暗压（红橙仅失球点短暂出现）后归于平静 |

- 对应乐句 `sfx.game.win`（约 900–1400 ms）/ `sfx.game.over`（约 700–1100 ms）；乐句放完后面板保持安静等待操作。结算期间场地移动/发球输入一律忽略，按钮始终可响应。
- **响应式**：卡片 300×260、按钮 200 宽为固定作者值；最小支持容器 320×480 下卡片 (10,110)→(310,370) 完整在视口（见 §12），compact 不缩窄；分数数字不缩字号，近等宽与固定文本框保证不抖不裁。

## 9. S6 加载错误界面

- **进入**：启动期 index/场景/UI/调值 JSON 拉取或解析失败，或必需绑定缺失之外的可重试错误（TECHNICAL_DESIGN §7.2）。**退出**：点"重试"重新执行启动装载；成功后进入开始界面。
- **元素**：居中列：标题「加载失败」→ 一行错误简述（中性、不展示技术堆栈）→「重试」主按钮（44 高，默认焦点）。无背景装饰、无自动重试。
- 必需绑定缺失（找不到 paddle/ball/brick/death-boundary 等）为 fail-fast 开发者错误，不进入本界面。图片资源非必需失败时不触发本界面，以降级呈现继续。

## 10. 输入、焦点与导航

### 10.1 键盘/鼠标

| 操作 | 按键 | 可用相位 |
|---|---|---|
| 移动挡板 | ←/→ 或 A/D（按住） | 待发球、球运动中 |
| 发球 | 空格（边沿，一次） | 待发球 |
| 暂停/继续 | Esc / P | 待发球、球运动中、已暂停 |
| 焦点移动 | Tab（开始界面/覆盖层上） | 非运动操控场景 |
| 激活焦点控件 | Enter / Space | 焦点在按钮上时 |

- 开始界面与所有覆盖层出现时，焦点自动落到主按钮（开始游戏/继续/再来一局/重试），支持纯键盘完成全部流转。焦点环为唯一焦点指示，不依赖颜色。
- 鼠标：水平移动映射挡板（指针直接映射，无速度上限）；点击 = 发球（待发球）/按钮激活。运动中不显示文本光标，game-view 设 `cursor` 为默认或隐藏。

### 10.2 触屏

- 在 game-view 内按住并水平拖拽 → 挡板映射到指针 x（场地夹取）；点按（无拖拽）→ 发球。
- game-view 设 `touch-action: none`，非被动监听阻止页面滚动/双击缩放；拖拽采样在帧内统一消费。
- 全部按钮命中盒 ≥ 44×44；拖拽与按钮触摸互不冲突（按钮位于 game-view 外的 HUD/覆盖层）。
- 移动端 URL 栏伸缩/旋转按容器变化处理，触发自动暂停规则不变。

### 10.3 自动暂停

`visibilitychange` 隐藏或窗口失焦（去抖）时，在待发球/球运动中自动进入暂停（`pausedReason=auto`）；恢复必须由玩家显式点"继续"，不在 focus/visible 时自动续球。

## 11. 转场与反馈规格（目的/触发/外观/时序）

| 反馈 | 目的 | 触发 | 外观 | 时序要求 |
|---|---|---|---|---|
