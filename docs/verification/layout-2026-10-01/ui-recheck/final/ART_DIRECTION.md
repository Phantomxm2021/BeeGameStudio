## 1. 目的与边界

本文把 GDD 确定的"风格化（Stylized）"落成**可执行的视觉方向**：形状语言、色彩、明度、材质、细节密度、字体气质、动态特征，以及各屏幕与各游戏对象的视觉身份与层级规则。

本文**不做**的事：

- 不写 UI 空间排布、锚点、尺寸、字号数值——归后续批次的 UI_UX_SPEC；
- 不列资产清单、不规定每个素材的生产路径（手绘/生成/检索/程序化均可）、不做概念图——归 ASSET_PLAN；
- 不新增任何玩法内容：无道具、无特殊砖块、无多关卡、无多球，范围严格限于 GDD 首版；
- 不重复 GDD 的规则描述，仅定义这些规则的**视觉表达**。

技术基线（来自 GDD 与内容格式约定，视觉设计必须服从）：Web · React · 2D；输入键盘/鼠标与触屏；设计坐标 480×672 逻辑像素、原点左上、+X 右 +Y 下，pixelsPerUnit=100；正交摄像机 letterbox 取景，游戏视图在宿主中拉伸留边；HUD 位于游戏视图内顶部；UI 绘制顺序为背景/描边 → 节点内容 → 子节点（文档顺序），背景不得覆盖内容。

**验收状态声明**：960×540 与 390×844 两视口下节点几何已验证不越界；但**文本度量未实测、视觉验收未做**，本文不对任何视觉效果的实际呈现作已完成声明。

## 2. 视觉主题：霓虹夜色街机（Neon Night Arcade）

### 2.1 选定方向与理由

选定**霓虹夜色街机**方向：深夜暗场 + 高饱和霓虹主体 + 统一外发光，整体气质是"一台在暗处发光的老式街机柜"。

理由：

1. **可读性天然适配玩法**。打砖块的核心观察对象是高速小球与砖块边界，暗背景上的亮主体轮廓分明、运动轨迹易追踪，长时间盯球不疲劳。
2. **关键信息层级与明度天然一致**：亮的球/挡板在暗场上最突出，砖块次之，背景最暗——美术层级即玩法重要性层级，不需要靠颜色硬分。
3. **主题与"一击即碎"的爽感匹配**。霓虹砖块碎裂时的光爆、暗场中的亮点扩散，是低成本高回报的反馈语言，也契合 Web 2D 的实现体量（纯色、描边、发光均可程序化表达，不依赖重资产）。
4. **记忆点明确**：暗夜里的一面发光砖墙 + 一颗拖着光尾的球，单一母题即可贯穿开始界面、游戏与结算。

不选柔和糖果积木风的原因：高明度浅色场会让高速小球的对比度与追踪性下降，且危险（死亡边界）在糖果语汇中缺少自然的表达位置；霓虹方向中"无光的深渊"本身就是危险语义。

### 2.2 情绪曲线

- 开始界面：夜幕中一整面砖墙被逐块"点亮"，期待、蓄势。
- 待发球：球安静贴在挡板上，发光呼吸，像充能完毕。
- 球运动中：全场最亮的点高速穿行，节奏紧张、专注。
- 暂停：世界冻结、辉光降温、噪声静止，从紧张中抽离。
- 胜利：砖墙位置只剩一片渐次熄灭又重新点亮的光，释放、明亮上扬。
- 失败：光向下沉没、暗场吞没，短促下沉后归于平静，鼓励重开。

## 3. 视觉语言基础（一致性标准）

以下标准适用于一切来源的素材（生成、检索、程序化），任何素材在进入项目前必须满足。具体素材清单与生产路径不在本文规定。

### 3.1 形状语言

- **一切几何为圆角矩形/圆形，不出现锐角与有机不规则形**。圆角传递街机塑料与霓虹灯管的质感，也与"安全、可碰"的语义一致。
- 圆角半径分三档语义区间（实际数值由 UI_UX_SPEC / ASSET_PLAN 按对象尺寸标定，此处只定区间关系）：
  - 小档：砖块、小型 UI 控件——轻微圆角，远看接近矩形以保证排列整齐；
  - 中档：挡板、按钮——明显圆角，强调"可握持/可按"；
  - 大档：面板、覆盖层容器——大圆角，卡片/机柜屏幕感。
- 球是全场唯一的**正圆形**主体，形状本身即"高速单体"的身份标识，不允许任何其他对象使用纯圆形主体（图标内可用）。
- 禁止使用三角形、尖刺形等形状表达危险（危险由"无发光的黑暗 + 警示条纹"表达，见 §5.2）。

### 3.2 描边（统一标准）

- 所有游戏主体（挡板、球、砖块）与关键 UI 控件使用**统一的描边粗细基准 U**（单一基准值，实际值在 ASSET_PLAN 锁定），允许的变化只有：主体 = 1×U，小图标 = 0.75×U，大面板外框 = 1.5×U；不允许中间值。
- 描边一律为**比填充更深的同色系深色描边**（深色压边，保证亮主体之间相接时轮廓不糊），霓虹发光是描边外侧的第二层效果，不用亮色当描边。
- 描边转角与对象圆角一致，直角描边不允许出现。

### 3.3 调色板（色板用法）

采用"近黑夜空底 + 一个冷色主调 + 一组砖块霓虹色 + 一个暖色强调"的受控色板。

| 角色 | 色相方向 | 用法 |
|---|---|---|
| 背景底 | 蓝紫近黑（冷） | 场地底色、letterbox 区域，面积最大、明度最低 |
| 背景辅 | 深青/深紫 | 背景网格、远景光晕、渐变，仅作层次 |
| 主调（安全/主角） | 青色（cyan） | 挡板专属；开始界面与主按钮可共用，建立"青色=你能控制的东西" |
| 砖块色组 | 洋红、紫、暖粉、琥珀等高饱和霓虹色 | 砖块按行分布于色组内循环；**同种砖块玩法上无差异，颜色只做节奏与装饰** |
| 强调/能量 | 暖白偏黄 | 球的核心高光、发球提示、分数跳字；全场最亮的小面积色 |
| 危险 | 红橙（仅警示线使用） | 只出现在底边死亡边界的警示元素，其他任何元素不得使用红橙色 |

用法规则：

- 任何一屏同时出现的砖块高饱和色相不超过色组总量，按行有序循环，不随机跳色；
- 青色（主角）与暖白（球/强调）不得用于砖块，保证挡板与球在砖墙前永远能被一眼挑出；
- 红橙色严格保留给死亡语义，宁可整屏无红橙，也不拿它做装饰；
- letterbox 留边区域使用比场地底更暗或同明度的纯色，不与场地争亮。

### 3.4 明度层级（关键，优先于颜色）

定义固定明度阶梯，所有对象先在明度阶梯上对号入座，再谈色相：

1. **最高（L5）**：球核心、发球提示、分数跳字——小面积、全场最亮；
2. **高（L4）**：挡板主体与描边外发光——玩家化身，稳定高亮；
3. **中高（L3）**：砖块填充——亮但不压过挡板与球；
4. **低（L2）**：背景网格、远景光晕、三边反弹墙——可察觉但退后；
5. **最低（L1）**：场地底、letterbox、死亡边界区域——近乎纯黑。

设计检查口径：把画面转成灰度，球与挡板必须最亮、砖块次之、背景退到底；若灰度下分不清对象，该配色不合格。**关键信息绝不只靠颜色承载**：挡板靠"青色 + 最长圆角横条 + L4 稳定辉光"，球靠"唯一正圆 + L5 最高明度 + 拖尾"，砖块靠"圆角矩形阵列 + L3 + 行内色相"，死亡边界靠"L1 黑暗 + 红橙警示条纹 + 形状断裂（无墙体）"四重区分，任何单一通道失效（色弱、暗光截图、小屏）时仍可辨别。

### 3.5 发光与阴影

- 发光（外辉光）是本主题的核心材质语言，但**分对象收敛使用**：
  - 球：最强、带方向性拖尾（运动中）/呼吸辉光（贴附时）；
  - 挡板：稳定中等辉光，不随运动拖尾；
  - 砖块：轻辉光，只够把砖块从背景里"提"出来，避免整面砖墙亮成一片（这是主要风险点，整墙辉光需按整体压暗处理）；
  - UI 主按钮/焦点：轻辉光，与砖块同级或更低；
  - 背景元素：**不发光**，只接受来自前景的假光照渐变。
- 辉光颜色取对象自身色相，不出现白光包边（球除外，球核心允许暖白）。
- 阴影：2D 风格下只使用**柔和的投影/环境闭塞**表达层次（如砖块在底面上的微弱暗边、面板在暗场上的暗影），不做写实投影、不做硬边长阴影。

### 3.6 材质与质感

- 材质气质：哑光深色底 + 霓虹灯管/发光塑料主体，**平面化、无写实质感**。
- 允许的质感细节：轻微的自上而下的明暗渐变（塑料体积感）、发光体中心到边缘的亮度衰减、开始界面与面板上极轻微的扫描线/机柜质感暗示。
- 禁止：金属反光、木纹、布料、照片纹理、拟物磨损、复杂法线细节。所有质感必须在缩小到移动端尺寸后退化为干净的纯色块与描边。

### 3.7 细节密度

- **远看是色块，近看才有细节**：对象在正常游玩视距下只呈现形状+填充+描边+辉光；细节（表面一道高光、砖块内隐约的次级纹样、面板扫描线）只在静止或大尺寸时可见。
- 单个对象上的细节元素不超过 2 层（如砖块 = 基础渐变 + 一道顶部高光，不再加纹理/图案/字符）。
- 砖块内**不写字、不标分值**，保持整墙节奏统一。
- 背景细节密度最低：网格 + 少量远景光晕即可，禁止可识别的叙事性图案（招牌文字、人物剪影等），避免与球的轨迹争夺注意。

### 3.8 字体气质

- 中文标题字体气质：**几何感、笔画干净、略带街机/电子感的无衬线**（笔画等粗或弱对比，字形方正、字面偏大），不使用书法体、手写体、衬线体。
- 正文/HUD：中性、清晰的现代无衬线，保证小字号数字（分数）与触屏小尺寸下的可读性。
- 数字（分数、生命数）要求字形等宽或近等宽，跳动时不左右抖动。
- 允许标题字做发光/深色压边处理（与主体同一套描边+辉光），正文字只允许纯色 + 必要时深色投影，不加辉光（小字辉光会糊）。
- 实际字体文件（开源中文字体的具体选择、字重、子集化方案）未定，见 §9。

## 4. 分层架构

分三个独立图层 + 一个 letterbox 外围层。各层必须独立于 Scene/UI 数据可单独调整明度与透明度，便于在不影响玩法层的情况下调整背景与特效强度。绘制顺序遵循内容格式约定：先背景后内容、后绘制者覆盖。

### 4.1 背景层（最远）

- 内容：近黑底色（可带极弱的垂直/径向渐变）、低明度网格线（呼应砖墙与街机机柜的几何感）、少量深青/深紫远景光晕。
- 明度 L1–L2，**无发光、无高饱和色**。
- 静态或极缓慢运动（如光晕缓慢呼吸），任何背景运动速度必须远低于球速，避免产生"背景在打球"的错觉。
- 透明度：整体不透明为主；网格线以低透明度叠在底色上。
- **平铺需求**：背景需以可平铺/可安全裁切的方式制作，中心区域可有最弱的视觉焦点，但关键纹理不得依赖固定构图——letterbox 在不同宽高比下会改变可见区域（960×540 横屏看到更宽、390×844 竖屏看到更窄更长），任何宽高比下背景都应自然填满、无拉伸感、无接缝、无被裁掉一半的醒目元素。

### 4.2 游戏层（中景/玩法层）

- 内容：三边反弹墙、砖块墙、挡板、球。
- 层次分离在**同一层内用明度与辉光强度**完成：反弹墙 L2 → 砖块 L3 → 挡板 L4 → 球 L5。
- 三边反弹墙与底边必须视觉断裂：三边是"有厚度、有微弱冷色边缘光的实体"，底边**没有实体墙**，只有深色虚空与死亡警示元素（见 §5.2），让玩家不用读规则就能感到"底边不一样"。
- 不透明。砖块之间的间隙露出背景，间隙保持干净（不加装饰），维持整墙的呼吸感。

### 4.3 前景特效层（最近）

- 内容：砖块碎裂光爆与碎片、球的拖尾、挡板击球瞬间的冲击光、失球/胜负的全屏表现、发球提示、HUD 分数跳字等一过性表现。
- 独立于游戏层，不参与碰撞、不改变任何对象的几何与判定（表现动画不延迟规则，与 GDD §5 一致）。
- 透明度策略：平时该层为空/全透明；事件触发时短暂出现并快速衰减。全屏特效（失球闪暗、胜利光涌）必须压低不透明度且时间短，**不得遮挡球与挡板的可读性**，游玩中不允许长时间存在的前景元素。
- 碎裂碎片可以飞出游戏层区域但不进入 letterbox 外围（或在游戏视图边缘自然衰减消失）。

### 4.4 letterbox / 外围层

- 摄像机 letterbox 与游戏视图拉伸留边（宿主内 anchor 0.02–0.98）产生的边缘区域使用背景层的延伸或更暗纯色，明度 ≤ L1。
- 屏幕空间分配以 UI_UX_SPEC 为准：摄像机 letterbox 的**上下留边带被预留给 HUD/发球提示等无辉光文本 UI**（纯文字、无发光元素、无动画），因此该保留带不是"一律空"；除此之外的留边区（尤其横向两侧）仍不放任何玩法信息、发光元素或动画。文字明度与暗底对比由 HUD 规格保证。

## 5. 各屏幕与对象的视觉身份

本文只定义视觉身份与情绪，不定义位置/尺寸/对齐——后者归 UI_UX_SPEC。

### 5.1 开始界面

- **主视觉母题**：一面在夜色中发光的霓虹砖墙为画面主体，球与挡板的组合在砖墙下方作为"蓄势"元素；标题与砖墙母题重叠或紧邻，形成"标题即嵌在街机机柜上"的感觉。
- 标题是绝对视觉焦点：使用标题字气质 + 与挡板同语言的描边和辉光，明度高于砖块（灰度下标题必须跳出砖墙）。
- 入场可做砖墙逐块点亮的一次性动效，建立母题并暗示目标（"这些砖就是你要击碎的东西"）。
- **留白与深度**：界面元素克制，画面靠三层明度（暗底/砖墙砖/标题与球）建立纵深，不铺满装饰；操作说明以短小中文文案安静放在次级视觉区，不与标题争亮。
- "开始游戏"入口使用主调青色 + 轻辉光，建立"青色=可操作"的第一课。

### 5.2 游戏场景（游玩中）

层次分离已在 §4.2 定义，此处定义对象身份：

- **挡板（主角/安全）**：青色、横向圆角长条、全场最高的稳定明度之一（L4）、中等稳定辉光。它看起来"结实、可靠、主动"；形状（最长的圆角横条）在任何尺寸下都不会与砖块、球混淆。
- **球（高速主体）**：唯一正圆，核心暖白 L5，运动时带短的、与运动方向一致的同色光尾（拖尾长度有限，不得长到遮挡预判）；贴附时辉光呼吸、无拖尾，呈现"充能等待"。球在任何背景（砖块上/墙前/暗底）上都必须保持 L5 对比。
- **砖块（可交互目标）**：统一圆角矩形、L3、轻辉光、按行在霓虹色组内循环。同种砖块视觉上也应感到"同种"——同尺寸、同明度、同辉光强度，颜色只是节奏。被击碎前砖块不预闪、不预告（一击即碎，不需要耐久度视觉）。
- **三边反弹墙（边界/安全）**：冷色暗实体，带微弱边缘光，表达"碰到这里会弹回来"；与底边形成明确对比。
- **底边死亡边界（危险）**：**没有墙实体**，是一片 L1 黑暗虚空；允许在边缘使用低亮度红橙警示条纹/短促脉冲，红橙全场仅此一处。危险信号 = 形状断裂（无墙）+ 黑暗虚空 + 红橙警示，三色与形状双通道，不靠单一红色。
- **装饰背景**：L1–L2、无发光、无叙事图案，永远退后。

### 5.3 待发球提示

球贴附挡板期间，发球提示（简短中文）以 L5 强调色轻微呼吸/闪烁出现于球附近的视觉区，提示强度高于背景、低于球本身；发球后立即消失。该提示同时承担 GDD 要求的"按发球键发出"教学。

### 5.4 暂停覆盖层

- 半透明暗压层覆盖游戏视图（压暗但不黑透，冻结的砖墙仍隐约可见），世界元素的辉光在视觉上"降温/变暗"，动效全部停止——冻结感优先。
- 中央面板为大圆角卡片（大档圆角、深色填充、细外框、柔和投影），面板本身不发光或仅极轻辉光，保持"操作中、非游戏内"的抽离气质。
- 进入/退出都快速、安静，不做庆祝性光效（暂停不是事件反馈，是状态切换）。

### 5.5 胜利结算

- 情绪：释放、上扬。最后一块砖碎裂后，砖墙位置光爆并转为柔和的余韵光，整体画面比游玩中更亮、更暖（允许背景短时被照亮再回落）。
- 结算面板与暂停面板同一卡片语言，但允许标题使用暖色强调 + 辉光（胜利文案是全场情绪高点）；最终分数以 L5 数字展示，可做一次分数结算动效。
- "再来一局"为主行动（青色主调），"退出"为次行动。

### 5.6 失败结算

- 情绪：短促下沉、不羞辱。失球瞬间光效向下/向心收束，全场短暂压暗（红橙只在失球点短暂出现，不铺满屏幕），随后暗场归于平静。
- 结算面板保持克制：失败文案不使用刺眼红底、不大面积红橙（危险色仅保留给死亡边界本身），明度低于胜利结算；最终分仍清晰展示，传达"差一点可以更好"。
- 同样提供"再来一局""退出"，主行动仍为再来一局——视觉上鼓励立即重试。

## 6. 状态变化与事件的视觉表达

规则触发点来自 GDD §6。各事件表现必须三类可区分（墙/挡板/砖块击球反馈不同），且均满足"动画只是表现，不延迟判定"。

| 事件 | 视觉表达 | 强度/尺度 |
|---|---|---|
| 球击中墙 | 撞击点一小圈冷色涟漪 + 墙体边缘光短促一亮 | 最小，冷、克制 |
| 球击中挡板 | 挡板整体短促"能量"反馈（明度一闪/轻微挤压形变即恢复）+ 小冲击光，青色 | 小，令人安心的正反馈 |
| 球击中砖块 | 砖块处短促亮闪，紧接碎裂（见下） | 中，爽感主体 |
| 砖块销毁 | 砖块光爆：碎片（保持该砖色相与圆角片段）向四周短距离飞散并快速衰减，同色光点粒子少量；HUD 分数即时更新并跳字 | 中，时长很短 |
| 得分变化 | HUD 分数即时刷新 + 小幅数字动效（强调色），不遮挡球 | 小 |
| 失球（有剩余生命） | 球在底边处被黑暗"吞没"：向下收束的光、短暂暗压与红橙警示脉冲；随后快速复位，砖块与分数视觉保持不变（明确传达"进度还在"） | 中，短促 |
| 生命减少 | HUD 生命指示即时减少，并给一次明确的消退动效（失去的指示变暗/破碎），让玩家不查规则也知道发生了什么 | 中 |
| 复位待发球 | 球重新贴附、辉光呼吸、发球提示出现，情绪快速回到蓄势态 | — |
| 胜利 | 见 §5.5：光爆余韵、整体提亮转暖、结算面板 | 大，正向 |
| 失败 | 见 §5.6：向下收束、暗压、克制的结算面板 | 大，下沉但克制 |
| 进入/退出暂停 | 快速暗压 + 辉光降温冻结 / 反向恢复 | 小，安静 |

补充规则：

- **同类反馈必须同语言**：三块墙的涟漪观感一致；每块砖的碎裂动效结构一致（仅随砖色相变色），避免玩家把表现差异误读为砖块种类差异。
- 形变（如挡板挤压）幅度小、回弹快，绝不改变碰撞判定的外观参照（玩家不能因为动画而误判挡板边缘位置）。
- 任何事件闪屏不得超过一次、不得全白，保证触屏玩家在亮环境下不眩光、暗环境下不刺眼。

## 7. 响应式与跨尺寸视觉要求

- 视觉适配策略：世界等比 letterbox，**美术不改玩法相对关系**；所有素材在 960×540（横、视野宽）与 390×844（竖、视野窄长）两类极端宽高比下都必须成立。
- 背景按 §4.1 的平铺/安全裁切要求制作；主体素材不依赖多细节读图，缩到竖屏小宽度时靠形状+明度仍可辨认（§3.7 已要求细节退化为色块）。
- 触屏小尺寸（尤其竖屏）下：球必须仍是全场明度最高点且正圆清晰；HUD 文字、发球提示、结算面板文字的实际可读性**尚未实测**，以实测为准，本文不预设结论。
- 辉光在小尺寸/低分辨率渲染下容易糊成一片（球与整墙辉光是两个高风险点），素材与渲染需允许辉光强度随实际呈现收敛；以实测调整。

## 8. 跨素材一致性检查清单（供评审/验收使用）

任一素材或屏幕交付时，美术侧逐项核对：

1. 灰度截图下明度层级是否为 球/标题 L5 → 挡板 L4 → 砖块 L3 → 墙/背景 L2–L1；
2. 是否所有圆角符合三档区间、全项目无锐角主体、球为唯一正圆主体；
3. 描边是否只使用 0.75×/1×/1.5×U 三档、深色压边、圆角转角；
4. 色相是否受控：青色未被砖块使用、红橙未出现在死亡语义以外、色组按行有序；
5. 发光是否按对象分级、整墙辉光是否已整体压暗、背景是否无发光；
6. 细节是否满足"远看色块、近看两层"、砖块内无文字；
7. 背景是否可平铺/安全裁切、letterbox 区域是否纯净；
8. 关键信息是否在去掉颜色后仍可由形状/明度/描边传达；
9. 字体是否符合气质、数字是否近等宽、小字是否未加辉光。

本清单是视觉身份的验收口径；**实际视觉验收尚未执行**，几何不越界不等于视觉合格。
