- 版本：v1.1（统一评审确认：取消 RES-HERO、改运行时组合的决策通过；为实施与验收基线）
- 作者：Bee Game Studio 资源规划代理

- 整合依据（均为 v0.1 草稿）：`GDD.md`、`LEVEL_SCENE_DESIGN.md`、`BALANCE_DESIGN.md`、`ART_DIRECTION.md`、`TECHNICAL_DESIGN.md`、`UI_UX_SPEC.md`、`AUDIO_DESIGN.md`

本文规划首版资源工作：**不执行**生成、提取、打包或注册。每项都对应一个实际设计用途；装饰性资源一律不设。

---

## 1. 规划原则

1. **简单霓虹形体优先程序化**：美术方向明确"不依赖重资产"，按钮、面板、墙体、死亡边界、碎裂/涟漪等由运行时以 Canvas/DOM 几何与辉光后处理表达，不烘焙成贴图。
2. **小精灵走单一图集**：加载生命周期相同、采样兼容的 2D 小元素合并为一个图集；大尺寸背景与不同生命周期的元素不入图集。
3. **不重复承载已程序化的信息**：动态文本、实时几何、参数驱动特效不烘焙贴图；砖块按行的颜色差异用运行时着色，不为 5 行各做一帧。
4. **内容文档不是清单资源**：Scene/UI JSON 与 `config/tuning.json` 是作者化内容/数据（经 content index 与运行时加载），不进入 asset-manifest（契约明确禁止在资源注册表中放内容定义）。

---

## 2. 必需资源清单（Required）

### 2.1 游戏精灵图集 `RES-SPRITE-GAMEPLAY`（sprite-atlas）

- **消费者**：游戏场景（游玩相位）、HUD、（经复用）开始界面主视觉。
- **分组理由**：全部为常驻小尺寸精灵，与游戏界面同生命周期、同采样需求；不纳入背景与无关界面。
- **来源建议（primary）**：**程序化/agent-authored**——按美术统一标准（统一描边基准、圆角、深色压边）将矢量形体一次性渲染成图集；备选 AI 单张生成整图（见 §6）。
- 建议图集画布 128×128，帧间 padding 4（辉光为运行时后处理，帧矩形贴合形体即可）；**确切裁剪矩形在图像产出后据实际像素确定，撰写阶段不臆造**。

| 命名帧 | 逻辑显示尺寸 | 枢轴 | 变体/着色 | 用途与消费节点 |
|---|---|---|---|---|
| `paddle` | 80×14 | [0.5, 0.5] | 青色固定 | 挡板（semantic `paddle`） |
| `ball` | 14×14 | [0.5, 0.5] | 暖白固定；贴附/拖尾为运行时表现 | 球（semantic `ball`） |
| `brick` | 52×20 | [0.5, 0.5] | **单帧 + 运行时按行着色**（行内色组循环） | 全部 40 块砖（semantic `brick`） |
| `icon-life` | 20×20 | [0.5, 0.5] | 存活/失去两态由运行时明度变化表达 | HUD 生命指示 |

- 图集交付：PNG + 同名 JSON sidecar，`frames` 矩形不旋转/不裁剪、全部落在画布内（契约 v9 sprite atlas 约定）。
- **着色可用性约束**：`brick` 基础帧须为可干净着色的中性亮形体，运行时按行染色后描边仍清晰；此为验收检查点，不能靠事后叠加颜色补丁。
- 不需要的帧（明确排除）：暂停图标（暂停按钮使用文字）、五种砖色帧、碎裂碎片帧（实时绘制）、阴影帧。

### 2.2 字体（font，必需，独立于图集）

- **用途**：标题（电子/几何感）、正文/HUD/按钮（清晰无衬线、数字近等宽）。
- **建议来源**：开源 OFL 许可 Web 字体，子集化（GB 常用字符 + 拉丁/数字/标点）：
  - 正文与 HUD：**Noto Sans SC（思源黑体）** Regular/Bold；
  - 标题：拉丁与数字用 **Orbitron**（电子感），中文字形回退 Noto Sans SC Bold，标题辉光为运行时效果。
- **可用性要求**：实际字体落地后，按 UI_UX_SPEC §10 对最大 4 位分数、生命、各文案做 textFit 实测；许可与中文覆盖完整度在注册前核查。具体字重/子集方案在制作时锁定。
- 标题文字以**动态文本**渲染，不烘焙成贴图。

### 2.3 音频行为（必需；首版以程序化合成实现，无音频文件）

依据 AUDIO_DESIGN，13 个命名 cue（12 类，暂停开合为 2 个命名：`sfx.hit.wall/paddle/brick`、`sfx.brick.destroy`、`sfx.ball.lost`、`sfx.life.lost`、`sfx.ball.serve`、`sfx.pause.open/close`、`sfx.ui.confirm`、`sfx.ui.focus`、`sfx.game.win/over`）。

- **来源决策（primary）**：**Web Audio API 实时合成**（振荡器 + 包络），不产出音频文件。理由：声音性格被定义为"短、干净、电子化"，合成器音色即设计本身；合成天然免解码、免加载、易于实现 AUDIO §4 的电平/抢占/节流，并与 TECHNICAL §7.1 兼容。
- **可用性要求**：合成参数（波形、音高包络、时长、相对电平）集中在运行时音频模块，按 cue 名订阅；首手势解锁上下文；胜利/失败等长句须能完整播放。
- 注册表现：若维持纯合成，则 manifest 中**不注册音频资源**（无文件）；合成配置作为运行时代码/数据存在。

### 2.4 必需但无文件的程序化表现（由运行时保证，列为制作项而非资源项）

| 表现 | 规格来源 |
|---|---|
| 三边反弹墙（冷色暗实体 + 边缘光） | ART §5.2 |
| 底边死亡边界（无墙虚空 + 红橙警示脉冲） | ART §5.2；GDD §3.1 |
| 背景（近黑渐变 + 低明度网格 + 远景光晕，可铺满任意宽高比） | ART §4.1 |
| 砖块碎裂碎片/光爆、击球涟漪、挡板挤压、全屏胜负表现 | ART §6；UI §8 |
| 按钮/面板（圆角、描边、轻辉光；无 nine-slice 贴图） | UI §6 |

这些表现的强弱（辉光、压暗、脉冲）随实测收敛；reduced motion 下退化为淡变/常亮。

## 4. 对既有草稿的资源决策修订（批次 4 收敛）

1. **开始界面主视觉 `RES-HERO` 取消，改为运行时组合**：UI_UX_SPEC 中原规划的砖墙主视觉图片（340×150），改为由图集 `brick` 帧在开始界面实时排布的一缩小砖墙（含逐块点亮动效）。该方案以更省的来源满足**同一视觉处理**（霓虹砖墙母题），且未用通用控件顶替必需表现；据此开始界面不再需要独立图片资源，UI JSON 的对应节点改为容器/精灵绑定（实施时执行，本文先锁定决策）。

## 5. 加载与注册映射（供实现阶段使用）

- `asset-manifest.json` 注册项（预期）：
  - `RES-SPRITE-GAMEPLAY`：asset_kind `sprite-atlas`，dimension `2D`，root_path 为 PNG（同名 JSON sidecar 同列 file_paths），status 待制作后 verified。
  - 字体资源（Web 字体文件，asset_kind `font`），子集文件按实际方案注册。
  - 纯合成音频与程序化表现：**不注册**。
- Scene/UI JSON 的 `assetRefs` 只引用上述已注册资源，资源绑定（frame/member）在作者化内容中声明；运行时按 content-format 的 resource-binding 校验（改动帧引用 → 渲染随之变化）。
- 加载顺序：startup 仅取首屏所需；图集在进入新一局时必须已就绪；字体随首屏加载。无第三个资源来源（TECHNICAL §5.6）。

## 6. 来源选择与备选

| 资源 | 首选 | 备选 | 理由 |
|---|---|---|---|
| 精灵图集 | 程序化/agent-authored 渲染整图 | AI 单张生成整图（一次请求出一整组），不逐元素生成 | 形体简单、统一标准易程序化；AI 仅在需要更丰富质感时使用，且保持一张整图以保证风格一致 |
| 字体 | 开源 OFL（Noto Sans SC + Orbitron） | 同气质其他 OFL 中文字体 | 许可清晰、中文覆盖、数字近等宽 |
| 音频 | Web Audio 实时合成 | 短音频文件 bank | 电子音色即设计目标，零加载、易混音 |

检索/生成/程序化均按用途选择，无统一强制；不配置未经说明的生成默认偏差。Web 来源须记录原始 URL、页面 URL、许可与获取时间。
