## 核心根因和系统修复

核心不是方向字段或某个按钮，而是公开工具、任务上下文和宿主检查没有完整衔接。作者必须自行找版本、猜接口和选择核对入口；模型一旦选错入口，会付出反复排查成本，且局部通过无法说明完整阶段合格。历史继续增长，又放大每次小操作的成本。另一类独立问题是行为断言太弱：记录结构与证据文件检查不能证明运行结论真实。

| 根因 | 已落盘的修复 | 保留的边界 |
| --- | --- | --- |
| 公开旧检查器与任务新版检查器并存 | 只发布 `acceptance-check-cli.ts`，任务、格式和指南统一使用 `.beegame/delivery/check-acceptance.mjs`；删除旧模块 CLI 和临时第二入口。公开 `--help`、实际解析器 `--format`、`--playable`、`--snapshot`。 | 检查器只读，不代替游戏测试或负责人批准。 |
| 制作阶段普通通过，最终宿主才核对完整交付 | 抽出既有内容、布局和资源检查供宿主与 CLI 共用。制作任务提供 `check-content.mjs --release`，运行验收也使用同一完整内容检查。 | 样例只查当前代表性内容和首个视口，不提前要求未来页面；宿主仍独立保留原始用户要求、版本及批准检查。 |
| Brief 页面身份、版本和资源格式不易取得 | 当前任务直接提供解析后的 Screens；`--authority` 返回实际规划 ID 与版本字段；明确指向已有 `assets/manifest/CONTRACT.md`，不另建清单规范。 | 不模糊匹配名称，不自动改页面身份，不把缺页放行。 |
| 制作与验收职责混在一起 | 制作上下文不再提供验收报告目标，只提供完整内容预检；可玩样例和最终验收才提供各自报告路径和规则。 | 制作仍须检查受影响行为，不等于可以把坏功能留给验收；没有新增阶段、审查 Agent 或硬次数限制。 |
| 重开测试只有瞬间状态或内部测试钩子 | 现有试玩 Skill 明确正常交互路径、源需求对应的失败断言、延迟结束后的持续恢复与后续操作；功能缺陷不能藏进审美未验证项。 | 方法更新不证明模型会执行或不再漏检，不能宣称任意游戏的行为可靠性已解决。没有写入案例路线、延迟秒数或答案。 |
| 会话差额与账务累计重复相减 | 会话提交累计快照，单轮差额仅用于诊断；新增数据库迁移以原有累计快照识别旧基线，只计后续新增量，不补扣历史差额。未知旧基线停止结算而非猜测。 | 数据库迁移未执行，SQL 未在真实 PostgreSQL 验证；必须先部署迁移再切换运行服务，尤其不能先恢复旧会话收费。没有改账单、余额或补收费用。 |

免费合成回归验证了公开命令真实可执行、缺页与资源策略冲突在本地和宿主得到同样结果、样例允许未完成的后续页面、错误方向不能被编辑本地配置绕过宿主，以及累计账务提交在大小轮次和原生计数重置下正确。77 个核心相关测试及另外 26 个 HTTP 生产流程、计量报表和账务接口测试通过，服务器类型检查通过，Skill 格式验证通过。这些结果只证明对应系统接口和确定性检查，不是完整游戏验收；数据库迁移仍待真实数据库验证。

降耗修复针对已证实的错误入口、格式摸索和提前重复验收，不设置 Token/调用次数硬限，不删除必要检查。具体节省幅度、模型是否采用公开接口及行为测试是否更有效，尚未经过修订后的真实生成，不能估算一个节省百分比当作验收结果。测试项目仍只读，原始问题保留。

上述付费验收只启动一次生成，生成期间未更改系统源码。早期源码基线于启动后约 1 分 43 秒保存，结束后的 4,561 份系统源码、工具和构建文件哈希无变化。本次根因修订没有追加付费运行。独立审计曾遇到 URL 解析、浏览器包路径、缺默认浏览器版本和按钮选择器错误，修正后使用现有 Chrome 正常运行；这些是审计工具错误，不计为游戏缺陷。审计记录按文档整理 Skill 保留事实、推断与未验证范围的区别，不用作者通过声明代替结论。
