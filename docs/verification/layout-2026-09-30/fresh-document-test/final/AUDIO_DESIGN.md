# 贪吃蛇 音频设计（AUDIO_DESIGN）

- 版本：v1.0（统一评审修订版，实现与验收基线）
- 作者：Bee Game Studio 主 Agent
- 日期：2026-09-30
- 上游：GDD（事件/状态）、BALANCE_DESIGN（节拍与触发频率）、ART_DIRECTION（俏皮现代街机情绪）、UI_UX_SPEC（界面反馈配对）。
- 文件清单与来源由 ASSET_PLAN 统一整合，本文只定义声音行为。

## 1. 音频目标与总原则

- 服务于街机感的**即时确认**：每个关键动作 80–200ms 内给出声音反馈；轻快、圆润、合成器/电子音色，与糖果视觉统一。
- 极简克制：节拍移动**不发声**（80ms 高频下会变成噪音），只在离散游戏事件上发声。
- **关键信息不依赖听觉**：吃食物、死亡、通关、暂停均有对应视觉反馈（UI_UX 第 5 章）；静音状态下游戏完全可玩。
- 浏览器自动播放策略：音频上下文在**用户手势处理器内同步创建/恢复**。开始按钮（或就绪屏静音按钮，若它是首个手势）的点击处理器中，先同步解锁，再同步触发该按钮的 ui_tap；解锁失败则该音静默放弃，不报错、不阻塞进入下一状态。不得在处理器外预先解锁，也不得在解锁后用异步回调补放导致首声丢失。

## 2. 必需声音（首版）

### 2.1 `eat` 吃到食物（必需）

- **目的**：确认进食/得分（最高频反馈，最多每秒 12.5 次@80ms 档）。
- **音色**：短电子“bubble blip”——正弦/三角波快速上挑（约 660→990Hz），圆润无噪声尾。
- **时长**：90–120ms，快速衰减，不循环。
- **重复触发**：每次进食重新触发；同一时刻只可能有一个 eat（节拍离散），重叠时新音截断旧音（最高 1 实例），避免 80ms 档堆积成刺耳连音。
- 随进程微调（可选行为，发布建议）：每提速一档音高基准 +半音，提供“变快变高”的递进感；上限后保持。

### 2.2 `fail` 失败（必需）

- **目的**：明确失败、与普通进食区分。
- **音色**：短促下行“wobble”——方波/三角波 400→150Hz 下滑 + 轻微颤动，低饱和度。
- **时长**：400–500ms；触发后蛇身去饱和动画同步。
- **优先级**：高；触发时截断任何正在响的 eat。
- 单局只响一次。

### 2.3 `win` 通关（必需）

- **目的**：奖励、与 fail 的下行形成对照。
- **音色**：三音快速上行琶音（C5-E5-G5，方波+轻滤波），明亮。
- **时长**：约 600ms；与金色脉冲同步。优先级高，截断 eat。

### 2.4 `ui_tap` / `ui_open` 界面（必需：ui_tap；可选：ui_open）

- `ui_tap`：按钮点按确认，80ms 轻柔 click（约 1200Hz 短脉冲，低音量）；所有按钮共用；重复点按允许重叠但限 2 实例。
- `ui_open`（可选增强）：ModalCard 入场，150ms 柔和 whoosh/双音；若省略不影响体验。

### 2.5 暂停（无声音，必需的“无声”语义）

- 进入/退出暂停不播放音效（避免误导为游戏事件）；暂停中全部游戏音静默（eat 等不可能触发）。继续时不补放暂停期间的任何声音。

## 3. 音乐

- **首版不设背景音乐**：会话短、循环快、高频音效本身承担节奏；引入音乐会与 80ms 节拍音效争占听觉，且加长资源加载。
- 因此无音乐系统、无音轨切换；不排除未来版本在菜单加短循环音乐（属范围扩展，需新决策）。

## 4. 混音、并发与优先级

| 层级 | 相对音量 | 并发上限 | 优先级 |
|---|---|---|---|
| fail / win | 0 dB（基准） | 1 | 1（最高，互斥并抢占） |
| eat | −6 dB | 1（新截旧） | 2 |
| ui_open | −10 dB | 1 | 3 |
| ui_tap | −12 dB | 2 | 4 |

- fail/win 互斥且一旦触发压制其他全部声音；eat 永不覆盖 fail/win。
- 整体动态范围小、无突响（峰值差 ≤12dB），保护耳机玩家。

## 5. 静音、音量与持久化

- 首版提供**单一静音开关**（IconButton，位于 R1：就绪屏独立存在、游玩屏与暂停按钮并列；状态变化 100ms），不提供分通道/音量滑杆（无音乐，无需）。
- **静音仅本会话有效、不持久化**：遵循 GDD 第 4 章“仅最高分持久化、无设置项持久化”；每次加载页面默认有声（受自动播放策略约束）。
- 静音影响全部声音；不影响视觉反馈；浏览器标签切换不改变静音。
- 若就绪屏首次手势是点击静音按钮：同一处理器内同步解锁并触发 ui_tap，随后立即应用静音（该 ui_tap 可能几乎不可闻，属预期，不重复播放）。

## 6. 跨状态转换的声音行为

| 转换 | 声音 |
|---|---|
| 就绪 → 游玩 | 开始按钮 ui_tap；首局节拍不发声 |
| 游玩 → 暂停 | 无 |
| 暂停 → 游玩 | 无 |
| 暂停 → 重新开始 | ui_tap；立即停止全部现存声音实例，新局无尾音带入（与 TECHNICAL 3.4 的清理一致） |
| 游玩 → 失败 | fail（eat 若在响被截断） |
| 游玩 → 通关 | win |
| 结算 → 新局 | ui_tap；状态完全复位，无尾音带入新局（重开时停止全部现存声音实例，与 TECHNICAL 3.4 清理一致） |
| 结算/暂停 → 主菜单 | ui_tap |
| 关闭/离开页面 | 全部声音自然终止，无淡出要求 |

## 7. 必需 vs 可选汇总

- **必需**：eat、fail、win、ui_tap；静音开关。
- **可选增强**：ui_open、eat 随档位升调。
- **不做**：背景音乐、环境音、语音、空间音频（2D 俯视无此需要）。

## 8. 未验证事项

声音的实际听感、80ms 档 eat 截断策略是否舒适、移动端扬声器电平均未经试听/真机验证；ASSET_PLAN 给出文件规格后在实现阶段以真机/浏览器试听验收。
