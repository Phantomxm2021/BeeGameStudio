# 贪吃蛇 关卡与场景设计（LEVEL_SCENE_DESIGN）

- 版本：v1.0（统一评审修订版，实现与验收基线）
- 作者：Bee Game Studio 主 Agent
- 日期：2026-09-30
- 上游依据：`docs/GDD.md`（玩法规则权威）；数值以 `docs/BALANCE_DESIGN.md` 为准；界面布局以 `docs/UI_UX_SPEC.md`（批次 3）为准；视觉风格以 `docs/ART_DIRECTION.md` 为准。
- 首版仅一个可复用关卡类型：**单棋盘「标准场地」**。无多关卡，本文档定义该唯一棋盘的可建造空间规格。

---

## 1. 关卡目标与空间概述

- **关卡目标**：在封闭的 21×21 方格场地中吃食物、增长并存活；蛇身填满全部 441 个格位即通关。
- **失败空间条件**：蛇头越出场地四周边界，或进入被自身身体占据的格位（规则见 GDD 3.5）。
- 场地是一个纯开放、无内部障碍的方形平面；挑战来自蛇身自身造成的动态空间收缩，而非静态地形。因此本关卡**没有区域分区、岔路或门**，但需明确定义坐标、边界与可见/可玩范围。

## 2. 坐标系、单位与尺度

- **设计单位**：采用与设备无关的设计坐标（design units，等价于 CSS 逻辑像素，记为 du）。参考尺寸不是宿主固定像素，运行时按缩放系数映射到实际视口。
- **网格**：21 列 × 21 行，奇数规格，存在唯一中心格 C = (10,10)（0 基索引，列 x 向右增大，行 y 向下增大）。
- **格位尺寸**：单格 32 du × 32 du；格间距 0，格间分隔以棋盘底纹的视觉描边表现（描边内缩，不占据可玩逻辑空间）。
- **棋盘世界范围**：672 du × 672 du，世界原点（棋盘左上角）记为 W(0,0)；格位 (cx, cy) 的世界矩形为 `(cx×32, cy×32, 32, 32)`。
- 蛇与食物的逻辑体均居中于格位矩形内，逻辑占据尺寸 = 1 格；视觉内缩与圆角由美术文档定义，不改变判定占据。

```
世界坐标示意（非美术稿）
W(0,0) ┌───────────────┐  x →
       │ 21×21 格       │
       │   C(10,10)     │  每格 32du
       │  棋盘 672du    │
       └───────────────┘
                          y ↓
```

## 3. 蛇与食物的出生/结束条件

### 3.1 蛇的初始布置

- 初始长度 3 节，水平居中于中心行，朝右（东）前进：

| 部位 | 格位 | 世界中心 (du) |
|---|---|---|
| 蛇头 | (10,10) | (336, 336) |
| 蛇身 | (9,10) | (304, 336) |
| 蛇尾 | (8,10) | (272, 336) |

- 开局空间：蛇头距右边界 10 格、距左边界 10 格、距上下边界各 10 格，四个初始方向都给玩家留足反应空间。

### 3.2 食物出生（程序化约束，而非“纯随机”）

- 恒有一个食物，进食后的同一节拍结算后立即重生。
- **候选集**：所有未被蛇身（含蛇头）占据的格位；候选集中等概率均匀随机选取。
- **连通性/可达性**：候选格不需要逐格连通性校验——开放无障网格中任意空格均与蛇可达；但**每局第一个食物**额外施加安全约束：生成格与蛇头 (10,10) 的曼哈顿距离 ≥ 5（具体值由平衡文档确认），避免开局食物贴脸且保证玩家有 ≥ 数个节拍的决策时间。
- **终局特例**：当蛇长 = 440 时，场上恰好只剩 1 个空格，食物必出生于该格（候选集大小为 1）；蛇进入该格即长度 441，触发通关，不再重生食物。
- 食物不会出生在蛇身格、边界外；无遮挡关系（俯视，蛇身不遮挡格位可选性）。

### 3.3 结束条件在空间上的含义

- 撞墙：蛇头目标格坐标超出 `0..20`。
- 撞身：蛇头目标格与移动后保留的身体格重合。
- 通关：进食后占据格位数 = 441（棋盘无剩余空格）。

## 4. 视野/取景：世界范围与显示范围

- **世界范围**恒为 672×672 du 的正方形棋盘；**显示范围**由容器视口与 UI 占用决定，二者不是一回事。
- 取景为**固定正交俯视，整盘完整可见**：不存在滚动、摄像机跟随或缩放视野；世界不随蛇移动而平移。
- 棋盘以“contain”方式适配：在去除 HUD/边距占用后的可用矩形内等比缩放并居中，保证 672×672 全部可见、不裁剪任何格位；不足方向以留白/棋盘外背景补足。
- 宽高比变化时的行为：
  - 竖屏手机：宽度受限，棋盘按宽适配，上下为 HUD 与安静留白区；棋盘不被竖向拉伸。
  - 宽屏桌面：高度（减去上下 HUD）受限，棋盘左右留白。
  - 任何情况下单格保持正方形（缩放各向同性），格位永不被非等比压缩。
- UI 占用：HUD（当前分数、最高分、暂停按钮）位于棋盘外的固定带，不压占棋盘世界格位；具体几何与响应式断点由 UI_UX_SPEC 定义。棋盘最小可读尺寸要求（每格逻辑像素下限）由 UI_UX_SPEC/技术文档给出，达不到时保持整盘可见并允许整体缩放，但不允许裁剪。

## 5. 引导、节奏与空间布置的关系

- **零文字教学的空间设计**：蛇居中、朝右、节拍较慢，玩家任意按一个方向键即可看到因果；开放棋盘不存在走错即死的初始地形。
- **节奏由空间拥挤度驱动，而非脚本遭遇**：前期（蛇短）全场皆为安全通道，玩家建立“吃食物→变长→变快”的因果；中期蛇身构成绕行障碍，需要预判尾部腾出的通道；终局仅剩单格通道（蛇长 440 时），此时场地存在一条由蛇身界定的唯一路径，是空间上最难的状态。
- 建议路线 vs 强制路线：玩家路线完全自由（建议性）；唯一“强制”的空间事实是终局最后一格——当蛇长 440 时进入唯一空格是通关的唯一动作。
- 无静态遭遇、资源点群或刷怪表；食物的随机分布就是本关唯一的资源分布机制，其约束已在 3.2 完整定义。

## 6. 场景数据所有权（Scene JSON）

- 棋盘根节点、网格背景节点、蛇容器节点、食物节点、世界原点与格位尺寸、资源绑定均编写在 Scene JSON 中（层级、transform、响应式变体）。
- 代码不硬编码 672/32 等编写决策作为布局来源；代码读取场景数据，把逻辑格位 (cx,cy) 绑定到对应世界变换并执行玩法。
- 具体 JSON 字段契约由 `docs/TECHNICAL_DESIGN.md` 与 `docs/ASSET_PLAN.md`（后续批次）落地。
