# 贪吃蛇 UI/UX 规格（UI_UX_SPEC）

- 版本：v1.0（统一评审修订版，实现与验收基线）
- 作者：Bee Game Studio 主 Agent
- 日期：2026-09-30
- 上游：GDD（状态/动作权威）、LEVEL_SCENE_DESIGN（空间/取景）、BALANCE_DESIGN（数值）、ART_DIRECTION（视觉语言）、TECHNICAL_DESIGN（运行时）。
- 本文是全部界面布局、导航与界面反馈的唯一权威；布局/响应式变体以 UI JSON 编写，代码只加载与绑定。

## 1. 坐标系、单位与适配总规则

- **单位**：设计坐标 du（≈CSS 逻辑像素）；**参考分辨率 720×960 du（竖屏基准，宽高比 3:4）**。参考值表达设计，不是固定运行时尺寸。
- **原点/锚点**：屏幕左上角为 (0,0)，x 向右、y 向下。所有子元素相对父区域锚定（左上/居中/右下等）与父相对偏移描述；不使用隐式引擎默认边距。
- 支持容器范围：宽度 320–1440du、高宽比 0.5（竖）–2.2（横）。输入能力（触屏/键鼠）与视口形状相互独立：触屏宽屏、鼠标竖屏均合法。
- **响应式变体（断点以短边 sw 判定，优先级自上而下，互斥）**：

| 变体 | 条件 | 布局行为 |
|---|---|---|
| S（小屏） | sw < 480 | 竖排单列；标题图缩小；按钮全宽 |
| M（基准） | 480 ≤ sw < 900 | 参考布局 |
| L（大屏） | sw ≥ 900 | 内容限宽 720du 居中，左右留白；横向是否重排一律由 2.2 节横向重排条件决定，本档不另行移动区域 |

- 宽高比与断点同时作用：先按短边选变体，再由方向决定“棋盘留白区”的方位（见第 3 章）。不枚举每个尺寸，规则 + 关键矩形即可推导。
- **安全区**：移动端以 safe-area inset 内缩（刘海/ home 条），以 UI JSON 变体承载；最小触控目标 44×44du。
- **最小可读保障**：棋盘每格渲染后逻辑边长 ≥ 13.5du（绝对下限）；若等比缩放达不到，则棋盘保持整盘可见并触发“棋盘优先”模式（第 2 章），但**永不裁剪棋盘、不靠缩小文字适配**；正文最小字号 14du、HUD 数字 24du。

## 2. 共享布局框架（页面区域分配）

全部屏幕共用一个三段式竖排框架（M/S 变体；L 横屏变体见 2.2）：

```
┌──────────────── Screen 720×960 ────────────────┐
│ R1 顶部信息带  h=80   [分数区(左) 最高分(中) 静音+暂停(右)] │ 固定高度
│ R2 棋盘区      弹性居中，正方形，contain 等比，居中锚点  │ 弹性（取剩余空间最小值）
│ R3 底部内容带  h=160（S:140）  [主按钮 + 次按钮/文案]    │ 固定高度
└────────────────────────────────────────────────┘
```

- R1 固定 80du；R3 固定（M 160 / S 140）；R2 尺寸 = `min(屏宽 − 2×边距24, 屏高 − R1 − R3 − 3×间距16)`，居中于 R2 区域。
- 外边距 24du（S:16）；区域间距 16du。
- **空间不足时的确定行为（两级，按顺序进入，无备选）**：
  1. R2 < 300du（每格 <14.3du）→ **棋盘优先**：R3 悬浮为半透明覆盖于棋盘底部（overlay，不占布局）、R1 文字标签隐藏只留数字与图标，棋盘取得全部剩余空间。
  2. 棋盘优先后 R2 仍 < 285du（每格 <13.5du，主要发生在横置小屏手机）→ **全悬浮**：R1 也转为 overlay——分数数字悬浮棋盘左上、静音/暂停图标悬浮右上（半透明深色底板，圆角 8du），棋盘取得除安全边距外的全部空间：R2 = min(屏宽−24, 屏高−24)。悬浮控件仅覆盖顶/底排局部区域，不遮挡蛇头主动线；暂停等操作照常可用。
  - R2 ≥ 300du 时保持正常布局，不提前触发。

### 2.1 共享组件（定义一次）

| 组件 | 规格（M） | 状态 |
|---|---|---|
| `PrimaryButton` | 高 52du，全宽（R3 内），胶囊，暖黄 #FBBF24 底 + #0F172A 文字，字 18du 粗体 | default/hover（亮度+8%）/pressed（缩放97%）/disabled（灰、无点击）/focus（2du 深色外环） |
| `SecondaryButton` | 高 44du，透明底 + 2du 浅色描边 | 同上 |
| `IconButton`（暂停/静音） | 44×44du，触控不小于 44 | default/pressed/focus |
| `ScoreDigit` | 右对齐等宽数字 24du，白色 | 数值变化 120ms 轻微上跳 |
| `ModalCard` | 宽 = 父宽−48，上限 420du，圆角 20，深色 #1F2937，内边距 24 | 入场 180ms 淡入+上移 8du；关闭反向 |
| `KeyHint` | 12du 次级文字，键名小圆角标签 | — |

### 2.2 横向重排（与短边变体独立的另一轴）

- 触发条件：容器宽 ≥ 1100du 且宽高比 ≥ 1.1（不依赖 sw 所属的 S/M/L 档位；两轴同时生效：变体决定字号/组件尺寸，横向重排决定区域位置）。
- 棋盘固定居中；R1 改为悬浮于棋盘左上的小条（半透明，overlay）；分数/最高分移到棋盘**左侧留白列**（宽 200du，垂直居中），主按钮移到**右侧留白列**垂直排列；R3 取消。
- 在上述触发条件下侧列宽恒 ≥200du，因此无回退分支；宽 1100–1299 或宽高比 1.1–1.29 的横屏不触发重排，保持常规竖排区域框架。

## 3. 各屏幕规格

### 3.1 就绪屏（主菜单）

- **进入**：加载完成 / 返回主菜单。**退出**：开始 → 游玩。
- R1：左侧留白（无当前分）、中显示最高分；右侧静音 IconButton（无暂停按钮）。
- R2：不显示棋盘逻辑，改为**标题主图**——螺旋盘蛇绕果实（ART 第 5 章），尺寸取 R2 的 min(边)，居中；主图下方安静区。
- R3：`PrimaryButton「开始游戏」`；下方 `KeyHint`：桌面“Enter / Space 开始 · 方向键或 WASD 转向”，触屏设备该提示文案替换为“滑动屏幕转向”（按输入能力显示，不按方向）。
- 注意力次序：主图 → 开始按钮 → 最高分。无错误态。

### 3.2 游玩 HUD

- **进入**：开始 / 继续。**退出**：暂停→暂停屏；死亡→失败；填满→通关。
- R1：左“分数 {score}”（ScoreDigit）、中“最高 {best}”、右侧 IconButton「静音」+ IconButton「暂停」（间距 8du）。
- R2：棋盘（场景层），无界面覆盖；触屏时不显示虚拟方向键（滑动转向，保持盘面干净）。
- R3：游玩中 R3 **隐藏并让给棋盘**（棋盘区扩展至 R3 顶，即游玩屏 R2 = 屏高−R1−32），这是与其他屏幕的唯一区域差异。
- 转向即时反馈：蛇头瞳孔转向 + 方向输入被缓存时无额外提示（缓存是无感的）。
- 失焦自动暂停：无需玩家操作，直接转 3.3。

### 3.3 暂停屏（覆盖层）

- **进入**：游玩中暂停输入 / 页面失焦。**退出**：继续 / 重新开始 / 返回主菜单。
- 全屏 45% 深色覆盖层 + 居中 `ModalCard`：标题「已暂停」；`PrimaryButton「继续」`、`SecondaryButton「重新开始」`、`SecondaryButton「返回主菜单」`，垂直排列间距 12。
- 失焦进入时标题为「已自动暂停」。
- 键盘：P/Esc/ Space 继续；R 重新开始（桌面显示 KeyHint）。

### 3.4 失败结算屏

- **进入**：死亡节拍后。**退出**：再来一局 / 返回主菜单。
- 棋盘保留并去饱和；中央 `ModalCard`：红色小标签「游戏结束」→ 本局分数大字（40du）→ “最高 {best}”（若本局破纪录，显示暖黄“新纪录！”并脉冲 2 次）→ `PrimaryButton「再来一局」`、`SecondaryButton「返回主菜单」`。
- 键盘 Enter/Space 再来一局。

### 3.5 通关结算屏

- 进入/退出同失败屏。ModalCard：暖黄标签「通关！」、本局分数大字、“最高 {best}”（破纪录同样显示“新纪录！”脉冲）、`PrimaryButton「再来一局」`、`SecondaryButton「返回主菜单」`；棋盘恢复饱和、果实金色脉冲。

## 4. 焦点与键盘/触屏导航

- **键盘焦点环**：所有可聚焦按钮显示 2du 外环；进入每个屏幕焦点自动落在该屏 PrimaryButton（游玩屏无焦点控件）。
- Tab 在当前 ModalCard/带内按钮间循环；方向键不参与 UI 焦点（方向键专属转向，避免冲突）。
- 触屏：无 hover；所有按钮满足 44du 命中区；overlay 按钮不依赖滑动。
- 转向手势：在棋盘区触摸起点记录，位移超过 24du（BALANCE 2.4）按主轴映射四向；每次触摸只产生一次转向，抬手复位。反向手势按 GDD 3.3 处理（无效，无错误弹窗）。

## 5. 界面反馈与转场（目的、触发、时机）

| 反馈 | 目的 | 触发 | 表现/时长 | 对应音频 |
|---|---|---|---|---|
| 吃到食物迸点+分数上跳 | 确认得分 | 进食节拍 | 120ms | eat（短促） |
| ModalCard 入场 | 状态切换 | 暂停/结算 | 180ms 淡入上移 | ui_open（可选；fail/win 已发声时被抢占，结算卡不播） |
| 暂停覆盖压暗 | 时间冻结语义 | 暂停 | 150ms | — |
| 死亡去饱和+蛇头红闪 | 理解死因 | 死亡节拍 | 300ms | fail |
| 通关金色脉冲 | 通关奖励 | 通关节拍 | 600ms | win |
| 新纪录脉冲 | 破纪录奖励 | 失败结算写入新最高分时 | 2 次 250ms | 无独立音效（结算卡音不重复播放） |
| 按钮 pressed | 操作确认 | 点按 | ≤100ms | ui_tap |

- 转场期间忽略新的转向输入（持续 ≤250ms，跨至多 1–3 个高速节拍：死亡/暂停转场伴随计时停止，不影响公平；重开转场结束前不启动节拍）。
- **减弱动效**：遵循 `prefers-reduced-motion`：禁用上移/脉冲/迸点，仅保留 80ms 淡入与颜色变化，信息不丢失。

## 6. 加载/错误/空状态

- 首次加载：静态轻量启动画面（标题文字 + 16du 呼吸圆点），数据就绪后转就绪屏；正常情况 <300ms，无进度条。
- 资源/数据加载失败（含 JSON 校验失败）：全屏“资源加载失败，点击重试”+ `PrimaryButton「重试」`，不进入黑屏。
- 最高分缺失/存储不可用：HUD 最高分位置显示“—”，无报错弹窗。

## 7. 矩形核算（参考与最小容器）

- **参考 720×960（M）**：边距 24；R2 = min(720−48, 960−80−160−48) = min(672,672) = 672du → 棋盘 672×672，与世界范围 1:1，每格 32du。✔
- **游玩屏**：R2 = min(720−48, 960−80−32) = min(672, 848) = 672 → 672×672。✔
- **S 360×640（正常 S）**：边距 16，R1=80，R3=140；R2 = min(360−32=328, 640−80−140−48=372) = 328du；328 ≥ 300 不触发棋盘优先；每格 328/21 ≈ 15.6du。✔ R3 内按钮 52du 全宽 328du 可用；KeyHint 12du 允许两行。
- **S 320×568（竖，棋盘优先）**：常态 R2 = min(320−32=288, 568−80−140−48=300) = 288du < 300 → 棋盘优先：R3 转 overlay、R1 标签隐藏；R2 = min(288, 568−80−24=464) = 288du；每格 ≈13.71du，棋盘完整可见。✔
- **S 横置 568×320（全悬浮）**：S 档（sw=320<480），宽 568<1100 不重排。棋盘优先 R2 = min(568−32=536, 320−80−24=216) = 216du < 285 → 全悬浮：R2 = min(568−24=544, 320−24=296) = 296du，每格 14.10du ≥13.5，棋盘完整可见。✔ 分数/图标悬浮四角。
- **S 横置 667×375（全悬浮）**：棋盘优先 min(635,271)=271<285 → 全悬浮 R2 = min(643,351)=351，每格 16.7du。✔
- **横向重排 1280×720（M 档位 + 横向重排）**：宽 ≥1100 且宽高比 1.78 ≥1.1 → 重排触发；棋盘受高约束 720−64=656du 居中；左右留白各 (1280−656)/2 = 312du，容纳 200du 信息/按钮列。✔
- 文字换行：结算卡文案最长“新纪录！”不换行；KeyHint 在 S 两行，行高 16，R3 140du 内（52 按钮 + 2×16 文案 + 间距）可容纳。

## 8. 视觉资源需求（按用途，供 ASSET_PLAN）

- 标题主图：螺旋蛇+果实（矢量或形状程序绘制皆可，保持圆润糖果语言）。
- 暂停、静音图标；蛇/果实/棋盘由场景形状承担。
- 无需位图装饰插画；背景为渐变程序绘制。
