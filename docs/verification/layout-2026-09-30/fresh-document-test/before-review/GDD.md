## 1. 游戏概述与首版范围

一款经典贪吃蛇：玩家在一个有边界的方形网格场地中控制一条持续前进的蛇，通过改变方向吃到随机出现的食物。每吃一个食物，蛇身增长一格、得分增加，移动节拍随进程加快；蛇头撞到场地边界或自身身体即失败。蛇身填满全部网格格位时达成通关。

首版目标是**一个完整、可重复游玩的核心循环**，含代表性最小内容：

**首版包含：**

- 一个固定规格的网格场地（单一棋盘，无多关卡）。
- 一条玩家控制的蛇、每次场上仅一个的食物。
- 开始（就绪）→ 游玩 → 暂停 → 失败/通关 → 重开 的完整状态流程。
- 当前分数、历史最高分显示；最高分本地持久化。
- 键盘/鼠标与触屏两套输入。
- 随吃到食物数量递增的难度（节拍加快）。

**首版明确不做（排除项）：**

- 多个关卡、多种棋盘布局、关卡选择。
- 多种游戏模式（穿墙模式、限时模式、多人/对战、道具模式等）。
- 特殊食物、增益/减益道具、障碍物。
- 账号、在线排行榜、成就、皮肤解锁、内购、广告。
- 元进度、成长系统、剧情；除最高分外无任何持久化解锁。

## 2. 玩家目标、可用动作与后果

### 2.1 玩家目标

- 短期：在蛇下一次移动前，把方向调整为朝向食物，同时避开边界与身体。
- 单局目标：尽可能多地吃到食物、获得高分，并在棋盘被填满时达成通关。
- 重复游玩目标：刷新本地历史最高分。

### 2.2 可用动作与后果

| 动作 | 输入方式 | 后果 |
|---|---|---|
| 转向（上/下/左/右） | 方向键或 WASD；触屏在场地滑动 | 在当前移动节拍结束后改变蛇的前进方向；不能直接反向（见 3.3） |
| 开始游戏 | 就绪界面点击「开始」按钮，或 Enter / Space；触屏点击按钮 | 从就绪状态进入新一局 |
| 暂停 / 继续 | 游玩中点击暂停按钮（鼠标或触屏），或 Space / P | 在游玩与暂停间切换；暂停时蛇与计时完全停止 |
| 重新开始 | 失败/通关界面点击「再来一局」，或暂停界面点击「重新开始」；结算界面也可用 Enter / Space | 放弃当前局，以初始状态立即开始新一局 |
| 返回菜单 | 失败/通关界面（及暂停界面）点击「返回主菜单」 | 回到就绪/主菜单状态 |
| 退出游戏 | 浏览器关闭或离开页面 | 无退出确认；当局进度不保存，仅最高分已持久化 |

鼠标仅用于点击界面按钮；场地内不支持点击移动。

### 2.3 挑战—反馈循环

1. 玩家观察蛇头方向、蛇身布局、食物位置与剩余空间。
2. 在节拍间隔内输入一次转向（输入在节拍之间被缓存，节拍到来时生效）。
3. 蛇整体前进一格：吃到食物则增长、加分、刷新食物、节拍加快，并给出明显的吃到反馈（视觉/音效，具体形式由美术与音频文档定义）；未吃到则蛇尾正常收回、长度不变。
4. 空间越来越拥挤、节拍越来越快，决策时间缩短 → 回到第 1 步，直到失败或通关。

## 3. 核心玩法规则（可观察规则）

### 3.1 场地与网格

- 场地为规则方格网格，行列数为奇数以保证存在唯一中心格；具体行列数与格位设计坐标尺寸以平衡数值文档为准。
- 场地四周边界封闭：蛇头离开网格即视为撞墙失败，**不穿墙、不绕回**。
- 场地、蛇、食物的层级关系与位置以 Scene/UI JSON 中编写的网格数据和绑定资源为可编辑来源；运行时代码加载该数据并执行玩法，代码中的常量不得替代这些编写决策。文中引用尺寸均为设计坐标，不是固定宿主像素尺寸；响应式适配由 UI/UX 文档与场景数据的响应式变体负责。

### 3.2 移动节拍

- 蛇以离散节拍移动：每个节拍蛇头前进一格，其余身体依次跟随。两次节拍之间蛇不在格间滑行（是否加入格间补间动画属于美术/表现层决策，不改变规则判定时机）。
- 节拍时长固定作用于当前整局，并随已吃食物数量分档缩短（加速）；初始时长、分档规则与最短时长以平衡数值文档为准。
- 加速在吃到食物的**同一节拍之后**对后续节拍生效；正在进行的节拍时长不因加速而改变。

### 3.3 转向规则

- 玩家只能让蛇左转或右转 90°；**禁止直接 180° 反向**（蛇长度大于 1 时，反向指令被忽略）。
- 节拍间隔内的方向输入被缓存，按输入顺序最多缓存近期有限个合法转向（缓存容量以平衡/交互文档为准），并在后续节拍依次应用，使快速连按两次转向（如“上→左”）可以在连续两个节拍内完成。
- 应用一个缓存转向时若其相对于届时实际前进方向构成反向，则该条输入作废。
- 蛇长度为 1（首版仅理论情况）时允许任意方向。

### 3.4 食物、进食、成长与计分

- 场上始终恰好有一个食物，占据一个网格格位。
- 初始时蛇位于场地中心区域、长度为若干节并朝一个固定方向前进（初始长度、朝向由平衡数值文档规定）；首局食物在蛇头若干格之外的可达格位中出现，避免开局即堵死。
- 蛇头进入食物所在格位的同一节拍：蛇增长（该节拍蛇尾不收回）、得分增加、食物消失，并在该节拍结算后立即于一个**未被蛇身占据**的空格中随机生成新食物。
- 每个食物的得分以平衡数值文档为准；HUD 同步显示当前分数。
- 食物生成在所有等概率空格中均匀随机；不生成在蛇身格位上，也不生成在场地外。

### 3.5 失败判定

满足任一条件，当前节拍结算为失败：

1. 蛇头目标格位于场地边界之外（撞墙）。
2. 蛇头目标格在移动后与自身某节身体占据同一格位（撞到自己）。

撞墙与撞自身均无宽限；失败在该节拍立即生效，随后进入失败结算状态。

### 3.6 通关判定

- 当一次进食使蛇身长度等于场地总格位数时，场上不再有可生成食物的空格：本节拍判定为**通关**（而非在结算后等待），进入通关结算状态。
- 通关与失败互斥：通关的最后一步是进入原本为空的食物格，不可能同时构成撞身体或撞墙。

### 3.7 同时序结果的裁决（歧义消解）

所有判定以“节拍”为唯一时间点，同一节拍内按下列可观察次序一次性结算：

1. 取缓存中合法的新前进方向（若有）；
2. 计算蛇头目标格；
3. 判定通关/失败：
   - 目标格出界或为移动后将被身体占据的格位 → 失败；
   - 进食后长度等于总格位数 → 通关；
4. 均未触发时：目标格有食物则进食（增长、加分、消去食物、生成新食物、安排后续加速），否则普通前进一步（蛇尾收回）。

即：死亡判定优先于进食表现；但由于食物只生成在空格，死亡格与食物格在同一局中不会重合。玩家在两次节拍之间的任何转向输入都不立即改变蛇的位置，只影响下一节拍及之后。

### 3.8 状态机

| 状态 | 进入条件 | 允许的动作 | 转移 |
|---|---|---|---|
| 就绪（主菜单） | 页面加载完成；或从暂停/结算选择「返回主菜单」 | 开始游戏 | 开始 → 游玩（新一局） |
| 游玩 | 从就绪开始；或从结算「再来一局」；或从暂停继续 | 转向、暂停 | 撞墙/撞身 → 失败结算；填满棋盘 → 通关结算；暂停 → 暂停 |
| 暂停 | 游玩中暂停输入 | 继续、重新开始、返回主菜单 | 继续 → 游玩（节拍倒计时在暂停时刻冻结，恢复后从剩余时间继续；蛇从停止处恢复）；重新开始 → 游玩（新一局）；返回主菜单 → 就绪 |
| 失败结算 | 游玩中触发失败判定 | 再来一局、返回主菜单 | 再来一局 → 游玩（新一局）；返回主菜单 → 就绪 |
| 通关结算 | 游玩中触发通关判定 | 再来一局、返回主菜单 | 同失败结算 |

页面失焦（如切换浏览器标签）时的期望表现：若正在游玩则自动进入暂停，避免后台计时造成失控；具体触发方式由交互契约/实现文档落实。

## 4. 持久化与重复游玩差异

- 仅持久化**历史最高分**（Web 本地存储）。新得分在一局结束（失败或通关）时写入：仅当当局分数高于已存最高分时更新。
- 无解锁内容、无关卡进度、无设置项持久化需求。
- 每局重复游玩的规则、场地与初始状态完全一致；差异仅来自食物随机位置、玩家操作，以及随每局进程的节拍加速。

## 5. 系统交互边界（供下游文档使用）

- **玩法规则（本 GDD 权威）**：网格、节拍、转向、进食、碰撞、状态机、结算次序。其他文档引用而不重新定义。
- **数值调优（平衡文档权威）**：网格行列数、初始长度与朝向、初始节拍时长与加速分档/最短时长、缓存容量、食物分数、食物与蛇头的初始安全距离、触屏滑动阈值。
- **交互契约（交互文档权威）**：具体按键映射、滑动判定、按钮焦点与可达性；必须实现本 GDD 的动作集合与暂停语义。
- **表现（美术/UI/音频文档权威）**：蛇、食物、场地的视觉风格与吃到/失败反馈、HUD 与各状态界面布局；不得改变判定时机（如补间动画不得提前或延后碰撞判定）。
- **数据驱动**：场景层级、变换、UI 布局、响应式变体与资源绑定以编写的 Scene/UI JSON 为唯一可编辑来源；运行时代码加载/编译这些数据并实现玩法。

## 6. 完成条件（可在游玩中观察）

首版交付被视为完成，当且仅当以下各项在实际运行中成立（由后续实现与验收阶段验证，本 GDD 不声称这些检查已经完成）：

1. 页面加载后进入就绪状态，可通过按钮或键盘开始新一局。
2. 游玩中蛇按节拍持续前进；键盘与触屏均能合法转向，反向输入不会导致立即撞死自己，连按转向可按序生效。
3. 吃食物时同节拍发生增长、加分、食物在空格重生；节拍随后按既定曲线加快。
4. 撞墙、撞自身必定且仅在对应节拍触发失败；填满棋盘触发通关。
5. 暂停完全停止蛇与计时，可继续、重开或返回菜单；页面失焦自动暂停。
6. 失败/通关后可「再来一局」或「返回主菜单」；历史最高分正确保存并在刷新页面后仍然显示。
7. 场景与界面由编写的 Scene/UI JSON 驱动，且在常见桌面与移动端视口下布局可用（具体视口与适配标准以 UI/UX 文档为准）。
