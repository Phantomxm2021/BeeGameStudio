## 1. 资源策略总述

本游戏视觉主体是**圆润哑光糖果形状**（ART_DIRECTION 2/4），蛇、食物、棋盘、按钮全部由简单圆角几何构成，且需要随棋盘整体等比缩放：这些**以运行时矢量/形状绘制（或轻量 SVG）为正式来源，烘焙位图反而会糊、增体积，因此不进图集、不生成位图**。

需要预制的静态资源只有三类：

1. 标题主图（一幅，含标题字处理）；
2. UI 功能图标（暂停、静音两态）；
3. 音频（4 个必需音效 + 1 个可选音效）。

外加字体。**首版无位图图集（atlas）、无 TileSet 位图、无背景大图、无 3D 模型、无音乐、无语音。**

资源绑定（哪个节点引用哪个资源）写入 Scene/UI JSON；代码只加载与绑定，不以常量替代（TECHNICAL 第 4 章）。

## 3. 各项规格

### 3.1 `hero_title` 标题主图

- **设计用途**：就绪屏视觉焦点，传达玩法与情绪——“盘成螺旋的蛇围着一颗发光果实”（ART 5、UI_UX 3.1）。
- **逻辑显示尺寸**：≤ 就绪屏 R2 边长（M 档 R2=672du，实际主体约 600du、四周留安静区），居中；随 contain 等比缩放。
- **建议来源（单一来源整图）**：一次生成包含蛇+果实+足够留白的方形构图；蛇与果实同属一个视觉整体、风格与细节密度一致，适合单次生成而非逐元素拼合（符合“同组风格元素一张 sheet”原则）。
  - 可接受回退：程序化矢量绘制（螺旋胶囊路径 + 发光圆），成本更低且天然可缩放；回退不得用通用默认插画或仅放按钮代替该主图。
- **生产要求**：源图建议 1200×1200（@2x），透明或与就绪屏背景相容的底色；主体居中、四周 ≥10% 留白以适配缩放；严格遵循 ART 色板与“无锐角、哑光、≤2 层细节”。
- **验收用途对应**：就绪屏一眼焦点；进入游玩后不再加载/显示（生命周期仅就绪屏，故不与任何游玩资源打同一加载包）。

### 3.2 图标

- `icon_pause`：双竖条；`icon_sound_on`：喇叭+声波；`icon_sound_off`：喇叭+斜杠（开关状态必须形状不同，不只靠颜色——ART 6）。
- **形式**：单色矢量（SVG/形状），深色 #0F172A 或白色按 R1 底色切换；逻辑显示 24×24du，命中区 44×44du（UI_UX 2.1）。
- 以矢量数据直接写/绑定于 UI JSON，无需位图帧；与按钮同生命周期，无图集需求。

### 3.3 字体 `font_ui`

- 中文字族：圆润、现代粗体（圆角感黑体类）；字重 400/700/800（正文/按钮/标题）。数字使用等宽数字（tnum）以稳定 HUD。
- 授权与体积：优先选用许可清晰、可子集化的 Web 字体；首屏仅需常用字（标题、按钮、HUD 文案），做中文子集控制体积；可接受系统圆润字体回退栈，回退不得改变粗体/圆润特征的可读性。
- 标题字 `title_wordmark`：用该字体 800 字重程序排版（“贪吃蛇”），不单独做位图字。
- 字体不是图集项；独立加载，字体未就绪期间用回退栈显示（不隐藏文字、不产生布局跳动过大：标题预留行高）。

### 3.4 音频

统一规格（行为详见 AUDIO_DESIGN，此处给生产规格）：

| ID | 时长 | 循环 | 生产要求 |
|---|---|---|---|
| `sfx_eat` | 90–120ms | 否 | 正弦/三角波 660→990Hz 上挑；干声、无长尾；单实例可被新音/失败截断 |
| `sfx_fail` | 400–500ms | 否 | 400→150Hz 下滑带轻颤动 |
| `sfx_win` | ≈600ms | 否 | C5-E5-G5 上行琶音 |
| `sfx_ui_tap` | ≈80ms | 否 | 1200Hz 短脉冲，低音量，限 2 重叠 |
| `sfx_ui_open`（可选） | ≈150ms | 否 | 柔和双音/whoosh |

- **来源建议**：首选 WebAudio 程序合成（零下载、与合成器音色定位一致、参数可随提速档位升调）；若采用音频文件，短单音 wav/ogg，总字节应极小，打包为一个音效包（共用整个游戏生命周期，互相会并发——但不是图集，音频不打图集）。
- 相对电平与抢占规则：fail/win 0dB、eat −6dB、ui_open −10dB、ui_tap −12dB；fail/win 互斥抢占（AUDIO 4）。
- 每个音效都有视觉配对（UI_UX 5），静音仅会话内有效（AUDIO 5）。

## 4. 加载与打包组织

| 加载包 | 内容 | 时机 | 生命周期 |
|---|---|---|---|
| 启动必需 | `font_ui`（子集）、图标矢量、`sfx_ui_tap` | 页面加载 | 全程 |
| 就绪屏 | `hero_title`、全部 sfx（首手势前完成音频解锁准备） | 就绪屏显示 | 主图仅就绪屏；音效全程 |
| 按需 | 无（游玩零额外资源） | — | — |

- 不启动图集：全部静态图片仅 `hero_title` 一张，图标为矢量，主体为实时形状——没有“共享加载生命周期 + 相同采样需求”的多个小位图，故无 atlas 收益，明确不建。
- 背景为程序渐变（可无限延展各宽高比），不加载位图；棋盘不是 Tilemap 位图，由格数据绘制，不存在 TileSet 帧引用一致性问题。

## 5. 数据与资源绑定

- 资源 ID、路径/生成产物在 Scene/UI JSON 中绑定到对应节点（主图节点、图标按钮、字体样式、音频事件）。
- 颜色、圆角、高光等美术参数随场景/样式数据提供，不烤进纹理；进食迸点、脉冲等参数驱动特效由运行时生成，不做帧动画序列。

## 6. 许可、来源与一致性校验

- 外部字体与任何检索素材须许可清晰（可 Web 分发）；AI 生成内容遵循平台生成默认配置，主图为单次生成无需偏离默认。
- 全部图像类资源入库前对照 ART 第 8 章四条：圆润无锐角、哑光无写实纹理、色板一致、光源统一与细节层数；图标检查形状可辨（非仅颜色）。
- 音频入库前试听：峰值差 ≤12dB、eat 在 80ms 档截断不刺耳（AUDIO 8）。

## 7. 需完成的制作工作（交接给后续阶段）

1. 定字体并子集化；2. 产出主图（一次生成，备选矢量方案）；3. 提供图标矢量；4. 合成或获取 4 个必需音效（+可选 ui_open）；5. 将全部绑定写入 Scene/UI JSON。
“可用”的标准：主图在就绪屏含留白等比显示、图标状态形状可辨、字体加载与回退不破坏布局、音效在移动端扬声器与耳机均可辨且不突响。

## 8. 未验证事项
