# V3 1.33：同工程消息、需求变更及中断续作审计

日期：2026-10-11。按照实施规范 §7 第 4 项推进，仅改 BGS 集成与独立 debug；未修改真实项目产物、正式 frontend、Claude Code 核心或 builtin-tools，未部署／重启／执行 SQL／付费调用。

## 结论与真实调用

同一工程现在能够追加讨论、明确变更和显式续作，复用原生历史／UUID、Question、权限与用量。没有宿主 Task、规划器、引擎选择或修复方案。只是打通本地最小闭环，不是完整游戏／真实模型通过。

| 模块 | 输入 → 输出／共享能力 | 已确认缺口或耦合 | 最小处理 |
|---|---|---|---|
| routes → agent-goal | 所属用户、项目、Chat、原始文本／授权类型／当前版本 → native turn | 原入口只接初始 goal；同工程追加消息无接线 | 添加 /agent/messages，复用正常身份／权限，校验本 Run／原 Chat，不走旧作者／Task |
| agent-goal → SessionManager | 原 Chat 与已保存 native UUID → sendWithDisplay／正常 native resume | start 可能复用 restored idle Chat，忽略显式 resume UUID | 在无活跃写者时关闭 idle Chat，再按原 UUID 恢复；核对原生 UUID／磁盘历史，缺失／空／不覆盖上一轮时不派发 |
| AgentTurn → Run/store | 原始消息、请求身份、需求版本、fence、退出／用量 → CAS JSON | 仅初始 requestKey；变更若先保存、再领取，可能留下重复执行窗口 | 变更版本、追加历史和写者一次 CAS；相同请求只返回已有执行，不同内容／过期授权拒绝 |
| 本轮变更 → 现有 RPC | requirements.changed + 原始 before/after + 既有修订计数 → 已有表 | RPC 要求变更历史与 planRevision 递增 | 沿用现有条件与 JSON，无新表／迁移；计数递增不生成任何 Task plan，远端未实测 |
| pause/resume/recover → 原生状态 | 持久暂停、实际退出、明确新消息 → 同工程续作 | 原来 resume 仅清暂停，不能提交后续授权；会话缺失不能证明退出 | 保留既有未知写者保护；最新中断／失败 + 显式恢复 + 新消息才继续；无自动重发原 goal |
| 独立 debug | 当前项目／凭据／Run／Chat／版本 + 用户文本 → 原始 API | 刷新若重绑草稿，可能扩大授权；相同按钮可能重复花费 | 准备时固定身份及正文；改变内容须新身份；身份切换／离页清空；无自动派发、轮询或重试 |
| 专业能力 | 原生工具与必要短说明 → 实际来源修改、定向检查 | 纯讨论无需生产工具桥 | 讨论不创建临时工具入口；生产／变更／续作仍按需供应，不限制原生计划与工具 |

新增数据只记录实际授权、身份、版本和退出，解决重复执行、历史丢失和变更追踪；更简单的“重发原始 idea／只给一条继续消息”无法保留这些事实。没有新增通用调度、状态机或业务阶段。

## 已验证的行为

独立 debug 页面 + 真实 CLI + 本机脚本模型，共 5 轮：

| 本次操作 | 实际结果 | 脚本模型合成 Token |
|---|---|---:|
| 原始 goal | 原生 Todo、Skill、Question；保存候选，真实失败测试、Read/Edit 修复及复测；实际资源目录／纯格式／空间算法 | 180 |
| 讨论 | 实际 Read；规则、测试和独立 notes 字节未变；需求版本不变 | 30 |
| 明确变更 | 原生 Edit 修改规则与其实际消费者测试，再真实 Bash 重测；需求新版本，notes 保留 | 75 |
| 后续变更中断 | 保存 partial，再发真实 Question；通过 debug 暂停，答复失效；部分成果保留 | 30 |
| 明确恢复 + 显式续作 | 恢复本身不执行；原 UUID 读 partial、Edit 为 complete、重测变更规则；无关 notes 不重造 | 60 |

25 次本机假模型请求；5 次真实 CLI 启动的后 4 次均传同一 resume UUID，后轮实际原生请求含之前的 Question／工具历史。重复 goal／消息没有新增执行。375 Token 是假模型脚本报告值，付费调用 0，不是实际成本或节省测量。

单元补验：持久暂停后的工作进程重建、原始历史／部分成果不丢失；缺失／空历史拒绝且不改需求；并发变更最多一个执行；失败变更不回滚授权／不重复执行；请求内容冲突、旧版本／错误 Chat、续作错误目标、未知写者均拒绝；历史不可改写。只有结算 CAS 重基，不重跑模型。

最终冻结版本定向回归：25 文件，283 通过、0 失败、2 跳过；全工程类型检查通过。跳过为旧 design-browser 两项未启用开关，新 debug 真 CLI 验收未跳过。包含原会话／Question／子代理通知、旧 Task 变更及退出恢复、专业工具消费者与安全边界；没有声称全仓库所有测试通过。

原始输出、执行命令、源码与受保护目录哈希见 [配套 JSON](bgs-v3-agent-conversation-2026-10-11.json)。本轮前后 src（2445）、builtin-tools（383）、frontend（508）文件计数及聚合哈希一致。1.32 原文逐字节归档后，主规范提升为 1.33；不追溯升级旧证据。

## 修改影响

- 集成内部：追加消息领取／结束／resume，共用原单写者和实际正常 CLI；回归身份、并发、请求去重、暂停、退出、UUID／历史和用量。
- 交接格式：AgentTurn 增加原始消息／需求版本；Run 沿用 requirementsChanges 与现有 CAS；旧 goal 重复请求改按起始需求核对。回归旧任务／需求变更，未更改数据库结构。
- 公共能力：不改 SessionManager、native runner、工具和 Claude Code；仅修正调用方式。讨论不创建新增资源桥，但原生正常能力不替换。
- 用户产物：仅受控临时合成工程被正常 BGS＋CLI 修改；没有人工修补真实项目，也未将合成成果当游戏验收。

## 不能据此宣称解决的边界

- discuss 是“不授权修改”的正常指令，不是强制文件系统只读；受控模型遵守不证明任意模型都会遵守。原生权限机制仍在。
- 原 brief/settings 是起始事实，原始授权变更追加保存并交给 Agent；宿主不解释自然语言或自动生成新结构化设置。实际专业来源／消费者更新仍需 Agent 正确执行，旧八文档 authority 接线仍不可直接用于这条主线。
- 每轮绑定需求版本并维持未验收；本轮确实重跑了合成规则，但还没有任意技术路线的通用质量覆盖、已测构建／发布闭环。ended、修订、恢复和模型通过声明都不是游戏合格。
- 真实数据库并发未测；没有新 SQL。真实模型自主修订、语义漏检、成本、真实 native 子代理跨中断、外部收费／引擎后台恢复未验收。硬崩溃后的未知写者仍需实际退出证据，不能因重启而解锁。
