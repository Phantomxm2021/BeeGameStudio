## UI 声明漏项与延迟阻断

这次方向报错与上文消耗来自同一次原始运行。事件 780、785、901 显示作者读取 `uiDocument` 和 `uiVocabulary`，未读取 `uiLayoutContract`，且对格式输出使用了 `head`。全部 Skill 调用没有 UI 设计 Skill；全部 Bash 工具启动记录没有 `--layouts`。

事件 2575 发起普通内容检查，2577 返回 `valid:true`、结构/引用范围、6 份文档。事件 6578 在北京时间 15:35:21.711 才报告五份 UI 的方向不一致；距上述检查启动约 19 分 41 秒。五份文件实际都是横向尺寸，且根节点 `data` 全部缺失。这解释了为什么作者能继续实现和排查，最后才被布局门槛拦住，但不等于这段时间或所有 Token 都能省掉。

| 分类 | 根因 | 修复 |
| --- | --- | --- |
| Agent 执行漏项 | 根节点未声明方向、目标尺寸和控件标准；未使用 UI Skill 或布局检查 | 不靠新增自检口号保证遵守；普通检查直接检查这些确定项 |
| 系统格式说明 | 被读取的通用节点只有 `data:{}`，根节点布局要求分散在另一节 | 在 `uiDocument` 展示明确根节点模板和适用条件；HUD 场景连接写清必需 |
| 系统检查入口 | 普通检查只查结构/引用，宿主推进才查布局 | 默认调用已有布局检查器；完整首发覆盖仍由 `--layouts` 和对应宿主阶段检查 |
| 系统事实衔接 | 旧 `--layouts` 没有传入用户确认方向，宿主却传入 | 将原始确认方向发布给本地 CLI；宿主仍独立读取原始请求，防止本地文件改写最终标准 |
| 检查器诊断缺陷 | `undefined !== Landscape` 被写成方向冲突；每文件第一个异常停止后续检查 | 区分缺失、非法值、真实冲突，并集中报告独立声明错误 |

因此原先结论需要补充：即使作者主动跑旧 `--layouts`，也没有完整核对原始确认方向。Agent 漏项确实存在，但校验集合和事实输入不一致是系统缺陷；不能把全部责任转交模型或宣称模型极限。
