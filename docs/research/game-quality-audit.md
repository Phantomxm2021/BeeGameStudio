### Discovery and actual execution chain

Built-in catalog is `.beegame/skills/bgs-game-skills` (21 entries). `src/bgs/skills.ts::configureBgsSkills` registers built-in and owner-private roots through native `skills/extraRoots/set`. `src/bgs/runner.ts` requests `skills/list` with `forceReload:true` and retains native read lifecycle evidence. Agent chooses applicable methods; listing/loading a Skill is not proof of applying it. Conditional references avoid loading all methods. No separate mandatory Art/UI/Audio/QA Agent chain is required by this change.

`workflow-v3/production-workflow.ts` builds the authorized assignment from confirmed brief/current request and preceding source handoffs. Normal complete-game work can go from GDD to selected visual design into implementation, producing needed resources there; independent resource delegation remains available. GDD consistency and independent visual **coverage** review do not certify game quality. The preparation guidance explicitly has no native Goal. This task does not change Goal compatibility or the parent's active workflow.

The implementation assignment already preserves selected design, authorizes resource/scene/UI assembly and affected design/resource repair within the same assignment, and directs observation of ordinary input through feedback. `agent-tools.ts` exposes existing `BgsWorkflow` / saved-session handoff, Preview access/helper, `BgsMeasurement`, and terminal `BgsFinishDelivery`. A local correction does not need to rerun all preparation. Passed report validation submits delivery; an actual external blocker can be reported blocked. Requested critique uses those same authorized source edits and retained checks, not a new review/repair loop.

`preview-test-browser.ts` owns isolated Chromium; `preview-test-recording.ts` retains actual viewport, console/network/runtime events and stills. `preview-play-capture.mjs` / supplied `withPlayCapture` retain a real-input clip, selected frames and optional explicitly selected Web Audio node. They do not invent state facts, choose a private audio master, establish novice comprehension or automatically provide every game's hidden state. Existing reports retain gameplayVerdict=not-evaluated. Headless capture is muted; native HTML audio, inaccessible graphs, physical output and XR comfort have explicit coverage limits. Previous actual-build observation also showed headless target activation kept the game visible/focused, so that action did not verify focus-loss pause.

Its title/HUD comparisons explicitly say `different`, with `nonBlockingReason` justified by the agent's GDD layout revisions. Thus the author's passed claim coexists with admitted visual differences. Selected concept and actual-build screenshots from the preceding task also show a different title subject/button relationship and typography.

This proves a **declared acceptance false positive**, not an independent aesthetic review having approved the work. The historical host's final admission is not reconstructed from that author-written JSON alone. Current `runtime-acceptance.ts` already rejects delivery differences, including the historical waiver; its test `delivery rejects declared visual differences while request reports may retain them` covers this actual failure shape. Current code also binds selected source image identity. Do not add a second waiver fix, rewrite the historical report or pretend hashes establish semantic quality. Remaining design judgment is not solved by another report field or automatic reviewer.
