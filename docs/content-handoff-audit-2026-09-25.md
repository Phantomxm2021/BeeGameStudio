# 项目阶段交接：根因、修复与验收

日期：2026-09-25。范围：BGS 平台；示例项目仅只读取证。

## 结论

不是摘要计算本身出错，也不是必须限制 Agent。BGS 把持续变化的执行输入留在文件中，却只给同一个长期会话发送泛化的“继续”。文件已更新不等于模型已收到更新。这同时影响了内容摘要和资源能力地址。

## 系统代码中的缺口

1. `refreshProjectContentContract` 原来丢弃契约生成函数的返回值，校验入口从未进入实际交接。
2. 原契约只提供人工编写的格式描述：2D 相机仅写“正数”，实际校验要求固定换算公式；UI 的资产引用必填语义也不够明确。
3. 原内容 CLI 把没有索引/契约文件的情况统称为“需要已验收资源版本”，与服务端的真实错误不一致。
4. 原回归测试主要断言磁盘文件和阶段推进，没有断言 native runner 实际收到的当前输入。
5. 原上下文声称包含“last worker reply”，实际只含初始目标和阶段；已订正措辞，不伪造恢复材料。

## 已落地的最小修复

- `content-format.json` 只描述设计期格式，不放假的摘要；`content-contract.json` 是内容阶段实际输入。
- 当回合传递小量 BGS 状态和当前摘要，不替换用户原文，不创建第二条 Chat 用户消息，不重启或拆分项目 session。完整规范仍按需读取。
- 当回合明确提供已有 `assets.mjs` 的稳定项目内命令；命令文件每回合使用当前能力地址。历史临时地址已失效这一事实也明确交接，不替 Agent 选择来源。
- 项目内 `check-content.mjs` 使用与服务端相同的内容校验和摘要实现。支持默认检查、`--authority`、`--inspect`；只读，不改游戏内容或自动盖章。
- 补齐已证实缺失的相机公式、UI 引用要求；去掉未被消费的旧 task/allowedPaths 和宿主预览命令描述，不把死字段当作实际能力。
- 本轮不改变阶段顺序、自动续跑策略、模型回合长度、权限策略、委派或工具选择。

编译说明：新增独立检查器在本进程多次 Bun.build 的回归中出现读取错误文件/路径失败；隔离到一次编译子进程并缓存结果后通过。没有据此推断原项目事故也由编译器导致。

## 交接修复后的遗留项

- Bash 可读取宿主源码是独立的执行隔离缺口；后续修复及其验证范围见下文，不与输入交接修复混为一谈。
- 资源库/生图的真实上游健康状态不能由过期 localhost 地址的失败推断。
- 格式说明与业务校验仍各有其职责；本轮补齐已知遗漏并提供同源可执行检查器，不声称所有自然语言说明已与所有校验条件逐条证明等价。
- 原“工作区有变化即视为进展”的自动续跑判断仍需单独评估；未用任意次数上限替代本次交接根因修复。

## 首次执行隔离试验：撤回（历史记录）

后续在临时项目、无模型调用的真实 macOS shell 中试验普通会话接入原生沙箱。结论：不能直接部署文档任务的隔离设置。

- 项目内普通文件的创建、移动、删除通过；原生 runner 的 32 项既有行为回归通过。
- 系统 `/usr/bin/git` 经由 Xcode 定位和宿主缓存访问时被拒绝。直接使用已选定工具链后，`git init` 仍因原生沙箱对 `.git/hooks` 的强制保护失败。这是现有沙箱的行为，不是新增游戏规则。
- 尚未完成项目外文件、符号链接、联网、安装依赖和浏览器的整套真实执行验收；不能据前面的通过项宣布隔离有效且兼容。
- 原生沙箱在不受支持的平台上也不能静默退回不隔离执行；Windows、Linux 的实际兼容性尚未验证。
- 因普通开发能力回归失败，本次新增的普通会话接入及辅助代码已撤下，未重启或部署。没有扩大宿主读取范围、添加 Git 命令特判、修改已有项目或变更 Agent 阶段规则。

接下来的验收标准必须同时包含：宿主源码/配置不可读取；项目文件、依赖安装、Git 初始化、资源访问、浏览器测试可用；子任务沿用同一边界；中断恢复维持单个 native session。若现有执行器不能同时满足，就需要先解决执行器兼容性，不能拿限制 Agent 行为替代。此前的输入交接修复不依赖这次试验，继续保留。

## 执行隔离兼容修复与付费验证（2026-09-25）

已证实的执行层根因：普通项目没有启用原生文件沙箱；文档任务已有的隔离配置不能直接复用。另一个绕过面是 CLI 隐式执行的 Git：即使 Bash 已隔离，仓库配置中的 fsmonitor/filter 仍可能通过未隔离的 Git 进程读取宿主文件。

修复保持在执行器边界，不增加阶段规则、工具白名单、强制委派或多 session：

- 普通项目使用原生沙箱，工作区可读写；仅系统工具链和明确发布的 Skill 目录额外只读。项目设置、切换 cwd、additionalDirectories 不得扩大宿主读取范围；无法启用隔离时明确失败，不静默降级。
- 临时文件、依赖缓存、浏览器安装目录使用项目临时目录；Git/NPM 不再隐式读取宿主用户配置。macOS 使用已选工具链，Git 初始化使用空模板目录，不移除原生 hooks 保护。
- 原生沙箱已有的 Git config 支持接入 CLI；CLI 隐式 Git 同样在沙箱中执行，子进程凭据过滤在环境合并之后执行。
- 保留原生工具、子任务和网络代理能力；已发布 Skill 引用仍可读取，不开放其父级运行时配置目录。

验收证据：

- 50 项无费用回归通过，后端 TypeScript 检查及 diff 检查通过；包括真实 CLI 的普通项目/文档任务隔离、主/子任务越界读取、符号链接、隐式 Git fsmonitor、项目 Git 提交、本地 HTTP 服务、Skill 引用、停止恢复和阶段切换单会话。
- 用户授权后，仅新建一个临时测试项目，通过产品 native runner 调用真实模型；本次上限 $1、14 turns、180 秒，CLI 估算实际费用 **$0.452589**，不等于最终账单对账值。
- Agent 写出三文件网页、启动 HTTP 服务并核对响应、初始化并提交 Git、委派一个原生子任务检查项目；对特设宿主测试文件的 Bash 读取收到 Operation not permitted。结束后服务已关闭，宿主测试文件未变；独立执行 JS 点击/重置逻辑通过。
