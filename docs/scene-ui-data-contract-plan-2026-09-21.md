# Scene / UI 数据规范与编辑器落地方案

状态：核心数据合同与矩形 Tilemap 编辑闭环已实施，并完成下述无费用验证；新项目交付及完整性能验收未完成。2026-09-21。

本方案替代已撤回的“共享游戏运行时/绘制模块”方案。此前试验性代码已撤销；不得恢复或据旧方案继续开发。

## 1. 唯一目标与边界

**BGS 提供完整、明确、引擎无关的数据；Agent 根据项目技术选择编写加载、解析和游戏代码。共享的是数据及含义，不是引擎实现。**

| 责任方 | 负责 | 不负责 |
| --- | --- | --- |
| BGS 数据规范 | 字段、类型、单位、资源引用、层级、格式版本和结构检查 | 游戏循环、渲染器、物理系统、运行时资源管理 |
| 资源/内容 Agent | 选择或制作素材，组织 Scene/UI/Tilemap 数据 | 不必采用某个固定引擎或固定工具顺序 |
| BGS Scene/UI Editor | 加载、显示、编辑、保存这些数据；自身的显示性能与交互 | 向生成游戏输出一套 BGS 引擎 |
| Implementation Agent | 消费相同数据，实现加载映射、玩法及目标技术下的运行验证 | 不应猜测未定义的数据含义或硬编码第二份场景布局 |

不新增游戏运行时包、跨引擎适配框架、通用资源缓存/GPU 生命周期模块或 Workflow 阶段。已有纯 schema/坐标辅助函数可在 BGS 内复用；已有可选消费 helper 保持可选，不扩展成游戏加载器，也不作为交付依赖。

只改系统、系统测试和契约文档。不直接修改已有测试项目的源码、资源、Scene/UI JSON 或 HUD。不启动付费生成、自动重试或付费复测。

## 2. 格式与权威数据

选择 **JSON**：沿用当前格式，类型明确，便于 Agent 输出、Schema 校验与编辑器读写。YAML 的注释与简洁性不足以抵消当前新增解析、隐式类型和双格式维护成本。不同时维护 JSON/YAML。

- 沿用现有 Manifest 与 Content Package：Manifest 管资源身份、文件/hash、来源与依赖；Content 管场景和 UI 的组成与实例配置。
- Scene/UI 引用资源 ID 和明确的成员/子资源 ID，不嵌入图片字节、不复制完整 Manifest。
- 图集/Tile 定义属于资源数据；格子布局属于 Scene。复用现有资源文件及登记方式，不另建资源数据库或强制导入流水线。
- 普通图片等资源继续使用其原文件，不要求每个文件额外包装一份 JSON。只有图集帧、Tile 集合等实际需要结构化描述的数据才补足定义。
- Content 是可编辑布局的唯一权威。允许 Agent 为目标技术生成可重建的构建产物，不允许独立维护另一套布局。游戏运行状态不反写设计数据。
- 每个正式字段说明类型、是否必填、缺省含义、单位/空间及引用目标。未知组件类型报错；玩法自定义元数据可使用已有明确扩展位置，但不能借此发明未经支持的渲染组件。

## 3. 要补齐的数据语义

借鉴 Unity 的对象/组件、Grid、Tile、Tilemap、RectTransform 职责，不复制 Unity 原生 YAML、fileID/GUID 或内部序列化结构，也不改变现有 [坐标约定](./content-coordinate-contract-2026-09-20.md)。

| 数据 | 必须表达清楚 |
| --- | --- |
| Scene | 稳定节点/组件 ID、父子关系、启用状态、父局部 Transform；资源与组件引用；明确的图层排序 |
| Sprite/Atlas | 图片成员、帧 ID/区域、pivot 与显示尺寸的关系；区分图片像素和场景尺寸，不能只写“某张图集” |
| Grid | 布局类型、格子尺寸与间距；格子原点、轴向及其与节点 Transform 的关系 |
| Tile 定义集合 | 稳定 tile ID、Sprite/帧引用、必要的局部视觉属性与可选碰撞形状 |
| Tilemap | Grid 引用、Tile 集合引用、格子坐标与 tile ID、排序及碰撞启用配置 |
| UI | 稳定 screen/node ID、父子层级、画布尺寸、anchor/pivot、偏移/尺寸、视觉字段、控件状态与绑定/事件 ID |
| 3D | 保持节点/组件模型、Mesh/Material 引用和局部 Transform；不套用二维单位、坐标翻转或 Tilemap |

其中“TileSet/Tile 集合”是通用数据称呼，不声称对应 Unity 的同名内置组件。业务名称（如 HUD、警觉槽）不能代替组件类型；也不为了名称对齐而重写全部 UI 数据模型。

### Tilemap 首批边界

- 先完成矩形、正交二维格子。六边形、等距、规则自动铺设暂不承诺支持，不预建空实现。
- 布局保存稀疏格子列表：整数坐标与 tile ID；空格省略，同层坐标唯一；不同层使用不同 Tilemap 节点。负格子坐标有效。
- 格子尺寸不自动等于贴图帧尺寸。明确 Tile 的显示尺寸/pivot 与格子原点的关系，避免树冠等图块被强制压进一个格子。
- Tilemap 引用自身或祖先 Grid；格子位置在 Tilemap 局部空间计算，继承节点变换一次。契约与示例必须明确偏移，不混用世界坐标。
- 同一集合允许引用多个已登记图集。引用按已定义字段逐层检查，不依赖文件名猜测，也不放开任意嵌套引用。
- 对尚未支持的图集变体（如当前解析器拒绝的 rotated/trimmed 帧）明确报错；不把“严格规范”写成已经支持所有 Unity 功能的承诺。
- 碰撞形状与视觉分开表达，单向/触发等行为必须显式声明；目标游戏如何创建物理对象由 Agent 实现。
- 渲染分块、GPU 合批等不是持久化布局的必填字段。编辑器可自行优化，生成游戏由 Agent 按所选技术处理。

给内容 Agent 的设计原则：**重复、网格化的二维环境优先评估 Tilemap；角色、机关、自由装饰和非网格背景按实际需求选择表达。** 不强制所有 2D 环境用 Tilemap，不用节点数量门槛替代设计判断。

## 5. 实施顺序与完成条件

| 顺序 | 落地动作 | 完成标准 |
| --- | --- | --- |
| 1. 固定数据合同 | 在现有 schema/资源登记中定义 Grid、Tile 集合、Tilemap 的字段与引用；核清 Sprite/UI 布局语义；同步合同和示例 | 每个字段有唯一含义；示例通过实际校验；缺失帧、重复格子、无效引用等给出定位明确的错误 |
| 2. 接入生成与交付 | 资源/Content authoring 使用同一合同；Implementation 上下文说明文件入口、坐标与引用规则，要求读取数据而非重建布局 | 不新增阶段、不限制 Agent 工具；没有 BGS 游戏运行时依赖；实际提供的是可消费的数据和说明，不是另一套引擎代码 |
| 3. 补齐编辑器 | 实现矩形 Tilemap 显示与格子增删改、资源选择、保存及 Undo/Redo；修正 Scene/UI 对合同的解释差异与预览猜测 | 同一文件导入、编辑、保存、重开不漂移；真实显示格子与正确帧，保留父变换及排序；现有 Sprite/基础 3D/UI 不回退 |
| 4. 清理并验收 | 删除被替代的假 Tilemap 路径、猜测解析及冲突文档；完成下节无费用检查 | 无新旧双轨、无运行时包、无示例项目补丁；逐项记录通过/未通过，不将 schema 通过当作游戏交付完成 |

步骤是本次开发顺序，不是新增产品 Workflow 阶段。步骤 2 的新能力在步骤 3 验收前不得作为已支持能力发布给运行中的 Agent。

不兼容字段改动必须明确版本和影响范围；不得静默解释旧布局、自动迁移用户项目或中断当前任务。实施时同步 reader/writer/validator/生成合同，不保留猜测式兼容。服务切换与重启按当次授权处理。

## 6. 验收：证明数据可消费，而不是证明自研引擎

本轮先做无费用验证，使用仓库自建最小 fixture，不修改用户测试项目：

1. **结构与引用**：合法 Tilemap、多图集、空图、负坐标可读；重复格子、缺失 Tile/帧、越界区域、层级循环、未知类型被正确定位。参数不能因为宽泛 data 而静默放行。
2. **编辑闭环**：Scene/UI 的资源选择、位置/旋转/缩放、父子层级、图层、anchor/pivot 及 Tile 增删改，保存重开与 Undo/Redo 正确；不丢失合法自定义元数据。
3. **独立预期**：fixture 给出人工可核算的世界坐标、UI 边界、帧区域和格子布局。校验器与编辑器都对这些预期验证，不能仅互相一致就算正确。
4. **编辑器显示与性能**：实际浏览器检查矩形 Tilemap、Sprite/Atlas、基础 3D 和 UI。记录固定视口下小图/万格图的加载、交互及内存情况；优化只作用于编辑器，不据此宣称游戏性能提升。
5. **边界检查**：不新增游戏 renderer、game loop、物理或运行时资源模块；交付说明不要求生成游戏导入 BGS 包。现有纯 helper 不因本次计划变成强制依赖。

之后由用户安排新项目测试：让 Agent 正常读取数据并实现游戏，核对布局和资源是否一致，编辑后重新读取数据能否反映变化、是否仍重复硬编码布局。无需本轮编写“测试用通用游戏加载器”或多引擎演示来替代真实 Agent 验证。

费用复测继续暂缓。JSON 体积、生成数据量、内容修复次数和阶段耗时可作为后续观测，不承诺节省比例。无费用检查通过只代表规范和编辑器能力通过，不代表跨引擎游戏均已验证。

## 7. 方案复审记录

- **越界检查**：已删除共享 Web 绘制、运行时包、缓存/解码/GPU 生命周期和多引擎映射框架的开发任务。
- **一致性检查**：要求同一数据及含义，不要求编辑器和游戏使用同一实现；有意的编辑器辅助显示不属于游戏效果。
- **Agentic 检查**：Tilemap 是有适用条件的建议；严格约束数据正确性，不约束创意、技术选型和执行步骤。
- **复杂度检查**：沿用 JSON、现有 Manifest/Content、现有编辑器；先补当前缺失的矩形 Tilemap，避免一次重构全部组件。
- **资源范围检查**：不强制所有素材增加描述文件；不把数据规范重构扩大成资源生成/导入服务重写。
- **可执行性检查**：每步有代码落点、产出和验收条件；正式字段与示例在第 1 步固化，本文不冒充已上线 schema。
- **证据检查**：规划后的实施与实际验证记录如下；不能把规划、单元测试或数据校验替代游戏交付。

## 8. 本轮实施与复审

已实现：

- 新 Grid/Tilemap/TilemapRenderer data 严格版本化；TileSet 沿用 Manifest 的 data 资源，无新增注册系统或运行时包。
- 资源/内容检查明确成员路径、命名帧、Grid 祖先关系、重复格子、缺失 Tile 和 PNG 图集越界；碰撞形状及单向语义为数据，不实现物理。
- 编辑器按格子和实际图集帧显示，显示尺寸独立于格子尺寸；逻辑像素与编辑器轴向只转换一次。
- Inspector 支持单格设置/删除、Grid 尺寸、排序、碰撞轮廓；保存重开、Undo/Redo、复制 Grid 的引用重映射。
- 画布 Tile Palette 按 Unity 的 Active Target → Tile → Paint/Erase/Pick/Box Fill 流程；保留 B/D/I/U 快捷键。图集缩略图使用真实帧，空图层可直接绘制；隐藏、锁定、禁用及 3D 视图下不可绘制。
- 笔画在编辑器局部预览，松手才形成一次现有历史操作；Escape、失焦、pointer cancel、切换目标丢弃草稿。快速拖动补齐格子，落点按 Tilemap 父子变换的逆变换计算。无游戏运行时新增依赖。
- 同图集按最多 1024 格合批；多图片保持绘制顺序，不按纹理重排覆盖关系。移动节点/修改格子不重复解码未变化的贴图。
- 清除了整张图片冒充 Tilemap 的编辑器路径、静态预览的节点名称猜测及旧合同示例；普通 Sprite、UI、3D 未改成另一套架构。
- 作者合同同时提供字段和实际示例；Implementation 自主写数据消费代码，不要求 BGS 运行时依赖。

## 9. 生成数据到编辑器的加载复核

- 确认资源任务、Content 任务提供同一 Tilemap 合同，Implementation 的初始/修复/变更 dispatch 交接实际合同文件；离线拦截模型启动验证，无模型调用。
- 修复 UI 完整图片路径无法解析和同名图片相互覆盖；选择器对有歧义的文件显示完整路径。
- 修复 Scene 同名图片匹配图集时串表或漏表：按同目录完整路径匹配侧文件。
- 修复 TileSet 图片/图集间接依赖请求失败被当作可选失败；在挂载编辑器前检查具体依赖和命名帧，不把缺地形的场景报告成加载成功。
- 自动测试覆盖 TileSet 位于资源根/显式 member、跨资源独立图片、非同名 atlasMember、精确 UV、保存回传，以及间接依赖 404。UI 覆盖同名图片的完整路径、图集裁剪和选择器。
- 本轮 55 项前端测试、7 项后端合同/实际交接测试通过；前端类型检查通过。测试使用系统 fixture/API mock，不代表已完成新项目 Agent 生成或游戏视觉验收；GPU 长期稳定性等限制仍然存在，静态 PNG 后续已补齐。

## 10. 无费用预览与万格编辑验证

- 静态 PNG 复用现有坐标、TileSet 和 Tile 矩形解释；同一图片/帧只解码和嵌入一次，裁掉画面外格子。它归属后端离线诊断，不提供游戏加载器、物理或运行循环。
- 像素断言覆盖图集帧、负格子坐标、高 Tile、父级旋转/缩放、遮挡顺序、禁用父节点和损坏图片；万格 800×800 PNG 两次样本约 165/233ms。仅为本机样本，不是生成游戏性能承诺。
- 确认每笔绘制存整份 Tilemap 会放大历史开销。改为现有撤销机制记录变化格子，保持整笔原子提交、过期值拒绝和删除格子撤销后的原始数组顺序；未新建历史系统，也未绕过文档校验。
- 独立基准：10000 格起步，20 笔、每笔新增 20 格，再各执行 20 次撤销/重做并保存重开。提交中位数约 98→49ms、撤销 83→45ms、重做 84→45ms；优化后历史 JSON 约 30KB。进程堆增长样本约 239→27MiB，包含未回收临时对象，不能当作精确保留内存或泄漏结论。
- 浏览器实操：万格图连续绘制 5 笔，撤销/重做，保存后重开确认 10017 格及画面一致。当前视角稳定 WebGL 计数为 34 buffers / 11 textures，切回小图恢复 22 / 11；这是有限资源回收观察，不替代长期 GPU profiling。
- 最终回归：Scene Editor 69 项、前端相关 65 项、后端合同/预览/交接 17 项通过；Scene Editor 构建、前后端类型检查及 diff 空白检查通过。没有因此宣称完整系统无缺陷。

## 11. UI Editor / Runtime 绘制语义一致性

`flag-pole-platformer` 暴露的按钮空白不是 UI JSON 缺字，而是项目 Runtime 把绝对定位背景绘制在文字之后。UI Editor 使用浏览器盒背景，文字正常，因此同一数据被两个消费者解释出了不同结果。

修复保持原架构边界：没有共享 React renderer，也没有给生成项目提供 BGS 引擎。现在坐标纯模块同时定义可执行的 `uiPaintOrder` 和小型一致性夹具：每个启用节点固定为背景/边框 → 自身内容 → 子节点，同级保持文档顺序，禁用节点抑制整个子树。UI Editor 的预览子节点顺序直接消费该函数；便携 Content helper 导出同一函数和夹具，供任何目标技术映射和测试。作者合同也包含相同规则。

Implementation 仍自行选择框架和实现方式，但交接明确区分“DOM 中有文字/按钮可点击”和“文字视觉可见”。后两者不能再作为前者的替代证据。该修复只规范可独立计算的绘制顺序，不实现字体栅格化、浏览器、Unity、Godot 或 UE 的 UI renderer。

无费用回归：共享坐标/绘制夹具、便携浏览器 ESM、内容合同共 20 项通过；UI Editor 19 项通过；Scene Editor 与前后端 TypeScript 检查通过。测试项目未修改，历史截图和历史验收也未伪造更新；其现有 Runtime 仍需项目 Agent 在后续授权的修复任务中按新合同订正。

复现：`bun run packages/scene-editor/tests/tilemap-benchmark.ts`；PNG 回归：`bun test packages/agent-workflow-server/src/beegame/tilemap-content-preview.test.ts`。全部使用独立系统 fixture，没有修改用户项目或触发模型调用。下一步由用户安排全新项目，验证 Agent 是否合理选择 Tilemap、正确交接资源并完成实际游戏加载；完整 3D 视觉回归仍待安排。
