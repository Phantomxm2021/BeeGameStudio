# 交付耗时与正确性调整

适用于所有项目；不改变原生 Agent 内核、工具调度或自主委派，不增加阶段、审核代理、自动重试循环。

## 已证实的问题与最小修复

| 问题 | 调整 | 验证 |
| --- | --- | --- |
| 宿主预览把编码后的 PNG 当作原始 alpha，半透明显示不正确，诱发 Agent 修改正确内容 | 在原始 RGBA 像素上缩放 alpha；图像/粒子/图集渲染失败报告文档和节点，不再静默漏画 | RGB 不变、原 alpha 按比例变化；坏图集元数据明确失败 |
| Content 首次任务重复内嵌整份 Manifest 和长格式契约 | 契约写入 `.beegame/workflow/content-authoring-contract.json`，任务仅传路径、版本和现有命令；Manifest 仍读唯一索引文件 | 契约内容无损落盘，任务不再含完整 Manifest/format |
| 生成文档的扩展可能掩盖用户只要小场景的范围 | 后续任务携带已确认的 idea、selected_option、settings，不重新注入全局交付指令或整份 GDD | 用户范围保留、旧全局验收指令不进入任务 |
| 运行时代码猜测 Content 字段，直到交互才暴露错误 | 实现任务按实际 Content 建立项目内解析/类型与受影响的检查，复用项目测试 | 使用真实配置运行项目检查与交互；宿主 JSON 校验通过不等于行为正确 |
| Workflow 更新时间覆盖较新的工具活动，等待授权被显示成工作中 | 保留原生等待授权状态；运行视图分开返回 workflow/agent/tool/subagent 活动时间 | 时间分离、空事件不伪造心跳；无自动超时或重启判断 |
| 工作流缺少数据库主密钥导致生图配置读取失败，手工测试却成功 | 通过既有受信任计费服务读取同一平台配置，保留数据库/服务状态及诊断 ID | 不向运行时注入数据库主密钥；只读检查配置链，不以真实生图补偿诊断缺口 |

资源修改与 Manifest 同步继续遵循 [实现问题修复方案](implementation-issue-repair-plan-2026-09-20.md)。不自动重算哈希、不沿用修改前的 PASS。

## 不采用的做法

- 不把八文档裁成阶段白名单：Agent 仍能按需阅读全部文档。
- 不为开放的组件 data 增加一套通用引擎字段协议。
- 不固定狐狸、石门、45 秒等测试用例动作；测试取自当前项目的明确需求。
- 不限制原生 subagent、预览次数或思考时间；也不强制额外验证代理。
- 不将累计 cache-read tokens 当成唯一上下文大小或模型生成耗时。

## 后续验收与统计

先完成无付费回归、部署与配置只读检查，再执行获准的真实项目验收。记录每阶段墙钟时间、首条任务字符数、输入/输出/cache-read/cache-write tokens、工具次数、返工原因和最终缺陷。只有存在请求起止事件时才计算模型或工具耗时；重叠区间不能相加冒充总时间，没有证据的间隔标为未归因。

本次代码回归不证明旧项目已经交付，也不预先承诺提速比例。既有长任务不会在运行中被热改 prompt；新任务或明确续跑才使用新上下文。
