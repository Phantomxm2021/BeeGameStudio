# Autonomous Author: bounded finishing and smaller working context

## Implemented

- Explicit resume after a prior attempt selects finishing only when all eight candidate documents are safe, nonblank UTF-8 files. An unchanged valid baseline document is permitted. Initial starts are not silently converted into finishing.
- Finishing limits are capped at 300,000 ms active time, 300,000 ms without document changes, and 12,000 output tokens; lower registered limits remain lower. The native runner reapplies these caps. Budget expiry preserves observed usage and requires another explicit user action.
- The finishing brief requests one requirements/completeness/contradiction pass, minimal edits, no wholesale regeneration, no delegation, and a completed/blocked report. Existing publication validation and independent Reviewer admission remain unchanged; eight files alone do not mean acceptance.
- Drafting prefers two or three independent native Agent scopes once shared decisions and dependencies are ready. A compact ownership ledger, one writer per document, no nested delegation, and waiting for delegates are prompt-level coordination rules, not filesystem locks or a fixed eight-document schedule.
- Both briefs use `.reference/index.json` plus relevant scoped references first. The 49,123-byte canonical reference remains byte-for-byte unchanged. The index is 3,984 bytes; the largest scoped reference is 16,986 bytes. Each document contract is an exact projection of its original reference entry, with downstream guidance retained in the scoped set.
- Derived references are immutable and read-only, including their parent directory. Old candidates receive helpers only after checking their canonical source. Missing/changed sources and unsafe paths fail closed.
- Host-generated start/deadline/finish-reserve timestamps give the coordinator clock hints. Runtime abort signals, not model estimates, enforce attempt limits.
- Budget pauses display a specific reason and retained-draft explanation. Author `needs_action` displays as waiting for action, not an authoring failure.

## Verification

- Backend Author, delivery workflow, native tools, and sandbox regression: 395 passed across 62 files, plus the new native parallel integration test (396 passed total across 63 files).
- Frontend workflow components and display models: 308 passed across 18 files.
- Backend and frontend TypeScript checks passed.
- Dedicated finishing tests cover lower-limit clamping, old candidates without helper files, retained baseline drafts, two distinct sealed usage events, idempotent explicit resume, unsafe later files despite earlier missing files, and output-budget priority over a late completion report.
- The real bundled CLI with a local fake provider runs two native Agent scopes concurrently at a bounded barrier. Each writes four distinct documents, the scripted coordinator reports after both return, and the aggregate usage settles once. This proves native parallel plumbing and accounting, not real-model compliance with the coordination brief.

## Scope and remaining validation

No paid project was resumed, no live provider comparison was run, and the existing eight drafts were not regenerated by this change. No service restart was performed. Actual elapsed-time savings, total token cost, model adherence to the parallel/ownership brief, and Reviewer outcomes still require a separately authorized live comparison. The drafting finish reserve is a coordination instruction; the separately resumed finishing attempt has enforced runtime caps. Network-poll freshness handling was not changed.
