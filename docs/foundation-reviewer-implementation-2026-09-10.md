# Reviewer 实施方案（本轮唯一落盘范围）

## 目标

一个 Agent 完整阅读原始需求与八文档，形成整体理解、验证疑点、补查边界并输出统一问题清单。原文不必始终同时占据上下文，但不能静默遗漏。没有原始需求就不宣称符合用户意图。

## 按当前实现落盘

1. 保持已经精简的单 Agent 审查提示、read/calculate 工具、可选草稿、直接 final、原文引用校验、现有计费/超时/停止保护。不接 Revision，不新增 Agent、机械语义判断器、覆盖台账或数值证明协议。
2. 增加一个小型输入呈现模块：完整编号输入编码不超过 256 KiB 时仍全部提供；超过时只在首轮提供文档/需求目录（路径、总行数），Agent 使用现有 read 按段阅读。该阈值只是首轮呈现策略，不是模型上下文容量判断。
3. 分段模式根据同一审查日志中成功的 read 结果计算尚未读取的原文范围；工具调用请求、失败读取和模型自述不计入已读。Agent 不填检查表。提交 final 前仍有原文未读取时，在同一上下文返回未读范围，允许继续回读；不能发布成功结论。
4. 分段模式提供连续阅读指引：先逐段理解全套文档，保留带出处的关键事实和疑点；跨文档判断时回查对应原文，不仅依据摘要。沿用现有原生运行时的上下文整理能力，不自行创建摘要管理器。资源不足时如实返回未完成，不提高现有执行上限或伪装成功。
5. 现有 2 MiB 文档输入限制改为 16 MiB 存储保护，错误文字不再把它称为上下文边界。此限制用于阻止异常体积输入，与是否分段阅读分开。
6. 增加回归：小输入原文完整保留、大输入只有目录且仍可精确回读、成功读取范围合并、失败/伪造读取不计覆盖、未读不能 final、读完可继续原有语义报告、旧全量审查兼容。

## 不做

不改模型、不加新工具、不开放任意脚本、不加第二套审查状态机、不改报告业务字段、不要求输出阅读笔记或逐项对照台账、不修改设计文档、不重启整个产品服务、不处理 Reviewer→Revision 集成。

## 验收

先通过全部 Reviewer 回归与服务端类型检查，再直接运行一次真实 Reviewer：使用现有已授权配置、同一冻结的八文档与需求，真实计费，隔离运行、不触发 Revision。该实际样本用于审查质量回归；分段机制由大输入回归验证，不把小样本实测说成大上下文验收。

真实结果逐项核对既有明确问题、误报、引用和工具声明，同时报告费用/耗时。执行通过不等于语义质量通过；不为单样本命中继续堆规则，不自动追加付费重跑。
