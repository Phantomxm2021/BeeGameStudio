# Token 使用优化与计量落地计划

日期：2026-09-23  
依据：`daily-homework-leaderboard--88bcfc92aa68` 的 workflow、项目聊天及阶段 Agent 日志。此计划优化 BGS 的通用运行机制，不改测试项目内容，不限制 Agent 可用工具或自主判断。

## 诊断结论

workflow `run.json` 记录总量 **17,685,668 tokens**：输入 892,514、缓存读取 16,637,560、输出 155,594。该值是当前 workflow 汇总，不等于 Credits；缓存输入与普通输入的计费权重不同。

目前能从各阶段日志重建的用量如下。作者和审核日志有完整 `message_delta`；资源、内容、Implementation 的阶段事件主要能看到输入及缓存读取，缺最终输出用量。可见阶段用量明显小于 workflow 总账，说明当前阶段分账不完整，不能据此声称某阶段的完整成本。

| 文档编写 | 182,471 | 1,773,784 | 49,984 | 完整 |

阶段之外的对话消耗更高：

这两轮占项目主聊天已记录总量约 **92%**。主要问题是长上下文继续累积，加上 Preview 排错反复启动脚本、重复观察；不是资源准备阶段天然最耗 token。单轮调用很多不代表每次都发送完整缓存内容，但日志显示模型反复处理的上下文规模很大。

## 落地顺序

### P0：让阶段成本可核对

1. 对每个模型响应保存最终 `message_delta` 用量：普通输入、缓存读取、缓存创建、输出。
2. 每条记录关联 `runId`、阶段、dispatch/任务 ID、session、subagent、provider/model；子 Agent 用量归属调用它的阶段，避免遗漏。
3. 以一个幂等账本汇总阶段 token 与实际 Credits。终端结算只写一次；缺失项明确显示“未记录”，不填 0。
4. 使 UI 的各阶段合计等于 workflow 总账；同时单列阶段外的项目聊天和图像/音频等非文本模型费用，禁止混加或重复计算。

验收：回放本项目日志时，能够解释 workflow 总账与每阶段之差；新日志可按阶段核对输入、缓存、输出与 Credits；重复事件不造成重复计费。

### P1：减少 Continue/Retry 的历史重放

1. 恢复任务时向 Agent 提供一份短的最新状态：原目标、当前阶段、已完成项、最近改动、最近验证结果、未解决项，以及对应文件/日志位置。
2. 完整历史仍可按需读取，但默认不再次塞入整段聊天、工具输出和所有旧阶段材料。
3. 用户只报一个局部 bug 时，保留局部任务边界；不自动重跑资源、内容或整项目分析。是否需要跨模块由 Agent 根据证据决定。

验收：在相同的 Continue/Retry 对话回放中，初始上下文只含继续任务所需信息；Agent 能打开历史证据；不重复输入整段旧工具输出；结果正确性不退化。

### P1：缩短预览排错回路

1. 首次失败先读取一次 Preview 状态和关键错误，再选针对性检查；修复后只重跑受影响检查，最后对当前构建做一次部署目标验证。
2. 复用项目现有托管测试浏览器和记录能力，避免重复手写启动/录屏/网络诊断脚本。
3. 保留 Agent 自主选择工具和验证方式，不设置固定工具次数上限；用重复失败、无代码变化的重复验证作为诊断信号。

验收：Preview 夹具回放能通过现有托管浏览器完成检查；错误证据可复读、不因读取而重跑；同一代码修复不重复执行完整 E2E。

### P2：降低阶段内重复上下文

1. 内容和资源 Agent 根据索引按需读取关联文档、资源记录和目标文件；完整原文仍然可访问。
2. 使用已有结构化检查器校验可确定的引用、格式、文件完整性；将模型调用用于设计决策、内容质量及非确定性判断。
3. 对生成的多媒体资源单独记录调用数、模型、尺寸、Credits 与结果，避免只看文本 token 而漏掉主要费用。

验收：阶段证据能够说明哪些上下文被引用、哪些规则由确定性检查完成；不能为了降低数字而移除必要设计信息或弱化 Agent 决策能力。

## 验证方法

1. 先用本项目现有只读日志建立基线，不调用模型、不重跑项目阶段。
2. 对计量与恢复上下文实现使用本地 fixtures 和日志回放验证；确认普通消息、subagent、失败/重试、终端总结均只计一次。
3. 如需真实新项目对比，先提供用户可安排的测试需求与目标；未授权前不触发生图或付费模型调用。
4. 报告原始输入/缓存/输出、加权 Credits、模型调用数、Bash/浏览器检查数和阶段耗时。缓存读取不能直接当作等价付费 tokens，也不能把“工具数变少”单独视为成功。
