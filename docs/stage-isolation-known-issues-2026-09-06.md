## P2-RECOVERY-001：已派发遗留进程缺少可安全清理的身份权威

状态：已派发遗留进程仍失败关闭，不宣称其清理已实现。2026-09-07 P2 独立模块离线验收按既定公开契约核对了正常停止／续行和 needs_action 响应；不将新增孤儿进程清理作为模块隔离的额外门槛，详见 Reviewer 独立验收记录。

- 公开 getResult 只读。仅当日志可证明从未认领任何 worker，且旧所有者已不存在时，显式 resume 可创建不可变后继租约标记；保留旧租约，不 unlink／覆盖旧证据，并发只能产生一个新执行者。
- 一旦有当前或历史 dispatch，以上恢复被拒绝。stop 不能把无执行所有者的 running claim 洗成可重试状态。
- 进程出生标记 helper 仅供诊断，所有平台 safeForCleanup 均为 false；Linux tick 和 macOS 秒级出生时间都不是原子发信号权威。不自动 kill，不以 PID 存在检查签发清理回执。
- 后续已加入 native onClosed 等待屏障及不可变 native-completions 观察：原执行者在直接子进程 close、输出队列排空后，持有原 lease 才记录 run/header/lease/dispatch/task/revision/packet、退出信息、实际观察到的 usage 和已 admission payload。未知用量显式 usageObserved=false。观察写入失败阻止 terminal 接纳；只读 journal 不可写观察。此数据仅声明 direct-child，不代表进程树清理，也尚未开放凭观察接管 stale lease。
- 后续完整 orphan 恢复需要与 run/lease/dispatch 绑定的原生进程清理和可信终态证据，不能使用自签布尔值、PID 列表或文件冒充。
