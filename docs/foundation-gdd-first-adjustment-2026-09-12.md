# Author 调整方案：GDD 先行

## 调整范围与原因

首页流程保持不变：idea → 三选一方案 → 配置与补充要求 → 确认需求。该阶段与 Author 独立。Reviewer、Revision、计费、公开阶段接口以及已有项目草稿均不重置。

机器人仓库案例在八分钟无文档进展时停止，交付 0/8；第一次委派直到 5 分 44 秒才开始，另一次委派契约错误，前台调用又等待了 120 秒。前置设计台账重复承担了正式文档的设计职责。本次删除该前置要求，不通过延长超时掩盖问题。

## 调整后的执行流程

1. 主 Author 读取已确认需求、参考索引和 GDD 专属格式要求，先产出可用的 `docs/GDD.md`。显式恢复时检查并复用已有有效草稿，不要求重写 GDD、先读完八份参考或完成全量设计台账。
2. GDD 承载核心玩法、规则与范围；其余文档展开专项设计，并引用相应权威文档。工作笔记不再保存另一套设计事实。允许的轻量任务记录仅包含分工、状态和待协调问题，不是前置关卡。
3. GDD 就绪后，其他七文档按实际依赖展开；独立任务通常以 2～3 个作用域后台并行，真实依赖保持串行。运行时在 Agent 启动前检查 GDD 是安全、非空的普通文件。此检查仅证明结构就绪，不代表 GDD 语义验收，也不是所有文件写入操作的全局调度锁。
4. 每个委派声明精确交付路径，一个文档同一时刻只有一个作者，GDD 由主 Author 负责。修改 GDD 前先等待或停止相关写作者；专项设计若改变核心规则，协调更新 GDD 和受影响文档。任务结果不可用时，不整组重新委派。
5. 八文档齐全并完成一次有界一致性检查后，才提交完成结果；后续独立 Reviewer / Revision 继续负责质量审核与修订。保留 30 分钟活动时长、8 分钟无文档进展、80,000 输出 token 的止损限制。台账、任务状态和模型输出流不算文档进展。

## 已实施的接口与运行时调整

- 统一受限文档委派的 Schema 与运行时契约：`expected_output_files` 必填，模型可见的文件枚举来自同一允许范围，运行时拒绝重复或非法路径。没有该宿主配置的普通 CLI Agent 保持原有行为。
- 文档委派默认后台执行，提示词也明确要求 `run_in_background: true`；保留显式前台调用能力。后台返回信息不再要求 Author 立即结束，而是要求继续独立工作、读取交付结果并等待子任务完成。
- Author 将其他七文档作为可委派范围，以 GDD 为前置文件传入共享运行时；区分契约缺失、路径非法和前置文件未就绪，日志只记录有界诊断，不暴露原始提示或路径内容。
- 不新增第二个模型阶段、不固定七文档的完整依赖图、不开放研究任务绕过接口、不增加自动付费重试。已有项目与历史日志保留。

## 验证范围

- 策略检查：GDD 先行、无前置设计台账、引用权威文档、后台分工、恢复保留草稿、有界收尾。
- 运行时检查：Schema 与校验一致、安全拒绝缺失/非法前置文件、普通 Agent 行为不变、后台默认值和脱敏错误诊断。
- 本地脚本模型驱动真实 CLI：GDD 前委派被拒绝；主 Author 写 GDD 后交付其余七文档；A 后台运行时 B 契约失败，父任务只修复 B；两个有效子任务并发，取回两份 TaskOutput 后才提交完成。检查实际模型可见 Schema、真实日志错误码、权限边界和用量汇总。
- 现有 Author / Reviewer / Revision、预算止损、持久回执、跨阶段一轮及两轮修订回归，以及 TypeScript 和构建检查。
- 离线验证不等于真实模型文档质量验收。本轮不自动创建付费案例、不恢复旧案例、不增加预算。

## 验证结果

- 最终主回归：416 项通过，0 失败，89 个测试文件。
- 独立生命周期测试：25 项通过，0 失败。该组有全局模块 mock，单独进程运行，避免污染真实回执模块测试。
- 合计 441 项不同测试通过；其中包含上述两条 GDD 先行 / 后台局部恢复的真实 CLI 离线用例。
- 原生 CLI 构建通过；TypeScript 与 `git diff --check` 通过。
- 测试夹具曾重复统计重放的对话历史，已按 Agent 的 `id` 与 tool_result 的 `tool_use_id` 去重后重新通过；不是把重复历史误报为实际重复启动。
- 已确认任务空闲并重载本地开发服务，五个服务端点均返回 HTTP 200；纸飞机和机器人仓库旧案例仍为 `needs_action / DOCUMENT_DRAFTING`。真实模型端到端验收另行进行。
