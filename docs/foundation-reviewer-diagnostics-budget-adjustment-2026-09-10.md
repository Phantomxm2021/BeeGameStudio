# Reviewer 诊断、预算与错误反馈调整

## 本轮范围

实现并离线验证，不重新发起付费审计、不修改原始八文档、不重启当前服务。

## 已实现

1. 原生每次模型请求单独记录输入和输出用量，按消息标识去重；输入未观测到时保存 null。终端累计用量仍作为实际计费依据，预测不修改账本。
2. 预算预测使用最近一次请求输入，加新增反馈字节数的一半和 4096 输出余量。这是启发式预测，不是供应商侧硬上限。旧的多消息记录若无分请求计量，预测为未知，不用整轮总和或简单平均数替代。
3. 提供草稿、确认及一次额外纠错的费用空间提示；此提示不保证审计一定能在预测空间内完成。
4. StructuredOutput 继续使用完整 Schema 校验，只筛选相关分支的错误反馈。多余字段会明确显示字段名，不自动删字段、不转换错误类型、不改算式。
5. CLI 通过带界定符的结构化诊断传递错误规则和字段位置。Reviewer 只保留白名单路径、规则、期待类型、动作和请求序号；未知错误保持 unknown，不保留原始异常或模型正文。日志上限为每轮 64 个请求摘要、32 次失败、每次 16 条错误。
6. Reviewer 公共请求增加可选 tokenBudget：省略沿用 400000；正整数指定累计 token 上限；null 显式关闭累计 token 上限。时间、轮次、重复无进展、计费屏障和报告校验保持有效。
7. 显式预算参与 inputDigest，并随不可变请求保存。调用 foundationReviewerInputDigest 时必须传入相同的 tokenBudget。不能改变旧请求的预算后沿用旧摘要或句柄；默认历史请求的摘要不变。

本轮未给前端增加预算选项。公共调用方需要显式传递 null 才能使用无 token 上限策略，不会把所有现有项目自动改为无上限。

## 验证结果

- 完整 Reviewer 离线回归：87 项通过，0 失败，584 个断言，13 个测试文件。
- 根项目与 agent-workflow-server TypeScript 检查通过。
- git diff --check 通过。
- 使用独立临时构建的真实 CLI，配合回环地址的假模型和假密钥；没有真实模型费用。
- 三请求回归复现：输入 70925 / 77784 / 78683；输出 7392 / 655 / 1012。两次失败后第三次成功，累计计费仍为 236451，单请求基础预测为 82779（尚未加新反馈增长），不会误用 231488。
- 单个多余字段的错误反馈从 30 条收敛为 1 条；嵌套表达式类型错误从 35 条收敛为叶子位置的相关错误。原始非法载荷仍被拒绝。
- 验证了诊断跨真实 CLI 工具错误包装传递、用量去重、停止后计费、缺失用量、显式无 token 上限、有限上限、预算摘要绑定、恢复与重复无进展保护。
- Reviewer 仍可独立打包：没有引入 CLI 工具实现依赖，诊断通过原生协议边界传递。

## 后续上线验收边界

新诊断同时涉及 CLI 和 Reviewer，需要一起更新。仅重启 Reviewer、仍使用旧 CLI 时，错误会保持 unknown。测试使用临时构建，没有覆盖当前 dist 或重启正在运行的开发服务。

下一轮真实验收应使用新构建、新请求并显式设置 tokenBudget: null（用户已表示不设费用上限）。仍需检验真实模型的格式遵循、八文档草稿、局部纠错、最终确认及报告语义质量。本轮离线通过不等于线上审计已通过，也不恢复此前未保存的两次失败载荷。
