# 交付后修复：按根因推进

适用于所有 BGS 项目。本轮不改原生 Agent 内核、不增加审计代理、自动重试或固定工具序列。

## 已实现的系统修复

1. 实施请求携带原始 changeRequest 与 changeRationale，修复提示明确针对已有项目的问题；保留原文，不按语言关键词判断。
2. Preview iframe 与任务上下文共用沙箱定义；运行中的 Preview 按项目工作目录绑定，传入当前地址。没有运行中的 Preview 时明确说明，不猜端口、不启动额外进程。浏览器连接器的可用性仍需现场验收，提供地址不等于连接器已修复。
3. 实施阶段可修改 content/、assets/，仍保护已接受的产品文档与项目外文件边界。Content 只通过文件入口传递，不再把整包内容复制进 prompt。
4. 修改后复用已有资源与 Content 接口检查，更新 receipt、资源绑定及版本；不因为合法修改而重跑上游 Agent。无效内容仍然失败，不能降低检查标准。停止后继续实施时，内容错误作为修复上下文交给 Agent，而不是阻止它进入项目。
5. 系统策略拒绝不再伪装成用户拒绝；保留本来就存在的具体权限原因。
6. 实施证据分别保存输入版本和实际输出版本；交接检查证据文件内部版本。宿主交接只记录 ready，不制造 acceptance_passed。API 显示 runtime acceptance 未建立，原有发布的验收门槛不放宽。

## 第二批：运行时与编辑器修复（2026-09-20）

### 通用系统修复

- Scene Editor 与静态 Scene Preview 复用同一个 spritesheet 选帧函数；有 Content frameSize、没有同名图集 JSON 时，裁切首帧，不再压扁整张图。可从所属 animator 读取 frameSize；已有图集元数据仍优先。
- 两个离线 Author 子进程测试桩不再依赖已删除的旧 prompt 句子，改为识别 requirements.md 与八个交付文件；生产 prompt 和原生 Agent 不为测试回退。
- Author→Review 集成测试等待真实资源阶段交接结束，再验证不可变文档与版本。不再把文档发布过程中的瞬时状态当成最终 needs_action。资源执行在该离线 fixture 中明确不可用，断言该边界失败，而非调用模型。

### 当前游戏修复

- 渲染、静态碰撞和内容几何校验使用同一父子二维仿射变换，保留旋转、缩放及碰撞器 offset。禁用父节点时，其静态碰撞也禁用。
- 出生点来自玩家节点，不再读取重复的 behavior.spawn。巡逻航点改为所属节点局部坐标，移动节点后路线一起移动；修正东侧路线穿过障碍的折线。明确的路径碰撞恢复为错误，网格可达性近似仍只作为告警。
- 环境粒子渲染继承发射器变换；入口场景按 entryScene 选择，不再选文件列表最后一个场景。
- UI 支持数组 pivot、layout.scale 和正确旋转中心；图片子节点恢复真正的父子 DOM；九宫格装饰边框不再挤偏内部坐标；图标按钮不使用文字按钮的固定 padding。
- 帮助卡与按钮布局冲突修正；弹窗约束键盘焦点，滑块支持方向键/Home/End，模态遮罩阻止穿透。
- 资源以资源组+member 定位；无资源组且重名时明确失败，不再随机取一个。图片、字体、音频加载/解码失败会进入内容错误，不能继续报 100% 成功。保留音频格式回退。
- 修复只写 font.assetRef、没写 member 时漏预载字体的问题；字体通过已登记 Manifest 解析和加载，不再默默使用系统替代字体。
- Game 销毁时断开 ResizeObserver；异步启动取消后不再晚到写入 TITLE。暂停测试改为驱动实际 Game 帧循环，不再以“不执行 step”证明暂停正确。

这些游戏源码修复只应用于本例，不声称自动修复所有旧项目，也不把它们提升为新的通用引擎框架。通用保证仍是可编辑 Content 契约、正确的资源/版本绑定和真实运行验证。

## 第三批：显式验收结果与编辑保存（2026-09-20）

### 通用系统实现

- 用户确认采用简短验收记录。Implementation Agent 自主选择工具和检查方法，结束时保存本次 dispatch 专属 JSON：`status`（passed/failed/blocked）、`summary`、实际检查的 `environment`、工作区内 `evidencePaths`。不增加验证 Agent、固定检查步骤、自动重试或自然语言 verdict 推断。
- 宿主将记录及证据文件摘要纳入 implementation evidence，再绑定实际交付版本。缺失记录只交接为 ready；明确 failed/blocked 保留原因并停在 ACCEPTANCE；passed 需要现存证据。此处 passed 是 **Agent 报告的运行验证结论**，不是宿主独立审计的质量保证。
- 发布时复核工作区版本、显式验收 receipt 与证据摘要。修改/丢失证据、旧的“未检查但 passed”记录均不能发布。项目级和会话级两个发布入口复用同一个 gate，移除会话级只看状态字段的弱判断。
- 浏览器实际复现编辑保存失败：run 已 stopped，activeDispatch 已 interrupted，但保存逻辑以 dispatch 对象存在为由拒绝。改为判断运行状态；保留历史 dispatch，不抹日志、不恢复工作流。运行中的任务仍禁止并发编辑。
- Foundation 离线集成 fixture 的预期资源失败可能由后台回调或当前 ensureProgress 返回；仅在已落盘的正确失败边界上接收该特定异常，其他异常仍失败。未修改生产 Author/Reviewer 行为。
