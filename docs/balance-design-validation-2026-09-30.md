# 数值设计初稿质量审计

## 方法

同一隔离 BGS 项目会话，仅下发当前系统 BALANCE_DESIGN 职责，以既有 GDD、场景、美术文档为输入。没有附带本次问题答案，没有修改成稿或进入资源/实现。Agent 调用了 game-balance-designer-expert 后一次写入 v0.1.0 并完成。

## 判断

参数定义具备初稿基础；代表性对局推导尚不合格。不是因为不够详细或存在小笔误，而是用于支持设计选择的推导没有可靠依据。

### 已具备

- 速度、引信、火焰持续、能力、对象数量有单位、初值和范围。
- 配置、运行状态、派生量有区分，没有给无经济的游戏新增经济系统。
- 尝试联系真实关卡计算教学缓冲、移动耗时、连锁和通关节奏。
- 明确未进行实际游玩，保留调优假设。

### 影响数值设计结论的问题

1. 当前一颗容量道具使容量从1变2，正文却以3颗同时布弹论证当前终段体验。不是只改一个数字；代表对局分析用了不可达的状态。
2. 从(2,1)退到(1,2)需要两个正交步，再到(1,3)需要三个；正文用1/2步。更重要的是只离开炸弹中心不等于离开十字火焰，安全判断应基于实际危险范围。现有引信可能仍足够，但推导不可靠。
3. 火焰分析混淆“在危险区外”“进入危险格”和“窗口结束”：紧邻敌人一格耗时恰为500ms，不能直接保证会在500ms窗口内死亡；不同方向、起始移动进度会影响进入时间。正文关于玩家距边界1格可生还的表述也未明确是内侧还是外侧。不能据此证明窗口设计公平。
4. 4块砖×每砖3–5秒并不能直接推导60–100秒；奖励路线120–180秒同样缺少额外耗时来源。可保留为目标或待测假设，不能标为有算术支撑的估算。

### 可由常规 Review/Revision 处理

- chainReactionDelay 初值0符合GDD，但可调范围0–80与立即连锁冲突。
- 敌人转向选择口径仍未确定，并推到GDD/实现层；应在整套设计内分清规则与数值职责。
- 文末“无未定义顺序、算术证明无死局”等结论强于实际检查范围。
- 文档日期沿用9月29日，可在评审更新。
