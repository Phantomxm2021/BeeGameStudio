# Runtime 内容消费修正

日期：2026-09-27。范围：BGS 系统接口和验收；不修改私有游戏或 CLI 测试副本。

## 已证实的根因

- 不是 JSON 没送到：CLI 已读取并解析 layout，但界面只消费 text/font/color，几何改用 CSS。为响应式重做布局不是合格实现。
- 独立浏览器仅拦截 main-menu.json 响应：按钮文字变为测试文字，位置加 100、尺寸改为 120×80；实际边界始终为 (520,283,240,52)。读取成功不等于消费正确。
- 原交付文字要求已写“不得维护第二套布局”，但验证允许用文字/单格变化作为代表；发布记录仅核对整体 PASS、运行环境和证据存在，未记录布局绑定覆盖。
- 格式文件仅在早期生成，已有项目恢复到实现时可能仍拿着旧响应式说明。新实现需要当前平台格式，而不是再猜规则。

## 本次修正

1. 当前格式中加入同源 runtimeConsumption：布局、父子关系、锚点、尺寸和响应式变体均来自数据。缺少合适的变体时补全内容，不另写脱离 JSON 的 CSS/引擎坐标。框架和渲染方法由 Agent 选择。
2. 实现/验收回合刷新平台生成的 content-format.json，不改游戏内容、八文档和资源，也不改内容版本摘要。
3. 沿用原验收报告，记录适用的数据绑定结果：UI layout、Scene transform/Tilemap、资源引用。文字变更不能代替几何变更。未验、失败、错误节点或未保存证据不能形成交付 PASS。没有相应内容就不要求该类别；普通问答/局部修复不承担完整交付验收。
4. 错误反馈保留具体缺失项，不改写成笼统的“重新验收”。不增加阶段、重试、模型调用或游戏引擎。

## 验收与边界

- 免费回归覆盖：同一 JSON 在桌面/竖屏按锚点和变体投影；改竖屏位置/尺寸后投影改变且桌面不变；2D/3D 场景检查；缺少布局验证、文字替代几何、失败绑定、无效节点、证据缺失/篡改；会话延续不变。
- 本轮结果：7 个测试文件、42 项通过，服务端 TypeScript 检查通过。使用根目录 .env.local/.env.billing 重启五个本地服务，健康请求均为 200；没有自动续跑模型或发布。
- 验收记录验证的是覆盖、声明结果和证据身份，**不是自动识别任意引擎截图的正确性**。不得将这些回归说成新项目已实际交付。
- 真实生成复测未做。发现忽略 JSON 后已停止付费 CLI；不继续把失败产物跑完，也不由 Codex 修游戏。
- 原项目墙体 PNG 的压缩像素流损坏已纳入资源交付校验，避免仅凭 PNG 文件头与尺寸误判通过；测试副本生产包漏带 content/assets 仍是独立问题，不能宣称已修复。

## 文档到内容的新增交接检查

直接 CLI 测试暴露的返工并非单纯“模型未读文档”：文档写了居中/响应式意图，但没有可直接落地的锚点、轴心和各视口边界；内容 JSON 随后把居中按钮写成负向偏移，运行时只能反复猜测并补救。平台不替 Agent 写布局，也不增加文档字数门槛。当前格式明确锚点与默认轴心语义；内容交付时复用 Editor 的坐标计算，检查启用的屏幕控件在基准、桌面、竖屏和横屏视口的实际边界，并返回节点与边界值。交付验收会再次检查当前内容，避免旧 PASS 掩盖新改坏的布局。世界空间 UI 不套用屏幕边界。

该静态检查只判断明显的越界，不判断美感、遮挡、触控可用性或任意引擎是否真正消费 JSON；这些仍须由 Agent 在目标运行时验证。旧私人项目只作只读复核，没有被修改；本轮也没有再调用付费模型。

## 实验记录

测试使用同一 bundled CLI/model，独立副本、一个 native session，不经 BGS 阶段调度。它仍出现布局半消费，因此不能将问题只归因于 BGS 封装。

实验受我配置的 npm 网络错误和 macOS 浏览器沙箱限制影响，不构成严格耗时 A/B。首次环境故障段 7分06秒、估算 $2.905；恢复段 18分50秒、估算 $6.092；合计约 $8.997，未与上游账单结算。两段新输入分别 128128/176186，缓存输入 4109016/8334624，输出 8397/41761。已停止模型与该副本服务器；原项目未由 Codex 修改。
