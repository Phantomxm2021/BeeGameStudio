# 八文档跨文档重复：计划与落地

## 目标与边界

减少多个文档独立维护同一事实造成的同步编辑、矛盾和返工，不通过删减音效、动画、反馈或无障碍体验来缩短文档。保持八文档交付、明确用户需求、必需图表与序列化字段、独立审查和既有自动修订上限。

本次落地修改 Author / Revision / Reviewer 的任务指令，不新增执行阶段、所有权台账、全局注册表、语言关键词判断、重复率门禁、重试或时间/token 上限。不修改运行中的项目文件，不为这次改动发起付费模型验收。

## 职责与引用

已有明确需求和契约所有权优先；以下边界用于阻止消费者重新定义来源事实，而不是迁移已有权威定义。

| 文档 | 本专业定义 | 跨文档处理 |
| --- | --- | --- |
| GDD | 玩法、产品范围、核心规则 | 其他文档引用规则，不另立版本 |
| LEVEL_SCENE_DESIGN | 内容编排、空间布局 | 消费 GDD 固定顺序；不另定 UI 像素断点 |
| BALANCE_DESIGN | 可调玩法参数与公式 | 不展开 reducer、定时器实现 |
| TECHNICAL_DESIGN | 状态、输入机制、技术接口 | 消费玩法规则与参数；保留必要消费实现 |
| UI_UX_SPEC | 交互、焦点、可读性尺寸、响应式断点 | 不复写技术状态机实现 |
| ART_DIRECTION | 视觉风格、动效表现 | 引用 UI 尺寸与共享时序，不设竞争定义 |
| AUDIO_DESIGN | cue 行为与声音规格 | 引用 UI / 技术边界，不独立新增产品控件 |
| ASSET_PLAN | 资源 ID、数量、格式、来源、许可、排期 | 通过 cue 引用音频规格，不复制波形、时长、触发规则 |

消费者仍需表达自己的用途、接口约束和验收结果。必需的序列化字段不能被一句“见其他文档”取代；其中重复的必要字面值应标明来源并同步维护。采用现有文件、章节或语义 ID，不凭空制造引用目标。

## 三处实施

1. **Author**：正常编写与 finish 共用简短职责指导；委派时传递相关来源位置与所有权边界。在原有一致性检查内处理重复，不增加前置台账或第二次全面审计。
2. **Revision**：对于当前分配问题涉及的非所有者重复定义，允许替换为准确引用和本专业影响说明；保留所有者决策与体验，不把普通修订变成全套清洗。
3. **Reviewer**：区分必要引用、兼容细化、纯重复和可证明冲突。不能仅因重复就阻塞，也不能把 `>=13` 与 `>=12` 这种可同时满足的约束直接判成互斥。保留对真实遗漏、回归和核心规则违反的独立审查。

## 具体验收样例

- ART 的字号/断点重复表 → 保留视觉层级，引用 UI 对应表；UI 仍有可执行的尺寸要求。
- ASSET_PLAN 的声音波形/时长/触发描述 → 引用 AUDIO cue；资源格式、数量、来源、许可和交付责任仍完整。
- UI / BALANCE 的 reducer 或开门事件展开 → 保留用户可观察约束与参数，引用 TECH 的实现机制。
- 合法接口字段、派生值和本专业验收不能被误删；核心规则、声音/动画等已确定体验不能被降级。
- Reviewer 对无冲突的重复仅给整理建议；对真实冲突给来源、反例或实现后果，不以篇幅或重复率判定通过。

## 验证与优化测量

离线测试验证指令在正常/恢复路径进入执行输入、必要边界保留以及原有契约/候选文件仍兼容；这不能证明实际模型一定遵守，不能宣称已实现文档或耗时降幅。

已完成规则侧实现与主代理复核（Reviewer / Revision 部分由用户授权的 Luna high 子代理实现）。六个专项测试文件共 **42 项通过、474 个断言**；服务端 TypeScript 检查与 `git diff --check` 通过。覆盖 Author 正常/finish、冻结引用兼容、旧稿恢复、Reviewer 来源相对路径与只读证据、Revision 分配范围及八文档输出路径。无害重复仅进可选摘要，不成为新的修订义务。

真实验收需在可安全启用新进程后，对同一明确需求保存新旧文档及逐轮日志。优先比较重复权威定义数量、引用准确性、核心规则与体验保留情况；其次比较模型响应次数、同步 Edit 次数、输出 token、审修轮数和实际耗时。候选段落扫描只是待检查列表，不能当作全部可删除内容。

原评估的净文本减少 5%–8%、单轮耗时减少 5%–15% 均为待验证假设，不是本次代码交付的已达成指标。已有长轮次、模型速度及真实缺陷修复仍可能主导耗时。

## 启用与现有项目

任务指令在新执行调用时构造；已经运行的模型不会自动收到修改。当前服务未重启、项目未重跑，正在运行的候选稿保持原样。冻结的 authoring-reference 内容、状态机与持久化协议不变。

已有八文档的全套去重需作为明确限定的整理任务，在没有并发写入的候选副本上执行，再由独立 Reviewer 检查；本次不在运行中强行替换其文档或覆盖其审查结论。
