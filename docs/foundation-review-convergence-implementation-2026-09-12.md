日期：2026-09-12  
范围：工作流验收政策、状态持久化、发布授权、用户操作接口和界面。  
执行：两名 GPT-5.6 Luna 子 Agent 分别实施后端与前端；主 Agent 独立编写审计测试、纠偏并复测。  
部署状态：源码已实现；本轮未重启开发服务、未更新线上运行时、未恢复真实付费任务。

后续进展：用户另行授权后，已加载本地新版并完成真实暂停任务的政策切换；仍未恢复付费审查。详见 [Chrome 验收记录](foundation-convergence-chrome-deployment-2026-09-12.md)。以下为实施阶段的原始审计记录。

## 实施结果

- 新验收周期和新建审查副本冻结使用 `foundation-acceptance.v1`，默认两次自动 Revision。
- LOW 保留为建议，不单独派发 Revision；未豁免 MEDIUM/HIGH 仍阻断。
- 原始 `issues_found` 报告完整保留；独立 `acceptanceDecision` 决定接受、附建议接受、继续修订或需要用户处理，不伪造 `passed`。
- 只有完整、有效、已结算的结果能够进入验收。发布仍验证身份、输入、文档集合摘要、确切字节和目标文件前像。
- 成功完成并结算的候选才计入修订次数。预算耗尽后普通恢复、重启和刷新不能增加预算。
- 无文档变化的候选仍得到一次复审；复审仍阻断时停止。用户明确追加预算可授权新的修订，不能因同一请求重放重复增加。
- 风险接受记录操作者、理由、时间和 finding，并绑定报告结果 ID、报告摘要、文档集合摘要；历史裁决不继承到新的报告或候选。
- 用户停止优先；政策切换和授权重放不重新观察或恢复旧的暂停调用。

## 接口与界面

新增 `POST /api/projects/:id/workflow/foundation-decision`，支持 `accept_risk`、`grant_repair_budget`、`switch_policy`。

接口验证项目归属与操作权限，并在工作流锁内核验 run、控制序号、政策和预算快照。相同稳定 ID 的相同操作可重放；更换理由、风险范围或预算增量会冲突。操作者和记录时间由服务端生成。

界面已接通完整链路：阶段卡片 → Dashboard 操作处理 → API → 刷新 runtime state。报告可展开查看原始发现，验收状态与原始审查结论分别展示；历史阶段和已接受状态不提供新裁决操作。

用户本轮明确批准：仅旧暂停任务的 `switch_policy` 不要求尚不存在的报告摘要，仍严格绑定任务、暂停控制序号、旧政策和预算，切换后保持暂停。`accept_risk` 的报告与文档绑定不变；前端追加修订按钮的报告绑定条件也保留。

显示状态识别原生 Bash、Agent、TaskOutput 等工具进度，不再将公有阶段执行中误投影为等待中。计时区分本次工作流观察到的调用耗时和历史已观察调用累计，排除人工暂停间隔，终态重读不增长。计时不是原生进程精确时钟；模型响应与网络等待合并说明，缺少历史证据时显示不可用，不补造零值。

## 兼容与不变边界

持久化 schema 从 52 升到 53。只允许无新政策字段、结构有效的 v52 公有 Foundation 链按原政策内存读取，不改写磁盘，不接受更旧的退休执行结构，也不自动恢复暂停任务。显式切换保留历史已完成修订数，不将未完成的修订误计为完成。

本轮未修改 Reviewer/Revision 的提示词、public result、原生 CLI、工具可用性或执行器。以下六处文件与本轮开始时的 SHA-256 完全一致：

- `packages/agent-workflow/src/native-file-agent.ts`
- `packages/agent-workflow/src/native-task-access.ts`
- Reviewer / Revision 的 `private/native-files.ts`
- Reviewer / Revision 的 `public.ts`

没有新增仲裁模型调用、审查范围限制、工具白名单、单次运行时限或思考长度限制。验收完成仍停在原有文档交接边界，不扩大到游戏制作或对外发布。
