# Author 时间限制与响应日志调整

## 本次范围

针对 `streamlined-cargo-drill--b00de6b6e37b` 暴露的问题，取消 Author 的硬性时间终止，补齐父子模型响应证据，并修复前台转后台时重新开始会话的问题。不自动恢复该项目、不追加其预算、不补写其设计文档。

## 行为变更

- 30 分钟总运行时间、8 分钟无文档内容变化，以及受限收尾的时间阈值，均改为告警。旧配置中的 `maxActiveMs` / `maxNoDocumentProgressMs` 字段保留兼容性，但不再是终止条件。
- 根据后续用户要求，普通 Author 的 80,000 和已有八份草稿收尾的 12,000 累计输出 token 自动终止限制也已移除。旧注册中的 `maxOutputTokens` 仅兼容读取，不再执行；新默认配置不再设置它。用量统计、计费和响应日志保留；手动停止、权限/文件安全检查、真实执行错误、结构化输出重试保护继续生效。模型连接层的网络错误处理、单次模型请求及提供方自身的限制未修改。
- 提示词不再提供截止时间、五分钟收尾时间墙或累计 token 预算；仍要求一次范围有界的一致性检查，不无限补充内容。
- 到达时间阈值时记录 `active_time_warning` / `document_progress_warning` 并更新状态提示，但模型继续执行。文件变化仍与模型活动明确区分。

## 响应证据

Author 启用 `responseTrace`。采集点在父子任务共同的 query 入口，而不是仅依赖父任务 stdout，因此显式后台与自动转后台任务都能记录。

仍使用每次尝试的 `<attempt-id>.native-events.jsonl`（0600 权限）：

| 事件 | 用途 |
| --- | --- |
| `response.query_start` / `response.query_end` | query、agent、父工具调用关联；正常结束、失败或中断 |
| `response.request_start` / `response.message_start` | 模型请求开始与首个响应、模型和消息 ID |
| `response.content_start` / `response.content_snapshot` / `response.content_end` | 可见文本和工具参数，包括尚未完成的 Write 内容 |
| `response.message` | 完整可见响应、工具调用和工具结果 |
| `response.message_delta` / `response.message_stop` | 输出用量和停止原因 |
| `response.reasoning_progress` | 仅记录隐藏推理的活动字节计数，不记录推理文本或签名 |
| `native_diagnostic` | 已有请求/重试/错误分类元数据，不保存请求头 |

正文每秒保存累计脱敏快照，并在块完成、query 结束和进程中断时刷新。快照是累计内容，不能把多个快照直接拼接为正文。凭据和常见敏感字段脱敏；不保存系统提示、原始用户提示、隐藏推理、图片或任意请求头。普通未启用 responseTrace 的原生任务仍保持原有元数据模式。

诊断缓冲每个内容块上限 8 Mi 字符，响应内容日志预算 128 MiB；触顶会明确记录截断，不杀模型、不停止用量采集。意外主进程崩溃可能损失最后一个刷新间隔内的内容。旧尝试未保存的 LLM 正文无法事后恢复。

后台用量通过同一证据通道增量汇入 Author 用量统计；按 query 区分交错响应、按模型消息 ID 去重。父任务最终累计用量仍是权威，迟到的后台快照不重复计费。

## 后台连续性

自动转后台不再关闭前台迭代器并用原始提示重新调用 runAgent，而是转交同一个迭代器与已发出的 pending next()。保留上下文、文件读取缓存、正在进行的响应及任务 ID。稳定的任务 AbortController 贯穿前后台：前台跟随父任务停止，转后台后解除这一关联；显式停止子任务和进程清理仍可中止它。资源、技能、摘要和工作树清理移交给实际完成的后台任务。
