# 开发测试：批量清空当前账号项目

此功能用于开发／测试数据清理，永久删除项目，不是归档。不会删除账号、资源库或源码仓库；不修改项目配额。

## 开关与权限

运行时同时满足 `NODE_ENV=development` 或 `test`，以及 `BEEGAME_ENABLE_DEV_PROJECT_PURGE=1` 才可使用。生产、未设置环境或未显式启用时，接口返回 404。沿用正常账号认证和项目所有权校验，不接受调用方指定 ownerId、工作区路径或跨账号 ID。

Chrome 开发版的“历史项目”在服务允许时显示“开发测试：清空全部项目”。点击先取最新清单，再明确确认永久删除。清理后关闭运行时开关。

## API

- `GET /api/dev/projects/purge`：只读返回当前账号的 `projectCount` 和 `projects: [{id, name}]`，无删除副作用。
- `POST /api/dev/projects/purge`：要求 JSON `{ "confirmation": "DELETE_ALL_MY_PROJECTS", "projectIds": ["从 GET 得到的全部 ID"] }`。
- ID 必须与执行前账号清单完全一致；清单变化返回 409 / `PROJECT_PURGE_LIST_CHANGED`，不删除任何项目。重复 ID、其他字段、错误确认、非 JSON 请求拒绝。
- 同一运行时内同账号已有批量清理时，后续请求返回 409 / `PROJECT_PURGE_IN_PROGRESS`。
- 并发度最多 4，复用单项目删除的会话／预览停止、远端项目及存储清理、安全工作区删除和审计逻辑。只消费已确认快照，执行中新建项目不加入删除范围。
- 返回 `requested`、`deleted`、`failed` 和逐项 `results`。部分失败不隐藏、不自动重试，失败项不暴露底层服务错误文本。
- 请求结果不确定时先刷新列表核实，不能假定失败意味着没有发生删除。

## 验证

后端 9 项测试覆盖环境门禁、认证、账号隔离、确认参数、清单变化、重复调用、部分失败、实际工作区删除与审计；前端 82 项相关回归通过，包含确认 UI 和十种语言。前后端类型检查通过。

## 2026-09-09 真实清理记录

用户明确确认永久删除当前账号的 100 个项目。先通过历史项目界面删除 12 个；随后按用户要求实现此 API，停止逐项操作。临时以进程环境变量启用功能，通过 Chrome 已登录会话读取 88 个项目快照并点击一次永久删除确认。

接口界面返回“已删除 88 个项目，失败 0 个”，列表为 0。随后重启运行时，移除临时清理开关；重新打开历史项目，仍显示 0 个项目，且开发清理入口不可见。没有修改持久环境配置或项目配额，没有删除账号、资源库或源码仓库。删除无产品内恢复入口；工作区是否可清理由既有单项目安全边界决定，不宣称清除了不受管理的目录。
