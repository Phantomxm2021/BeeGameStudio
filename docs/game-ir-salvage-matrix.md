# Game IR salvage matrix

This is a read-only, exact inventory of the old dirty attempt. The old dirty
tree, generated bytes, run state, receipts, and uncommitted deltas are not
migration inputs. The inventory was obtained from the old export manifest and
AST/`rg` importer list; those files are absent from this isolated checkout.
Each item has one ID and one disposition. No dirty-tree content is migrated.

Stable Foundation baseline: `70df2e2c`. The five protected Stage 3/4 files
(`types.ts`, `schema.ts`, `controller.ts`, `transition.ts`, `recovery.ts`)
are byte-identical to it. Phase 1 only projects a real READY receipt and parses
the compile request; it does not construct a domain producer or route.

Reviewer and Revision deltas are explicitly `REPROVE` or `DISCARD`; none is
`KEEP` or `ADAPT`. Implementation records and their design ideas have separate
IDs because §9.2 allows a sound idea to be refined while its implementation is
discarded. Reviewer/Revision outputs and interfaces are all discarded/reproved,
not migrated.

Phase 1 integrates all Game IR core modules as isolated, tested code, but they
remain unreachable: no production imports, markers, compatibility layer,
fallback, cap, or routing switch exists. The next plan may add producers through
`FoundationReadyReceipt` only after the complete domain model exists and old
readers are deleted in the same cutover.
