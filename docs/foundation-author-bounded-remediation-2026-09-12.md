# Author 有界执行与原生工具修复

本轮范围：落实《花蜜冲刺》停止后的诊断建议，仅修改代码并做离线验证。没有恢复真实项目、发起付费模型调用或重启开发服务；尚未做修复后的真实模型验收。

## 已实现

- Bash 保留原命令字节：修复 eval 参数层和沙箱包装层对感叹号的错误转义。沙箱内解码执行；权限检查、OS 沙箱与禁止逃逸规则不变。非沙箱分支不变。
- 大段工具输出保存在任务内的 `.native-tool-results/<session>/`。主任务和委派任务可以读取；模型 Write、Edit 和沙箱 Bash 无权改写。普通 CLI 未设置任务范围时维持原存储路径；不开放整个运行时目录。
- Author 自主决定写作顺序、工具及委派。完成边界是八份交付文档与一次有界的一致性检查；不要求自评 PASS，不替代独立 Reviewer，不恢复固定八文档调度。
- 每次尝试默认限制：总执行 30 分钟、连续 8 分钟未观察到文档内容变化、累计输出 80,000 token，任一触发即取消原生调用。上限可由公开配置 `executionLimits` 指定，新请求注册时冻结；明确续跑获得同一配置的新尝试，不自动增加或重试。
- 只有八份交付文档的非空内容变化重置文档进展计时。读取、流式输出、工具轮询、工作笔记、mtime 变化不算；删除或截断后恢复相同字节也不算。只读检查拒绝链接及超大文件，并允许正常并发写入的下一次检查。
- 超限进入 `needs_action`，保留候选文件和用量，等待明确续跑；最后用量继续收齐与结算，晚到的完成报告不能绕过超限发布。
- 诊断日志增加工具耗时、哈希化父子/任务关联、后台与续接标志、TaskOutput 取回状态、子任务状态及有限错误分类。不记录提示词、命令、思考或结果正文。错误分类只是线索，不是语义审查结论。
- 界面进展区分“观察到内容变化”与验收进度；修复 Author 工作中误显示等待，补当前尝试与已结束尝试累计耗时，并避免把 Author 时间投到 Reviewer 卡片。没有可靠结束时间的孤儿执行不补算停机时间。
- 持久化工作流版本为 v54，增加可选公开 Author 耗时。v53 仅在完整通过当前结构验证后做内存兼容读取，保留停止状态和旧政策；不改写源快照，不虚构旧任务耗时。原 v52 窄兼容条件保留。

- 主后端/原生工具回归：382 通过，0 失败（60 个文件）。
- 前端工作流组件与显示模型：307 通过，0 失败（18 个文件）。
- 补充 Author 生命周期与服务端卡片投影：26 通过，0 失败。
- 服务端 TypeScript 检查、CLI 构建、diff 空白检查通过。
- 真实 CLI + 本地模拟模型验证：Python heredoc 的 `!=`、JavaScript 的 `!!`、主子任务读取大段持久化输出、缓存防改写、工作区外拒绝、凭证隔离、后台进程退出、五次 StructuredOutput 失败保护。
- 预算测试验证：输出或笔记活跃不能掩盖无文档进展；真实内容变化不能延长总时限；超限后的尾部用量保留；明确且幂等的续跑只启动一次，并维持冻结限制。

## 边界与后续

时间/token 限制是取消触发阈值，不是服务商的硬计费封顶：流式用量上报与取消清理期间仍可能产生尾部用量，必须按实际观测结算。缓存读取 token 不计入输出 token 阈值；网络、工具及子任务等待计入执行时间。内容变化只证明活动，不证明质量提升。

现有前端 62173 与运行时 62174 仍在监听，本轮没有重启或部署服务。需要加载新服务代码后，再经明确授权做一次新的真实模型验收，才能评价实际耗时、费用与文档质量；不能把离线测试等同于真实流程已通过。
