# 项目架构对照与当前制品边界

日期：2026-09-07。范围：对照既定阶段隔离计划与平台解耦提案；本轮只实现 P4 版本发布返修，不宣告全项目架构迁移完成。

## 对照结论

| 文档要求 | 当前实现与证据 | 判定 |
| --- | --- | --- |
| Author / Reviewer / Revision 通过公开生命周期交接 | 三个 `stage-modules/*/public.ts` 暴露 start/getResult/stop/resume；`delivery-workflow/foundation-review-link.ts` 传递公开结果和句柄 | 已落地阶段执行隔离；不等于平台完全解耦 |
| 旧 Foundation 执行入口退役 | controller 选择公开端口；dispatch 与 delivery-worker-session-port 拒绝旧 Foundation 执行 | 已落地；历史证据不删除、不接管 |
| 通过版本供产品与下游读取 | 已撤回快照替代读面；应用发布真实文件，预览／ZIP 回读磁盘，八文档与批准结果核验一致 | 目录发布返修通过；后续 P5 仍未接入 |
| 不可变候选携带正确版本 | Revision 自有 attempt 在封存前提升版本；第三轮真实候选出现 1.0.1 与下一轮 1.0.2，未改文档保持原字节 | 本轮返修已实测；历史已审核字节不补签 |
| 平台身份、授权、用量、执行、存储适配 | 当前仍依赖 runtimeConfiguration/billing 公共客户端，阶段内部直接使用 Native CLI 和本地文件存储 | 平台解耦提案尚未整体实施，不能以 P1-P3 验收替代新增验收 |
| 后续业务阶段独立化 | Checklist、资源、规划、实现、审计、验收、交付仍使用 controller/dispatcher/run-store 的共享路径 | P5 及后续工作，不在此次发布修复内 |
| 产物读取只暴露公开内容 | 当前通用 artifact read 路由允许工作区内路径，索引的可发现白名单不等于读取权限白名单 | 另列读取权限与私有路径隔离整改；本轮当前快照不读取阶段私有目录 |

依据：`independent-stage-programs-plan-2026-09-05.md` 第 5–8 节与 P4/P5；`stage-platform-decoupling-architecture-2026-09-07.md` 第 1、5、7、9–11 节。后者明确标记为提案，其建议迁移顺序不是已授权实施清单。

## 本轮确定的写入权

1. Revision 在候选封存、摘要计算与送审之前完成被修改文档的版本元数据。未修改或同轮保留文档保持原字节。
2. Reviewer 只读验证指定候选，结果绑定候选身份、内容摘要与通过结论，不写文档、不补版本。
3. `foundation-accepted-artifacts.ts` 是应用映射边界：核对公开通过结果与实际送审字节，调用通用制品存储；不计算修复范围、不解析业务正文。
4. `project-artifact-store.ts` 只理解身份、发布 ID、相对路径、字节与摘要；负责把批准字节发布到真实项目文件，快照仅作历史／恢复依据，不导入任何阶段模块。
5. app 与活跃 session 的预览、索引及 ZIP 必须读取实际项目文件，不再用快照内容覆盖。应用读面须识别发布中／跨版本读取，不以旧快照兜底隐藏磁盘错误。

项目制品入口继续校验工作区 realpath 是当前用户根目录的严格子目录，拒绝 foreign root、owner root 本身与项目路径中的 symlink alias。取消快照读源不撤销这些权限边界，也不把工作区任意路径读取误称为已完成公开内容白名单整改。

编排在持久化通过接纳前等待发布成功，并将 `run.revision.document` 更新为通过文档集合摘要。发布成功但编排保存失败时重放同一发布身份，不重新启动阶段。存储的并发与故障保证以实现测试为准，不承诺分布式事务或自动旧执行接管。

制品存储使用项目内独立发布锁，旧发布 ID 重放不能回滚当前文件；未知旧执行不自动接管。目录发布需要显式记录进行中的事务，并验证原文件摘要，不能悄悄覆盖不相符的用户编辑。普通异常后的同事务重放与硬崩溃残留锁是不同恢复条件，具体保证以实现与测试为准。

## 项目目录是实际交付物

用户未要求把预览改读快照；此前由实现者自行选择的替代读面已撤回。正确发布必须更新 `docs/*.md` 的实际字节；原始输入和审核证据保存在已有不可变导出／历史记录中，而不是让交付目录永久停留在初稿。多文件逐一替换不等于文件系统级整组原子提交，不能作此承诺。P5 仍须核验读取字节与批准版本绑定，不应绕过发布中状态或把被用户修改的文件默认为已审核版本。

历史已通过候选保持不变；新的内容或版本号必须由新的 Revision 候选生成并重新审核，不能在审核之后补签。把第三轮已经通过的原字节写入目录只是补做应用发布，不重新审核或改写阶段结果。修正后的目录与产品读面证据另记入 P4 真实验收记录；不据此宣称平台整体解耦或 P5 已完成。
