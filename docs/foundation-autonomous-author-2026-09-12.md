## 目标与边界

新建 Author 任务一次委托完整八文档。Agent 自行决定写作顺序、工具使用、自检与委派；宿主不再按文档依赖拆分调用，不要求 Agent 返回八份文档正文。

- 需求、原有完整文档与必要交付契约均放入隔离工作目录，可由 Agent 自行读取。
- 最终交付物是八个 Markdown 文件。Agent 的终态仅报告完成/阻塞及摘要，文件摘要由宿主计算。
- 保留固定路径、下游使用的格式约定、元数据、身份与文件绑定；不增加自然语言质量打分、固定自检清单或自动纠错调用。
- 全套文件验证后才生成公有完成结果；未完成候选不成为正式文档。停止、失败和恢复保留候选文件，只有显式恢复可以重新调用模型。
- 保留旧版 Author 实现用于既有任务恢复和对照。入口按持久化任务版本路由，不把旧任务悄悄升级；新任务默认自主模式。
- Reviewer、Revision、收敛政策、付费真实项目和已接受文档不在本次修改范围。

## 验证计划

验证单次整套委托、开放工具/委派策略、全套完整性、只读输入、链接与路径逃逸、发布前像冲突、不可变产物、幂等启动/发布/计费、跨实例观察、崩溃恢复、停止优先、旧任务版本保持及公有交接。原生工具集成使用离线模拟服务，不启动真实付费验收。

## 已完成实现

- `private/author-routing.ts`：新请求默认 `autonomous.v1`，既有无版本注册仍走 legacy；相同请求重放与旧 handle 不受当前配置切换影响。公有配置可显式指定 `mode: 'legacy'` 做对照。
- `private/autonomous-native.ts`：通过共享原生文件 Agent 运行整套任务，允许 Read、Write、Edit、Bash、Agent 等现有工具；保留原生沙箱、凭据隔离和 StructuredOutput 的既有失败保护。一次原生任务可有多轮模型响应和子 Agent，并不是限制为一次模型请求。
- `private/autonomous-files.ts`：在私有候选目录提供完整上下文；只读输入、文件类型/大小/UTF-8、链接、前像与不可变产物绑定由宿主检查。沿用服务元数据规范，不执行语义评分或自动修复。
- `private/autonomous-lifecycle.ts`：执行前持久化 attempt；失败/阻塞/中断不因读取或重新打开而自动再调用模型。显式恢复保留文档和工作笔记，以新原生任务继续。跨实例停止在进程退出前保持未确认状态，停止清理期间到达的更新恢复指令不会丢失。
- 计费使用现有 outbox；父/子 Agent 累计用量统一结算，重复快照不重复累计；结算未完成时不发布正式文档，结算恢复不重复运行模型。
- 公有八文档结果和下游交接保持兼容；运行状态增加安全的模型响应/工具活动进度，未暴露内部调度状态。

## 剩余限制与运行状态

- 八个正式文件分别执行原子替换，不构成文件系统级八文件 ACID 事务。发布前已持久化完整 prepared 包；中断可能留下部分正式文件，但不会产生公有 completed。恢复只能重放同一包的相同字节，遇到用户修改则暂停，不重新生成。
- 原生进程可能仍存活时保守阻止复用候选目录，不擅自终止未知 PID。工作目录和笔记会保留，但显式恢复不承诺恢复旧模型会话的隐含上下文。
- 格式说明版本仍由代码提供；以后修改交付契约时，需要同步考虑既有自主任务只读证据的版本兼容。
- 未进行真实付费模型的质量、耗时或成本对比，不据离线测试宣称质量提升或成本下降。
