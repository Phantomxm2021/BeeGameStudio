# Reviewer 原生工具 v2：实施与验收

日期：2026-09-10。范围：当前 `game-ir-isolation-recovery` 工作树内的 Reviewer 协议重构及本地部署。不是全局 Claude Code 升级，不是完整审查语义可靠性放行。

## 已落地

- 修复计算契约：subtract/divide/power 恰好两个参数；add/multiply/min/max 为 2–32 个参数。新请求的 schema 与执行器一致，历史三参数减法错误记录仍可读取、重放，不能作为新请求执行。
- 新审查使用 9 个专用原生工具：`review_read`、7 个算术工具、可选 `review_save_draft`。二元运算用 `left/right`，聚合运算用 `values` 数组，不向模型发送递归表达式。
- `StructuredOutput` 只提交最终报告；不再用 action/report/calls 包装承载工具动作，不走 JSON 字符串外壳。9 个工具及最终报告的所有模型侧 schema 都是普通根对象，不含 oneOf、anyOf 或递归引用。
- 工具只在 `foundation-reviewer-tools-v2` CLI 会话注册；注册表和 worker 双重限定名单。不能调用通用 Read、Bash、写文件、联网或 eval。读取限于冻结的输入副本，草稿只写内部审查状态。
- 保留单 Agent、完整阅读、引用行位置与原文绑定、业务准入、公开结果 v3 和原认证/计费接口。源文档不被工具修改。

共享 CLI 的本轮改动是专用工具注册，以及让 reviewer 模式在最终报告成功后结束。既有逻辑仍等待整个模型流、同批工具和末尾用量，不在工具确认时提前退出。另补充了通用 schema **错误定位**对分组枚举的支持；它不修改原始参数、不放宽校验。HTTP 客户端、鉴权、SSE/JSON 解析未因本轮重构改变。

## 状态、恢复与预算

每次调用持久保存调用 ID、参数、输入摘要、前项摘要、结果及校验摘要；先落盘再返回。相同 ID/参数返回已有结果，不重复执行或新增记录；ID 改换含义被拒绝。并行调用串行提交记录。

worker 只把实际收到工具结果的调用纳入当前审查上下文；成功提交前检查所有本轮已记录结果均已交付。取消期间已经执行但未交付的记录保留在工具日志，不冒充模型已阅读的内容。主审查日志先封存结果和用量，计费结算后才推进上下文；恢复计费复用原事件，不重新调用模型。不会自动接管缺乏进程退出/计量证据的崩溃任务。

沿用每个原生回合最多 6 次模型迭代、最多 12 个宿主轮次、累计 12 分钟活跃时间及默认 400,000 tokens；显式无 token 上限仍受其他限制。模型迭代不等同 HTTP 网络重试次数。另设累计 144 个工具调用保护，包含历史调用；重复验证无进展会持久化停止原因，显式恢复不能清空限制。

## 明确保留的限制

此次证明的是新工具协议在三次真实小样例中的兼容性，以及状态/计费边界的工程回归。它不证明所有模型、长报告、长会话或完整八文档审查稳定，也不保证发现所有问题。

人工检查发现 Flash/M3 的报告仍有“其余七份文档只有标题”等计数/措辞失真；实际只有六份纯标题文档。此类语义错误没有被程序偷偷修复，原报告原样保留。普通数值叙述、严重程度和影响判断仍需模型正确理解，schema 通过不能证明这些内容正确。

因此，[可靠性总计划](foundation-reviewer-reliability-plan-2026-09-10.md)中的完整语义质量门槛、真实八文档 P4 和保留样本验收仍未据此放行。本次没有发送真实全文/保留组，也没有启动真实 Revision。
