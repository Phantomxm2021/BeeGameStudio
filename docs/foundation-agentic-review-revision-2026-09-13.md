# Foundation 文档自主审修方案

Foundation 文档完成后执行最多两次原生文件 Agent 会话：

1. 第一次会话阅读八份文档与用户需求，自主审计并直接修正会造成需求违背、游戏行为冲突或验收失败的问题。
2. 宿主只比较输入与输出文件摘要。没有修改且没有未解决问题时直接发布。
3. 如果第一次修改了文档，启动一次全新的最终会话，对当前八份文档重新审计并直接修正剩余实质问题。
4. 第二次完成后停止，不再启动第三轮；如果 Agent 明确报告无法安全解决的问题，则停止并请求处理。

Agent 不输出 blocker、严重度、优先级或问题配额，不把已修复问题作为下一阶段任务清单。两次会话之间只传递当前文档、确认需求和必要来源绑定，不生成独立的问题修复协议。

BGS 只负责工作区隔离、文件边界、结果绑定、持久化、停止/恢复、日志和计费；文档阅读、问题判断、修改方案及修订完整性均由文件 Agent 自主完成。不存在时间墙、累计 token 上限或自动重试项目。

原 Reviewer → 问题报告 → Revision → 全量 Reviewer 的生产调度、Host 接线和 Revision 模块均已删除。旧运行不会被当前 schema 接纳或恢复。
