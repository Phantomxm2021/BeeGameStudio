# Producing and reconciling visual designs

Use when producing or revising actual visual designs or modular assets.

Use the relevant requirements across the eight design documents to create one coherent set of complete game screens: Scene, subjects, HUD and planned UI states together. Choose individual screens or readable groups; a single overview board is optional. Reuse pictures across UI/Scene responsibilities. A reference-image assignment covers those complete screens and key states, not additional component explanation boards or runtime asset production. Identify supplied images as inspiration, selected designs or runtime captures.

For a consequential correction, revise the affected complete screen using the existing image as a reference and describe the intended change while preserving established composition and identity. With BGS assets.mjs, use referenceImagePath with prompt or uiReference; seeing an image in chat does not pass it to the image provider. Check the available quote and authorized budget; a revision need not become a new set of alternatives.

Inspect composition, hierarchy, subject appearance and key-state coverage. When several images warrant an authorized independent comparison, a short-context read-only sub-agent can receive the image paths and relevant design sections, then return consequential mismatches with image locations and implementation impact. The parent reconciles those findings; this is optional and does not authorize regeneration or document edits. Correct consequential omissions or contradictions; minor text, grid-count or pixel deviations need not trigger whole-image regeneration. Exact values remain in the documents and implementation. Deliver image paths and consequential unresolved deviations in the completion message. Keep existing design documents unchanged during reference generation unless the user explicitly requests a design change; do not adopt image imperfections as new requirements. A document-only assignment stops before production. Runtime production preserves appearance while separating independently controlled parts; a flattened screen board is not runtime UI.

For modular families preserve scale, pivots, coordinates, materials and assembly transforms. Check provenance, use, compatibility and download/runtime cost of sourced assets. Inspect the smallest useful complete screen/scene before propagating an uncertain treatment; use available renders or authorized image tools. This is not another mandatory review stage.
