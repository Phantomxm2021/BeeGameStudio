# Saved Content Checks

Read only for an assigned geometry/integration question using these actual inputs, or a supplied legacy handoff. This reference preserves format-specific details without making them a default design-review workflow. Native engine or DOM tasks use their actual source and runtime, not BGS JSON created for a checker.

Read the relevant original design clauses, existing task pointers and current resource records. Compare requirements with actual resource files, hashes and atlas structures; inspect retained verification results and their source versions. Source reads do not certify native scene/UI bindings, runtime consumption or semantic quality.

## Linked Scene/UI geometry

Inspect the actual scene/UI sources used by the selected engine/framework and the applicable [runtime layout guidance](../../game-ui-ux-designer/references/layout-calculation.md). Compare hierarchy, transforms, scale, collision, camera/framing and state visibility with the owning space/UI decisions in their actual allocated view. Resource-dependent bounds and dynamic/3D/XR framing need their applicable evidence; static structure does not establish runtime visibility or interaction.

Compare required screen/expanded-state coverage, active controls, supported targets and clearance with both global and state-specific prose. Hidden or disabled content is not an inspected expanded state; independently fitting components do not establish a usable combined view. A geometry pass does not prove complete resources, visual agreement or runtime consumption. New work uses the selected runtime’s native sources; historical BGS JSON is not an authoring prerequisite.

In authorized revision, correct the owning sources and affected prose, then recheck invalidated evidence. Binding completion is not permission to change geometry. Preserve agreed control minima and required content; a calculation does not select an overlay policy or certify text fit, appearance or interaction. Reuse valid diagnostics and actual runtime measurements for unchanged inputs.

## Only when legacy handoff inputs are supplied

For actual historical BGS Scene/UI inputs, use the supplied checker and its current `--help`. Choose the applicable saved-source check from the supplied checker’s current contract. Inspect owner links, schema/Camera and combined game-view relationships required by that saved format; missing links or unsupported bounds remain gaps, not runtime PASS.

Handoff indexes point to authoritative prose and necessary acceptance expectations, not duplicate design. Use results for the inspected versions and the commands actually supplied for that legacy assignment. The current autonomous tools do not require a batch handoff or release sequence. Do not create indexes, batches, delivery files or receipts merely to invoke an old command.

Preserve existing version/hash metadata. Inspect actual producer/consumer meaning and source conditions; neither matching IDs/headings nor different professional names establishes semantic agreement/conflict. A retained hash binds the declared source identity, not truth. Do not populate irrelevant tables or infer platform absence from a tool-scope rejection. A structural correction repairs a real contract violation without selecting a missing owner decision.
