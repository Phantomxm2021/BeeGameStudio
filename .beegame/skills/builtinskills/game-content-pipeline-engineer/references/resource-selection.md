# Resource Matching and Small Samples

Use for an uncertain asset family, production route or compatibility question, not every resolved binding. Start from its actual visual/audio purpose and runtime needs. Choose library, generated, procedural or custom work under the user's resource policy; absence of a tool does not establish absence of suitable resources.

| Family | What to inspect in a relevant sample | Why existence alone is insufficient |
|---|---|---|
| Modular environment | Scale, edge treatment, pivots, tile joins, lighting/material and required variants in the scene | Attractive isolated tiles can fail to assemble coherently or omit a needed corner/transition |
| UI/font family | Real glyph coverage, proportions, meaningful control states, stretch/crop behavior and legibility in the layout | An attractive preview can lack Chinese glyphs, readable counters or usable stretch regions |
| Repeated feedback sound | Event meaning, attack/tail, variation, mix space and loading/playback constraints | A valid file can be wrong in tone, mask another cue or fail in its actual playback path |

Inspect the smallest critical sample in its intended composition before propagating an uncertain choice. Compare candidates only on the dimensions that matter; do not download whole catalogs or create a new procurement report. Record the selected source/production route, required transformations, dependencies and unresolved rights in the existing resource plan. Verify the actual source and asset license when importing; repository code licensing does not automatically license its fonts or sounds.

Examples of concrete reference material: [Unciv's UI skins](https://github.com/yairm210/Unciv/blob/master/docs/Modders/Creating-a-UI-skin.md) show reusable shapes and nine-patch behavior; [Veloren's models](https://book.veloren.net/contributors/artists/voxel-models.html) place assets in a shared style/scale context; [OpenRA's mod guide](https://github.com/OpenRA/OpenRA/wiki/Modding-Guide) separates authored rules/maps/UI and resources. These illustrate matching and integration, not mandatory file formats or a reason to copy their look.

A fallback must preserve the required function and selected treatment. If it would replace a required visual/audio identity, change geometry or remove a state, identify the actual dependency and obtain the necessary decision rather than silently treating a placeholder as final. Resource presence, binding resolution and runtime consumption establish different things.
