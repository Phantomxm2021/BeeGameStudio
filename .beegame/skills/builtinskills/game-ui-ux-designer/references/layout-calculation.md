# UI layout calculation

Use containers for menu/action groups and HUD regions; anchors suit overlays and independently attached indicators. Describe ordering, allocation, alignment, spacing, size limits and the selected space-constrained behavior. Reference dimensions are not a fixed runtime window. No particular game engine is required.

In BGS UI JSON, `layout.container` supports row/column flow or a grid with equal-width `columns`. Its `gap` and `padding: [top,right,bottom,left]` are logical lengths. Children use `layout.size` as preferred size, `layout.minSize`/`layout.maxSize` as limits and `layout.item.grow`/`layout.item.shrink`/`layout.item.basis` as allocation choices. Shrink defaults to zero. Enabled children participate in document order; `layout.item.absolute: true` leaves an anchored overlay out of flow. `item` belongs inside `layout`, never at node top level. Flow owns child position; do not also give a flow child stretch anchors. Grid owns cell width; don't override it with grow/basis. Responsive variants can change the arrangement.

During planning, document composition, interaction, region relationships, sizing limits and adaptation. When the assignment starts UI data, save the actual ui-screen/ui-hud files directly in content/ui and link them with ../content/ui/<file>.json. Include each relevant expanded/modal geometry as an active composition, retaining shared unchanged relationships instead of manually calculated positions. Read the relevant format together with `bun .beegame/delivery/check-content.mjs --format uiDocument uiVocabulary uiLayoutContract`; do not discover fields by reading bundled source. While the prose/links are unfinished, use `--design-layouts` to check saved geometry at the declared reference, target and transition sizes. After the linked document is saved, use `--review-layouts` for the final geometry/link check; neither command needs delivered resources or content/index.json. Read `valid` and all `issues`, not just a filtered diagnostic field: a schema failure may have no geometry diagnostics. Repair related failures together with local edits instead of rewriting unchanged files; rerun after inputs change, not repeatedly for the same result. Keep unavailable bindings pending rather than pretending assets exist. Content completes these same files in place; do not keep a parallel calculation copy. The existing baseline protects node identity, text and geometry but permits later resource/action bindings. Other narrow questions can use:

```sh
bun .beegame/delivery/check-content.mjs --layout-draft content/ui/menu.json 960 540
```

The draft uses `schema: "beegame-content.v1"`, `kind: "ui-screen"` (or `"ui-hud"`), an `id`, `assetRefs: []`, and `data: {rootId, nodes}`. Each node has an `id`, canonical `role`, optional `parentId`, and `layout`. Responsive overrides belong at `node.responsive.compact/portrait`, not inside `layout`; each override may contain `enabled`, `layout` and `style`. A declared override `layout.container` still requires `direction`, even when changing only padding or gap. For example, a root column container with centered alignment/justification can contain a title and another column container holding the action buttons; its preferred child sizes and gaps determine the group's bounds without authored button positions. `layout.anchor` is a named string such as `middle-center`, not a normalized pair; stretch uses `anchorMin/anchorMax`, and `data.anchor` is the pivot object. A centered panel normally has position [0,0], not a second half-size offset. Use the supplied format for exact fields.

`--appendix` optionally emits Markdown tables for the requested size and declared targets, including resolved positions/sizes, diagnostics and input hashes. Retain a result only when it supports an actual design decision, with its assumptions and limitations. A minimum-size sample does not establish a preferred composition or all supported sizes. Successful execution alone does not establish fitting; read the relevant diagnostics. Recalculate only affected cited results. If a necessary calculation cannot run, report that gap rather than inventing evidence.


Record the selected allocation, orientation, reference resolution, supported sizes and agreed control minimum in the design. Formal UI inputs encode these as root data.orientation, referenceResolution, targetViewports and minimumControlSize. An optional calculation needs only the values relevant to its question; local layout.minSize does not establish a host-pixel minimum after transforms. The calculator does not choose the fallback for unsupported orientation or insufficient space. Define full-host game-view/HUD allocation once. When a question needs the camera connection, use:

```sh
bun .beegame/delivery/check-content.mjs --layout-draft .beegame/tmp/layout-check.json 960 540 --game-view game-view --camera .beegame/tmp/camera-check.json
```

The game-view node is an ordinary UI container; its resolved bounds supply camera width/height and host offset. When planning supplies Scene JSON, link that same Scene using root.data.layoutCamera {nodeId,path}; retain its Camera and requiredVisibleNodeIds instead of copying framing fields. A standalone camera calculation provides framing only, not Scene visibility. --review-layouts checks owner-linked Scene drafts together with UI geometry. Content later binds real resources in those same files and rechecks resource-dependent bounds. Technical consumers do not duplicate rectangles or expected camera offsets. A temporarily empty cell or disappearing camera margin is not reserved overlay space.

For UI tied to a static top-left 2D camera reference plane, keep one rectangle in the full-host input. Add a container under game-view with data.space:"camera-reference-2d", layout.size matching the Camera viewport and layout.item.absolute:true. The orthographic camera requires positive pixelsPerUnit. Set root data.layoutCamera to {nodeId,path} linking this game-view to the existing camera calculation input; explicit CLI arguments may override it. The inspector projects local geometry with the camera span/framing and host offset; it does not represent arbitrary Scene camera poses, moving cameras, 3D or XR projection.

Reference-plane controls are not universally forbidden. The calculator checks their final transformed size against minimumControlSize, not their local sizes or minSize. It does not implement rendering, clipping or inverse pointer mapping; these must be verified in the actual runtime before claiming usable interaction. Do not invent an unrepresented larger hit region or waive the agreed minimum.

Declare constraints, not manually calculated outcomes: child `minSize`, gaps, padding and arrangement belong in the draft. To calculate required container space, let a nested flow container size itself from its contents instead of assigning it a guessed height. For a minimum-size calculation, use the children's declared minimum dimensions as their preferred sizes in that calculation input; keep it explicitly distinct from the preferred/reference composition. The same layout engine then derives the container extent, including gaps and padding. A result for one reference allocation does not establish the minimum required allocation.

Formal Content represents each planned menu, HUD and modal or genuinely shared composition with its child content, relevant state differences and resource/action bindings. When separate UI files coexist, the upper composition root uses `data.layoutUnderlay: {path:"content/ui/<actual-file>.json",clearance:"preserve"|"allow-cover"}`. Link the actual retained layer instead of copying its rectangles. Choose the policy from the requirements for that state and reconcile general and local clauses; do not silently weaken a general prohibition. Declare protected regions and actual occluding elements with the existing `data.layoutOcclusion` markers. Preserve checks inherited protected rectangles against marked occluders at the overlay's supported targets; allow-cover permits covering the inherited layer in that state, not violating local clearance or control minima. These links are composition inputs, not automatic rendering or input suppression. Content/runtime still consume those same sources and enforce the designed state behavior.

`bun .beegame/delivery/check-content.mjs --design-layouts --report` recomputes saved UI inputs at their declared reference, target and transition sizes without a package index. `--review-layouts --report` also checks planned source coverage. The readable report groups identical failures while retaining every affected Scene, measured geometry and close condition. It supplies a saved full JSON path for additional inspection; do not write a parser or rerun merely to discover result fields. Without `--report`, the existing machine JSON remains available. Missing links/markers cannot prove combined clearance; geometry does not establish complete state coverage, prose agreement or visual quality.

For registered content, use `--layout ui/menu.json width height`; the saved layoutCamera link and explicit --game-view/--camera connection are supported. Inspections are read-only. outsideViewport, outsideParent, outsideContentArea, outsideCameraView and belowMinimumControlSize expose geometry issues; overlapCandidates require interpretation, not a universal overlap prohibition. Absolute overlays opt out of flow padding. Unmeasured text is not proof of fitting.

The portable browser helper exports `initializeUiLayout`, `resolveUiNodesForViewport`, `inspectUiLayout` and `createUiTextMeasurer`. Await initialization once before using containers. For camera-reference planes call `inspectUiLayout(nodes, rootId, viewport, {camera: {nodeId, input: camera}})`; returned corners/bounds are projected while `layout` remains in its authored local space. Rendering must apply that same projection to text and graphics, not treat the local layout as screen pixels. For automatic text size, supply a measurement callback after loading the actual font. Canvas intrinsic metrics measure unwrapped text and explicit newlines; browser/engine wrapping, shaping and clipping still need actual rendering checks. Do not infer font size from character counts or call a geometry-only result visual acceptance.

Geometry checks can use legal labels/counter ranges and typography constraints before delivered fonts or a rendered composition exist; those checks do not prove text fit. When checking delivered fonts and a complete rendered Scene/UI, inspect text wrapping and interaction. For browser measurements without building a measurement program or game server, use:

```sh
node .beegame/delivery/inspect-design.mjs content/ui/menu.json 960 540 --preview-api CURRENT_URL --font Arial --samples text-samples.json
```

Read `--help` for optional `--preview composition.html --capture capture.png`, using an existing complete design composition. The current Preview capability owns browser startup/cleanup. The command serves local preview dependencies read-only, records source hashes, measures the final input with the shared helper and refuses missing delivered FontFaces or overwriting captures. Without a preview it is measurement-only, not visual acceptance; a capture still requires inspection for actual Scene/UI consumption, completeness and art direction. Use a candidate font explicitly, not a silent delivered-font substitution. No game package or Vite setup is required. The stable helper lives at `.beegame/delivery/content-consumer.mjs`; its API is documented here and in the supplied format, so minified source discovery is unnecessary.

For custom previews or runtime checks, combined browser font loading, sample checks and shared geometry remain available through `inspectUiLayoutInBrowser`:

```js
const ui = readUiData(await (await fetch(uiDocumentUrl)).json());
const result = await inspectUiLayoutInBrowser(ui.nodes, ui.rootId, viewport, {
  fontFamily: node => node.style?.fontFamily ?? 'sans-serif', // Explicit preliminary choice.
  textSamples, // Authored text node IDs -> legal longest labels/counter strings.
  // fontFaces: delivered fonts keyed by data.font.assetRef, already loaded and registered.
  // camera: the same authored game-view connection when this UI uses a reference plane.
});
```

This returns computed nodes/diagnostics and textMeasurements, including measured values and candidate-font versus registered-font basis. It does not render a screen or certify glyph coverage or aesthetics. Computed nodes contain id, bounds, layout and diagnostic fields, not the authored style/text/role; use id to associate each result with its original source node when consuming geometry. Missing referenced font files must not silently become verified fallback metrics. Inspect complete rendered compositions with the delivered fonts, and recheck affected text/rendering when inputs change.

The target runtime may consume the projected rectangles or map these relationships to native containers. It must retain the authored hierarchy and responsive rules, not invent a second layout. Check actual rendered rectangles against the data at the same container size.
