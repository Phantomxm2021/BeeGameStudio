# Game Development Workflow

Work within the current assignment, using its brief, selected pictures, configuration, existing design and actual progress. Start at the first unresolved dependency below, rather than repeat completed work. Design-only, resource-only and repair assignments keep their own stopping points; required design review and handoffs remain with the existing task. This workflow requires no additional document, approval or Agent.

## Resolve dependencies before expanding work

| Current work | Methods to use for its open questions | Basis for continuing |
| --- | --- | --- |
| Establish the player experience | [Systems](../game-systems-designer-expert/SKILL.md) for rules; [Art](../game-art-director-expert/SKILL.md) for selected appearance; [UI](../game-ui-ux-designer/SKILL.md) for information/actions; [Scene](../game-scene-designer/SKILL.md) for playable arrangements. | The action, consequence, required information and adopted visual relationships can coexist under the confirmed platform and inputs. Reuse resolved decisions; develop only the gaps within the assignment. |
| Obtain and prepare appearance/sound inputs | [Pipeline](../game-content-pipeline-engineer/SKILL.md) for visual acquisition and preparation under its source order; [Audio](../game-audio-designer/SKILL.md) for the required audible expression. | The adopted resources preserve the required shapes, material treatment, states or sound identity at gameplay size. Use existing suitable material or relevant production evidence. If fit is unresolved, resolve the smallest consequential part within the applicable source before expanding across a resource family or the whole game. |
| Implement a representative player situation | The selected engine's APIs/documentation, [UI](../game-ui-ux-designer/SKILL.md), [Feel](../game-feel-designer/SKILL.md) and the relevant Art/Audio methods. | Bring the adopted inputs into the actual scene, camera and controls. Follow one required action through its visible/audible consequence at play speed, comparing the affected appearance with the selected design before extending content. A diagnostic placeholder answers only its behavior question; it does not establish the final appearance. |
| Complete and verify the authorized scope | [Playtest](../game-playtest-performance/SKILL.md), reusing applicable observations. | Actual outcomes and adopted presentation hold under the required inputs and display conditions. Retain observed defects and unverified conditions; fix the affected source or implementation and retest that scope. A local visual defect does not reopen the whole direction. |

These are dependencies within the assignment, not four new stages or a requirement to load every linked Skill. Read the method for the decision being made, reusing sufficient guidance already in context. Use [Creative](../game-creative-director-expert/SKILL.md) only for an unresolved player promise or direction; a selected direction does not need another candidate-selection round.

Honor explicit runtime choices and existing projects. For a new Web game, a React selection specifies the host. Default the game scene to [Phaser 4](../phaser4-gamedev/SKILL.md) for 2D or [Three.js](../threejs-gamedev/SKILL.md) for 3D. Unity, Godot, Unreal and other selected engines use their own native facilities. The working criteria come from this game's adopted design and target conditions, not a fixed palette, layout, numeric aesthetic score or browser-only abstraction.
