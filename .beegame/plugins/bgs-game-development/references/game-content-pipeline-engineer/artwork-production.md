# Artwork production

## Preserve appearance and separable parts

Use confirmed source requirements and the owning design's shapes, proportions, materials and scene behavior, including environmental activity; a selected reference image is not required. For the planned parts, retain exposed coverage behind moving artwork and front/back parts or masks for intended occlusion. A fixed camera does not imply a motionless environment; parallax serves camera movement, not a required layer recipe.

Choose the required silhouettes, proportions, materials, lighting and visible state changes at gameplay size. When control, contact, occlusion or resizing affects the representation, use the relevant [assembly example](runtime-assembly-examples.md): place artwork with anchors/transforms and independent collision geometry; compose occlusion with ordered parts or masks; resize skins by their fixed and stretchable regions. For the first concrete realization of a broad style, or a consequential unresolved appearance choice, use the shared [finished-picture comparisons](../game-art-director-expert/ui-visual-hierarchy.md#finished-game-references); reuse the adopted project sources once established.

## Produce or revise selected artwork

For authorized AI image production, carry the chosen appearance into the planned static entries or temporal changes using the current tool help. A rejected generation prompt needs its input corrected; a prompt-check outage is not evidence that the image provider cannot produce the artwork. Static entries need complete elements with suitable separation; temporal entries need the actual ordered visual changes defined by the project. Use the [spritesheet/atlas method](spritesheet-production.md) for layout and preparation, loading character or effect details only when that material needs them. Keep live labels, counters, progress and hit areas out of UI skins.

For a local revision, start from the adopted asset and isolate the affected layer, path, element or state. Choose the change by its actual defect or authorized new appearance, retaining the usable silhouette, proportions, material, lighting and contact relationships outside that change. Work in the editable source when available; layers or masks can retain surrounding pixels while changing a local region. Selected AI edits use the actual image as the edit target through the system imagegen Skill, rather than regenerating the whole subject from a description. A requested preservation is not proof that the delivered image kept it.

Carry the result back into its existing bindings. An edit retaining the source-pixel frame layout and contact locations can keep its regions and anchors; cropping or moving content changes that basis. For a crop beginning at source point `(8, 4)`, a hook at `(20, 12)` becomes `(12, 8)` in the cropped image. Preserve that attachment by adjusting the existing anchor/offset, or retain the original canvas layout when appropriate. Measure resized or redrawn contacts from the delivered image. Repacking updates affected named regions and consumer bindings, not the logical identity of unchanged entries. Retain editable sources and compare the changed part at its runtime size, including its alpha edge and neighboring parts.

[GIMP's layer-mask documentation](https://docs.gimp.org/3.0/en/gimp-dialogs-structure.html) illustrates local transparency control; [canvas sizing](https://docs.gimp.org/3.0/en/gimp-image-resize.html) distinguishes changing image bounds from scaling its contents. These explain editing operations, not a required editor or an additional production stage.

## Prepare delivered sheets and atlases

For supplied, sourced or generated sheets/atlases, locate each static element in the actual image and record its source-pixel bounds for import. For a compatible family consumed by region, deliver the shared atlas and named bounds rather than exporting a file per object. Separate controls can select regions of the same image. Export complete, separable parts only for a consumer that needs independent files or for processing that changes the pixels; use the existing media tools and retain the resulting bindings. Keep any generation master and the source provenance; deliver and check both representations only if distinct consumers need both. Register the selected runtime files and their dependencies. Cropping cannot remove an occluding object, recover hidden artwork or create transparency from painted background pixels; a flat concept is not a layered source or a ready runtime atlas.

## Integrate when in scope

Assemble the selected artwork with its live controls, text and effects. Procedural noise, emission, trails and shader composition serve the required effects; painted detail and changing material silhouettes still need their artwork. When producing or importing effect textures or flipbooks, use [effect textures and sequences](../game-art-director-expert/vfx-craft.md#effect-textures-and-sequences) for representation, extraction and blend choices. For 3D/XR, use compatible models, materials and rigs to realize the selected design; an image derivative supplies only an applicable texture, not missing geometry or animation.

Within implementation, bring the first critical parts into one representative player situation with the actual scene, camera and UI. Follow the required action through its visible and audible consequence to resolve construction questions before extending the treatment. Resource-only work can use an asset composition or preview and retain the runtime integration still needed. Reuse sufficient existing observations; this is construction feedback within the assignment, not a second full acceptance pass.

Inspect delivered parts against the owning appearance definitions for shape, material, proportions and required states; a shared style label is insufficient. Reuse the acquisition/processing tools' saved file and provenance facts, then bind the delivered parts in the target's native scene/UI implementation when in scope. Those file facts do not establish agreement with the design. If a required part cannot be produced within authorization, retain the specific dependency rather than relabel a substitute as final.

## Transparent output in use

Judge transparent artwork composited over its intended surface and a contrasting
light or dark surface with the intended filtering. An image viewer's backdrop is
not a painted pixel; alpha metadata establishes the channel, not edge quality.
Repair visible baked halos in that composition without clipping soft edges or
glow. Preserve atlas separation for the consumer's filtering.
