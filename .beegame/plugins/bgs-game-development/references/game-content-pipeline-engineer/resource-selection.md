# Resource Matching and Small Samples

Use for unresolved sources of required images, audio, models or other resources. Visual parts fully expressed by native capabilities while preserving the established art requirements and explicit source constraints need no asset-source search; other required visual inputs in the same subject remain within this source order. For audio, apply [Audio's production choice](../../skills/game-audio-designer/SKILL.md#choose-and-produce-the-audible-roles) to determine the required inputs. Preserve explicit user source choices, suitable supplied assets and adopted project sources. For each remaining resource family, search the self-hosted resource library first, then suitable Web sources, then use authorized AI generation; programmatic drawing as a replacement for missing artwork is the final fallback. Move on when the preceding source cannot provide a usable, licensed match, and stop once a suitable source is found. Keep searches relevant and bounded rather than browsing whole catalogs. Unavailable access is an access failure, not an empty library.

For game subjects, environments and UI artwork, use [artwork production](artwork-production.md) to assess usability against GDD appearance definitions and any selected pictures. Match actual shapes, proportions, viewing angle, materials and actions rather than category/style labels. Respect explicit user budgets and source exclusions.

Select candidates within the chosen production method by required appearance, states, readable cues, runtime format and quality. Keep unresolved appearance choices with their owning design decisions. For supplied, sourced or generated sheets/sequences of any subject, use the shared [spritesheet/atlas method](spritesheet-production.md) to preserve entry identities, temporal order where applicable, and actual consumer use. Read character or VFX specialist methods only for their particular production questions. For 3D animation, acquire compatible models, rigs and clips; generated images can supply textures for those assets. Keep unavailable required inputs explicit.

The catalog returns `items`, `total`, `facets` and optional `nextCursor`. Use returned facets for structured filters and paginate only as needed. `readyElementCount` counts technically browsable files, not proven game-role matches. Empty `usageTags` means unclassified, not unavailable: inspect or audition the candidate. An access error is not an empty result, and semantic `no-match` is not proof that no files exist. An explicit `fetch` resolves and downloads the selected element's complete declared dependency closure, preserving each dependency's parent key, reference path and local path in the acquisition result. Retain the acquisition tools’ actual delivered-file facts and concise query/download evidence and material rejection reasons in existing implementation progress, without inventing a sourcing history or requiring a report for every discarded candidate.

For a concrete source-family comparison, use the [environment, UI/font and audio sample criteria](production-integration.md#matching-a-source-family).

Compare only consequential candidates, without downloading whole catalogs or creating another procurement report. Keep source choices, fallback constraints and material rejection reasons with existing production decisions; retain delivered-file facts and licenses with the actual acquisition records. The GDD retains appearance goals, product constraints and explicit user source requirements. Revise it for an actual design conflict or authorized change, rather than recording routine sourcing facts or preselecting a drawing method. Verify the actual source and asset license when importing; repository code licensing does not automatically license its fonts or sounds.

A fallback must preserve the required function and selected treatment. If it would replace a required visual/audio identity, change geometry or remove a state, identify the actual dependency and obtain the necessary decision rather than silently treating a placeholder as final. Resource presence, binding resolution and runtime consumption establish different things.

For a loading or runtime-memory question, use [loading and resource representation](../game-art-director-expert/runtime-cost-tradeoffs.md#loading-and-resource-representation). Source selection alone does not require that reference or a profiling pass.
