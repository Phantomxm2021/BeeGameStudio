# Producing and reconciling visual designs

Use for authorized direction exploration, commissioned concepts or reconciling selected pictures with production. Source study alone does not select a direction or authorize assets/implementation. Initial exploration can use the confirmed brief, configuration and references before a GDD exists; existing designs retain their applicable GDD and selected pictures.

## Explore the unresolved appearance

Start from the player situation: what must be recognized, done and felt? Use [visual studies](ui-visual-hierarchy.md) to compare actual subjects, proportions, layers, material and world/UI relationships. Separate observed facts, proposed interpretations and confirmed decisions. Study only a missing basis; an established design needs no renewed style search for a local repair.

Compare alternatives at the same player moment. Keep confirmed facts shared while letting genuinely open composition, material and transition relationships differ. Picture-based exploration uses suitable supplied designs or authorized system `imagegen`. Describe the scene/UI relationship and relevant visible details rather than paste whole GDD sections or hidden implementation rules. Do not replace image exploration with a fully implemented HTML/CSS/SVG/Canvas concept. A consequential dynamic/feel uncertainty can instead use a simple local prototype; it need not implement the whole game. Static pictures cannot resolve timing, interaction or sound.

Preserve selected subjects, proportions, spatial/material relationships and information hierarchy. A new palette or matching theme alone does not preserve the design. Reconcile a demonstrated weakness in its owning decision rather than reopen the direction for novelty. A picture cannot add mechanics, controls or gameplay rules.

## Commission and inspect screen concepts

For an actual screen-concept assignment, describe each player situation, necessary information/actions, chosen composition and open visual details. Show one complete player-visible state per panel. Conditional copy/value/control variants may share a composition when they need no new layout/art; a missing key element, action or genuinely different composition remains a gap. State coverage is not panel count. Entity actions and internal transitions do not automatically require new screens or buttons.

Gameplay camera/visibility constraints apply to scenes retaining play; titles and standalone results follow their own composition. Use meaningful working copy unless wording is user-fixed. Request target aspect ratio; choose any board/atlas layout from needed representations, not a fixed panel quota. A requested layout is not measured output geometry, and usable concepts need not be regenerated solely for ratio deviation.

Inspect the actual concepts for the assigned subjects, information/actions, hierarchy and visual direction. Repair omissions/contradictions preventing that design from being represented; retain usable compositions. A generated panel does not prove motion or runtime correctness. Production details belong in the affected resource/runtime work, not another concept resubmission.

## Hand off the selected expression

Use the existing source record to identify selected images/panels, relevant requirements, editable sources if present and consequential adaptations/open choices. Distinguish inspiration, selected design and actual runtime assets. Pass adopted material to consumers rather than ask them to choose among intermediate captures. Actual dimensions come from decoded metadata, not requested sizes.

Carry the selected appearance and intended behavior into [resource production](../../skills/game-content-pipeline-engineer/SKILL.md), which derives usable parts, frame contents and layout for their consumers. A flattened board is not a ready-made set of runtime parts. Shared scale, pivots and coordinates matter for modular assembly. Keep known provenance/rights and actual adopted paths. A failed method leaves required art unresolved rather than authorize generic replacements.

Record intended visible changes with their owning states; animation completion is not a gameplay event. Keep design intent in the current design source and runtime details with their implementation. Updating an agreed appearance does not inherently require rewriting the GDD; revise it only for an actual design contradiction or authorized change.

## Reconcile an implementation within its scope

During authorized implementation, use the smallest player situation resolving camera, scale, occlusion, input or timing uncertainty. For 3D, inspect real scene views; a concept cannot establish navigable space. Compare selected subjects, contacts, scale, scene/UI relationships and material/light treatment. The [scene study](../game-scene-designer/encounter-design-patterns.md#worked-scene-study-an-existing-platformer) pairs a picture with its scene/state/sound sources when that comparison is relevant.

Use the existing preview/capture tools and retain relevant viewport, state and input conditions. Capture settled fonts/images; viewport changes alone do not emulate touch. Reuse valid observations, distinguishing an adopted-design loss from an untested experience hypothesis or alternative preference. Stills establish composition, not motion, input or audio; observe those only when their implementation/verification is in scope. No extra approval or review stage is implied.
